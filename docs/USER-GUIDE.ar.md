## 1. نظرة عامة على النظام

CoreFusion عبارة عن لوحة إدارة وكيل متعددة البروتوكولات تدعم VLESS وVMess وTrojan وShadowsocks وHysteria2 وTUIC والمزيد، مع إدارة العقد وتسليم الاشتراك وإدارة العملاء والفوترة والشهادات والوكلاء المتسلسلين.

### 1.1 الميزات الأساسية

| الوحدة النمطية | الوصف |
|--------|-------------|
| متعدد البروتوكولات | VLESS، VMess، Trojan، Shadowsocks، Hysteria2، TUIC، WireGuard، إلخ. |
| متعدد النواة | Xray-core وsing-box (Hysteria2/TUIC وبروتوكولات QUIC الأخرى تعمل على sing-box) |
| متعدد العقدة | خمسة أنواع من العقد: مستقلة، مرآة، نشطة/استعدادية، دخول متسلسل، خروج متسلسل |
| تسليم الاشتراك | تنسيقات الاشتراك المتعددة ونقاط النهاية وإدارة التنسيق |
| الفواتير | قوالب الخطط، بطاقات الشحن، الرصيد، الطلبات، عمولة الموزع |
| الشهادات | دعونا نقوم بتشفير الإصدار، والتحقق من صحة DNS-01/HTTP-01، وتوزيع الشهادات |
| وكيل بالسلاسل | موازنة التحميل متعددة المخارج، وتسجيل العقدة الخارجية، والتوجيه المتسلسل |
| حصص المرور | مراقبة حركة المرور الشهرية لكل عقدة، والتعليق التلقائي، وإعادة تعيين السجلات |
| البوابة | محرر البوابة المرئية، قوالب مخصصة متعددة اللغات |
| الإخطارات | البريد الإلكتروني وTelegram والقوالب وعمليات البث |

### 1.2 الهندسة المعمارية

- **الخلفية**: انطلق، gRPC
- **الواجهة الأمامية**: Vue 3 + Element Plus
- **قاعدة البيانات**: SQLite (افتراضي) / MySQL / PostgreSQL
- ** الوكيل **: الوكيل العكسي Caddy / Nginx
- **منفذ اللوحة**: يتم تعيينه بواسطة معالج الإعداد (منفذ مجاني عشوائي بشكل افتراضي؛ 8080 هو خيار شائع)
- **منفذ gRPC للوكيل**: 18443 بشكل افتراضي

## 2. التثبيت

### 2.1 البيئات المدعومة

| البند | الدعم |
|------|---------|
| توزيعات | ديبيان / أوبونتو، RHEL / CentOS / Rocky / AlmaLinux / Fedora، Alpine، Arch، openSUSE |
| بنيات وحدة المعالجة المركزية | الثنائيات الرسمية: `amd64`، `arm64`؛ تدعم إصدارات المصدر أيضًا `armv7`، و`armv6`، و`386`، و`ppc64le`، و`s390x`، و`riscv64`، و`loong64` |
| مدير الخدمة | systemd (مستحسن)؛ يعود إلى `nohup` في الحاويات أو البيئات الأخرى التي لا تحتوي على systemd |
| الذاكرة / القرص | ≥ 1 جيجابايت / ≥ 10 جيجابايت (قاعدة البيانات والشهادات والسجلات والثنائيات الأساسية موجودة في دليل البيانات) |
| منفذ اللوحة | تم اختياره في معالج الإعداد (المنفذ الحر العشوائي افتراضيًا؛ `8080` وما شابه جيد) |
| وكيل جي آر بي سي | `18443` بشكل افتراضي |

يتم تثبيت أوامر وقت التشغيل الخارجية تلقائيًا بواسطة برنامج التثبيت (`scripts/install.sh` والبرنامج النصي لتثبيت Agent الذي تم إنشاؤه بواسطة اللوحة؛ قم بالتخطي باستخدام `--no-deps` / `CF_SKIP_DEPS=1`):

| الغرض | الحزمة |
|---------|---------|
| جدار الحماية / حد المعدل / وضع علامات التزامن | `nftables` (`nft`) |
| تشكيل حركة المرور والروابط والمآخذ | `iproute2` (`tc` / `ip` / `ss`) |
| الإجراء الاحتياطي عندما لا يكون nft متاحًا | `iptables` (`iptables-nft` على EL8+، `iptables` على EL7) |
| تتبع الاتصال | `conntrack-tools` (`conntrack`) |
| تحميل `nf_conntrack` / `ifb` | `kmod` (`modprobe` / `lsmod`) |
| الكشف عن العملية والتنظيف | `procps` (`pgrep` / `pkill`) |
| فحص المنفذ / معلمات DH | `lsof` / `openssl` |
| إنشاء مستخدم الوكيل | `shadow-utils` (ديبيان `passwd`، جبال الألب/قوس `shadow`) |
| التنزيلات والمحفوظات | `curl` / `ca-certificates` / `tar` / `gzip` / `xz` |

> يؤثر فقدان `nft` / `tc` فقط على ميزات تحديد المعدل وجدار الحماية؛ لا تزال اللوحة تبدأ.
> قم بتشغيل `--cpu-info` أولاً لمعرفة كيفية اكتشاف البيئة والحزم المفقودة.

### 2.2 التثبيت في سطر واحد (مستحسن)

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh -o install.sh
sudo bash install.sh
```

أو قم بتوجيهه مباشرةً (بدون تفاعل، ولا توجد علامات إضافية):

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash
```

البرنامج النصي سوف:

1. اكتشاف التوزيع وبنية وحدة المعالجة المركزية وlibc، ثم تثبيت الحزم الأساسية وتبعيات وقت التشغيل؛
2. قم بتنزيل `corefusion-linux-<arch>` من إصدارات GitHub وتحقق منه باستخدام `.sha256` المطابق؛
3. التثبيت على `/opt/corefusion` وإنشاء `data/{sqlite,certs,logs,runtime}`؛
4. اكتب فقط عنصرًا نائبًا `.env` مع `SAFE_PATHS=data` - لا يوجد تكوين لقاعدة البيانات - بحيث تدخل البداية الأولى إلى معالج الإعداد (يتم إنشاء `.env` الكامل بواسطة المعالج)؛
5. تثبيت خدمة systemd وبدء تشغيلها (أو تشغيلها تحت `nohup` عندما لا يكون systemd متاحًا)؛
6. انتظر حتى تصبح جاهزًا، ثم اطبع مسار الإعداد URL والرمز المميز والدليل.

مثال الإخراج:

```text
==================================================================
 CoreFusion installation complete
------------------------------------------------------------------
 Install dir : /opt/corefusion
 Data dir    : /opt/corefusion/data
 Binary      : /opt/corefusion/corefusion
 Logs        : journalctl -u corefusion -f
------------------------------------------------------------------
 Setup wizard : http://<server-ip>:<random-port>/init?init_token=<token>
 Setup token  : <token>
 Valid for    : 2 hours (see startup log)
 Note         : the token is shown once; after setup this port closes and the panel switches to its normal port.
==================================================================
```

إذا كانت اللوحة تستمع فقط إلى `127.0.0.1` (على سبيل المثال خلف وكيل عكسي)، فسيقوم البرنامج النصي بطباعة أمر نفق SSH بدلاً من URL الذي لا يمكن الوصول إليه.

> فقدت الرمز؟ اقرأ سجل بدء التشغيل مرة أخرى: `journalctl -u corefusion -n 50 --no-pager`
> (بدون systemd: `tail -n 50 /opt/corefusion/data/logs/panel.log`).

### 2.2.1 إخراج متعدد اللغات

يشتمل برنامج التثبيت على أربع لغات لواجهة المستخدم: الصينية المبسطة، والإنجليزية، والفارسية (فارسی)، والروسية (Русский). يقوم بالكشف التلقائي عن نظام `LANG`، أو يمكنك الاختيار بشكل صريح:

```bash
# English
sudo bash install.sh --lang en

# Persian via environment variable
sudo CF_LANG=fa bash install.sh

# Pass options through a pipe
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash -s -- --lang ru
```

القيم المدعومة: `zh` / `en` / `fa` / `ru`؛ يتم قبول `--lang=ru` أيضًا. تفشل القيمة الصريحة غير المدعومة مع قائمة اللغات المتوفرة.

### 2.3 تثبيت الإصدار / المرايا / التثبيت دون اتصال

```bash
# Pin a version
sudo bash install.sh --version v0.13.0

# GitHub download mirror (used as a URL prefix)
sudo bash install.sh --mirror https://ghproxy.net --version latest

# Use a local binary (offline / intranet / pre-built)
sudo bash install.sh --local ./dist/corefusion-linux-arm64

# Explicit target architecture
sudo bash install.sh --arch arm64 --local ./corefusion-linux-arm64
```

> بدون `--version`، يستخدم البرنامج النصي أحدث إدخال في قائمة إصدارات GitHub.
> معظم الإصدارات هي إصدارات مسبقة، لذلك لا يتم استخدام نقطة النهاية `/releases/latest`.
>
> الإصدارات الرسمية توفر فقط `amd64` / `arm64`؛ استخدم `--source` أو ثنائي مترجم مع `--local` للبنيات الأخرى.

### 2.4 البناء من المصدر

```bash
sudo bash install.sh --source --version v0.13.0
```

يقوم `--source` باستنساخ المستودع (أو يستخدم عملية السحب الموجودة عندما يكون البرنامج النصي بداخله) ويقوم بتشغيل `make panel`. يتم اختيار إصدارات Toolchain لكل بيئة:

| التبعية | التحديد |
|------------|-----------|
| اذهب | القراءة من `toolchain` / `go` في `go.mod` (حاليًا **Go 1.27+**)؛ إذا كان إصدار النظام قديمًا جدًا، فسيتم تنزيل سلسلة الأدوات المطابقة إلى `<install-dir>/.toolchain` |
| عقدة | **العقدة 22 LTS** افتراضيًا (يتطلب Vite ≥ 18)؛ يتم تنزيل الإصدار الرسمي المطابق عند الحاجة |
| العقدة (glibc <2.28) | يستخدم الإصدار `unofficial-builds` glibc-217 (على سبيل المثال CentOS 7) |
| العقدة (جبال الألب / musl) | يستخدم التوزيع `nodejs` / `npm` |

التجاوزات:

```bash
# Force Go / Node versions
sudo CF_GO_VERSION=1.27.5 CF_NODE_MAJOR=22 bash install.sh --source

# Go toolchain mirror (default https://go.dev/dl)
sudo CF_GO_MIRROR=https://golang.google.cn/dl bash install.sh --source
```

البناء اليدوي (التطوير / التصحيح):

```bash
git clone https://github.com/qist/corefusion.git
cd corefusion

# Frontend + panel for the current architecture; the frontend is embedded via go:embed
make panel

# Cross-compile
make panel-linux-amd64
make panel-linux-arm64
```

> `go build ./...` لا ينتج ثنائي. قم ببناء اللوحة باستخدام
> `go build -o corefusion ./cmd/corefusion/` أو `make panel`.

### 2.5 أعلام المثبت

| العلم | الوصف |
|------|-------------|
| `-d, --dir <PATH>` | دليل التثبيت، الافتراضي `/opt/corefusion` |
| `-v, --version <TAG>` | نسخة اللوحة، على سبيل المثال. `v0.13.0`; الافتراضي `latest` |
| `--binary` | استخدم الإصدار الثنائي GitHub (افتراضي) |
| `--source` | البناء من المصدر وإعداد مطابقة Go / Node |
| `--local <FILE>` | استخدام ثنائي محلي (تثبيت دون اتصال) |
| `--arch <ARCH>` | بنية الهدف: `amd64` / `arm64` / `armv7` / `armv6` / `386` / `ppc64le` / `s390x` / `riscv64` / `loong64` |
| `--mirror <URL>` | بادئة التنزيل GitHub، على سبيل المثال. `https://ghproxy.net` |
| `--repo <URL>` | مستودع المصدر، الافتراضي `https://github.com/qist/corefusion.git` |
| `--ref <REF>` | فرع / علامة المصدر؛ الإعدادات الافتراضية هي `--version`، وإلا `main` |
| `--no-deps` | تخطي تثبيت تبعية النظام |
| `--no-start` | تثبيت وكتابة ملف الخدمة دون البدء |
| `--cpu-info` | قم بطباعة الكشف عن البيئة والتبعيات المفقودة، ثم قم بالخروج |
| `--lang <LANG>` | لغة الإخراج: `zh` / `en` / `fa` / `ru` (الافتراضي: نظام `LANG`) |
| `--uninstall` | إيقاف الخدمة وإزالة البرنامج (يحتفظ بالبيانات و`.env`) |
| `--purge` | باستخدام `--uninstall`، قم أيضًا بإزالة دليل البيانات و`.env` |

> الإصدارات الرسمية تشحن فقط الثنائيات `amd64` / `arm64`. تتطلب البنى الأخرى `--source`،
> وإلا فإن التنزيل يعود 404.

متغيرات البيئة ذات الصلة:

| متغير | الغرض |
|----------|---------|
| `CF_GO_VERSION` | تجاوز إصدار Go المطلوب للبنيات المصدر |
| `CF_NODE_MAJOR` | تجاوز إصدار Node الرئيسي (الافتراضي 22) |
| `CF_GO_MIRROR` | اذهب إلى مرآة تنزيل سلسلة الأدوات |
| `CF_SKIP_DEPS` | اضبط على `1` في البرنامج النصي لتثبيت Agent لتخطي تثبيت التبعية |
| `CF_LANG` | تجاوز لغة إخراج المثبت (مثل `--lang`) |

### 2.6 تخطيط الدليل

```text
/opt/corefusion/
├── corefusion                 # panel binary
├── corefusion.bak             # previous version (when upgrading)
├── .env                       # environment file (0600, generated by the setup wizard)
├── .env.secret                # encryption key file (0600, generated on first start)
├── .toolchain/                # Go / Node downloaded for source builds
└── data/                      # data directory (SAFE_PATHS)
    ├── sqlite/app.db          # default SQLite database
    ├── certs/                 # certificates and keys
    ├── logs/                  # runtime logs (without systemd)
    ├── runtime/               # core runtime config and state
    ├── binaries/              # downloaded xray / sing-box cores
    └── proxy/                 # proxy (Caddy/Nginx) sites and config
```

> يقوم المثبت بإنشاء `sqlite/` و`certs/` و`logs/` و`runtime/` فقط؛ يتم إنشاء `binaries/`، `proxy/`، `rules/` وغيرها بواسطة اللوحة أو عند تثبيت النوى.
> يأتي دليل البيانات من `SAFE_PATHS` في `.env` وقد يكون مسارًا مطلقًا. لا يؤدي تغيير دليل التثبيت إلى نقل البيانات الموجودة.

### 2.7 إدارة الخدمة

systemd (معظم التوزيعات):

```bash
systemctl status corefusion --no-pager
systemctl restart corefusion
systemctl stop corefusion
journalctl -u corefusion -f          # follow logs
journalctl -u corefusion -n 100      # last 100 lines
```

بدون systemd (الحاويات، وما إلى ذلك):

```bash
cd /opt/corefusion && ./corefusion            # foreground (debugging)
cd /opt/corefusion && setsid nohup ./corefusion >> data/logs/panel.log 2>&1 &
tail -f data/logs/panel.log
```

> بدون systemd، لا تبدأ العملية عند التمهيد؛ أعد تشغيله يدويًا بعد إعادة التشغيل (أو أعد تشغيل برنامج التثبيت).

### 2.8 الترقية وإلغاء التثبيت

الترقية (تحتفظ بالبيانات والتكوين):

```bash
sudo bash install.sh --version <new-version>
```

يقوم البرنامج النصي بإيقاف الخدمة، وعمل نسخة احتياطية للملف الثنائي القديم باسم `corefusion.bak`، واستبداله وإعادة التشغيل. يتم ترك `.env` و `data/` الحاليين دون تغيير.

إلغاء التثبيت:

```bash
# Remove the program only; keep data and .env
sudo bash install.sh --uninstall

# Also remove the data directory and .env (irreversible)
sudo bash install.sh --uninstall --purge
```

### 2.9 ملف البيئة (.env)

يتم إنشاء `.env` الكامل ** بواسطة معالج الإعداد ** عند حفظ التكوين (قاعدة البيانات DSN، دليل البيانات، الأسرار، المنافذ، المجالات).

في عملية تثبيت جديدة، يكتب المثبت هذا العنصر النائب فقط، وبالتالي لا تخطئ اللوحة في أن `data/` الموجود هو تثبيت مبدئي وتتخطى المعالج:

```env
SAFE_PATHS=data
```

> عندما يكون التكوين الكامل (`.env` مع `CF_DB_DSN`) موجودًا بالفعل، فلن يقوم المثبت بالكتابة فوقه مطلقًا ولن يظهر المعالج مرة أخرى.
> تدخل التعديلات اليدوية اللاحقة على `.env` حيز التنفيذ بعد إعادة التشغيل.

#### دليل البيانات

```env
SAFE_PATHS=data                       # relative to the install directory
# SAFE_PATHS=/srv/corefusion-data     # or an absolute path
```

#### قاعدة البيانات

تم اكتشاف `CF_DB_DSN` بواسطة البادئة:

| بادئة | قاعدة البيانات |
|--------|----------|
| غير محدد أو طريق عارية | SQLite (افتراضي) |
| `sqlite://` | SQLite (صريح) |
| `mysql://` | MySQL |
| `postgres://` / `postgresql://` | PostgreSQL |

`CF_DB_TYPE` اختياري ويتجاوز الكشف (`sqlite` / `mysql` / `postgres`).

> **كلمات المرور المشفرة**: MySQL/PostgreSQL DSNs المكتوبة بواسطة اللوحة (معالج الإعداد / مفتاح قاعدة البيانات)
> يتم تخزينها في `.env` كـ `enc:...` (AES-256-GCM، المفتاح `CF_SECRET_ENCRYPTION_KEY`).
> يتم فك تشفيرها عند القراءة؛ لا تزال أرقام DSN ذات النص العادي المكتوبة يدويًا تعمل.

**SQLite (افتراضي)**

```env
# Bare path (detected as SQLite)
CF_DB_DSN=data/sqlite/app.db

# Or explicit sqlite:// prefix
CF_DB_DSN=sqlite:///opt/corefusion/data/sqlite/app.db
```

**MySQL**

```env
# Format: mysql://user:password@tcp(host:port)/dbname?params
CF_DB_DSN=mysql://corefusion:password@tcp(127.0.0.1:3306)/corefusion?charset=utf8mb4&parseTime=True&loc=Local
```

**PostgreSQL**

```env
# Format: postgres://user:password@host:port/dbname?params
CF_DB_DSN=postgres://corefusion:password@127.0.0.1:5432/corefusion?sslmode=disable
```

#### تجمع الاتصال (اختياري، MySQL/PostgreSQL)

```env
CF_DB_MAX_OPEN_CONNS=100
CF_DB_MAX_IDLE_CONNS=10
```

#### المتغيرات المشتركة الأخرى

| متغير | الوصف |
|----------|-------------|
| `JWT_SECRET` | مفتاح التوقيع لرموز تسجيل الدخول؛ تم إنشاؤها عند البداية الأولى عند فقدانها |
| `CF_SECRET_ENCRYPTION_KEY` | مفتاح تشفير الإعدادات الحساسة (AES-256-GCM)؛ تم إنشاؤها عند فقدانها |
| `CF_INITIAL_ADMIN_PASSWORD` | كلمة مرور المسؤول الأولية (اختيارية؛ عشوائية ويتم طباعتها مرة واحدة بشكل افتراضي) |
| `CF_NETWORK_TRAFFIC_ACCOUNTING` | اضبط على `0` لتعطيل حساب حركة المرور المستند إلى iptables (ممكّن افتراضيًا) |
| `CF_NETWORK_TRAFFIC_TABLE` | جدول iptables المستخدم لحساب حركة المرور، الافتراضي `corefusion` |

> **يعيش مفتاح التشفير في `.env.secret`**: عند البداية الأولى، تتم كتابة `CF_SECRET_ENCRYPTION_KEY` إلى `.env.secret` (0600، نفس الدليل مثل `.env`) بدلاً من `.env`؛ يتم ترحيل المفتاح القديم في `.env` تلقائيًا. قم بعمل نسخة احتياطية من هذا الملف بشكل منفصل - ففقدانه يجعل كل قيمة `enc:` غير قابلة للتشفير.

> لم يعد يتم تكوين الوكلاء العكسيين الموثوق بهم لحل عناوين IP للعميل الحقيقي عبر متغيرات البيئة؛
> يتم تخزينها كـ `panel.trusted_proxies` في **الإعدادات → الشبكة**.

> يحتوي كل من `.env` و`.env.secret` على أسرار؛ تقوم اللوحة بتشديد أذوناتها على `0600` عند البداية. لا ترتكبهم أبدًا.

### 3.2 خطوات المعالج

المعالج لديه 8 خطوات. يمكنك العودة في أي وقت. لا يتم الالتزام بأي شيء حتى الحفظ النهائي.

| خطوة | المحتوى |
|------|---------|
| 1. قاعدة البيانات | SQLite / MySQL / PostgreSQL |
| 2. دليل البيانات | مكتوب على `SAFE_PATHS` في `.env` |
| 3. مفاتيح التشفير | `JWT_SECRET` و`CF_SECRET_ENCRYPTION_KEY` |
| 4. النوى | أي النوى الوكيل لتثبيت |
| 5. الوكيل | لا شيء/Nginx/Caddy |
| 6. المواقع والمجالات | المنافذ، مسار الويب، حساب المسؤول، العملة، المنطقة الزمنية، المجالات |
| 7. شهادة HTTPS | معطل/تحميل/ACME |
| 8. ملخص | قم بمراجعة وتنزيل `.env` وحفظه وإعادة تشغيله |

#### الخطوة 1: قاعدة البيانات

- **SQLite (ملف محلي، مستحسن)**: اترك المسار فارغًا لاستخدام `<data-dir>/sqlite/app.db`.
- **MySQL / PostgreSQL**: المضيف، المنفذ، المستخدم، كلمة المرور، اسم قاعدة البيانات؛ PostgreSQL يدعم أيضًا `disable` / `require` / `verify-full`.
- انقر فوق "اختبار الاتصال" للتحقق من الصحة. الحفظ يختبره أيضًا. يتم إنشاء قاعدة البيانات المفقودة تلقائيًا (قم بإنشائها يدويًا إذا كان الحساب يفتقر إلى `CREATE`).
- يتم تشفير DSN (بما في ذلك كلمة المرور) قبل كتابته إلى `.env`.

#### الخطوة 2: دليل البيانات

يخزن قاعدة البيانات والشهادات والسجلات والثنائيات الأساسية والمزيد؛ هذا هو `SAFE_PATHS` في `.env`. الإعدادات الافتراضية هي `data`
(نسبة إلى دليل التثبيت)؛ يُسمح بالمسار المطلق. **لا تغيرها بشكل عرضي لاحقًا** أو اللوحة
لن تجد قاعدة البيانات والشهادات الموجودة.

#### الخطوة 3: مفاتيح التشفير

- `JWT_SECRET`: علامات تسجيل الدخول المميزة.
- `CF_SECRET_ENCRYPTION_KEY`: يقوم بتشفير الإعدادات الحساسة (كلمة مرور قاعدة البيانات، بيانات اعتماد DNS، بطاقات إعادة الشحن، وما إلى ذلك).
- يتم إنشاء كلاهما بشكل عشوائي بشكل افتراضي؛ استخدم "تجديد" للحصول على قيم جديدة. **تغيير `CF_SECRET_ENCRYPTION_KEY` يجعل البيانات المشفرة مسبقًا غير قابلة للقراءة** — قم بعمل نسخة احتياطية منها.

#### الخطوة 4: النوى

حدد مراكز الوكيل لتثبيتها:

- **Xray**: VLESS / VMess / Trojan / Shadowsocks، وما إلى ذلك؛
- **sing-box**: يحمل Hysteria2 / TUIC وبروتوكولات QUIC الأخرى.

بعد الحفظ وإعادة تشغيل اللوحة، يتم تنزيلها وتثبيتها تلقائيًا. تحقق من الإصدارات والحالة ضمن "البروتوكولات". ويمكنك أيضًا تثبيتها لاحقًا.

#### الخطوة 5: الوكيل

- **لا شيء**: تخدم اللوحة العملاء مباشرة (تعامل مع TLS بنفسك).
- **Nginx / Caddy**: تدير اللوحة الوكيل العكسي واستضافة الشهادات؛ اختر واحدة.

مع تحديد الوكيل، تستمع اللوحة عادةً إلى `127.0.0.1` فقط ويخدم الوكيل العالم الخارجي.

#### الخطوة 6: المواقع والمجالات

| الميدان | الوصف |
|-------|-------------|
| عنوان الاستماع | مشتق تلقائيًا: الوكيل → `127.0.0.1`؛ لا يوجد وكيل بشهادة → `0.0.0.0`؛ خلاف ذلك → `127.0.0.1` |
| منفذ اللوحة | منفذ حر عشوائي بشكل افتراضي؛ قم بتغييره إذا أردت (على سبيل المثال 8080) |
| منفذ الاشتراك | اختياري؛ يشارك `0` منفذ اللوحة |
| ميناء البوابة | اختياري؛ يشارك `0` منفذ اللوحة |
| مسار الويب | مسار واجهة المستخدم الإدارية، `/` الافتراضي؛ API هو دائمًا `/api/v1` |
| اسم المستخدم / كلمة المرور للمسؤول | عشوائي بشكل افتراضي؛ **كلمة المرور تظهر مرة واحدة فقط في الملخص** — احفظها |
| وضع الوصول | "المجال" أو "IP" |
| العملة الافتراضية / المنطقة الزمنية | العملة الافتراضية لبطاقات الشحن والأرصدة. المنطقة الزمنية لسجل اللوحة والوكيل (على سبيل المثال `Asia/Shanghai`) |
| إضافة إلى الوكيل العكسي | عند تعيين الوكيل والمجالات، قم بإضافة مجالات اللوحة / الاشتراك / البوابة الإلكترونية إلى الوكيل دفعة واحدة |

يؤدي إدخال المجالات إلى كتابة الإعدادات المقابلة (مجال رد الاتصال، ونقطة نهاية الاشتراك، ومجال المشاركة).

#### الخطوة 7: شهادة HTTPS

| المصدر | الوصف |
|--------|-------------|
| تعطيل HTTPS | يتم تقديم اللوحة/البوابة/الاشتراكات عبر HTTP (غير آمن)؛ باستخدام وكيل عكسي يمكنك إضافة TLS على جانب الوكيل لاحقًا |
| تحميل الشهادة | لصق شهادة PEM والمفتاح الخاص PEM (وضع الوصول إلى المجال فقط) |
| ACME | يصدر الشهادة عند تقديم هذه الخطوة؛ يدعم المجال وشهادات IP |

خيارات ACME:

- **CA**: Let's Encrypt، Let's Encrypt (Staging)، ZeroSSL، Google Public CA؛
- **الهدف**: المجال الذي تم تكوينه، أو عنوان IP العام (شهادات IP مدعومة بواسطة Let's Encrypt فقط)؛
- **التحدي**: `HTTP-01` (يتطلب المنفذ 80) أو `DNS-01` (أحرف البدل، لا يوجد منفذ 80؛ اختر موفر DNS وأدخل بيانات الاعتماد)؛
- **نوع/حجم المفتاح**: ECC 256/384 أو RSA 2048/3072/4096؛
- **Google CA العام**: يتطلب EAB؛ أدخل معرف المفتاح / HMAC يدويًا أو استخدم حساب خدمة GCP.

> تكتشف شهادات IP تلقائيًا IPv4/IPv6 العام للمضيف. خلف الوكيل، العنوان المكتشف هو عنوان المضيف، وليس مخرج الوكيل.
> يمكن أيضًا إصدار شهادات النطاق لاحقًا ضمن "الشهادات".

#### الخطوة 8: ملخص

يُظهر قاعدة البيانات ودليل البيانات والنوى والوكيل والمنافذ وحساب المسؤول والمجالات ومفاتيح `.env` (أسرار مقنعة)، ويوفر:

- **تنزيل .env**: احتفظ بنسخة من التكوين؛
- **عناوين URL للوصول**: عناوين URL النهائية للوحة/الاشتراك/البوابة؛ تم وضع علامة على HTTP على أنها غير آمنة.

انقر فوق "حفظ وإعادة التشغيل" لكتابة قاعدة البيانات و`.env`؛ تتم إعادة تشغيل اللوحة إلى الخدمة العادية.

### 3.3 بعد الإعداد

- تتم إعادة تشغيل الخدمة ويطبع سجل بدء التشغيل عنوان الاستماع النهائي؛
- قم بتسجيل الدخول باستخدام حساب المسؤول، وقم بالوصول إلى URL ومسار الويب من الملخص؛
- في حالة فقدان كلمة المرور، قم بإعادة تعيينها دون الاتصال بالإنترنت باستخدام `./corefusion admin reset-password`.

### 3.4 إعداد CLI غير التفاعلي

بالنسبة للتشغيل الآلي أو الخوادم بدون رأس، اكتب التكوين وقم بوضع علامة على اكتمال الإعداد مباشرة:

```bash
cd /opt/corefusion
./corefusion init \
  --db-type sqlite \
  --data-dir /opt/corefusion/data \
  --admin-username admin \
  --admin-password 'change-me-strong-password' \
  --listen-port 8080 \
  --proxy-type caddy \
  --cores xray,singbox \
  --panel-domain panel.example.com \
  --tls-mode acme --tls-domain panel.example.com --tls-email you@example.com
```

الأعلام المشتركة:

| العلم | الوصف |
|------|-------------|
| `--db-type` / `--db-host` / `--db-port` / `--db-user` / `--db-password` / `--db-name` | إعدادات قاعدة البيانات |
| `--data-dir` | دليل البيانات؛ الإعدادات الافتراضية هي `SAFE_PATHS` أو `./data` |
| `--listen-port` / `--subscription-port` / `--portal-port` / `--web-path` | المنافذ ومسار الويب (منفذ مجاني عشوائي بشكل افتراضي) |
| `--admin-username` / `--admin-password` | حساب المسؤول (كلمة المرور العشوائية مطبوعة مرة واحدة عند حذفها) |
| `--proxy-type` | `none` / `nginx` / `caddy` |
| `--cores` | النوى المراد تثبيتها، مفصولة بفواصل: `xray,singbox` |
| `--panel-domain` / `--subscription-domain` / `--portal-domain` | المجالات (مكتوبة في الإعدادات وإضافتها إلى الوكيل العكسي) |
| `--tls-mode` | `none` / `self_signed` / `acme` |
| `--tls-domain` / `--tls-email` / `--tls-challenge` / `--tls-key-type` / `--tls-key-bits` | خيارات الشهادة (الإعدادات الافتراضية `--tls-challenge` هي `http-01`؛ `dns-01` تحتاج إلى `--tls-dns-channel` أو `--tls-dns-provider`) |
| `--tls-ip-cert` | إصدار شهادة لعنوان IP العام المكتشف (Let's Encrypt فقط) |
| `--acme-provider` | `lets_encrypt` / `lets_encrypt_staging` / `zerossl` / `google` |
| `--currency` / `--timezone` | العملة الافتراضية / المنطقة الزمنية |

القائمة الكاملة: `./corefusion init --help`. ثم ابدأ الخدمة:

```bash
systemctl restart corefusion
```

### 3.5 إعادة تشغيل معالج الإعداد

للبدء من جديد (إزالة `.env` وعلامات الإعداد، **الاحتفاظ بالبيانات**):

```bash
cd /opt/corefusion
./corefusion reset-init      # type RESET to confirm
systemctl restart corefusion
```

ثم استخدم URL الجديد والرمز المميز من سجل بدء التشغيل.

> تؤدي إعادة التهيئة إلى إعادة تعيين حساب المسؤول ومسار الويب. تبقى بيانات العمل في قاعدة البيانات القديمة، ولكن قد تحتاج إلى إعادة إنشاء حساب تسجيل الدخول.
>
> يقوم `reset-init` بحذف `.env` بالكامل (بما في ذلك `SAFE_PATHS`). **إذا كان دليل البيانات الخاص بك عبارة عن مسار مطلق مخصص**، فاستعد `SAFE_PATHS` قبل إعادة التشغيل، وإلا فستظهر اللوحة في `./data`:
>
> ```باش
> printf 'SAFE_PATHS=/srv/corefusion-data\n' > /opt/corefusion/.env
> ```

### 3.6 الأمان بعد تسجيل الدخول لأول مرة

#### تغيير كلمة المرور الأولية

1. انقر فوق اسم المستخدم في الزاوية العلوية اليمنى؛
2. اختر "تغيير كلمة المرور"؛
3. أدخل كلمات المرور القديمة والجديدة.
4. انقر فوق "حفظ".

#### تمكين تسجيل الدخول بالرمز الديناميكي (2FA / TOTP)

> بمجرد التمكين، يتحول الحساب إلى **تسجيل الدخول بالرمز الديناميكي**: لم تعد كلمة المرور الثابتة مقبولة؛ فقط
> يعمل الرمز المكون من 6 أرقام من تطبيق المصادقة (أو رمز الاسترداد لمرة واحدة). هذا **يستبدل** كلمة مرور تسجيل الدخول — إنه كذلك
> وليس التحقق بخطوتين "كلمة المرور + الرمز".

1. انقر فوق اسم المستخدم في الزاوية العلوية اليمنى؛
2. اختر "تمكين المصادقة الثنائية"؛
3. أدخل كلمة المرور الحالية (فقط لتأكيد هذا التغيير)؛
4. امسح رمز QR ضوئيًا باستخدام تطبيق المصادقة (Google Authenticator / 1Password، وما إلى ذلك)، أو أدخل المفتاح يدويًا؛
5. أدخل الرمز المكون من 6 أرقام لإنهاء التمكين؛
6. **احفظ رموز الاسترداد فورًا** (قابلة للتنزيل)؛ كل رمز يعمل مرة واحدة.

تسجيل الدخول بعد ذلك:

- بعد إدخال اسم المستخدم، يصبح حقل كلمة المرور "رمز مكون من 6 أرقام / رمز الاسترداد" ويصبح الزر "تسجيل الدخول باستخدام الرمز"؛
- أدخل الرمز الحالي. **لم يعد من الممكن استخدام كلمة المرور الثابتة**;
- رموز الاسترداد مخصصة للاستخدام مرة واحدة؛ قم بإعادة إنشائها ضمن "تسجيل الدخول بالرمز الديناميكي (2FA)" عند نفادها (وهذا يبطل جميع الرموز القديمة).

إذا فقدت أداة المصادقة واستنفدت رموز الاسترداد، فقم بتعطيل المصادقة الثنائية في وضع عدم الاتصال على الخادم:

```bash
cd /opt/corefusion
./corefusion admin 2fa reset -u admin    # disables 2FA, clears the secret and recovery codes, revokes all sessions
```

> لا يمكن للمشرف المتميز الوحيد الذي ليس لديه المصادق ولا رموز الاسترداد الاسترداد من خلال واجهة مستخدم الويب ويجب عليه استخدام الأمر أعلاه.

#### تسجيل Passkey (اختياري)

2. اختر "إدارة Passkey"؛
3. انقر فوق "تسجيل Passkey الجديد"؛
4. أكمل موجه الجهاز.

> **ملاحظة**: تتطلب مفاتيح المرور HTTPS أو مضيفًا محليًا، ويجب أن يكون النطاق مدرجًا في القائمة المسموح بها.

## 4. لوحة القيادة

تعرض لوحة المعلومات نظرة عامة على المجموعة متعددة العقد وصحة العقدة.

### 4.1 ما يظهر

- **معلومات النظام**: اسم المضيف، إصدار نظام التشغيل، وقت التشغيل، وحدة المعالجة المركزية، الذاكرة
- **حركة المرور**: عرض النطاق الترددي في الوقت الفعلي، إجمالي حركة المرور، الاتجاه الشهري
- ** صحة العقدة **: الأعداد المتصلة / غير المتصلة بالإنترنت / المتدهورة، والعقد ذات التحميل العالي
- **التنبيهات**: العقد غير المتصلة بالإنترنت، والعقد المتدهورة، والشهادات التي تنتهي صلاحيتها قريبًا، وتحذيرات الحصص
- **موارد المجموعة**: متوسط وحدة المعالجة المركزية والذاكرة والقرص والإنتاجية

### 4.2 الإجراءات

- انقر على "عرض التفاصيل" لفتح صفحة تفاصيل العقدة
- انقر فوق بطاقة عقدة لرؤية حالتها المباشرة
- استخدم عوامل التصفية للتضييق حسب الحالة أو النوع أو المنطقة

## 5. إدارة العقدة

تعد إدارة العقدة جوهر CoreFusion وتدعم العديد من أنواع العقد.

### 5.1 أنواع العقد

| اكتب | الوصف |
|------|-------------|
| مستقل (`standalone`) | عقدة أساسية مستقلة |
| مرآة (`mirror`) | مزامنة التكوين من العقدة المستهدفة |
| أساسي/احتياطي (`primary_backup`) | العقد الشريكة التي تفشل مع بعضها البعض |
| دخول السلسلة (`chain_entry`) | عقدة دخول الوكيل المتسلسل |
| مخرج السلسلة (`chain_exit`) | عقدة الخروج من الوكيل المتسلسل |

### 5.2 إضافة عقدة

1. افتح "إدارة العقدة"؛
2. انقر فوق "إضافة خادم";
3. املأ الأساسيات:
   - الاسم، على سبيل المثال. `HongKong-HK01`
   - اسم المضيف: IP أو المجال
   - المنطقة، على سبيل المثال. `HK`، `JP`، `US`
   - نوع العقدة؛
4. قم بتعيين منفذ الوكيل (`18443` الافتراضي)؛
5. حدد النوى المدعومة؛
6. انقر فوق "حفظ".

### 5.3 النشر بنقرة واحدة

1. بعد إضافة العقدة، اختر "أمر النشر" في قائمة العقد (توفر صفحة التفاصيل أيضًا
 "أمر تثبيت Bootstrap")؛
2. انسخ الأمر - يحتوي على رمز تسجيل لمرة واحدة (صالح لمدة 24 ساعة، لا يجوز إعادة استخدامه)؛
3. قم بتشغيله كجذر على العقدة البعيدة؛ يبدو مثل:

   ```bash
   bash <(curl -fsSL "http://<panel-host>:<panel-port>/api/v1/agent/install?id=<node-id>&token=<one-time-token>&port=<panel-port>")
   ```

4. يقوم الوكيل بتنزيل الحزمة والتسجيل في اللوحة ويبدأ.

### 5.4 تفاصيل العقدة

انقر فوق العقدة لفتح صفحة التفاصيل الخاصة بها:

- **نظرة عامة**: المعلومات الأساسية، وحالة الوكيل، وحالة الشهادة؛ تُظهر بطاقات الموارد استخدام وحدة المعالجة المركزية / الذاكرة / القرص، ومعدل أعلى/أسفل NIC، ومعدل حركة مرور المستخدم الأساسية، وحركة المرور المستخدمة شهريًا، واتصالات TCP، وتحميل النظام، وحركة المرور التراكمية لبطاقة NIC (التحديث الصامت كل 10 ثوانٍ)
- **مركز البروتوكول**: تكوين العملية الأساسية
- **الوكيل**: تكوين Caddy / Nginx
- ** العمليات الأساسية **: البدء / الإيقاف / إعادة التشغيل
- **حركة المرور الأساسية**: حركة مرور المستخدم التي تتم إعادة توجيهها بواسطة النواة وإجماليها الشهري
- **WARP**: تكوين WARP
- **المجالات المباشرة**: إدارة المجال
- ** حد السعر **: تشكيل حركة المرور
- **الشهادات**: روابط الشهادات
- **المستخدمون عبر الإنترنت**: المستخدمون عبر الإنترنت في الوقت الفعلي

### 5.5 إجراءات العقدة

- **تكوين المزامنة**: ادفع تكوين اللوحة إلى العقدة
- **فرض إعادة الاتصال**: قم بإسقاط اتصال الوكيل ثم أعد الاتصال
- **تحديث الوكيل**: ادفع تحديث الوكيل
- ** إبطال الشهادة **: إبطال شهادة وكيل العقدة

## 6. مركز البروتوكول

يقوم مركز البروتوكول بتكوين معلمات البروتوكول للعمليات الأساسية.

### 6.1 النوى المدعومة

| الأساسية | الوصف |
|------|-------------|
| Xray-النواة | VLESS / VMess / Trojan / Shadowsocks والمزيد |
| sing-box | منصة وكيل عالمية معيارية مع دعم TUN؛ يحمل Hysteria2 / TUIC وبروتوكولات QUIC الأخرى |

### 6.2 وحدات التكوين

تختلف الوحدات بين المركزين؛ تعرض اللوحة المجموعة التي تطابق النواة المحددة:

**Xray-النواة**

- **السجل**: سجل الوصول، سجل الأخطاء، وضع الإخراج
- **API**: عنوان الاستماع gRPC API، قائمة الخدمات
- **DNS**: خوادم DNS، واستراتيجية الاستعلام، والمضيفات الثابتة
- ** التوجيه **: قواعد التوجيه، موازنة التحميل، توجيه VLESS
- **الواردات/الصادرات**: البروتوكول، النقل، TLS
- **النقل**: WebSocket، وgRPC، وXHTTP، وما إلى ذلك (TUN عبارة عن بروتوكول وارد، وليس وسيلة نقل)
- **TLS**: الشهادات، ALPN، بصمة uTLS، ECH
- **Reality**: إدارة الأهداف، وأزواج المفاتيح، والمعرفات القصيرة
- **فحص السلامة / FakeDNS / المقاييس / السياسة / البيانات الجغرافية / حدود الإصدار **: التحقيقات، تجمع IP، Prometheus، المهلات والمخازن المؤقتة، ملفات الموارد، نطاق الإصدار الأساسي

**sing-box**

- **السجل**: المستوى، الطابع الزمني، الإخراج
- **NTP**: مزامنة الوقت
- **DNS**: خوادم وقواعد DNS
- ** التوجيه **: الصادر الافتراضي `final`، ** مجموعات القواعد **، ** القواعد **، محلل المجال الافتراضي، استراتيجية الشبكة والاحتياطي (راجع 6.6)
- **الواردات/الصادرات**: البروتوكول، النقل، TLS
- **نقاط النهاية**: WireGuard (بما في ذلك تكوينات WARP)، وعملاء MASQUE وما شابه؛ يمكن للعديد منها أن تتعايش وتتميز بـ `tag`

> مع تمكين "استخدام تكامل شبكة النظام"، يكون **اسم** نقطة النهاية هو اسم واجهة kernel:
> 15 حرفًا/رقمًا/`._-` على الأكثر. يتم التراجع تلقائيًا عن الاسم الطويل جدًا أو غير الصالح
> إلى نقطة النهاية `tag`. نقاط النهاية الجديدة مسبوقة لكل بروتوكول (`wg-` / `ts-` / `oc-` / `ovpn-c-` /
> `ovpn-s-` / `mq-c-` / `mq-s-`)، ويتم عرض السجلات القديمة مثل `WireGuard-xxxxxx` بشكل طبيعي
> بمجرد فتح المحرر.
- **الخدمات**: مصفوفة sing-box `services` ذات المستوى الأعلى، مثل `hysteria-realm` أو DERP أو `resolved`
- **الشهادات / عملاء HTTP / مساحات أسماء الشبكة**: أقسام JSON التي يمكنك توسيعها فقط عند الحاجة
- **التجريبي**: `clash_api` وما شابه؛ ** لم تتم كتابة أي شيء في التكوين الذي تم إنشاؤه ما لم يتم تمكينه **

> قام sing-box 1.12 بإزالة حقول التوجيه `geosite` / `geoip`؛ يتم الآن تنفيذ التوجيه الجغرافي
> `rule_set`. يؤدي الاحتفاظ بالحقول القديمة إلى فشل النواة في فك تشفير التكوين (`unknown field`).

### 6.3 التكوين الوارد

1. حدد الأساسية والبروتوكول؛
2. املأ الأساسيات:
   - علامة
   - الاستماع عنوان والميناء
   - نوع البروتوكول
3. تعيين معلمات البروتوكول (UUID، كلمة المرور، وما إلى ذلك)؛
4. اختر وسيلة النقل (TCP، WebSocket، gRPC، وما إلى ذلك)؛
5. تكوين TLS (الشهادة، ALPN)؛
6. حفظ وتطبيق على القلب.

> يتم الاستماع للواردات الجديدة على `::` بشكل افتراضي (المكدس المزدوج على Linux، والتعامل مع كل من IPv4 وIPv6).
> قم بتغييره إلى `0.0.0.0` أو عنوان محدد فقط عندما تحتاج إلى تقييد الواجهة.

توفر أوضاع المنفذ "استخدام المنفذ الوارد" أيضًا **إنشاء جدار حماية يسمح بالقواعد تلقائيًا**: فتح ملف
يقوم المحرر الوارد بالتحقق من جدار حماية العقدة أولاً، وعند اكتشاف جدار الحماية / ufw / nftables / iptables
يمكنك السماح للمنفذ بالحفظ وفقًا لبروتوكول الاستماع (TCP/UDP).

- يسمح التنقل بين منفذ hy2 / hysteria لكل من منفذ الاستماع وكل نطاق منافذ ديناميكي (على سبيل المثال `20000-30000`)؛ نطاقات متعددة مفصولة بفواصل؛
- البدل غير فعال: لم يتم إنشاء قاعدة التغطية الحالية (نطاق المنفذ / المنافذ المتعددة) مرة أخرى؛
- يؤدي تغيير المنفذ إلى إلغاء القاعدة القديمة قبل السماح بالقاعدة الجديدة؛ يؤدي حذف المنفذ الوارد أو تعطيل التنقل بين المنافذ أو التبديل إلى Unix Switch / tun (بدون منفذ استماع) إلى تنظيفه؛
- عند عدم اكتشاف أي جدار حماية ممكّن، يظهر تلميح فقط ولا تتم كتابة أي قاعدة.

### 6.3.1 مسار الوكيل العكسي (مجال الوصول ← أمامي TLS ← مسار الوكيل العكسي)

عندما يكون مسار النقل الداخلي هو `/` ولكن nginx / caddy الخارجي يقوم بتثبيته تحت مسار فرعي
(على سبيل المثال، `location /apps { proxy_pass http://127.0.0.1:8080/; }`)، يجب على العملاء الاتصال بـ `/apps` أو
لا يصل الطلب أبدًا إلى هذا الموقع - لا يزال الاشتراك يتم تنزيله، لكن العقدة لا تتصل.
املأ ** مسار الوكيل العكسي ** ضمن "نطاق الوصول → Front TLS":

- أدخل `/apps` أو `/apps?ed=2560` (مع البيانات المبكرة)؛ الاشتراكات ومشاركة الروابط **استبدال** بمسار النقل الداخلي بها؛
- ينطبق على ws وhttpupgrade وxhttp وh2/http؛ يتم تجاهل عمليات النقل بدون مسار (raw/tcp, kcp)؛
- إنه مستقل عن المكان الذي ينتهي فيه TLS: لا يزال المسار ساريًا عند إيقاف تشغيل Front TLS (اتبع النواة)؛
- لا يحتوي gRPC على مفهوم بادئة URL (مسار العميل دائمًا هو `/{serviceName}/…`)، لذلك يتم دمج المسار ** في اسم الخدمة **
(`/apps` + `svc` → `apps/svc`)؛ يجب أن يقوم الوكيل العكسي بإزالة تلك البادئة في `grpc_pass`.

2. تعيين العلامة والبروتوكول؛
3. تعيين عنوان الخادم والمنفذ؛
4. تكوين النقل وTLS؛
5. حفظ وتطبيق.

### 6.6 توجيه sing-box ومجموعات القواعد

في "مركز البروتوكول" → sing-box → "التوجيه" هناك جزأين: **مجموعات القواعد** تعلن أنها قابلة لإعادة الاستخدام
ملفات القاعدة، و**القواعد** تحدد شروط المطابقة والمغادرة. يتم تقييم القواعد من
من أعلى إلى أسفل والمباراة الأولى تفوز.

#### 6.6.1 مجموعات القواعد

| الميدان | الوصف |
|-------|-------------|
| علامة | معرف مجموعة القواعد المشار إليه بواسطة القواعد؛ يجب أن تكون فريدة من نوعها |
| اكتب | يقرأ `local` ملفًا على العقدة؛ يتيح `remote` للنواة تنزيله على `update_interval` |
| التنسيق | `binary` لـ `.srs` (افتراضي)؛ `source` لتنسيق المصدر `.json` |
| المسار | ترتبط مسارات `local` بدليل بيانات العقدة؛ الملفات الموجودة في `data/rules/` تستخدم `rules/xxx.srs` |
| URL | عنوان التنزيل لـ `remote`؛ `download_detour` يحدد الاتجاه الصادر المستخدم للتنزيل (عادةً `direct`) |

مجموعات القواعد المحلية (موصى بها؛ قم بتنزيل الملفات أولاً ضمن "موارد الخدمة ← ملفات القاعدة"):

```jsonc
"route": {
  "rule_set": [
    { "type": "local", "tag": "geosite-cn", "format": "binary", "path": "rules/geosite-cn.srs" },
    { "type": "local", "tag": "geoip-cn", "format": "binary", "path": "rules/geoip-cn.srs" }
  ]
}
```

> لا يكفي تنزيل الملف على اللوحة: يجب أولاً دفع مجموعة قواعد `local` إلى
> العقد ("ادفع إلى جميع العقد") بحيث يكون الملف موجودًا في `data/rules/` للعقدة؛ وإلا جوهر
> فشل في البدء لأنه لا يمكن العثور على الملف.

مجموعات القواعد عن بعد (يجب أن تكون العقدة قادرة على الوصول إلى URL):

```jsonc
{ "type": "remote", "tag": "geosite-openai", "format": "binary",
  "url": "https://raw.githubusercontent.com/SagerNet/sing-geosite/rule-set/geosite-openai.srs",
  "download_detour": "direct", "update_interval": "1d" }
```

عند اختيار ملف محلي، يتم اشتقاق العلامة من اسم الملف (`rules/geosite-cn.srs` →
`geosite-cn`)؛ بالنسبة للأجهزة البعيدة، فهي تأتي من نهاية URL. يتم ملء التنسيق أيضًا من
الامتداد (`.srs` → `binary`، `.json` → `source`). يمكن تحرير القيم المشتقة بحرية، و
لا يتم الكتابة فوق القيم التي كتبتها بالفعل.

> تم إهمال `download_detour` منذ sing-box 1.14 وستتم إزالته في 1.16؛ لا يزال
> يعمل على 1.15 يجب أن تستخدم التكوينات الجديدة المستوى الأعلى من `http_clients` مع
> `route.default_http_client` بدلا من ذلك.

#### 6.6.2 القواعد

| الميدان | مباريات |
|-------|---------|
| `domain` | المجال الدقيق |
| `domain_suffix` | لاحقة المجال، بما في ذلك النطاقات الفرعية |
| `domain_keyword` | مطابقة السلسلة الفرعية |
| `domain_regex` | التعبير العادي |
| `ip_cidr` / `ip_is_private` | عنوان IP الوجهة |
| `source_ip_cidr` | مصدر IP |
| `port` / `port_range` | ميناء الوجهة |
| `network` | `tcp` / `udp` |
| `rule_set` | علامات مجموعات القواعد المراد استخدامها |
| `outbound` | العلامة الصادرة المراد استخدامها (يجب أن تكون موجودة ضمن "Outbounds" أو "Endpoints") |
| `type: "logical"` | تم ضبط الشروط المجمعة مع `mode` على `and` / `or` |

يتم دمج الحقول المتعددة في قاعدة واحدة باستخدام AND (على سبيل المثال `network` + `port`)، لذلك لا
هناك حاجة إلى غلاف `logical`. استخدم `type: "logical"` فقط لمجموعات OR/NOT. `rule_set`
يجب وضعها داخل القواعد الفرعية `rules`، وليس بجوار `rules`:

```jsonc
"rules": [
  { "domain_suffix": ["gstatic.com", "googleapis.com"], "outbound": "direct" },
  { "domain_keyword": ["ip.sb", "yandex.com"], "outbound": "warp" },
  { "rule_set": ["geosite-openai", "geosite-google"], "outbound": "warp" },
  { "rule_set": ["geoip-cn"], "outbound": "warp" },
  { "network": "tcp", "port": 443,
    "rule_set": ["geosite-google"], "outbound": "warp" },
  { "type": "logical", "mode": "or",
    "rules": [
      { "rule_set": ["geosite-google"] },
      { "rule_set": ["geosite-openai"] }
    ],
    "outbound": "warp" }
]
```

#### 6.6.3 ترحيل قواعد xray

| xray | sing-box |
|------|----------|
| سلسلة عارية (بما في ذلك القيم العارية في `domain`؛ مطابقة السلسلة الفرعية) | `"domain_keyword": ["ip.sb"]` |
| `"domain": ["a.com"]` | `"domain_keyword": ["a.com"]`; استخدم `"domain_suffix": ["a.com"]` لمطابقة لاحقة حقيقية أو `"domain": ["a.com"]` لمطابقة تامة |
| `"domain:clstorage.net"` | `"domain_suffix": ["clstorage.net"]` |
| `"full:a.com"` | `"domain": ["a.com"]` |
| `"regexp:..."` | `"domain_regex": ["..."]` |
| `"ip": ["geoip:cn"]` | `"rule_set": ["geoip-cn"]` |
| `"domain": ["geosite:cn"]` | `"rule_set": ["geosite-cn"]` |
| `"outboundTag": "direct"` | `"outbound": "direct"` |

ملاحظات:

- **لا تتم مشاركة العلامات بين النوى**: لا يمكن استخدام العلامة الصادرة xray في قاعدة sing-box؛
 استخدم علامة موجودة بالفعل ضمن sing-box "Outbounds" أو "Endpoints".
- تشير العلامة الصادرة أو نقطة النهاية الخاطئة إلى `outbound not found`؛ تقارير علامة مجموعة قواعد خاطئة
 `rule-set not found`.
- ضع قواعد القائمة المباشرة/القائمة المسموح بها أولاً؛ بمجرد تطابق القاعدة، لن يتم تطبيق القواعد اللاحقة.

---

## 7. إدارة الوكيل

تقوم إدارة الوكيل بتكوين الوكيل العكسي Caddy أو Nginx.

### 7.1 أنواع الوكيل

- **Caddy**: HTTPS وHTTP/1.1 وHTTP/2 التلقائي (تم تعطيل HTTP/3 / QUIC لتجنب تعارض UDP 443 مع توجيه الطبقة 4)
- **Nginx**: أداء عالي وتكوين مرن

### 7.2 تكوين الموقع

1. افتح "إدارة الوكيل"؛
2. اختر نوع الوكيل (Caddy / Nginx)؛
3. إضافة موقع:
   - المجال
   - المنبع
   - ميناء محلي
4. حفظ.

### 7.3 الحقول

- **المنبع**: عنوان الواجهة الخلفية، على سبيل المثال. `127.0.0.1:8082`
- **local_port**: منفذ الاستماع المحلي، على سبيل المثال. `8443`
- **portal_forward**: قاعدة إعادة توجيه البوابة
- **subscription_forward**: قاعدة إعادة توجيه الاشتراك
- **توجيه SNI**: عندما يستخدم أحد الواردين TLS / REALITY ويتصل العملاء دائمًا على 443، تستمد اللوحة
 443 قواعد توجيه TCP من ClientHello SNI (كلاهما xray `streamSettings` وsing-box `tls.reality`)؛
 الوكيل الأمامي يقوم فقط بإعادة توجيه TCP وTLS ولا يزال منتهيًا داخل المركز

## 8. موارد التوجيه

تقوم موارد التوجيه بجمع الأصول المشتركة المستخدمة بواسطة الاشتراكات والتوجيه. تحتوي الصفحة على خمس علامات تبويب:

| علامة التبويب | الغرض |
|-----|---------|
| المجالات المفضلة المباشرة وCF | الدخول إلى المجالات المباشرة / عناوين IP والمجالات المفضلة Cloudflare، المستخدمة عند إعادة كتابة عناوين الوصول في الاشتراكات والعقد الخارجية |
| تجمع CF IP | مصادر IP المفضلة والمنافذ وإعدادات المسبار، التي يستهلكها "مجال الوصول" |
| القواعد العالمية WAF | مصادر القاعدة وملفات القاعدة للوكيل العكسي WAF، مدفوعة إلى العقد |
| ملفات القواعد | التنزيل والمزامنة المجدولة ودفع ملفات القاعدة (`.srs` / `.json` / `.dat`) |
| العقد الخارجية | استيراد العقد الخارجية من v2ray URI / Base64 / الاشتراك URL (انظر 16.3) |

### 8.1 المجالات المفضلة المباشرة وCF

- **الوصول المباشر**: مجال الدخول أو عنوان IP، المنفذ 443 بشكل افتراضي؛ ربط العقد أو تركها فارغة للعالمية؛
- **نطاقات CF المفضلة**: النطاق المفضل Cloudflare بالإضافة إلى المنفذ، مع التحقق من الاتصال؛
- كلاهما يغذيان مرشحي "مجال الوصول" الذي تستخدمه الاشتراكات وإعادة كتابة العقدة الخارجية (انظر 16.3).

### 8.2 تجمع CF IP

- الحفاظ على مصادر IP المفضلة (بما في ذلك مصادر نمط `bestproxy`)، وفاصل الجلب والمنافذ؛
- تتحكم "إعدادات المسبار" في الفاصل الزمني للمسبار وعتبة الكمون وعقدة دخول المسبار؛ التحقيق المحلي
 يقوم فقط بتصفية عناوين IP التي لا يمكن الوصول إليها بشكل واضح، بينما يؤدي تحديد عقدة الإدخال إلى محاكاة خط تلك العقدة؛
- قد يكون "المتصل" تلقائيًا (النوى المثبتة)، `singbox`، `xray` أو `mihomo`؛ النوى التي ليست كذلك
 لم يتم سرد المثبتة. يعمل الفحص كعملية مؤقتة تخرج عند الانتهاء ولا تقرأ أو
 يكتب التكوين الأساسي الخاص به؛
- عندما يستخدم "مجال الوصول" تجمع CF IP بدون قيمة محددة، يكون هناك إدخال واحد (مع المنفذ الخاص به).
 اختار عشوائيا.

### 8.3 القواعد العالمية WAF

- قم بتكوين مصدر قاعدة WAF URL وملفات القاعدة للمزامنة؛
- بعد المزامنة، يتم دفعها إلى العقد وتحميلها بواسطة وكيل العقدة (Nginx / Caddy)؛
- يتم تنزيل ملف بكامل URL من URL؛ وإلا فسيتم استخدام "المصدر URL + / اسم الملف"؛
- يتم تمكين "مطابقة ذاكرة التخزين المؤقت" (`match_cache` / `config_match_cache`) افتراضيًا: حدود على مستوى العملية
 تعمل ذاكرة التخزين المؤقت لنتائج مطابقة القواعد الساخنة على تقليل اجتياز القاعدة لكل طلب. إنه عالمي فقط بدون أي
 تجاوز لكل مجال؛ قم بتعطيله مؤقتًا لمقارنة A/B عند التحقق من النتائج الإيجابية الخاطئة
 (يعني التعطيل تقييمًا كاملاً للقاعدة لكل طلب واستخدامًا أعلى لوحدة المعالجة المركزية).

### 8.4 ملفات القواعد (ملفات قواعد التوجيه)

تقوم علامة التبويب هذه فقط بتنزيل ملفات القواعد الموجودة على اللوحة ودفعها إلى العقد؛ لا شيء يصبح ساري المفعول
تلقائيا. لاستخدامها في التوجيه، قم بالإشارة إليها ضمن "مركز البروتوكول → sing-box → التوجيه"
في مجموعات القواعد والقواعد (انظر 6.6).

- **مستودعات القواعد**: أدخل `owner/repo` (GitHub، قابل للتصفح) أو تنزيل كامل URL؛ المقرر
 يمكن تشغيل المزامنة كل 6/12 ساعة، يوميًا عند الساعة 03:00، يوميًا عند منتصف الليل أو أسبوعيًا يوم الأحد؛
- **إضافة ملف**: للملفات الفردية خارج إصدار المستودع (على سبيل المثال فرع SagerNet `.srs`)
 الملفات)؛ أدخل URL بالكامل وسيتم تنزيله تلقائيًا؛
- **قائمة الملفات**: تعرض الاسم والحجم وآخر تحديث ومفتاح "المزامنة التلقائية"، مع "تنزيل" لكل ملف؛
 يقوم زر "الدفع إلى جميع العقد" الموجود في الجزء العلوي بدفع كل ملف قاعدة إلى جميع العقد؛
- يتم تنزيل الملفات إلى `data/rules/` الخاصة باللوحة، وبمجرد دفعها، يتم حفظها ضمن بيانات العقدة
 الدليل `rules/`؛ قم بالإشارة إليها في sing-box باسم `rules/<file name>`؛
- التنسيقات:
  - `.srs`: مجموعة القواعد الثنائية sing-box، الموصى بها والأصغر؛
  - `.json`: مجموعة قواعد تنسيق المصدر؛ يجب أن يقوم `rule_set` بتعيين `format: "source"`؛
  - `.dat`: xray `geosite.dat` / `geoip.dat`، والتي لا يمكن لـ sing-box استخدامها مباشرة.

> تحتوي كتلة "الاستخدام" القابلة للطي في أعلى الصفحة على أمثلة مرجعية، ورسم الخرائط xray
> الجدول والأخطاء الشائعة

### 8.5 العقد الخارجية

تمت تغطية استيراد العقد الخارجية وإدارتها في [16.3 العقد الخارجية ](#163-external-nodes).

## 9. مركز الاشتراك

يقوم مركز الاشتراك بتجميع العقد في اشتراكات جاهزة للعميل: حدد **تنسيقات الاشتراك** (ما سيتم إصداره، وما هي القواعد، وما هي الخطط التي يمكنها رؤيتها)، ثم الاشتراك **نقاط النهاية** (المجال العام / المسار)، ثم قم بتسليم الروابط.

### 9.1 تنسيقات الاشتراك

"مركز الاشتراك" ← "تنسيقات الاشتراك"; صف واحد لكل مخرجات العميل:

| الميدان | الوصف |
|---|---|
| الاسم | فريدة من نوعها؛ يتطابق `?config=<name>` عليه ويعرضه مربع حوار العميل |
| نوع العميل | clash / shadowrocket / Singbox / v2ray - تجميع العرض فقط |
| تنسيق الإخراج | `mihomo_yaml` (Clash/Mihomo)، `singbox_json`، `xray_json`، `base64_uri`، `raw_uri` |
| نوع المحتوى / الامتداد | رأس الاستجابة واسم الملف |
| منصة | فوز / ماك / android / ios / عالمي؛ مطابق لـ `?platform=`، فارغ = عالمي |
| خطط ملزمة | فارغ = متاح لكل خطة؛ وإلا فإن تلك الخطط فقط هي التي يمكنها استخدامها |
| القواعد | قواعد التوجيه لكل تنسيق (محرر منظم لـ Mihomo، وJSON أولي لكل قاعدة لـ sing-box / Xray). **لا يتم تحويل القواعد بين التنسيقات** |

ملاحظات:

- قد توجد عدة تكوينات لنفس تنسيق الإخراج (على سبيل المثال، `out`، `home`)؛ اختر واحدة مع `config=` في الرابط؛
- بدون `config`، يكون الترتيب "التكوين المرتبط بالاشتراك → مطابقة `platform` → الافتراضي"؛
- قد يحمل قالب sing-box `route.rule_set` الخاص به للعملاء، عادةً باسم `remote` لذا
 يقوم العميل بتنزيله؛ الملفات المحلية التي تم دفعها إلى `rules/` للعقدة ضمن "ملفات القاعدة" متاحة فقط
 إلى جوهر تلك العقدة، وليس إلى اشتراكات العميل؛
- عند إنشاء قوالب sing-box / Xray، تقوم اللوحة بإزالة المراجع المتدلية (`final`، `dns.final`،
 `default_domain_resolver`، `download_detour`، `rule_set` المحلي، تعريفات `rule_set` غير صالحة، فارغة
 `balancer`، وما إلى ذلك) حتى لا يفشل العميل عند بدء التشغيل بسبب خطأ فادح؛
- يتم حل الأسماء المستعارة الصادرة في القواعد مقابل العلامات الحقيقية (`REJECT` / `blocked` → `block`، `DIRECT` →
 `direct`، غير حساس لحالة الأحرف)؛ تعود الحدود الخارجية غير القابلة للحل إلى الاتجاه الصادر الافتراضي والقاعدة
 تحافظ على مكانتها؛
- يتم دائمًا إنشاء مجموعة تحتوي على `tag = proxy`: `selector` لـ sing-box وموازن `random` لـ
 تتم إعادة كتابة Xray و`outbound: proxy` في القواعد إلى `balancerTag` المطابقة. يتم تحميل محرر القواعد
 المرشحون الخارجيون ديناميكيًا من "مجموعات الوكيل + الخارجين المخصصين"، والعلامات المدخلة يدويًا هي
 لا يزال التحقق من صحتها؛
- يجب إنشاء تكوينات sing-box / Xray بشكل منفصل؛ إذا لم تكن موجودة فلن تظهر في روابط العملاء (انظر 10.3).

### 9.2 نقاط نهاية الاشتراك

"مركز الاشتراك" ← "نقاط نهاية الاشتراك"؛ صف واحد لكل عنوان عام:

| الميدان | الوصف |
|---|---|
| المجال | مجال الاشتراك العام |
| المسار | البادئة ضمن المجال، الافتراضي `/` |
| ممكّن | يتم تجاهل نقاط النهاية المعطلة عند إنشاء الروابط |
| الوصف | مذكرة نصية حرة |

- **صفوف متعددة (متعددة المجالات)** مدعومة؛ عندما يتم تمكين العديد من مجال الموفر يتبع المجال المستخدم بواسطة الطلب الحالي (انظر 9.4)؛
- يعمل منفذ اشتراك مخصص عند الجذر (`/<token>`، no `/sub`)؛ عند مشاركة منفذ اللوحة يكون `/sub/<token>`؛
- يجب أن يقوم الوكلاء العكسيون بإعادة توجيه `X-Forwarded-Proto` / `X-Forwarded-Host`، وإلا فسيتم استخدام أول نقطة نهاية ممكنة. تشتمل قوالب موقع Caddy / Nginx التي تم إنشاؤها على اللوحة على كلا الرأسين؛ تحتاج تكوينات الوكيل التي يتم صيانتها يدويًا إلى إضافتها يدويًا.

### 9.3 روابط الاشتراك

النموذج الأساسي: `https://<sub-domain>/<token>` (منفذ اللوحة: `https://<panel-domain>/sub/<token>`)

| المعلمة | الوصف |
|---|---|
| `format` | تنسيق الإخراج؛ الأسماء المستعارة: `clash` → mihomo_yaml، `singbox`/`sing-box` → Singbox_json، `xray` → xray_json، `raw` → Raw_uri، `base64`/`v2ray` → base64_uri |
| `config` | تطبيق تنسيق الاشتراك بالاسم؛ يجب أن يتطابق مع `format`، وإلا فسيتم تجاهله |
| `platform` | مطابقة التكوين حسب النظام الأساسي (عند حذف `config`) |
| `providers` | `1` / `true`: وضع الموفر Clash (`proxy-providers` + `use`)؛ العقد المضمنة الافتراضية |

أمثلة:

```bash
# Clash dynamic subscription (config template + providers)
https://sub.example.com/<token>?format=clash&config=out&providers=1

# sing-box / Xray (only meaningful when such a config exists)
https://sub.example.com/<token>?format=singbox_json&config=sing-box-home
https://sub.example.com/<token>?format=xray_json&config=xray-home

# generic clients / plain text
https://sub.example.com/<token>?format=base64_uri
https://sub.example.com/<token>?format=raw_uri
```

### 9.4 النطاق المتعدد ووضع الموفر

مع `providers=1`، يشير كل إدخال `proxy-providers` إلى نقطة نهاية الاشتراك. اختيار المجال:

1. **المجال الذي استخدمه هذا الطلب** (القيمة الأولى `X-Forwarded-Host`، المنفذ المجرد، وإلا `Host`) إذا كان يطابق نقطة نهاية **ممكّنة**؛
2. وإلا فإن نقطة النهاية الممكّنة ذات **أدنى معرف**؛
3. يأتي المسار من نقطة النهاية تلك: `https://<domain><path>/<token>?format=mihomo_proxies_yaml...`.

لذا فإن تغيير النطاق لا يحتاج إلى تغيير اللوحة: فالعملاء الذين يتم جلبهم عبر النطاق الجديد يحصلون على النطاق الجديد داخل مقدمي الخدمة، والنطاق القديم الذي تم تركه ممكّنًا لم يعد مشفرًا بشكل ثابت. إذا قام العميل بتخزين الموفر القديم URL مؤقتًا، فقم بتحديث الاشتراك (أو امسح ذاكرة التخزين المؤقت للموفر / أعد تشغيل العميل).

ملاحظات إضافية:

- يتم تجاهل `proxy-providers` داخل التنسيق المشترك (`config_json`) (يتجنب التسرب عبر المخطط)؛ يأتي مقدمو الخدمة من مجموعات عقدة الخطة ومصادر خارجية؛
- يتم دائمًا اشتقاق مسارات ذاكرة التخزين المؤقت للموفر الداخلي والخارجي من "الإعدادات الافتراضية للموفر الداخلي ← قالب مسار ذاكرة التخزين المؤقت" (الافتراضي `./providers/{key}.yaml`)؛ لا يمكن للمصادر الخارجية أن تحدد مصادرها الخاصة؛
- لم يعد الموفر المحجوز القديم `subscription-nodes` ينبعث: تتوسع المجموعات التي تستخدم "جميع العقد" لتشمل موفري الخدمات الملموسين، أو العقد المضمنة عندما لا تحتوي الخطة على أي منها.

## 10. إدارة العملاء

إدارة العملاء تتعامل مع المستخدمين النهائيين.

### 10.1 إضافة عميل

1. افتح "إدارة العملاء"؛
2. انقر فوق "إضافة عميل"؛
3. املأ:
   - البريد الإلكتروني
   - كلمة المرور
   - خطة
   - حصة المرور
   - وقت انتهاء الصلاحية
4. يحفظ.

### 10.2 إجراءات العملاء

- **تحرير**: تغيير تفاصيل العميل
- **تعليق**: تعليق الخدمة
- **السيرة الذاتية**: استعادة عميل معلق
- **إعادة ضبط حركة المرور**: إعادة ضبط حركة المرور المستخدمة
- **إعادة تعيين كلمة المرور**: إعادة تعيين كلمة المرور الخاصة بالعميل
- **التجديد**: تمديد تاريخ انتهاء الصلاحية
- ** الترقية / الرجوع إلى إصدار أقدم **: قم بتغيير الخطة
- **حذف**: إزالة العميل

### 10.3 تفاصيل الاشتراك

إدارة العملاء ← عمود "الاشتراك" ← "التفاصيل". يسرد مربع الحوار روابط لكل تنسيق متاح لخطة العميل:

- **Clash / Mihomo**: صفين — العقد المضمنة و`providers=1` (موفري الوكيل)، وكلاهما يحمل `config=<name>`؛
- **Sing-box / Xray**: يظهر فقط عند وجود تكوين بهذا التنسيق ويكون مرئيًا للخطة؛ الروابط تحمل `config=<name>`؛
- ** Base64 URI / Raw URI **: معروض دائمًا (لا يوجد `config`)؛
- يحتوي كل صف على زر النسخ الخاص به؛ يؤدي النقر فوق أحد الصفوف إلى تحويل رمز الاستجابة السريعة الموجود أدناه إلى هذا التنسيق.

لذا، باستخدام تهيئة Clash فقط، يعرض مربع الحوار Clash + Base64 + Raw؛ تظهر روابط sing-box / Xray فقط بعد إنشاء التكوينات الخاصة بها.

يعرض مربع الحوار نفسه أيضًا استخدام حركة المرور وسجل الطلبات وسجل المعاملات.

## 12. إدارة إعادة الشحن

تتعامل إدارة إعادة الشحن مع مواقع إعادة الشحن والأوامر وبطاقات الشحن.

> **تكامل الدفع**
>
> اللوحة **لا تتكامل بشكل مباشر مع مؤسسات الدفع** (Alipay وWeChat Pay وStripe والبنوك وما إلى ذلك). فهو يتصل فقط بـ **منصة دفع وسيطة**، والتي تتكامل بدورها مع مؤسسة الدفع المقابلة، وتتعامل مع التعاقد والاستحواذ والتسوية، وتبلغ عن نتائج الدفع مرة أخرى من خلال واجهة رد الاتصال [charge API](api/charge-callback.md).
>
> منصة الدفع الوسيطة ** ليست جزءًا من هذا المشروع؛ يجب على المشغلين تطويره بأنفسهم (أو استخدام نظامهم الخاص)**. بمجرد نشره، قم بتسجيله ضمن "مواقع إعادة الشحن" وأكمل التحقق من النطاق لاستخدامه كنقطة دخول لإعادة الشحن؛ موقع إعادة الشحن هنا هو تلك المنصة الوسيطة، وليس مؤسسة الدفع نفسها. يتم الاتفاق على مؤهلات الدفع والرسوم والتسوية والامتثال ويتحملها المشغل ومؤسسة الدفع والمنصة الوسيطة.

### 12.1 مواقع إعادة الشحن

1. افتح "إدارة إعادة الشحن" ← "مواقع إعادة الشحن";
2. إضافة موقع:
   - اسم الموقع
   - طرق الدفع التي تدعمها تلك المنصة الوسيطة (Alipay وWeChat وUSDT وStripe وما إلى ذلك، والتي يتم توفيرها من خلال تكاملها مع مؤسسات الدفع)
   - العملة
   - سعر الصرف
3. حفظ؛
4. التحقق من الموقع (ملف HTTP أو التحقق DNS).

### 12.2 أوامر إعادة الشحن

- عرض جميع طلبات إعادة الشحن
- التصفية حسب الحالة (معلق، مدفوع، فاشل، منتهية الصلاحية، مستردة)
- عرض تفاصيل الطلب
- إصدار المبالغ المستردة المشرف

### 12.3 بطاقات الشحن

1. افتح "بطاقات إعادة الشحن"؛
2. إضافة بطاقة:
   - النوع (المبلغ، الخطة، إضافة المرور)
   - القيمة الاسمية / الخطة
   - وقت انتهاء الصلاحية
3. أو توليد بكميات كبيرة:
   - الكمية (حتى 1000)
   - بادئة رقم البطاقة
   - تنسيق رقم البطاقة
4. تصدير كـ CSV.

### 12.4 إدارة الرصيد

- عرض أرصدة العملاء
- ضبط الأرصدة (زيادة / نقصان / ضبط)
- ضبط الكميات المجمدة

## 17. مستخدمي الإنترنت

يُظهر المستخدمون عبر الإنترنت حالة الاتصال بالإنترنت في الوقت الفعلي.

### 17.1 ما يظهر

- الاشتراكات عبر الإنترنت
- الأجهزة المتصلة بالإنترنت/عناوين IP
- العقدة وIP ووقت الاتصال لكل اشتراك
- في الوقت الحقيقي معدل الوصلة الصاعدة / الوصلة الهابطة
- إجمالي الوصلة الصاعدة / إجمالي الوصلة الهابطة / إجمالي حركة المرور

> يتراكم إجمالي الوصلة الصاعدة وإجمالي الوصلة الهابطة وإجمالي حركة المرور خلال **جلسة مستمرة عبر الإنترنت**:
> ولا تؤدي عمليات إعادة الاتصال قصيرة الأمد وعمليات إعادة التشغيل الأساسية وعمليات إعادة تعيين العدادات إلى مسحها. إلا بعد 60
> ثواني بدون تقرير جديد تبدأ الجلسة الجديدة من الصفر. هذا مقياس مختلف
> من عداد "حركة المرور منذ هذه البداية" الخاص بالنواة ويعكس بشكل أفضل ما يفعله المستخدم فعليًا
> المستخدمة خلال الدورة الحالية.

### 17.2 التصفية

- التصفية حسب العقدة
- البحث عن طريق البريد الإلكتروني / العميل / العقدة / IP

## 25. امتدادات العمليات

تقوم "ملحقات العمليات" (`/client-ext`) بتكوين تسويق الإحالة والعمولات والسحب؛
تحتفظ "المستندات القانونية" (`/legal-documents`) باتفاقيات جانب البوابة الإلكترونية.

### 25.1 الإحالات والعمولات

- **تكوين الخصم**: معدل الخصم (النسبة المئوية للدفعة الأولى للمدعو، `0` = معطل)، وضع العمولة (الشراء الأول فقط / جميع المشتريات)، الحد الأدنى لمبلغ السحب (يجب أن يصل رصيد العمولة إلى هذا المبلغ قبل طلب السحب)
- **رموز الدعوة**: عند التمكين، يتطلب التسجيل رمز دعوة؛ قم بتعيين طول الكود وأيام انتهاء الصلاحية والحد الأقصى للاستخدامات (`0` = غير محدود)، وقم بإنشاء/عرض قائمة الرموز
- **مراجعة السحب**: التصفية حسب المعلق / المعتمد / المرفوض؛ أضف مذكرة معالجة وقم بتسجيل طريقة الدفع وعنوان المحفظة
- **سجلات الإحالة**: المدعو والمدعو ومبلغ العمولة وحالة العمولة

### 25.2 الوثائق القانونية

- الحفاظ على "سياسة الخصوصية" و"شروط الخدمة" بشكل منفصل، مستند تخفيض واحد لكل لغة، مع معاينة مباشرة؛
- قد يستخدم كل مستند URL خارجيًا بدلاً من الصفحة المضمنة؛ عندما تكون فارغة، يتم استخدام الصفحة المدمجة URL (قابلة للنسخ على الصفحة)؛
- تعرض البوابة الإلكترونية إصدار اللغة الحالية وتعود إلى اللغة الافتراضية في حالة فقدانها.

## 26. الأسئلة الشائعة

### 26.1 لا تبدأ اللوحة

- تحقق مما إذا كان المنفذ قيد الاستخدام بالفعل
- تأكد من صلاحية `.env`
- تحقق من السجلات: `journalctl -u corefusion -f`؛ بدون systemd، `tail -f <install-dir>/data/logs/panel.log`

### 26.2 العقدة غير متصلة بالإنترنت

- تأكد من تشغيل الوكيل: `systemctl status corefusion-agent`
- تحقق من اتصال الشبكة
- التحقق من قواعد جدار الحماية (المنفذ `18443`)

### 26.3 فشل إصدار الشهادة

- تحقق من دقة DNS
- تأكد من إمكانية الوصول إلى المنفذ 80
- تحقق من تكوين موفر DNS
- تحقق من سجلات الشهادات

### 26.4 الاشتراك لا يعمل

- التحقق من رابط الاشتراك
- تأكد من أن العقدة متصلة بالإنترنت
- تأكد من أن العملية الأساسية قيد التشغيل
- تحقق من قواعد جدار الحماية

### 26.5 فشل رد الاتصال بإعادة الشحن

- تحقق من رد الاتصال URL
- تأكد من تطابق مفتاح الموقع
- تحقق من قائمة IP المسموح بها
- تحقق من سجلات الطلب

### 26.6 صفحة البوابة غير قابلة للوصول

- تأكد من أن منفذ البوابة مفتوح
- تحقق من تكوين مسار البوابة
- **هام**: تأكد من أن الوكيل العكسي يعيد توجيه مجال البوابة الإلكترونية إلى **منفذ محرك البوابة**، وليس منفذ اللوحة الرئيسية — تؤدي إعادة التوجيه إلى المنفذ الخاطئ إلى ظهور صفحة فارغة أو اللوحة بدلاً من البوابة الإلكترونية. تحقق من `upstream` / `local_port` في سجل موقع الوكيل.
- افتح `http://<portal-domain>:<portal-port>` مباشرة للتحقق من محرك البوابة نفسه
- تحقق من تكوين الوكيل العكسي
- التحقق من سجلات البوابة

## الملحق

### أ. المنافذ الافتراضية

| ميناء | الغرض |
|------|---------|
| تم تعيينه بواسطة معالج الإعداد (منفذ مجاني عشوائي بشكل افتراضي) | لوحة الإدارة (قابلة للتغيير) |
| 18443 | وكيل gRPC (قابل للتغيير) |
| 0 (معطل افتراضيًا) | منفذ محرك الاشتراك المخصص (فارغ أو يشارك `0` المنفذ الرئيسي) |
| 0 (معطل افتراضيًا) | منفذ محرك البوابة المخصص (فارغ أو يشارك `0` المنفذ الرئيسي) |
| 80 / 443 | الوكيل العكسي (Caddy / Nginx) HTTP / HTTPS |

### ب. المسارات الافتراضية

| المسار | الغرض |
|------|---------|
| `/` | لوحة الإدارة (توجد البوابة أيضًا في `/` عندما لا يتم تكوين محرك بوابة مخصص) |
| `/sub/:token` | جلب الاشتراك (عند عدم تكوين منفذ اشتراك مخصص) |
| `/p` | صفحة البوابة (في حالة عدم تكوين منفذ بوابة مخصص) |
| `/:token` | جلب الاشتراك (مع منفذ اشتراك مخصص، بدون البادئة `/sub`) |

### ج. أداة سطر الأوامر

يدعم ثنائي اللوحة هذه الأوامر الفرعية (لا توجد وسيطات لبدء تشغيل الخادم):

```bash
# Start the panel (same as ./corefusion server)
./corefusion

# Run database migrations
./corefusion migrate

# Non-interactive init / reset init state (see 3.4, 3.5)
./corefusion init --help
./corefusion reset-init

# Offline administration (when you cannot sign in)
./corefusion admin reset-password -u admin -p 'new-password'
./corefusion admin 2fa reset -u admin
./corefusion admin list

# Version / help
./corefusion version
./corefusion help
```

> مع systemd، استخدم `systemctl restart corefusion` و`journalctl -u corefusion -f`؛ بدون
> systemd (الحاويات وما شابه ذلك)، أوقف العملية القديمة وابدأها مرة أخرى باستخدام `nohup`، يتم حفظ السجلات
> في `data/logs/panel.log`.

## تغييرات v0.13.0-rc.1

- **ترقية لوحة التحكم عبر الإنترنت**: «إعدادات النظام → تحديث اللوحة» — اختيار الإصدار
  (علامة `pre` تعني إصدارًا تجريبيًا)، التحديث، سجل المهام، والرجوع إلى الملف التنفيذي السابق.
- **ترقية Agent عبر الإنترنت**: في تفاصيل العقدة «تحديث Agent» من الملف المحلي في اللوحة أو
  من GitHub Releases؛ العقد المحدّثة من إصدارات قديمة تحصل تلقائيًا على
  `update.public_key` (0600) عند أول اتصال ثم تتحقق من توقيع ed25519.
- **مزامنة WAF**: يُحفظ وقت آخر مزامنة في `waf.github_source.last_sync`، وإعادة التشغيل لا
  تعيد ضبط المؤقت؛ يعمل `0 3 * * *` الساعة 03:00 حسب `panel.timezone` (الافتراضي
  Asia/Shanghai)؛ وتُعوَّض النوافذ الفائتة بعد نحو 15 ثانية من البدء.
- **قائمة WAF البيضاء**: نطاق اللوحة يحتفظ تلقائيًا بملف `whiteurl.rule`؛ تُتجاوز فحوص
  URL/المعاملات/POST لواجهات الإدارة فقط، لذا لم يعد حفظ موقع دفع بعنوان
  `http://127.0.0.1:18081` يُحجب بقاعدة SSRF.
- **سياسة الحصة**: التجميع عند التجديد / المسح عند الانتهاء / إعادة الضبط عند التجديد (يمكن
  للمتغير وراثة الخطة)؛ في الوضع «الشهري» تفحص اللوحة كل ساعة وتصفّر الاستخدام.
- **مواقع الدفع**: التفعيل/التعطيل لا يغيّر المفاتيح أو طرق الدفع؛ ويمكن تصفية طلبات الشحن
  حسب النوع وتصديرها CSV.
- **البوابة**: زر «شحن» يدعم الدفع عبر الإنترنت من موقع مفعّل واستبدال البطاقات؛ وعند عدم
  وجود موقع يظهر استبدال البطاقة فقط.
