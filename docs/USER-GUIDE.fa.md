## 1. نمای کلی سیستم

CoreFusion یک پنل مدیریت پروکسی چند پروتکلی است که از VLESS، VMess، Trojan، Shadowsocks، Hysteria2، TUIC و موارد دیگر پشتیبانی می‌کند، با مدیریت گره، مدیریت اشتراک، گواهینامه‌های ارائه شده توسط مشتریان،x.

### 1.1 ویژگی های اصلی

| ماژول | توضیحات |
|--------|-------------|
| چند پروتکلی | VLESS، VMess، Trojan، Shadowsocks، Hysteria2، TUIC، WireGuard، و غیره. |
| چند هسته ای | Xray-core و sing-box (Hysteria2/TUIC و سایر پروتکل‌های QUIC روی sing-box اجرا می‌شوند) |
| چند گره | پنج نوع گره: مستقل، آینه ای، فعال/آماده به کار، ورودی زنجیردار، خروجی زنجیره ای |
| تحویل اشتراک | چندین فرمت اشتراک، نقاط پایانی و مدیریت قالب |
| صورتحساب | قالب های طرح، کارت های شارژ، موجودی، سفارشات، کمیسیون نمایندگی فروش |
| گواهینامه ها | اجازه دهید صدور را رمزگذاری کنیم، اعتبار سنجی DNS-01/HTTP-01، توزیع گواهی |
| پروکسی زنجیر شده | تعادل بار چند خروجی، ثبت گره خارجی، مسیریابی زنجیره ای |
| سهمیه های ترافیکی | نظارت بر ترافیک ماهانه در هر گره، تعلیق خودکار، بازنشانی گزارش‌ها |
| پورتال | ویرایشگر پورتال بصری، چند زبانه، قالب های سفارشی |
| اطلاعیه ها | ایمیل و Telegram، قالب ها و پخش ها |

### 1.2 معماری

- **پشت زمینه**: برو، gRPC
- **Frontend**: Vue 3 + Element Plus
- **پایگاه داده**: SQLite (پیش فرض) / MySQL / PostgreSQL
- **پراکسی**: پروکسی معکوس Caddy / Nginx
- **پورت پانل**: توسط جادوگر راه اندازی اختصاص داده شده است (درگاه آزاد تصادفی به طور پیش فرض؛ 8080 یک انتخاب رایج است)
- **پورت عامل gRPC**: 18443 به طور پیش فرض

## 2. نصب و راه اندازی

### 2.1 محیط های پشتیبانی شده

| مورد | پشتیبانی کنید |
|------|---------|
| توزیع ها | دبیان / اوبونتو، RHEL / CentOS / Rocky / AlmaLinux / Fedora، Alpine، Arch، openSUSE |
| معماری های CPU | باینری های رسمی: `amd64`، `arm64`؛ بیلدهای منبع نیز از `armv7`، `armv6`، `386`، `ppc64le`، `s390x`، `riscv64`، `loong64` پشتیبانی می کنند |
| مدیر خدمات | systemd (توصیه می شود)؛ در کانتینرها یا محیط های دیگر بدون systemd به `nohup` برمی گردد |
| حافظه / دیسک | ≥ 1 گیگابایت / ≥ 10 گیگابایت (پایگاه داده، گواهی‌ها، گزارش‌ها و باینری‌های هسته موجود در فهرست داده‌ها) |
| پورت پنل | انتخاب شده در جادوگر راه اندازی (درگاه آزاد تصادفی به طور پیش فرض؛ `8080` و موارد مشابه خوب هستند) |
| عامل gRPC | `18443` به طور پیش فرض |

دستورات خارجی Runtime به طور خودکار توسط نصب کننده نصب می شوند (`scripts/install.sh` و اسکریپت نصب Agent تولید شده توسط پنل؛ با `--no-deps` / `CF_SKIP_DEPS=1` رد شوید):

| هدف | بسته |
|---------|---------|
| فایروال / محدودیت نرخ / علامت گذاری همزمان | `nftables` (`nft`) |
| شکل دهی ترافیک، لینک ها و سوکت ها | `iproute2` (`tc` / `ip` / `ss`) |
| بازگشت زمانی که nft در دسترس نیست | `iptables` (`iptables-nft` در EL8+، `iptables` در EL7) |
| ردیابی اتصال | `conntrack-tools` (`conntrack`) |
| بارگذاری `nf_conntrack` / `ifb` | `kmod` (`modprobe` / `lsmod`) |
| شناسایی و پاکسازی فرآیند | `procps` (`pgrep` / `pkill`) |
| بررسی بندر / پارامترهای DH | `lsof` / `openssl` |
| ایجاد کاربر پروکسی | `shadow-utils` (Debian `passwd`، Alpine/Arch `shadow`) |
| دانلود و آرشیو | `curl` / `ca-certificates` / `tar` / `gzip` / `xz` |

> گم شدن `nft` / `tc` فقط بر محدودیت نرخ و ویژگی های فایروال تأثیر می گذارد. پانل هنوز شروع می شود
> ابتدا `--cpu-info` را اجرا کنید تا ببینید محیط چگونه شناسایی می شود و کدام بسته ها گم شده اند.

### 2.2 نصب تک خطی (توصیه می شود)

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh -o install.sh
sudo bash install.sh
```

یا مستقیماً آن را لوله کنید (بدون تعامل، بدون پرچم اضافی):

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash
```

اسکریپت:

1. توزیع، معماری CPU و libc را شناسایی کنید، سپس بسته های پایه و وابستگی های زمان اجرا را نصب کنید.
2. `corefusion-linux-<arch>` را از نسخه‌های GitHub دانلود کنید و آن را با `.sha256` منطبق تأیید کنید.
3. در `/opt/corefusion` نصب کنید و `data/{sqlite,certs,logs,runtime}` را ایجاد کنید.
4. فقط یک مکان نگهدار `.env` با `SAFE_PATHS=data` بنویسید - بدون پیکربندی پایگاه داده - بنابراین اولین شروع وارد جادوگر نصب می شود (`.env` کامل توسط جادوگر تولید می شود).
5. یک سرویس systemd را نصب و راه اندازی کنید (یا زمانی که systemd در دسترس نیست، تحت `nohup` اجرا شود).
6. منتظر بمانید تا آماده شود، سپس مسیرهای نصب URL، نشانه و مسیرهای فهرست را چاپ کنید.

خروجی نمونه:

```text
==================================================================
 CoreFusion installation complete
------------------------------------------------------------------
 Install dir : /opt/corefusion
 Data dir    : /opt/corefusion/data
 Binary      : /opt/corefusion/corefusion
 Logs        : journalctl -u corefusion -f
------------------------------------------------------------------
 Setup wizard : http://<server-ip>:<random-port>/init?init_token=<token>
 Setup token  : <token>
 Valid for    : 2 hours (see startup log)
 Note         : the token is shown once; after setup this port closes and the panel switches to its normal port.
==================================================================
```

اگر پانل فقط به `127.0.0.1` گوش می دهد (مثلاً در پشت پراکسی معکوس)، اسکریپت به جای یک URL غیرقابل دسترس، یک دستور تونل SSH را چاپ می کند.

> رمز را گم کرده اید؟ گزارش راه اندازی را دوباره بخوانید: `journalctl -u corefusion -n 50 --no-pager`
> (بدون systemd: `tail -n 50 /opt/corefusion/data/logs/panel.log`).

### 2.2.1 خروجی چند زبانه

نصب کننده شامل چهار زبان رابط کاربری است: چینی ساده، انگلیسی، فارسی (فارسی) و روسی (Русский). به طور خودکار سیستم `LANG` را شناسایی می کند، یا می توانید به صراحت انتخاب کنید:

```bash
# English
sudo bash install.sh --lang en

# Persian via environment variable
sudo CF_LANG=fa bash install.sh

# Pass options through a pipe
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash -s -- --lang ru
```

مقادیر پشتیبانی شده: `zh` / `en` / `fa` / `ru`؛ `--lang=ru` نیز پذیرفته می شود. یک مقدار صریح پشتیبانی نشده با لیست زبان های موجود ناموفق است.

### 2.3 نسخه پین / آینه / نصب آفلاین

```bash
# Pin a version
sudo bash install.sh --version v0.13.0

# GitHub download mirror (used as a URL prefix)
sudo bash install.sh --mirror https://ghproxy.net --version latest

# Use a local binary (offline / intranet / pre-built)
sudo bash install.sh --local ./dist/corefusion-linux-arm64

# Explicit target architecture
sudo bash install.sh --arch arm64 --local ./corefusion-linux-arm64
```

> بدون `--version`، اسکریپت از جدیدترین ورودی در لیست انتشارات GitHub استفاده می کند.
> اکثر نسخه ها پیش از انتشار هستند، بنابراین نقطه پایانی `/releases/latest` استفاده نمی شود.
>
> نسخه های رسمی فقط `amd64` / `arm64` را ارائه می دهند. از `--source` یا یک باینری متقابل کامپایل شده با `--local` برای معماری های دیگر استفاده کنید.

### 2.4 ساختن از مبدا

```bash
sudo bash install.sh --source --version v0.13.0
```

`--source` مخزن را شبیه سازی می کند (یا وقتی اسکریپت داخل آن است از پرداخت موجود استفاده می کند) و `make panel` را اجرا می کند. نسخه های زنجیره ابزار در هر محیط انتخاب می شوند:

| وابستگی | انتخاب |
|------------|-----------|
| برو | خواندن از `toolchain` / `go` در `go.mod` (در حال حاضر **برو 1.27+**)؛ اگر نسخه سیستم خیلی قدیمی باشد، زنجیره ابزار منطبق در `<install-dir>/.toolchain` دانلود می شود |
| گره | ** Node 22 LTS ** به طور پیش فرض (Vite به ≥ 18 نیاز دارد). یک بیلد رسمی منطبق در صورت نیاز دانلود می شود |
| گره (glibc < 2.28) | از ساخت `unofficial-builds` glibc-217 استفاده می کند (به عنوان مثال CentOS 7) |
| گره (آلپ / musl) | از توزیع `nodejs` / `npm` استفاده می کند |

لغو:

```bash
# Force Go / Node versions
sudo CF_GO_VERSION=1.27.5 CF_NODE_MAJOR=22 bash install.sh --source

# Go toolchain mirror (default https://go.dev/dl)
sudo CF_GO_MIRROR=https://golang.google.cn/dl bash install.sh --source
```

ساخت دستی (توسعه / اشکال زدایی):

```bash
git clone https://github.com/qist/corefusion.git
cd corefusion

# Frontend + panel for the current architecture; the frontend is embedded via go:embed
make panel

# Cross-compile
make panel-linux-amd64
make panel-linux-arm64
```

> `go build ./...` یک باینری تولید نمی کند. ساخت پانل با
> `go build -o corefusion ./cmd/corefusion/` یا `make panel`.

### 2.5 پرچم نصب

| پرچم | توضیحات |
|------|-------------|
| `-d, --dir <PATH>` | دایرکتوری، پیش فرض `/opt/corefusion` را نصب کنید |
| `-v, --version <TAG>` | نسخه پنل، به عنوان مثال `v0.13.0`; پیش فرض `latest` |
| `--binary` | استفاده از باینری GitHub Release (پیش‌فرض) |
| `--source` | از منبع بسازید و Go/Node مطابق را آماده کنید |
| `--local <FILE>` | استفاده از باینری محلی (نصب آفلاین) |
| `--arch <ARCH>` | معماری هدف: `amd64` / `arm64` / `armv7` / `armv6` / `386` / `ppc64le` / `s390x` / `riscv64` / `loong64` |
| `--mirror <URL>` | پیشوند دانلود GitHub، به عنوان مثال. `https://ghproxy.net` |
| `--repo <URL>` | مخزن منبع، پیش فرض `https://github.com/qist/corefusion.git` |
| `--ref <REF>` | شاخه / برچسب منبع؛ پیش فرض `--version` است، در غیر این صورت `main` |
| `--no-deps` | از نصب وابستگی سیستم صرف نظر کنید |
| `--no-start` | فایل سرویس را بدون شروع نصب کنید و بنویسید |
| `--cpu-info` | شناسایی محیط و وابستگی های از دست رفته را چاپ کنید، سپس خارج شوید |
| `--lang <LANG>` | زبان خروجی: `zh` / `en` / `fa` / `ru` (پیش‌فرض: سیستم `LANG`) |
| `--uninstall` | سرویس را متوقف کنید و برنامه را حذف کنید (داده ها و `.env` را حفظ می کند) |
| `--purge` | با `--uninstall`، دایرکتوری داده و `.env` را نیز حذف کنید |

> نسخه های رسمی فقط باینری های `amd64` / `arm64` را ارسال می کنند. سایر معماری ها به `--source` نیاز دارند،
> در غیر این صورت دانلود 404 را برمی گرداند.

متغیرهای محیطی مرتبط:

| متغیر | هدف |
|----------|---------|
| `CF_GO_VERSION` | نسخه Go مورد نیاز برای ساخت منبع را لغو کنید |
| `CF_NODE_MAJOR` | لغو نسخه اصلی Node (پیش‌فرض 22) |
| `CF_GO_MIRROR` | Go toolchain دانلود آینه |
| `CF_SKIP_DEPS` | در اسکریپت نصب Agent روی `1` تنظیم کنید تا از نصب وابستگی رد شود |
| `CF_LANG` | لغو زبان خروجی نصب کننده (همان `--lang`) |

### 2.6 طرح دایرکتوری

```text
/opt/corefusion/
├── corefusion                 # panel binary
├── corefusion.bak             # previous version (when upgrading)
├── .env                       # environment file (0600, generated by the setup wizard)
├── .env.secret                # encryption key file (0600, generated on first start)
├── .toolchain/                # Go / Node downloaded for source builds
└── data/                      # data directory (SAFE_PATHS)
    ├── sqlite/app.db          # default SQLite database
    ├── certs/                 # certificates and keys
    ├── logs/                  # runtime logs (without systemd)
    ├── runtime/               # core runtime config and state
    ├── binaries/              # downloaded xray / sing-box cores
    └── proxy/                 # proxy (Caddy/Nginx) sites and config
```

> نصب کننده فقط `sqlite/`، `certs/`، `logs/` و `runtime/` را ایجاد می کند. `binaries/`، `proxy/`، `rules/` و موارد دیگر توسط پنل یا زمانی که هسته ها نصب می شوند ایجاد می شوند.
> دایرکتوری داده از `SAFE_PATHS` در `.env` می آید و ممکن است یک مسیر مطلق باشد. تغییر دایرکتوری نصب، داده های موجود را جابجا نمی کند.

### 2.7 مدیریت خدمات

systemd (اکثر توزیع ها):

```bash
systemctl status corefusion --no-pager
systemctl restart corefusion
systemctl stop corefusion
journalctl -u corefusion -f          # follow logs
journalctl -u corefusion -n 100      # last 100 lines
```

بدون systemd (ظروف و غیره):

```bash
cd /opt/corefusion && ./corefusion            # foreground (debugging)
cd /opt/corefusion && setsid nohup ./corefusion >> data/logs/panel.log 2>&1 &
tail -f data/logs/panel.log
```

> بدون systemd فرآیند در بوت شروع نمی شود. پس از راه اندازی مجدد، آن را به صورت دستی مجدداً راه اندازی کنید (یا نصب کننده را مجدداً اجرا کنید).

### 2.8 ارتقا و حذف نصب کنید

ارتقاء (داده ها و پیکربندی را حفظ می کند):

```bash
sudo bash install.sh --version <new-version>
```

اسکریپت سرویس را متوقف می کند، از باینری قدیمی به عنوان `corefusion.bak` پشتیبان می گیرد، آن را جایگزین می کند و دوباره راه اندازی می شود. `.env` و `data/` موجود دست نخورده باقی مانده اند.

حذف نصب:

```bash
# Remove the program only; keep data and .env
sudo bash install.sh --uninstall

# Also remove the data directory and .env (irreversible)
sudo bash install.sh --uninstall --purge
```

### 2.9 فایل محیطی (.env)

`.env` کامل ** توسط جادوگر راه اندازی** هنگامی که پیکربندی ذخیره می شود (پایگاه داده DSN، فهرست داده ها، اسرار، پورت ها، دامنه ها) ایجاد می شود.

در یک نصب جدید، نصب کننده فقط این مکان نگهدارنده را می نویسد، بنابراین پانل `data/` موجود را با نصب اولیه اشتباه نمی گیرد و از جادوگر صرف نظر می کند:

```env
SAFE_PATHS=data
```

> هنگامی که یک پیکربندی کامل (`.env` با `CF_DB_DSN`) از قبل وجود داشته باشد، نصب کننده هرگز آن را رونویسی نمی کند و جادوگر دوباره ظاهر نمی شود.
> ویرایش‌های دستی بعدی `.env` پس از راه‌اندازی مجدد اعمال می‌شوند.

#### دایرکتوری داده ها

```env
SAFE_PATHS=data                       # relative to the install directory
# SAFE_PATHS=/srv/corefusion-data     # or an absolute path
```

#### پایگاه داده

`CF_DB_DSN` با پیشوند شناسایی می شود:

| پیشوند | پایگاه داده |
|--------|----------|
| تنظیم نشده یا یک مسیر خالی | SQLite (پیش‌فرض) |
| `sqlite://` | SQLite (صریح) |
| `mysql://` | MySQL |
| `postgres://` / `postgresql://` | PostgreSQL |

`CF_DB_TYPE` اختیاری است و تشخیص را لغو می کند (`sqlite` / `mysql` / `postgres`).

> **رمزهای رمزگذاری شده**: MySQL/PostgreSQL DSN نوشته شده توسط پنل (جادوگر راه اندازی / سوئیچ پایگاه داده)
> در `.env` به عنوان `enc:...` (AES-256-GCM، کلید `CF_SECRET_ENCRYPTION_KEY`) ذخیره می شوند.
> آنها در خواندن رمزگشایی می شوند. DSNهای متن ساده که با دست نوشته شده اند هنوز کار می کنند.

**SQLite (پیش فرض)**

```env
# Bare path (detected as SQLite)
CF_DB_DSN=data/sqlite/app.db

# Or explicit sqlite:// prefix
CF_DB_DSN=sqlite:///opt/corefusion/data/sqlite/app.db
```

**MySQL**

```env
# Format: mysql://user:password@tcp(host:port)/dbname?params
CF_DB_DSN=mysql://corefusion:password@tcp(127.0.0.1:3306)/corefusion?charset=utf8mb4&parseTime=True&loc=Local
```

**PostgreSQL**

```env
# Format: postgres://user:password@host:port/dbname?params
CF_DB_DSN=postgres://corefusion:password@127.0.0.1:5432/corefusion?sslmode=disable
```

#### استخر اتصال (اختیاری، MySQL/PostgreSQL)

```env
CF_DB_MAX_OPEN_CONNS=100
CF_DB_MAX_IDLE_CONNS=10
```

#### سایر متغیرهای رایج

| متغیر | توضیحات |
|----------|-------------|
| `JWT_SECRET` | کلید امضا برای نشانه های ورود؛ در اولین شروع در هنگام گم شدن تولید می شود |
| `CF_SECRET_ENCRYPTION_KEY` | کلید رمزگذاری تنظیمات حساس (AES-256-GCM)؛ هنگام گم شدن ایجاد می شود |
| `CF_INITIAL_ADMIN_PASSWORD` | رمز عبور اولیه مدیریت (اختیاری؛ تصادفی و یک بار چاپ شده به طور پیش فرض) |
| `CF_NETWORK_TRAFFIC_ACCOUNTING` | برای غیرفعال کردن حسابداری ترافیک مبتنی بر iptables روی `0` تنظیم کنید (به طور پیش فرض فعال است) |
| `CF_NETWORK_TRAFFIC_TABLE` | جدول iptables مورد استفاده برای حسابداری ترافیک، پیش فرض `corefusion` |

> **کلید رمزگذاری در `.env.secret` زندگی می‌کند**: در شروع اول `CF_SECRET_ENCRYPTION_KEY` به جای `.env` در `.env.secret` (0600، همان فهرست `.env`) نوشته می‌شود. یک کلید قدیمی در `.env` به طور خودکار منتقل می شود. از این فایل به طور جداگانه نسخه پشتیبان تهیه کنید - از دست دادن آن باعث می شود هر مقدار `enc:` غیرقابل رمزگشایی شود.

> پروکسی های معکوس قابل اعتماد برای حل IP های مشتری واقعی دیگر از طریق متغیرهای محیطی پیکربندی نمی شوند.
> آنها به عنوان `panel.trusted_proxies` در **تنظیمات → شبکه** ذخیره می شوند.

> `.env` و `.env.secret` هر دو حاوی اسرار هستند. پانل مجوزهای خود را در شروع به `0600` محکم می کند. هرگز آنها را مرتکب نشوید.

### 3.2 مراحل جادوگر

جادوگر 8 مرحله دارد. شما می توانید در هر زمان به عقب برگردید. هیچ چیز تا ذخیره نهایی متعهد نیست.

| مرحله | محتوا |
|------|---------|
| 1. پایگاه داده | SQLite / MySQL / PostgreSQL |
| 2. فهرست داده ها | به `SAFE_PATHS` در `.env` نوشته شده است |
| 3. کلیدهای رمزگذاری | `JWT_SECRET` و `CF_SECRET_ENCRYPTION_KEY` |
| 4. هسته ها | کدام هسته های پروکسی را نصب کنیم |
| 5. پروکسی | هیچکدام / Nginx / Caddy |
| 6. سایت ها و دامنه ها | پورت ها، مسیر وب، حساب مدیریت، ارز، منطقه زمانی، دامنه ها |
| 7. گواهی HTTPS | غیرفعال / آپلود / ACME |
| 8. خلاصه | بررسی، دانلود `.env`، ذخیره و راه اندازی مجدد |

#### مرحله 1: پایگاه داده

- **SQLite (فایل محلی، توصیه می شود)**: مسیر را برای استفاده از `<data-dir>/sqlite/app.db` خالی بگذارید.
- **MySQL / PostgreSQL**: میزبان، پورت، کاربر، رمز عبور، نام پایگاه داده؛ PostgreSQL از `disable` / `require` / `verify-full` نیز پشتیبانی می کند.
- برای تأیید اعتبار، روی «آزمایش اتصال» کلیک کنید. ذخیره کردن نیز آن را آزمایش می کند. یک پایگاه داده گم شده به طور خودکار ایجاد می شود (اگر حساب فاقد `CREATE` است آن را به صورت دستی ایجاد کنید).
- DSN (شامل رمز عبور) قبل از نوشتن در `.env` رمزگذاری می شود.

#### مرحله 2: فهرست اطلاعات

پایگاه داده، گواهی ها، لاگ ها، باینری های هسته و موارد دیگر را ذخیره می کند. این `SAFE_PATHS` در `.env` است. پیش‌فرض `data` است
(نسبت به دایرکتوری نصب)؛ یک مسیر مطلق مجاز است. **بعداً آن را به طور تصادفی تغییر ندهید**، یا پانل
پایگاه داده و گواهی های موجود را پیدا نمی کند.

#### مرحله 3: کلیدهای رمزگذاری

- `JWT_SECRET`: نشانه های ورود را امضا می کند.
- `CF_SECRET_ENCRYPTION_KEY`: تنظیمات حساس (رمز عبور پایگاه داده، اعتبار DNS، کارت های شارژ و غیره) را رمزگذاری می کند.
- هر دو به طور پیش فرض به صورت تصادفی تولید می شوند. برای بدست آوردن مقادیر جدید از "Regenerate" استفاده کنید. **تغییر `CF_SECRET_ENCRYPTION_KEY` داده های رمزگذاری شده قبلی را غیرقابل خواندن می کند** — از آن نسخه پشتیبان تهیه کنید.

#### مرحله 4: هسته ها

هسته های پروکسی را برای نصب انتخاب کنید:

- **Xray**: VLESS / VMess / Trojan / Shadowsocks و غیره؛
- **sing-box**: دارای پروتکل های Hysteria2 / TUIC و سایر پروتکل های QUIC است.

پس از ذخیره و راه اندازی مجدد پنل به صورت خودکار آنها را دانلود و نصب می کند. نسخه ها و وضعیت را در قسمت «پروتکل ها» بررسی کنید. شما همچنین می توانید آنها را بعدا نصب کنید.

#### مرحله 5: پروکسی

- **هیچ**: پنل مستقیماً به مشتریان خدمات ارائه می دهد (خودتان با TLS رسیدگی کنید).
- **Nginx / Caddy**: پنل پروکسی معکوس و میزبانی گواهی را مدیریت می کند. یکی را انتخاب کنید

با انتخاب یک پروکسی، پنل معمولاً فقط به `127.0.0.1` گوش می دهد و پراکسی به دنیای خارج سرویس می دهد.

#### مرحله 6: سایت ها و دامنه ها

| میدان | توضیحات |
|-------|-------------|
| آدرس گوش کن | به طور خودکار مشتق می شود: پروکسی → `127.0.0.1`; بدون پروکسی با گواهی → `0.0.0.0`. در غیر این صورت → `127.0.0.1` |
| پورت پنل | پورت رایگان تصادفی به طور پیش فرض؛ اگر دوست دارید آن را تغییر دهید (به عنوان مثال 8080) |
| پورت اشتراک | اختیاری؛ `0` پورت پنل را به اشتراک می گذارد |
| پورتال پورتال | اختیاری؛ `0` پورت پنل را به اشتراک می گذارد |
| مسیر وب | مسیر رابط کاربری مدیریت، پیش‌فرض `/`؛ API همیشه `/api/v1` است |
| نام کاربری / رمز عبور ادمین | تصادفی به طور پیش فرض؛ ** رمز عبور فقط یک بار در خلاصه نشان داده می شود ** - آن را ذخیره کنید |
| حالت دسترسی | «دامنه» یا «IP» |
| واحد پول / منطقه زمانی پیش‌فرض | ارز پیش فرض برای کارت های شارژ و موجودی. پانل و منطقه زمانی گزارش پراکسی (مانند `Asia/Shanghai`) |
| به پراکسی معکوس اضافه کنید | هنگامی که یک پروکسی و دامنه تنظیم می شود، دامنه های پانل / اشتراک / پورتال را به یکباره به پروکسی اضافه کنید |

با ورود به دامنه ها، تنظیمات مربوطه را می نویسد (دامنه پاسخ به تماس، نقطه پایان اشتراک، دامنه اشتراک).

#### مرحله 7: گواهی HTTPS

| منبع | توضیحات |
|--------|-------------|
| HTTPS را غیرفعال کنید | پنل/پورتال/اشتراک‌ها از طریق HTTP (ناامن) ارائه می‌شوند. با یک پروکسی معکوس می توانید TLS را بعداً در سمت پروکسی اضافه کنید |
| گواهی آپلود | چسباندن گواهی PEM و کلید خصوصی PEM (فقط حالت دسترسی به دامنه) |
| ACME | هنگام ارسال این مرحله گواهی را صادر می کند. از گواهینامه های دامنه و IP پشتیبانی می کند |

گزینه های ACME:

- **CA**: Let's Encrypt, Let's Encrypt (Staging), ZeroSSL, Google Public CA;
- **هدف**: دامنه پیکربندی شده یا IP عمومی (گواهینامه های IP فقط توسط Let's Encrypt پشتیبانی می شوند).
- **چالش**: `HTTP-01` (به پورت 80 نیاز دارد) یا `DNS-01` (کارت های عام، بدون پورت 80؛ ارائه دهنده DNS را انتخاب کنید و اعتبارنامه ها را وارد کنید).
- **نوع / اندازه کلید**: ECC 256/384 یا RSA 2048/3072/4096؛
- **Google عمومی CA **: به EAB نیاز دارد. شناسه کلید / HMAC را به صورت دستی وارد کنید یا از یک حساب سرویس GCP استفاده کنید.

> گواهی IP به طور خودکار IPv4/IPv6 عمومی میزبان را شناسایی می کند. در پشت پراکسی، آدرس شناسایی شده مربوط به میزبان است، نه خروجی پروکسی.
> گواهینامه‌های دامنه نیز می‌توانند بعداً تحت «گواهینامه‌ها» صادر شوند.

#### مرحله 8: خلاصه

پایگاه داده، دایرکتوری داده ها، هسته ها، پروکسی، پورت ها، حساب مدیریت، دامنه ها و کلیدهای `.env` (اسرار پنهان شده) را نشان می دهد و ارائه می دهد:

- **دانلود env**: یک کپی از پیکربندی را نگه دارید.
- ** آدرس های اینترنتی دسترسی **: آدرس های نهایی برای پانل / اشتراک / پورتال. HTTP به عنوان ناامن علامت گذاری شده است.

برای نوشتن پایگاه داده و `.env` روی "ذخیره و راه اندازی مجدد" کلیک کنید. پانل دوباره به سرویس عادی راه اندازی می شود.

### 3.3 پس از راه اندازی

- سرویس دوباره راه اندازی می شود و گزارش راه اندازی آدرس نهایی گوش دادن را چاپ می کند.
- با حساب مدیریت وارد شوید، به URL و مسیر وب از خلاصه دسترسی پیدا کنید.
- اگر رمز عبور گم شد، آن را به صورت آفلاین با `./corefusion admin reset-password` بازنشانی کنید.

### 3.4 راه اندازی غیر تعاملی CLI

برای سرورهای اتوماسیون یا بدون هد، پیکربندی را بنویسید و تنظیم را به طور مستقیم علامت بزنید:

```bash
cd /opt/corefusion
./corefusion init \
  --db-type sqlite \
  --data-dir /opt/corefusion/data \
  --admin-username admin \
  --admin-password 'change-me-strong-password' \
  --listen-port 8080 \
  --proxy-type caddy \
  --cores xray,singbox \
  --panel-domain panel.example.com \
  --tls-mode acme --tls-domain panel.example.com --tls-email you@example.com
```

پرچم های رایج:

| پرچم | توضیحات |
|------|-------------|
| `--db-type` / `--db-host` / `--db-port` / `--db-user` / `--db-password` / `--db-name` | تنظیمات پایگاه داده |
| `--data-dir` | فهرست اطلاعات؛ پیش فرض `SAFE_PATHS` یا `./data` است |
| `--listen-port` / `--subscription-port` / `--portal-port` / `--web-path` | پورت ها و مسیر وب (درگاه آزاد تصادفی به طور پیش فرض) |
| `--admin-username` / `--admin-password` | حساب مدیریت (پسورد تصادفی یک بار در صورت حذف چاپ می شود) |
| `--proxy-type` | `none` / `nginx` / `caddy` |
| `--cores` | هسته برای نصب، با کاما از هم جدا شده است: `xray,singbox` |
| `--panel-domain` / `--subscription-domain` / `--portal-domain` | دامنه ها (در تنظیمات نوشته شده و به پروکسی معکوس اضافه شده است) |
| `--tls-mode` | `none` / `self_signed` / `acme` |
| `--tls-domain` / `--tls-email` / `--tls-challenge` / `--tls-key-type` / `--tls-key-bits` | گزینه‌های گواهی (`--tls-challenge` پیش‌فرض روی `http-01` است؛ `dns-01` به `--tls-dns-channel` یا `--tls-dns-provider` نیاز دارد) |
| `--tls-ip-cert` | صدور گواهی برای IP عمومی شناسایی شده (فقط اجازه دهید رمزگذاری کنیم) |
| `--acme-provider` | `lets_encrypt` / `lets_encrypt_staging` / `zerossl` / `google` |
| `--currency` / `--timezone` | واحد پول / منطقه زمانی پیش‌فرض |

لیست کامل: `./corefusion init --help`. سپس سرویس را شروع کنید:

```bash
systemctl restart corefusion
```

### 3.5 اجرای مجدد جادوگر راه اندازی

برای شروع مجدد (`.env` و علامت های راه اندازی را حذف می کند، **داده ها را حفظ می کند**):

```bash
cd /opt/corefusion
./corefusion reset-init      # type RESET to confirm
systemctl restart corefusion
```

سپس از URL و توکن جدید از لاگ راه اندازی استفاده کنید.

> راه‌اندازی مجدد حساب مدیریت و مسیر وب را بازنشانی می‌کند. داده های کسب و کار در پایگاه داده قدیمی باقی می مانند، اما ممکن است لازم باشد حساب ورود را دوباره ایجاد کنید.
>
> `reset-init` کل `.env` (از جمله `SAFE_PATHS`) را حذف می کند. **اگر فهرست اطلاعات شما یک مسیر مطلق سفارشی است**، قبل از راه اندازی مجدد، `SAFE_PATHS` را بازیابی کنید، در غیر این صورت پنل در `./data` به نظر می رسد:
>
> ```bash
> printf 'SAFE_PATHS=/srv/corefusion-data\n' > /opt/corefusion/.env
> ```

### 3.6 امنیت پس از اولین ورود به سیستم

#### رمز اولیه را تغییر دهید

1. روی نام کاربری در گوشه سمت راست بالا کلیک کنید.
2. "تغییر رمز عبور" را انتخاب کنید؛
3. رمز عبور قدیمی و جدید را وارد کنید؛
4. روی «ذخیره» کلیک کنید.

#### فعال کردن ورود با کد پویا (2FA / TOTP)

> پس از فعال شدن، حساب به **ورود با کد پویا** تغییر می کند: رمز عبور ثابت دیگر پذیرفته نمی شود. فقط
> کد 6 رقمی از برنامه احراز هویت شما (یا کد بازیابی یک بار مصرف) کار می کند. این **جایگزین** ورود رمز عبور می شود - این است
> نه تایید دو مرحله ای "رمز عبور + کد".

1. روی نام کاربری در گوشه سمت راست بالا کلیک کنید.
2. "فعال کردن 2FA" را انتخاب کنید.
3. رمز عبور فعلی را وارد کنید (فقط برای تأیید این تغییر).
4. کد QR را با یک برنامه احراز هویت (Google Authenticator / 1Password و غیره) اسکن کنید یا کلید را به صورت دستی وارد کنید.
5. کد 6 رقمی را وارد کنید تا فعال سازی به پایان برسد.
6. **کدهای بازیابی را فوراً ذخیره کنید** (قابل دانلود)؛ هر کد یک بار کار می کند.

ورود به سیستم پس از آن:

- پس از وارد کردن نام کاربری، قسمت رمز عبور به "کد 6 رقمی / کد بازیابی" تبدیل می شود و دکمه به "ورود با کد" تبدیل می شود.
- کد فعلی را وارد کنید؛ **از رمز عبور ثابت دیگر نمی توان استفاده کرد**.
- کدهای بازیابی یکبار مصرف هستند. وقتی تمام شد آنها را تحت «ورود کد پویا (2FA)» بازسازی کنید (این کار همه کدهای قدیمی را باطل می کند).

اگر احراز هویت گم شده و کدهای بازیابی تمام شده اند، 2FA آفلاین را در سرور غیرفعال کنید:

```bash
cd /opt/corefusion
./corefusion admin 2fa reset -u admin    # disables 2FA, clears the secret and recovery codes, revokes all sessions
```

> یک سوپرمدیر انحصاری بدون احراز هویت و کدهای بازیابی نمی تواند از طریق رابط کاربری وب بازیابی شود و باید از دستور بالا استفاده کند.

#### ثبت Passkey (اختیاری)

1. روی نام کاربری در گوشه سمت راست بالا کلیک کنید.
2. "Passkey management" را انتخاب کنید؛
3. روی "ثبت نام جدید Passkey" کلیک کنید.
4. درخواست دستگاه را کامل کنید.

> **توجه**: کلیدهای عبور به HTTPS یا میزبان محلی نیاز دارند و دامنه باید در لیست مجاز باشد.

## 5. مدیریت گره

مدیریت گره هسته CoreFusion است و از چندین نوع گره پشتیبانی می کند.

### 5.1 انواع گره

| تایپ کنید | توضیحات |
|------|-------------|
| مستقل (`standalone`) | یک گره اصلی مستقل |
| آینه (`mirror`) | پیکربندی را از یک گره هدف همگام سازی می کند |
| اصلی/پشتیبان (`primary_backup`) | گره های شریکی که در مقابل یکدیگر شکست می خورند |
| ورودی زنجیره ای (`chain_entry`) | گره ورودی یک پروکسی زنجیره ای |
| خروجی زنجیره ای (`chain_exit`) | گره خروج از یک پروکسی زنجیره ای |

### 5.2 اضافه کردن یک گره

1. "مدیریت گره" را باز کنید؛
2. روی "افزودن سرور" کلیک کنید؛
3. اصول اولیه را پر کنید:
   - نام، به عنوان مثال `HongKong-HK01`
   - نام میزبان: IP یا دامنه
   - منطقه، به عنوان مثال `HK`، `JP`، `US`
   - نوع گره؛
4. پورت Agent را تنظیم کنید (پیش‌فرض `18443`)؛
5. هسته های پشتیبانی شده را انتخاب کنید.
6. روی «ذخیره» کلیک کنید.

### 5.3 استقرار با یک کلیک

1. پس از افزودن گره، "Deploy command" را در لیست گره انتخاب کنید (صفحه جزئیات نیز ارائه می دهد
 "فرمان نصب بوت استرپ")؛
2. دستور را کپی کنید - حاوی یک رمز ثبت نام یک بار مصرف (معتبر برای 24 ساعت، استفاده مجدد از آن) است.
3. آن را به عنوان ریشه در گره راه دور اجرا کنید. به نظر می رسد:

   ```bash
   bash <(curl -fsSL "http://<panel-host>:<panel-port>/api/v1/agent/install?id=<node-id>&token=<one-time-token>&port=<panel-port>")
   ```

4. Agent بسته را دانلود می کند، در پنل ثبت نام می کند و شروع می کند.

### 5.4 جزئیات گره

روی یک گره کلیک کنید تا صفحه جزئیات آن باز شود:

- ** نمای کلی **: اطلاعات اولیه، وضعیت نماینده، وضعیت گواهی. کارت‌های منبع میزان مصرف CPU/حافظه/دیسک، نرخ بالا/پایین NIC، نرخ ترافیک اصلی کاربر، ترافیک استفاده شده ماهانه، اتصالات TCP، بار سیستم و ترافیک تجمعی خروجی NIC را نشان می‌دهند (بازسازی بی‌صدا هر 10 ثانیه)
- **مرکز پروتکل**: پیکربندی فرآیند اصلی
- **پراکسی**: پیکربندی Caddy / Nginx
- ** فرآیندهای اصلی **: شروع / توقف / راه اندازی مجدد
- **ترافیک اصلی**: ترافیک کاربر ارسال شده توسط هسته و کل ماهانه آن
- **WARP**: پیکربندی WARP
- **دامنه های مستقیم**: مدیریت دامنه
- **محدودیت نرخ**: شکل دهی ترافیک
- **گواهی نامه ها**: الزام آور گواهی
- **کاربران آنلاین**: کاربران آنلاین بلادرنگ

### 5.5 اقدامات گره

- ** پیکربندی همگام سازی **: پیکربندی پانل را به گره فشار دهید
- **اجباری اتصال مجدد**: اتصال Agent را رها کرده و دوباره وصل کنید
- **Update Agent**: فشار به روز رسانی عامل
- **Revoke Certificate**: ابطال گواهی Agent گره

## 6. مرکز پروتکل

مرکز پروتکل پارامترهای پروتکل را برای فرآیندهای اصلی پیکربندی می کند.

### 6.1 هسته های پشتیبانی شده

| هسته | توضیحات |
|------|-------------|
| هسته Xray | VLESS / VMess / Trojan / Shadowsocks و موارد دیگر |
| sing-box | پلت فرم پروکسی جهانی مدولار با پشتیبانی TUN. دارای پروتکل های Hysteria2 / TUIC و سایر پروتکل های QUIC |

### 6.2 ماژول های پیکربندی

ماژول ها بین دو هسته متفاوت هستند. پانل مجموعه ای را نشان می دهد که با هسته انتخاب شده مطابقت دارد:

**Xray-core**

- ** ثبت نام **: گزارش دسترسی، گزارش خطا، حالت خروجی
- **API**: gRPC API آدرس گوش، لیست خدمات
- **DNS**: سرورهای DNS، استراتژی پرس و جو، هاست استاتیک
- **مسیریابی**: قوانین مسیریابی، تعادل بار، مسیریابی VLESS
- ** ورودی / خروجی **: پروتکل، حمل و نقل، TLS
- **حمل و نقل**: WebSocket، gRPC، XHTTP و غیره (TUN یک پروتکل ورودی است، نه یک انتقال)
- **TLS**: گواهینامه ها، ALPN، اثر انگشت uTLS، ECH
- **Reality**: مدیریت هدف، جفت کلید، شناسه کوتاه
- **بررسی سلامت / FakeDNS / معیارها / خط‌مشی / داده‌های جغرافیایی / محدودیت‌های نسخه **: کاوشگر، استخر IP، Prometheus، زمان‌بندی‌ها و بافرها، فایل‌های منبع، محدوده نسخه اصلی

**sing-box**

- ** ثبت نام **: سطح، مهر زمانی، خروجی
- **NTP**: همگام سازی زمان
- **DNS**: سرورها و قوانین DNS
- **مسیریابی**: خروجی پیش‌فرض `final`، **مجموعه‌های قوانین**، **قوانین**، حل‌کننده دامنه پیش‌فرض، استراتژی شبکه و بازگشت (نگاه کنید به 6.6)
- ** ورودی / خروجی **: پروتکل، حمل و نقل، TLS
- **نقاط پایانی**: WireGuard (شامل پیکربندی های WARP)، کلاینت های MASQUE و موارد مشابه؛ چندین می توانند با هم وجود داشته باشند و با `tag` متمایز می شوند

> با فعال بودن «استفاده از یکپارچگی شبکه سیستم»، **نام** نقطه پایانی نام رابط هسته است:
> حداکثر 15 کاراکتر، فقط حروف/رقوم/`._-`. نام خیلی طولانی یا نامعتبر به طور خودکار برمی گردد
> به نقطه پایانی `tag`. نقاط پایانی جدید در هر پروتکل پیشوند هستند (`wg-` / `ts-` / `oc-` / `ovpn-c-` /
> `ovpn-s-` / `mq-c-` / `mq-s-`)، و سوابق قدیمی مانند `WireGuard-xxxxxx` عادی نشان داده می شوند
> به محض باز شدن ویرایشگر
- **خدمات**: آرایه سطح بالای sing-box `services`، مانند `hysteria-realm`، DERP یا `resolved`
- **گواهینامه ها / مشتریان HTTP / فضاهای نام شبکه **: بخش های JSON را فقط در صورت نیاز گسترش می دهید
- **تجربی**: `clash_api` و مشابه؛ **هیچ چیزی در پیکربندی تولید شده نوشته نمی شود مگر اینکه فعال باشد**

> sing-box 1.12 فیلدهای مسیریابی `geosite` / `geoip` را حذف کرد. اکنون مسیریابی مبتنی بر جغرافیا انجام می شود
> `rule_set`. حفظ فیلدهای قدیمی باعث می شود که هسته در رمزگشایی پیکربندی (`unknown field`) شکست بخورد.

### 6.3 پیکربندی ورودی

1. هسته و پروتکل را انتخاب کنید.
2. اصول اولیه را پر کنید:
   - برچسب بزنید
   - آدرس و پورت گوش کنید
   - نوع پروتکل
3. تنظیم پارامترهای پروتکل (UUID، رمز عبور، و غیره)؛
4. حمل و نقل را انتخاب کنید (TCP، WebSocket، gRPC، و غیره)؛
5. پیکربندی TLS (گواهینامه، ALPN)؛
6. ذخیره کنید و روی هسته اعمال کنید.

> ورودی های جدید به طور پیش فرض به `::` گوش می دهند (دو پشته در Linux، هر دو IPv4 و IPv6 را مدیریت می کند).
> تنها زمانی که نیاز به محدود کردن رابط دارید، آن را به `0.0.0.0` یا یک آدرس خاص تغییر دهید.

حالت‌های پورت «استفاده از پورت ورودی» همچنین **ایجاد فایروال مجاز قوانین به صورت خودکار** را ارائه می‌دهد: باز کردن
ویرایشگر ورودی ابتدا فایروال گره را بررسی می کند و هنگامی که فایروال / ufw / nftables / iptables شناسایی شد
می توانید طبق پروتکل گوش دادن (TCP/UDP) اجازه ذخیره پورت را بدهید.

- پرش پورت hy2 / hysteria به پورت گوش دادن و هر محدوده پورت پویا (به عنوان مثال `20000-30000`) اجازه می دهد. محدوده های متعدد با کاما از هم جدا می شوند.
- Allowance بی توان است: یک قانون پوشش موجود (محدوده پورت / چند پورت) دوباره ایجاد نمی شود.
- تغییر پورت قبل از اجازه دادن به قانون جدید، قانون قدیمی را لغو می کند. حذف ورودی، غیرفعال کردن پرش پورت یا سوئیچ کردن به سوکت/تن یونیکس (بدون درگاه گوش دادن) آن را پاک می کند.
- هنگامی که هیچ فایروال فعالی شناسایی نمی شود، فقط یک اشاره نشان داده می شود و هیچ قانونی نوشته نمی شود.

### 6.3.1 مسیر معکوس پروکسی (دامنه دسترسی → جلو TLS → مسیر پروکسی معکوس)

هنگامی که مسیر انتقال خود ورودی `/` است اما یک nginx / caddy بیرونی آن را در زیر یک مسیر فرعی نصب می کند.
(به عنوان مثال `location /apps { proxy_pass http://127.0.0.1:8080/; }`)، مشتریان باید به `/apps` یا
درخواست هرگز به آن مکان نمی رسد - اشتراک همچنان بارگیری می شود، اما گره متصل نمی شود.
**مسیر پروکسی معکوس** را در قسمت «دامنه دسترسی → جلوی TLS» پر کنید:

- `/apps` یا `/apps?ed=2560` (با داده های اولیه) را وارد کنید. اشتراک ها و پیوندهای اشتراک ** مسیر حمل و نقل ورودی را با آن جایگزین کنید.
- برای ws، httpupgrade، xhttp و h2/http اعمال می شود. انتقال‌های بدون مسیر (خام/tcp، kcp) نادیده گرفته می‌شوند.
- مستقل از جایی که TLS خاتمه می‌یابد: وقتی جلوی TLS خاموش است، مسیر همچنان اعمال می‌شود (هسته را دنبال کنید).
- gRPC مفهوم پیشوند URL ندارد (مسیر مشتری همیشه `/{serviceName}/…` است)، بنابراین مسیر **در serviceName** ادغام می شود.
(`/apps` + `svc` → `apps/svc`); پراکسی معکوس باید آن پیشوند را در `grpc_pass` حذف کند.

### 6.4 پیکربندی خروجی

1. اضافه کردن یک خروجی؛
2. تگ و پروتکل را تنظیم کنید.
3. آدرس سرور و پورت را تنظیم کنید.
4. پیکربندی حمل و نقل و TLS؛
5. ذخیره و اعمال کنید.

### 6.5 پیوندها را به اشتراک بگذارید

1. در لیست ورودی، روی "اشتراک گذاری پیوند" کلیک کنید.
2. یک قالب را انتخاب کنید:
   - URI را به اشتراک بگذارید
   - Mihomo YAML
   - sing-box JSON
   - Xray JSON
3. پیوند را کپی کنید یا یک کد QR ایجاد کنید.

### 6.6 sing-box مسیریابی و مجموعه قوانین

در "مرکز پروتکل" → sing-box → "مسیریابی" دو بخش وجود دارد: ** مجموعه قوانین** قابلیت استفاده مجدد را اعلام می کند.
فایل‌های قانون، و **قوانین** شرایط مسابقه و خروجی را تعیین می‌کنند. قوانین از ارزیابی می شود
از بالا به پایین و اولین مسابقه برنده می شود.

#### 6.6.1 مجموعه قوانین

| میدان | توضیحات |
|-------|-------------|
| برچسب زدن | شناسه مجموعه قوانین که توسط قوانین ارجاع شده است. باید منحصر به فرد باشد |
| تایپ کنید | `local` یک فایل را روی گره می خواند. `remote` به هسته اجازه می دهد آن را در `update_interval` دانلود کند |
| قالب | `binary` برای `.srs` (پیش‌فرض)؛ `source` برای فرمت منبع `.json` |
| مسیر | مسیرهای `local` نسبت به دایرکتوری داده گره هستند. فایل های موجود در `data/rules/` از `rules/xxx.srs` استفاده می کنند |
| URL | آدرس دانلود برای `remote`; `download_detour` خروجی مورد استفاده برای دانلود را انتخاب می کند (معمولا `direct`) |

مجموعه‌های قوانین محلی (توصیه می‌شود؛ ابتدا فایل‌ها را در قسمت «منابع خدمات → فایل‌های قانون» دانلود کنید):

```jsonc
"route": {
  "rule_set": [
    { "type": "local", "tag": "geosite-cn", "format": "binary", "path": "rules/geosite-cn.srs" },
    { "type": "local", "tag": "geoip-cn", "format": "binary", "path": "rules/geoip-cn.srs" }
  ]
}
```

> دانلود فایل روی پنل کافی نیست: ابتدا باید یک مجموعه قانون `local` به
> گره ها ("Push to all node") بنابراین فایل در `data/rules/` گره وجود دارد. در غیر این صورت هسته
> شروع نمی شود زیرا فایل پیدا نمی شود.

مجموعه قوانین راه دور (گره باید بتواند به URL برسد):

```jsonc
{ "type": "remote", "tag": "geosite-openai", "format": "binary",
  "url": "https://raw.githubusercontent.com/SagerNet/sing-geosite/rule-set/geosite-openai.srs",
  "download_detour": "direct", "update_interval": "1d" }
```

هنگامی که یک فایل محلی را انتخاب می کنید، برچسب از نام فایل مشتق شده است (`rules/geosite-cn.srs` →
`geosite-cn`)؛ برای مجموعه های راه دور از انتهای URL می آید. فرمت نیز از پر شده است
پسوند (`.srs` → `binary`، `.json` → `source`). مقادیر مشتق شده را می توان آزادانه ویرایش کرد، و
مقادیری که قبلاً تایپ کرده اید هرگز رونویسی نمی شوند.

> `download_detour` از sing-box 1.14 منسوخ شده است و در 1.16 حذف خواهد شد. هنوز
> در 1.15 کار می کند. پیکربندی‌های جدید باید از سطح بالای `http_clients` با استفاده کنند
> در عوض `route.default_http_client`.

#### 6.6.2 قوانین

| میدان | مسابقات |
|-------|---------|
| `domain` | دامنه دقیق |
| `domain_suffix` | پسوند دامنه، از جمله زیر دامنه ها |
| `domain_keyword` | مطابقت رشته فرعی |
| `domain_regex` | بیان منظم |
| `ip_cidr` / `ip_is_private` | IP مقصد |
| `source_ip_cidr` | آی پی منبع |
| `port` / `port_range` | بندر مقصد |
| `network` | `tcp` / `udp` |
| `rule_set` | برچسب‌های مجموعه قوانین برای استفاده |
| `outbound` | برچسب خروجی برای استفاده (باید در زیر "Outbounds" یا "Endpoints" وجود داشته باشد) |
| `type: "logical"` | شرایط ترکیبی با `mode` روی `and` / `or` تنظیم شده است |

چندین فیلد در یک قانون با AND ترکیب می شوند (به عنوان مثال `network` + `port`)، بنابراین هیچ
لفاف `logical` مورد نیاز است. از `type: "logical"` فقط برای ترکیبات OR / NOT استفاده کنید. `rule_set`
باید در زیر قوانین `rules` قرار گیرد، نه در کنار `rules`:

```jsonc
"rules": [
  { "domain_suffix": ["gstatic.com", "googleapis.com"], "outbound": "direct" },
  { "domain_keyword": ["ip.sb", "yandex.com"], "outbound": "warp" },
  { "rule_set": ["geosite-openai", "geosite-google"], "outbound": "warp" },
  { "rule_set": ["geoip-cn"], "outbound": "warp" },
  { "network": "tcp", "port": 443,
    "rule_set": ["geosite-google"], "outbound": "warp" },
  { "type": "logical", "mode": "or",
    "rules": [
      { "rule_set": ["geosite-google"] },
      { "rule_set": ["geosite-openai"] }
    ],
    "outbound": "warp" }
]
```

#### 6.6.3 مهاجرت قوانین xray

| xray | sing-box |
|------|----------|
| رشته خالی (از جمله مقادیر خالی در `domain`؛ مطابقت زیر رشته) | `"domain_keyword": ["ip.sb"]` |
| `"domain": ["a.com"]` | `"domain_keyword": ["a.com"]`; از `"domain_suffix": ["a.com"]` برای مطابقت پسوند واقعی یا `"domain": ["a.com"]` برای مطابقت دقیق استفاده کنید |
| `"domain:clstorage.net"` | `"domain_suffix": ["clstorage.net"]` |
| `"full:a.com"` | `"domain": ["a.com"]` |
| `"regexp:..."` | `"domain_regex": ["..."]` |
| `"ip": ["geoip:cn"]` | `"rule_set": ["geoip-cn"]` |
| `"domain": ["geosite:cn"]` | `"rule_set": ["geosite-cn"]` |
| `"outboundTag": "direct"` | `"outbound": "direct"` |

یادداشت ها:

- **برچسب ها بین هسته ها به اشتراک گذاشته نمی شوند**: تگ خروجی xray را نمی توان در قانون sing-box استفاده کرد.
 از برچسبی استفاده کنید که واقعاً در زیر sing-box "Outbounds" یا "Endpoints" وجود دارد.
- یک تگ خروجی یا نقطه پایانی اشتباه `outbound not found` را گزارش می دهد. تگ مجموعه قوانین اشتباه گزارش می دهد
 `rule-set not found`.
- ابتدا قوانین مستقیم / لیست مجاز را قرار دهید. هنگامی که یک قانون مطابقت داشته باشد، قوانین بعدی دیگر اعمال نمی شوند.

## 7. مدیریت پروکسی

مدیریت پراکسی پروکسی معکوس Caddy یا Nginx را پیکربندی می کند.

### 7.1 انواع پروکسی

- **Caddy**: خودکار HTTPS، HTTP/1.1 و HTTP/2 (HTTP/3 / QUIC برای جلوگیری از تداخل UDP 443 غیرفعال است) با روت لایه 4
- **Nginx**: عملکرد بالا، پیکربندی انعطاف پذیر

### 7.2 پیکربندی سایت

1. "مدیریت پروکسی" را باز کنید؛
2. نوع پروکسی را انتخاب کنید (Caddy / Nginx)؛
3. اضافه کردن یک سایت:
   - دامنه
   - بالادست
   - بندر محلی
4. ذخیره کنید.

### 7.3 فیلدها

- **بالا جریان**: آدرس باطن، به عنوان مثال. `127.0.0.1:8082`
- **local_port**: پورت گوش محلی، به عنوان مثال. `8443`
- **portal_forward**: قانون ارسال پورتال
- **subscription_forward**: قانون حمل و نقل اشتراک
- **مسیریابی SNI**: وقتی ورودی از TLS / REALITY استفاده می کند و کلاینت ها همیشه روی 443 متصل می شوند، پنل استخراج می شود
 443 قانون مسیریابی TCP از ClientHello SNI (هر دو xray `streamSettings` و sing-box `tls.reality`)؛
 پروکسی جلو فقط TCP را فوروارد می کند و TLS هنوز داخل هسته خاتمه یافته است

## 8. منابع مسیریابی

منابع مسیریابی دارایی های مشترک مورد استفاده توسط اشتراک ها و مسیریابی را جمع آوری می کند. این صفحه دارای پنج تب است:

| Tab | هدف |
|-----|---------|
| دامنه های ترجیحی مستقیم و CF | دامنه‌های مستقیم / IP و دامنه‌های ترجیحی Cloudflare که هنگام بازنویسی آدرس‌های دسترسی در اشتراک‌ها و گره‌های خارجی استفاده می‌شوند |
| استخر IP CF | منابع IP ترجیحی، پورت‌ها و تنظیمات کاوشگر، مصرف‌شده توسط «دامنه دسترسی» |
| قوانین جهانی WAF | منابع قواعد و فایل‌های قانون برای پروکسی معکوس WAF، به گره‌ها منتقل می‌شوند |
| فایل های قانون | دانلود، همگام سازی برنامه ریزی شده و فشار فایل های قانون (`.srs` / `.json` / `.dat`) |
| گره های خارجی | گره های خارجی را از v2ray URI / Base64 / اشتراک URL وارد کنید (به 16.3 مراجعه کنید) |

### 8.1 دامنه های ترجیحی مستقیم و CF

- **دسترسی مستقیم**: دامنه ورودی یا IP، پورت 443 به طور پیش فرض. گره ها را متصل کنید یا برای جهانی خالی بگذارید.
- **دامنه های ترجیحی CF**: دامنه ترجیحی Cloudflare به اضافه پورت، با بررسی اتصال.
- هر دو نامزدهای "دامنه دسترسی" مورد استفاده توسط اشتراک ها و بازنویسی گره خارجی را تغذیه می کنند (به 16.3 مراجعه کنید).

### استخر IP 8.2 CF

- منابع IP ترجیحی (از جمله منابع سبک `bestproxy`)، بازه و پورت‌های واکشی را حفظ کنید.
- "تنظیمات پروب" فاصله پروب، آستانه تاخیر و گره ورودی پروب را کنترل می کند. کاوش محلی
 فقط IP های غیرقابل دسترسی را فیلتر می کند، در حالی که انتخاب یک گره ورودی، خط آن گره را شبیه سازی می کند.
- شماره‌گیر ممکن است خودکار (هسته‌های نصب‌شده)، `singbox`، `xray` یا `mihomo` باشد. هسته هایی که نیستند
 نصب شده در لیست نیست. کاوشگر به عنوان یک فرآیند موقت اجرا می شود که پس از انجام خارج می شود و هرگز یا نمی خواند
 پیکربندی خود هسته را می نویسد.
- وقتی «دامنه دسترسی» از مخزن IP CF بدون مقدار مشخص استفاده می‌کند، یک ورودی (با پورت آن)
 به صورت تصادفی انتخاب شده است

### 8.3 قوانین جهانی WAF

- منبع قانون WAF URL و فایل های قانون را برای همگام سازی پیکربندی کنید.
- پس از همگام سازی، آنها به گره ها فشار داده می شوند و توسط پروکسی گره بارگذاری می شوند (Nginx / Caddy).
- یک فایل با URL کامل از آن URL دانلود می شود. در غیر این صورت از "منبع URL + / نام فایل" استفاده می شود.
- «حافظه پنهان» (`match_cache` / `config_match_cache`) به طور پیش‌فرض فعال است: یک فرآیند محدود شده
 حافظه پنهان نتایج تطابق قانون داغ، پیمایش قانون هر درخواست را کاهش می دهد. این فقط جهانی با شماره است
 نادیده گرفتن هر دامنه؛ هنگام بررسی موارد مثبت کاذب، آن را به طور موقت برای مقایسه A/B غیرفعال کنید
 (غیرفعال کردن به معنای ارزیابی کامل قانون در هر درخواست و استفاده بالاتر از CPU است).

### 8.4 فایل های قانون (فایل های قوانین مسیریابی)

این برگه فقط فایل های قانون را در پانل دانلود می کند و آنها را به گره ها می برد. هیچ چیز تاثیر نمی گذارد
به صورت خودکار برای استفاده از آنها در مسیریابی، به آنها در قسمت "مرکز پروتکل → sing-box → مسیریابی" مراجعه کنید.
در مجموعه قوانین و قوانین (به 6.6 مراجعه کنید).

- ** مخازن قانون**: `owner/repo` (GitHub، قابل مرور) را وارد کنید یا URL را دانلود کنید. برنامه ریزی شده است
 همگام سازی می تواند هر 6/12 ساعت، روزانه در ساعت 03:00، روزانه در نیمه شب یا هر هفته یکشنبه اجرا شود.
- **افزودن فایل**: برای فایل های منفرد خارج از نسخه مخزن (به عنوان مثال شعبه SagerNet `.srs`
 فایل ها)؛ URL کامل را وارد کنید و به طور خودکار دانلود می شود.
- **فهرست فایل**: نام، اندازه، آخرین به روز رسانی و سوئیچ "همگام سازی خودکار" را با هر فایل "دانلود" نشان می دهد.
 دکمه "Push to all nodes" در بالا، هر فایل قانون را به همه گره ها فشار می دهد.
- فایل‌ها در `data/rules/` پانل دانلود می‌شوند و پس از فشار دادن، در زیر داده‌های گره زنده می‌شوند.
 دایرکتوری `rules/`; آنها را در sing-box به عنوان `rules/<file name>` معرفی کنید.
- فرمت ها:
  - `.srs`: مجموعه قوانین باینری sing-box، توصیه شده و کوچکترین.
  - `.json`: مجموعه قوانین منبع-فرمت. `rule_set` باید `format: "source"` را تنظیم کند.
  - `.dat`: xray `geosite.dat` / `geoip.dat` که sing-box نمی تواند مستقیماً از آن استفاده کند.

> بلوک تاشو «استفاده» در بالای صفحه حاوی نمونه‌های مرجع، نقشه‌برداری xray است.
> جدول و خطاهای رایج

### 8.5 گره های خارجی

وارد کردن و مدیریت گره های خارجی در [16.3 گره های خارجی](#163-external-nodes) پوشش داده شده است.

## 9. مرکز اشتراک

مرکز اشتراک گره‌ها را در اشتراک‌های آماده مشتری بسته‌بندی می‌کند: **فرمت‌های اشتراک ** (چه چیزی منتشر شود، کدام قوانین، کدام برنامه‌ها می‌توانند آن‌ها را ببینند)، سپس اشتراک **نقاط پایانی** (دامنه عمومی / مسیر) را تعریف کنید، سپس پیوندها را تحویل دهید.

### 9.1 فرمت های اشتراک

"مرکز اشتراک" → "فرمت های اشتراک"؛ یک ردیف در خروجی مشتری:

| میدان | توضیحات |
|---|---|
| نام | منحصر به فرد؛ `?config=<name>` روی آن مطابقت دارد و گفتگوی مشتری آن را نشان می دهد |
| نوع مشتری | clash / shadowrocket / singbox / v2ray — فقط گروه بندی نمایش |
| فرمت خروجی | `mihomo_yaml` (Clash/Mihomo)، `singbox_json`، `xray_json`، `base64_uri`، `raw_uri` |
| نوع محتوا / پسوند | هدر پاسخ و نام فایل |
| پلت فرم | win / mac / android / ios / یونیورسال؛ مطابق با `?platform=`، خالی = جهانی |
| طرح های مقید | خالی = در دسترس برای هر طرح. در غیر این صورت فقط آن طرح ها می توانند از آن استفاده کنند |
| قوانین | قوانین مسیریابی هر قالب (ویرایشگر ساختار یافته برای Mihomo، خام JSON در هر قانون برای sing-box / Xray). **قوانین بین فرمت ها تبدیل نمی شوند** |

یادداشت ها:

- ممکن است چندین پیکربندی برای یک فرمت خروجی وجود داشته باشد (به عنوان مثال `out`، `home`). یکی را با `config=` در پیوند انتخاب کنید.
- بدون `config`، دستور "پیکربندی محدود به اشتراک → مطابقت `platform` → پیش فرض" است.
- یک الگوی sing-box ممکن است `route.rule_set` خود را برای مشتریان حمل کند، معمولاً به عنوان `remote`، بنابراین
 مشتری آن را دانلود می کند. فایل‌های محلی که به `rules/` یک گره تحت «فایل‌های قانون» فشار داده می‌شوند، فقط در دسترس هستند
 به هسته در آن گره، نه به اشتراک مشتری.
- هنگام تولید الگوهای sing-box / Xray، پانل ارجاعات آویزان را حذف می کند (`final`، `dns.final`،
 `default_domain_resolver`، `download_detour`، `rule_set` محلی، تعاریف `rule_set` نامعتبر، خالی
 `balancer` و غیره) بنابراین مشتری هنگام راه اندازی با خطای FATAL شکست نمی خورد.
- نام مستعار خروجی در قوانین با برچسب های واقعی حل و فصل می شوند (`REJECT` / `blocked` → `block`، `DIRECT` →
 `direct`، حساس به حروف کوچک و بزرگ)؛ خروجی های غیرقابل حل به خروجی پیش فرض و قانون برمی گردند
 موقعیت خود را حفظ می کند؛
- یک گروه با `tag = proxy` همیشه ایجاد می شود: یک `selector` برای sing-box و یک تعادل `random` برای
 Xray و `outbound: proxy` در قوانین به `balancerTag` منطبق بازنویسی می شود. ویرایشگر قانون بارگیری می شود
 نامزدهای خروجی به صورت پویا از "گروه های پروکسی + خروجی های سفارشی" و برچسب های وارد شده به صورت دستی هستند
 هنوز تایید شده است.
- تنظیمات sing-box / Xray باید به طور جداگانه ایجاد شوند. اگر وجود نداشته باشند در پیوندهای مشتری ظاهر نمی شوند (به 10.3 مراجعه کنید).

### 9.2 نقاط پایانی اشتراک

"مرکز اشتراک" → "نقاط پایانی اشتراک"؛ یک ردیف در هر آدرس عمومی:

| میدان | توضیحات |
|---|---|
| دامنه | دامنه اشتراک عمومی |
| مسیر | پیشوند زیر دامنه، پیش‌فرض `/` |
| فعال شد | هنگام ایجاد پیوند، نقاط پایانی غیرفعال نادیده گرفته می شوند |
| توضیحات | یادداشت متن آزاد |

- ** چند ردیف (چند دامنه) ** پشتیبانی می شود. هنگامی که چندین مورد فعال هستند، دامنه ارائه دهنده از دامنه استفاده شده توسط درخواست فعلی پیروی می کند (به 9.4 مراجعه کنید).
- یک پورت اشتراک اختصاصی در ریشه کار می کند (`/<token>`، بدون `/sub`). هنگام اشتراک گذاری پورت پنل `/sub/<token>` است.
- پراکسی های معکوس باید `X-Forwarded-Proto` / `X-Forwarded-Host` را ارسال کنند، در غیر این صورت از اولین نقطه پایانی فعال استفاده می شود. الگوهای سایت Caddy / Nginx ایجاد شده پانل شامل هر دو سرصفحه است. تنظیمات پروکسی دستی نیاز به اضافه شدن دستی دارند.

### 9.3 پیوندهای اشتراک

فرم پایه: `https://<sub-domain>/<token>` (پورت پنل: `https://<panel-domain>/sub/<token>`)

| پارامتر | توضیحات |
|---|---|
| `format` | فرمت خروجی؛ نام مستعار: `clash` → mihomo_yaml، `singbox`/`sing-box` → singbox_json، `xray` → xray_json، `raw` → raw_uri، `base64`/`sing-box` |
| `config` | یک فرمت اشتراک را با نام اعمال کنید. باید با `format` مطابقت داشته باشد، در غیر این صورت نادیده گرفته می شود |
| `platform` | مطابقت یک پیکربندی بر اساس پلتفرم (زمانی که `config` حذف شده است) |
| `providers` | `1` / `true`: حالت ارائه دهنده Clash (`proxy-providers` + `use`); گره های درون خطی پیش فرض |

مثال ها:

```bash
# Clash dynamic subscription (config template + providers)
https://sub.example.com/<token>?format=clash&config=out&providers=1

# sing-box / Xray (only meaningful when such a config exists)
https://sub.example.com/<token>?format=singbox_json&config=sing-box-home
https://sub.example.com/<token>?format=xray_json&config=xray-home

# generic clients / plain text
https://sub.example.com/<token>?format=base64_uri
https://sub.example.com/<token>?format=raw_uri
```

### 9.4 حالت چند دامنه و ارائه دهنده

با `providers=1` هر ورودی `proxy-providers` به نقطه پایانی اشتراک باز می گردد. انتخاب دامنه:

1. **دامنه ای که این درخواست استفاده می کند** (مقدار اول `X-Forwarded-Host`، پورت حذف شده، در غیر این صورت `Host`) اگر با نقطه پایانی **فعال** مطابقت داشته باشد.
2. در غیر این صورت نقطه پایانی فعال شده با **کمترین شناسه**؛
3. مسیر از آن نقطه پایانی می آید: `https://<domain><path>/<token>?format=mihomo_proxies_yaml...`.

بنابراین تغییر دامنه نیازی به تغییر پانل ندارد: مشتریانی که از طریق دامنه جدید واکشی می‌شوند، دامنه جدید را در داخل ارائه‌دهندگان دریافت می‌کنند، و دامنه قدیمی که فعال است، دیگر کدگذاری سختی ندارد. اگر مشتری ارائه دهنده قدیمی URL را در حافظه پنهان ذخیره کرد، اشتراک را به روز کنید (یا کش ارائه دهنده را پاک کنید / کلاینت را مجدداً راه اندازی کنید).

نکات تکمیلی:

- `proxy-providers` در قالب مشترک (`config_json`) نادیده گرفته می شود (از نشت بین پلان جلوگیری می کند). ارائه دهندگان از گروه های گره طرح و منابع خارجی می آیند.
- مسیرهای کش ارائه‌دهنده داخلی و خارجی همیشه از «پیش‌فرض‌های ارائه‌دهنده داخلی → الگوی مسیر کش» (پیش‌فرض `./providers/{key}.yaml`) مشتق می‌شوند. منابع خارجی نمی توانند منابع خود را تنظیم کنند.
- ارائه‌دهنده ذخیره‌شده قدیمی `subscription-nodes` دیگر منتشر نمی‌شود: گروه‌هایی که از «همه گره‌ها» استفاده می‌کنند به ارائه‌دهندگان بتن گسترش می‌یابند، یا گره‌های درون خطی زمانی که طرح هیچ‌کدام را ندارد گسترش می‌یابد.

### 10.2 اقدامات مشتری

- **ویرایش**: تغییر جزئیات مشتری

- **رزومه**: بازیابی مشتری معلق
- **بازنشانی ترافیک**: بازنشانی ترافیک استفاده شده
- **بازنشانی رمز عبور**: رمز عبور مشتری را بازنشانی کنید
- **تجدید**: تمدید تاریخ انقضا
- ** ارتقا / تنزل **: تغییر طرح
- **حذف**: حذف مشتری

### 10.3 جزئیات اشتراک

مدیریت مشتری → ستون "اشتراک" → "جزئیات". گفتگو پیوندها را برای هر قالب موجود در طرح مشتری فهرست می کند:

- **Clash / Mihomo**: دو ردیف - گره های خطی و `providers=1` (ارائه دهندگان پروکسی) که هر دو دارای `config=<name>` هستند.
- **Sing-box / Xray**: فقط زمانی نشان داده می شود که پیکربندی با آن فرمت وجود داشته باشد و برای طرح قابل مشاهده باشد. پیوندها `config=<name>` را حمل می کنند.
- **Base64 URI / خام URI**: همیشه نشان داده شده است (بدون `config`)؛
- هر ردیف دکمه کپی مخصوص به خود را دارد. با کلیک روی یک ردیف، کد QR زیر به آن قالب تغییر می کند.

بنابراین تنها با یک پیکربندی Clash، گفتگوی Clash + Base64 + Raw را نشان می دهد. پیوندهای sing-box / Xray فقط پس از ایجاد تنظیمات ظاهر می شوند.

همین گفتگو همچنین میزان استفاده از ترافیک، تاریخچه سفارش و سابقه تراکنش را نشان می دهد.

## 12. مدیریت شارژ

مدیریت شارژ سایت های شارژ، سفارشات و کارت های شارژ را مدیریت می کند.

> **یکپارچه سازی پرداخت**
>
> پنل **مستقیماً با مؤسسات پرداخت ** (Alipay، WeChat Pay، Stripe، بانک ها و غیره) ادغام نمی شود. این فقط به یک **سکوی پرداخت میانی** متصل می شود، که به نوبه خود با مؤسسه پرداخت مربوطه ادغام می شود، قراردادها، خرید و تسویه حساب را انجام می دهد و نتایج پرداخت را از طریق پاسخ تماس [charge API](api/charge-callback.md) گزارش می دهد.
>
> پلت فرم پرداخت میانی ** بخشی از این پروژه نیست. اپراتورها باید خودشان آن را توسعه دهند (یا از سیستم خود استفاده کنند)**. پس از استقرار، آن را در «سایت‌های شارژ مجدد» ثبت کنید و تأیید دامنه را کامل کنید تا از آن به عنوان نقطه ورود شارژ استفاده کنید. سایت شارژ اینجا آن پلتفرم میانی است، نه خود موسسه پرداخت. شرایط پرداخت، کارمزدها، تسویه و انطباق بر عهده اپراتور، مؤسسه پرداخت و پلتفرم واسطه است.

### 12.1 سایت های شارژ

1. "مدیریت شارژ" → "سایت های شارژ" را باز کنید؛
2. اضافه کردن یک سایت:
   - نام سایت
   - روش‌های پرداخت پشتیبانی شده توسط آن پلتفرم میانی (Alipay، WeChat، USDT، Stripe و غیره، که از طریق ادغام آن با مؤسسات پرداخت ارائه می‌شود)
   - ارز
   - نرخ ارز
3. ذخیره؛
4. سایت را تأیید کنید (فایل HTTP یا تأیید DNS).

### 12.2 سفارشات شارژ

- مشاهده تمامی سفارشات شارژ
- فیلتر بر اساس وضعیت (در انتظار، پرداخت شده، ناموفق، منقضی شده، بازپرداخت شده)
- مشاهده جزئیات سفارش
- بازپرداخت ادمین را صادر کنید

### 12.3 کارت های شارژ

1. "کارت های شارژ" را باز کنید؛
2. اضافه کردن کارت:
   - نوع (مبلغ، طرح، افزودنی ترافیک)
   - ارزش اسمی / طرح
   - زمان انقضا
3. یا به صورت عمده تولید کنید:
   - تعداد (تا 1000)
   - پیشوند شماره کارت
   - فرمت شماره کارت
4. صادرات به عنوان CSV.

### 12.4 مدیریت تعادل

- مشاهده موجودی مشتری
- تنظیم تعادل (افزایش / کاهش / تنظیم)

## 25. پسوند عملیات

«افزونه‌های عملیات» (`/client-ext`) بازاریابی ارجاعی، کمیسیون و برداشت را پیکربندی می‌کند.
"اسناد قانونی" (`/legal-documents`) قراردادهای سمت پورتال را حفظ می کند.

### 25.1 ارجاعات و کمیسیون

- **پیکربندی تخفیف**: نرخ تخفیف (درصد از اولین پرداخت دعوت شده، `0` = غیرفعال)، حالت کمیسیون (فقط اولین خرید / همه خریدها)، حداقل مبلغ برداشت (موجودی کمیسیون باید قبل از درخواست برداشت به آن برسد)
- **کدهای دعوت**: وقتی فعال باشد، ثبت نام نیاز به کد دعوت دارد. تنظیم طول کد، روزهای انقضا و حداکثر استفاده (`0` = نامحدود)، و ایجاد/مشاهده لیست کد
- **بررسی انصراف **: فیلتر توسط در انتظار / تایید / رد شد. یک یادداشت پردازشی اضافه کنید و روش پرداخت و آدرس کیف پول را ثبت کنید
- **سوابق ارجاع**: دعوت کننده، دعوت کننده، میزان کمیسیون و وضعیت کمیسیون

### 25.2 اسناد حقوقی

- "خط مشی رازداری" و "شرایط خدمات" را به طور جداگانه حفظ کنید، یک سند Markdown در هر منطقه، با پیش نمایش زنده.
- هر سند ممکن است به جای صفحه داخلی از یک URL خارجی استفاده کند. در صورت خالی بودن صفحه داخلی URL استفاده می شود (قابل کپی در صفحه).
- پورتال نسخه محلی فعلی را نشان می دهد و در صورت عدم وجود به محلی پیش فرض برمی گردد.

## 26. سوالات متداول

### 26.1 پانل شروع نمی شود

- بررسی کنید که آیا پورت از قبل در حال استفاده است یا خیر
- بررسی کنید که `.env` معتبر است
- سیاهههای مربوط را بررسی کنید: `journalctl -u corefusion -f`; بدون systemd، `tail -f <install-dir>/data/logs/panel.log`

### 26.2 گره آفلاین

- بررسی کنید که Agent در حال اجرا باشد: `systemctl status corefusion-agent`
- اتصال شبکه را بررسی کنید
- قوانین فایروال را بررسی کنید (پورت `18443`)

### 26.3 صدور گواهینامه ناموفق است

- وضوح DNS را بررسی کنید
- بررسی کنید که پورت 80 قابل دسترسی باشد
- پیکربندی ارائه دهنده DNS را بررسی کنید
- گزارش های گواهی را بررسی کنید

### 26.4 اشتراک کار نمی کند

- لینک اشتراک را بررسی کنید
- بررسی کنید که گره آنلاین است
- بررسی کنید که فرآیند اصلی در حال اجرا باشد
- قوانین فایروال را بررسی کنید

### 26.5 شارژ مجدد با شکست مواجه می شود

- پاسخ تماس URL را بررسی کنید
- بررسی کنید که کلید سایت مطابقت داشته باشد
- فهرست مجاز IP را بررسی کنید
- ثبت سفارشات را بررسی کنید

### 26.6 صفحه پورتال غیر قابل دسترسی است

- بررسی کنید که پورت پورتال باز باشد
- پیکربندی مسیر پورتال را بررسی کنید
- **مهم**: مطمئن شوید که پراکسی معکوس دامنه پورتال را به **درگاه موتور پورتال** و نه درگاه اصلی پنل ارسال می کند — ارسال به پورت اشتباه یک صفحه خالی یا پانل را به جای پورتال نشان می دهد. `upstream` / `local_port` را در سابقه سایت پراکسی بررسی کنید.
- `http://<portal-domain>:<portal-port>` را مستقیماً باز کنید تا موتور پورتال را تأیید کنید
- پیکربندی معکوس پروکسی را بررسی کنید
- گزارش های پورتال را بررسی کنید

## ضمیمه

### A. پورت های پیش فرض

| بندر | هدف |
|------|---------|
| اختصاص داده شده توسط جادوگر راه اندازی (درگاه آزاد تصادفی به طور پیش فرض) | پنل مدیریت (قابل تغییر) |
| 18443 | عامل gRPC (قابل تغییر) |
| 0 (به طور پیش فرض غیرفعال است) | پورت موتور اشتراک اختصاصی (خالی یا `0` پورت اصلی را به اشتراک می‌گذارد) |
| 0 (به طور پیش فرض غیرفعال است) | پورت موتور پورتال اختصاصی (خالی یا `0` پورت اصلی را به اشتراک می گذارد) |
| 80/443 | پراکسی معکوس (Caddy / Nginx) HTTP / HTTPS |

### ب. مسیرهای پیش فرض

| مسیر | هدف |
|------|---------|
| `/` | پنل مدیریت (در صورتی که موتور پورتال اختصاصی پیکربندی نشده باشد، پورتال در `/` نیز فعال است) |
| `/sub/:token` | واکشی اشتراک (زمانی که هیچ پورت اشتراک اختصاصی پیکربندی نشده باشد) |
| `/p` | صفحه پورتال (زمانی که پورتال اختصاصی پیکربندی نشده باشد) |
| `/:token` | واکشی اشتراک (با درگاه اشتراک اختصاصی، بدون پیشوند `/sub`) |

### ج. ابزار خط فرمان

پانل باینری از این دستورات فرعی پشتیبانی می کند (بدون آرگومان سرور را شروع می کند):

```bash
# Start the panel (same as ./corefusion server)
./corefusion

# Run database migrations
./corefusion migrate

# Non-interactive init / reset init state (see 3.4, 3.5)
./corefusion init --help
./corefusion reset-init

# Offline administration (when you cannot sign in)
./corefusion admin reset-password -u admin -p 'new-password'
./corefusion admin 2fa reset -u admin
./corefusion admin list

# Version / help
./corefusion version
./corefusion help
```

> با systemd، از `systemctl restart corefusion` و `journalctl -u corefusion -f` استفاده کنید. بدون
> systemd (ظروف و موارد مشابه)، روند قدیمی را متوقف کنید و دوباره آن را با `nohup` شروع کنید، لاگ ها هستند
> در `data/logs/panel.log`.

## تغییرات v0.13.0-rc.1

- **به‌روزرسانی آنلاین پنل**: «تنظیمات سیستم → به‌روزرسانی پنل» — انتخاب نسخه
  (`pre` = پیش‌انتشار)، به‌روزرسانی، تاریخچه وظایف و بازگشت به باینری قبلی.
- **به‌روزرسانی آنلاین Agent**: در جزئیات نود، «به‌روزرسانی Agent» از باینری محلی پنل یا
  GitHub Releases؛ نودهایی که از نسخه‌های قدیمی ارتقا یافته‌اند در نخستین اتصال
  `update.public_key` (0600) را می‌گیرند و سپس امضای ed25519 را بررسی می‌کنند.
- **همگام‌سازی WAF**: زمان آخرین همگام‌سازی در `waf.github_source.last_sync` ذخیره می‌شود و
  راه‌اندازی مجدد تایمر را بازنشانی نمی‌کند؛ `0 3 * * *` ساعت 03:00 به وقت `panel.timezone`
  (پیش‌فرض Asia/Shanghai) اجرا می‌شود؛ پنجره‌های ازدست‌رفته حدود ۱۵ ثانیه پس از شروع جبران
  می‌شوند.
- **فهرست سفید WAF**: دامنه پنل به‌طور خودکار `whiteurl.rule` را نگه می‌دارد؛ بررسی
  URL/پارامتر/POST فقط برای API مدیریت نادیده گرفته می‌شود، بنابراین ذخیره سایت پرداخت با
  `http://127.0.0.1:18081` دیگر با قاعده SSRF مسدود نمی‌شود.
- **سیاست سهمیه**: افزایش در تمدید / پاک‌سازی در انقضا / بازنشانی در تمدید (مشخصه می‌تواند
  از طرح ارث‌بری کند)؛ در حالت «ماهانه» پنل هر ساعت بررسی و مصرف را صفر می‌کند.
- **سایت‌های پرداخت**: فعال/غیرفعال کردن کلیدها یا روش‌های پرداخت را تغییر نمی‌دهد؛ سفارش
  شارژ بر اساس نوع فیلتر و به CSV صادر می‌شود.
- **پورتال**: دکمه «شارژ» پرداخت آنلاین از سایت فعال و کارت هدیه را پشتیبانی می‌کند؛ اگر
  سایتی فعال نباشد فقط استفاده از کارت نمایش داده می‌شود.
