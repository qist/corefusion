# คู่มือ CA สาธารณะ Google (การออก EAB อัตโนมัติ)

> ภาษา: [简体中文](cert-google-eab.md) · [English](cert-google-eab.en.md) · [繁體中文](cert-google-eab.zh-TW.md) · [Русский](cert-google-eab.ru.md) · [日本語](cert-google-eab.ja.md) · [한국어](cert-google-eab.ko.md) · [Deutsch](cert-google-eab.de.md) · [Français](cert-google-eab.fr.md) · [Español](cert-google-eab.es.md) · [Português](cert-google-eab.pt.md) · [Türkçe](cert-google-eab.tr.md) · [Bahasa Indonesia](cert-google-eab.id.md) · ไทย · [Tiếng Việt](cert-google-eab.vi.md) · [العربية](cert-google-eab.ar.md) · [فارسی](cert-google-eab.fa.md)

> รหัส: `internal/service/certificate/eab_google.go`, `internal/api/handlers/certificates/eab_config.go`

## 1. เหตุใด Google จึงต้องใช้ EAB

| แคลิฟอร์เนีย | EAB จำเป็นสำหรับ ACME หรือไม่ | วิธีรับ EAB |
|---|---|---|
| มาเข้ารหัสกันเถอะ | ❌ ไม่ | — |
| ZeroSSL | ✅ใช่ | **แลกเปลี่ยนอีเมลหนึ่งฉบับ** (`api.zerossl.com/acme/eab-credentials-email` เช่นเดียวกับ acme.sh) แผงสามารถดึงข้อมูลได้โดยอัตโนมัติ |
| **Google แคลิฟอร์เนียสาธารณะ** | ✅ **ใช่** | **ต้องสร้างโดยได้รับอนุญาตจาก GCP** (อีเมลไม่เพียงพอ) → เนื้อหาหลักของหน้านี้ |

กล่าวอีกนัยหนึ่ง Google **ไม่สามารถหลีกเลี่ยง "การอนุญาต"**: ไม่ว่าจะเป็นไฟล์ JSON ของบัญชีบริการหรือโทเค็นการเข้าถึงชั่วคราว

## 2. กฎยากของ Google (อ่านก่อน)

| กฎ | คำอธิบาย |
|---|---|
| **ใช้งานได้ภายใน 7 วัน** | คีย์ EAB **หมดอายุ** หากไม่ได้ใช้ภายใน 7 วัน และต้องสร้างขึ้นใหม่ |
| **บัญชีเดียวเท่านั้น** | คีย์ EAB หนึ่งคีย์จะลงทะเบียนบัญชี ACME หนึ่งบัญชีเท่านั้น หลังจากลงทะเบียนแล้ว คีย์ **ใช้งานไม่ได้** และไม่สามารถนำมาใช้ซ้ำได้ |
| **บัญชี ACME ไม่มีวันหมดอายุ** | บัญชี ACME ที่สร้างขึ้นด้วย **มีอายุยืนยาว** → **ไม่จำเป็นต้องต่ออายุ EAB** |
| ⚠ **การลบโครงการ GCP จะเป็นการฆ่าบัญชีทั้งหมด** | การลบโปรเจ็กต์จะทำให้ **บัญชี ACME ทั้งหมด** ภายใต้โปรเจ็กต์เป็นโมฆะทันที และ **การต่ออายุจะเป็นไปไม่ได้** |

> สรุป: **EAB เป็น "ข้อมูลรับรองการเริ่มต้นใช้งาน" แบบครั้งเดียว; บัญชี ACME เป็นสิ่งที่คงอยู่**
> แผงจะจัดเก็บบัญชีไว้ที่ `data/acme/accounts/<ca>.json` — **สำรองไดเร็กทอรีนี้**

## 3. สามเส้นทาง (เริ่มต้นด้วยเส้นทาง A — ไม่มีการล่าเมนู)

> จุดเข้าใช้งาน Cloud Console มีการเปลี่ยนแปลงหลายครั้ง ดังนั้นลิงก์โดยตรงและ Cloud Shell จึงมาก่อน เส้นทางเมนูเป็นทางเลือก

### เส้นทาง A (ง่ายที่สุด แนะนำก่อน): 1 คำสั่งใน GCP Cloud Shell

Cloud Shell เป็นเทอร์มินัลเบราว์เซอร์ที่ติดตั้ง **gcloud ไว้ล่วงหน้าและลงชื่อเข้าใช้แล้ว**; ไม่มีการตั้งค่าท้องถิ่นและไม่มีเมนู

1. เปิด <https://console.cloud.google.com/cloudshell> (หรือไอคอน `>_` ที่มุมขวาบนของคอนโซล)
2. เลือกโปรเจ็กต์ (รหัสโปรเจ็กต์มองเห็นได้ในเครื่องมือเลือกโปรเจ็กต์ที่ด้านบน):
   ```bash
   gcloud config set project <your-project-id>
   ```
3. เปิดใช้งาน Public CA API (**เทียบเท่า** เพื่อเปิดใช้งานในไลบรารี API):
   ```bash
   gcloud services enable publicca.googleapis.com
   ```
4. สร้าง EAB (**นี่คือสองสตริงที่คุณต้องการ**):
   ```bash
   gcloud publicca external-account-keys create
   ```
 ในเอาต์พุต: `keyId` → แผงของ **EAB-KID**; `b64MacKey` → **EAB-HMAC-Key** ของแผงควบคุม
5. กลับไปที่แผงควบคุม: **ใบรับรอง → การกำหนดค่า EAB → เพิ่มการกำหนดค่า EAB → CA: Google Public CA** →
 ป้อนค่าทั้งสองลงใน `EAB-KID` / `EAB-HMAC-Key` → บันทึก ✓

> ⚠ ราคา: คีย์ Google EAB คือ **7 วัน ครั้งเดียว** ✗ → หลังจาก 7 วัน (หรือเมื่อสลับบัญชี) **ทำซ้ำขั้นตอนที่ 4**
> เพื่อหลีกเลี่ยงปัญหานี้ ให้ใช้เส้นทาง B (จัดเก็บบัญชีบริการหนึ่งครั้งและปล่อยให้แผงควบคุมส่งคำขออีกครั้งโดยอัตโนมัติ)

### เส้นทาง B (การตั้งค่าครั้งเดียว จากนั้นเป็นแบบอัตโนมัติ): คีย์บัญชีบริการ JSON

**① เปิดใช้งาน Public CA API** (ลิงก์โดยตรงจะง่ายที่สุด)
<https://console.cloud.google.com/apis/library/publicca.googleapis.com?project=YOUR_PROJECT_ID> → คลิก “เปิดใช้งาน”
ทางเลือก: ☰ → **API และบริการ → ห้องสมุด** → ค้นหา `Public CA` → เปิด → “เปิดใช้งาน”

**② สร้างบัญชีบริการ**
<https://console.cloud.google.com/iam-admin/serviceaccounts?project=YOUR_PROJECT_ID>
→ “**+ สร้างบัญชีบริการ**” → ชื่อใดก็ได้ (เช่น `corefusion-eab`) → “สร้างและดำเนินการต่อ” → คุณสามารถ **ข้าม** ขั้นตอนบทบาท → “เสร็จสิ้น”
ทางเลือก: ☰ → **IAM และผู้ดูแลระบบ → บัญชีบริการ**

**3 มอบบทบาทขั้นต่ำ** (ง่ายที่สุดในหน้าเดียวกัน)
คลิกบัญชีที่สร้างขึ้นใหม่ → **แท็บ “สิทธิ์”** → “ให้สิทธิ์การเข้าถึง” → หลักการใหม่: **อีเมลบัญชีบริการ**
→ ค้นหาบทบาทสำหรับ `publicca` → เลือก **“ผู้สร้างคีย์บัญชีภายนอก CA สาธารณะ”** → บันทึก
ทางเลือกสำรอง: ☰ → **IAM และผู้ดูแลระบบ → IAM** → “ให้สิทธิ์การเข้าถึง” → อีเมล + บทบาทเดียวกัน
⚠ **อย่าให้สิทธิ์เจ้าของ/ผู้แก้ไข** ✗

**④ ดาวน์โหลดคีย์ JSON**
บัญชีบริการ → เปิดบัญชี → **แท็บ “คีย์”** → “**เพิ่มคีย์**” → “**สร้างคีย์ใหม่**” → **JSON** → สร้าง
(เบราว์เซอร์ดาวน์โหลด `xxx.json` หรือแถว `⋮` → “จัดการคีย์” → โฟลว์เดียวกัน)

**⑤ กลับไปที่แผง**: ป้อน **รหัสโครงการ** และวาง **เนื้อหาทั้งหมด** ของ JSON ลงใน “ไฟล์คีย์บัญชีบริการ” → คลิก “ขอ EAB โดยอัตโนมัติ”
→ หลังจากนั้นแผงควบคุม **ขอ EAB อีกครั้งโดยอัตโนมัติ** เมื่อหมดอายุ ✓ ไม่มีการเข้าชม GCP อีกต่อไป ✓

### เส้นทาง C (การทดสอบครั้งเดียวเท่านั้น): วางโทเค็นการเข้าถึง

ในคลาวด์เชลล์:
```bash
gcloud auth print-access-token
```
วางเอาต์พุตลงใน "โทเค็นการเข้าถึงชั่วคราว" ของแผงพร้อมรหัสโปรเจ็กต์ → คลิก "ขอ EAB โดยอัตโนมัติ"
⚠ ใช้ได้ประมาณ 1 ชั่วโมง และ **ไม่ได้จัดเก็บ** ✓ → การตรวจสอบเท่านั้น ไม่มีคำขอซ้ำอัตโนมัติ ✗

### แผ่นโกงเมื่อคุณไม่พบจุดเริ่มต้น (เมนูคอนโซลเปลี่ยนไป)

| งาน | ลิงค์ตรง (น่าเชื่อถือที่สุด) | ทางเลือก: เมนู |
|---|---|---|
| เปิดใช้งาน CA สาธารณะ API | `https://console.cloud.google.com/apis/library/publicca.googleapis.com?project=<PROJECT_ID>` | ☰ → API และบริการ → ห้องสมุด → ค้นหา `Public CA` |
| บัญชีบริการ | `https://console.cloud.google.com/iam-admin/serviceaccounts?project=<PROJECT_ID>` | ☰ → IAM และผู้ดูแลระบบ → บัญชีบริการ |
| มอบบทบาท | `https://console.cloud.google.com/iam-admin/iam?project=<PROJECT_ID>` | ☰ → IAM และผู้ดูแลระบบ → IAM → ให้สิทธิ์การเข้าถึง |
| คลาวด์เชลล์ | `https://console.cloud.google.com/cloudshell` | ไอคอน `>_` ที่มุมขวาบน |

> เคล็ดลับ: แทนที่ `<PROJECT_ID>` / `YOUR_PROJECT_ID` ด้วยรหัสโปรเจ็กต์จริง (เช่น `my-project-123456`) เพื่อข้ามไปที่หน้าโดยตรง

## 4. การกำหนดค่าแผงควบคุม (สองวิธี)

ไปที่ **ใบรับรอง → การกำหนดค่า EAB → เพิ่มการกำหนดค่า EAB** และเลือก **Google Public CA**:

### ตัวเลือก A (แนะนำ): วางบัญชีบริการ JSON

| สนาม | ความคุ้มค่า |
|---|---|
| รหัสโปรเจ็กต์ GCP | รหัสโครงการจากส่วนที่ 3 เช่น `my-project-123456` |
| บัญชีบริการ JSON | วาง **เนื้อหาทั้งหมด** ของ `corefusion-eab.json` |
| โทเค็นการเข้าถึงชั่วคราว | เว้นว่างไว้ |
| ชื่อ | สร้างอัตโนมัติเป็น `Google Public CA - <project-id>`; สามารถแก้ไขได้ |

คลิก **ขอ EAB โดยอัตโนมัติ** → เมื่อสำเร็จ ระบบจะกรอกและบันทึกคีย์ KID/HMAC หลังจากนั้นเพียงเลือก `CA = Google Public CA` เมื่อออก (EAB เชื่อมโยงต่อ CA; ไม่มีการเลือกด้วยตนเอง)

> บัญชีบริการ JSON ได้รับ **เข้ารหัสในการกำหนดค่า EAB ของฐานข้อมูลแผงควบคุม** (`json:"-"` **ไม่เคยส่งคืนไปยังฟรอนต์เอนด์**)
> จุดประสงค์คือ **ขอคีย์อีกครั้งโดยอัตโนมัติหลังจากหมดอายุ 7 วัน** แทนการเข้าชม GCP ด้วยตนเอง

### ตัวเลือก B: โทเค็นการเข้าถึงชั่วคราว (ครั้งเดียว)

```bash
gcloud auth print-access-token        # valid ~1 hour
```

วางลงใน “โทเค็นการเข้าถึงชั่วคราว” กรอกรหัสโปรเจ็กต์ คลิก **ขอ EAB โดยอัตโนมัติ**
⚠ โทเค็นนี้ **ไม่ได้จัดเก็บ** และจะต้องได้รับใหม่หลังจากหมดอายุ → ใช้ได้สำหรับการทดสอบครั้งเดียว ไม่ใช่สำหรับการใช้งานในระยะยาว

### เทียบเท่าบรรทัดคำสั่ง (เป็นทางเลือก สำหรับการเปรียบเทียบ)

```bash
gcloud publicca external-account-keys create
# returns keyId / b64MacKey, corresponding to ACME's --eab-kid / --eab-hmac-key
```

## 4.5 ทำไม JSON แทนที่จะเป็น "คีย์เดียว"

นี่เป็นคำถามที่พบบ่อยที่สุด แยก "คีย์" สองประเภท:

| สิ่งที่คุณอาจคาดหวัง | สิ่งที่จำเป็นจริงๆ |
|---|---|
| **คีย์ API** (สตริง `AIza…`) | ❌ **ไร้ประโยชน์** — คีย์ API เป็นเพียงตัวระบุสาธารณะเท่านั้น และ **ไม่มีข้อมูลประจำตัว**; การสร้าง EAB จำเป็นต้องมี **สิทธิ์ IAM** ดังนั้นจึงจำเป็นต้องมีข้อมูลประจำตัวในการยืนยันตัวตน |
| — | ✅ **คีย์บัญชีบริการ**: **ไฟล์** ที่ดาวน์โหลดจาก GCP “IAM → บัญชีบริการ → คีย์ → สร้างคีย์ใหม่ → **JSON**” |

ประเด็นสำคัญ: **ไฟล์ JSON นั้นเป็น "คีย์"** — GCP รวมข้อมูลระบุตัวตนของบัญชี (`client_email`) และคีย์ส่วนตัว (`private_key`) ไว้ในไฟล์เดียว แผงจะลงนาม JWT ด้วย → แลกเปลี่ยนโทเค็นการเข้าถึง OAuth2 → เรียก Public CA API
ดังนั้น “วาง JSON” ≠ กรอกข้อมูลหลายช่อง; **วางทั้งไฟล์** (แผงยังกรอกข้อมูลในช่องที่ไม่บังคับ เช่น `type` / `token_uri`)

**EAB จริงคือสองสาย** (`EAB-KID` + `EAB-HMAC-Key`) ซึ่งเป็น **ผลลัพธ์** ของการร้องขอ แผงจะกรอกข้อมูลโดยอัตโนมัติ

### ไม่ต้องการที่จะส่งมอบไฟล์? สองทางเลือก

| วิธีการ | อย่างไร | ราคา |
|---|---|---|
| **โทเค็นการเข้าถึงชั่วคราว** | `gcloud auth print-access-token` → วางลงใน “โทเค็นการเข้าถึงชั่วคราว” | อายุการใช้งาน ~1 ชั่วโมง **ไม่ได้จัดเก็บ** → ครั้งเดียวเท่านั้น ไม่มีการร้องขอซ้ำอัตโนมัติ |
| **คู่มือ KID/HMAC** | รัน `gcloud publicca external-account-keys create` ในเครื่อง → ป้อน `keyId` / `b64MacKey` ลงใน “EAB-KID / EAB-HMAC-Key” | ไม่มีการส่งมอบหนังสือรับรอง ✓; แต่ Google EAB คือ **7 วัน ครั้งเดียว** → ทำซ้ำหลังจากหมดอายุ |

> แผงควบคุมแนะนำบัญชีบริการ JSON ด้วยเหตุผลหนึ่งข้อ: **EAB จะหมดอายุหลังจาก 7 วัน** และมีเพียงบัญชีบริการที่เก็บไว้เท่านั้นที่อนุญาต **คำขอซ้ำอัตโนมัติ** โดยไม่ต้องดำเนินการด้วยตนเอง

## 4.6 คำถามที่พบบ่อย: ฉันสามารถใช้คีย์ API ได้หรือไม่

**ไม่** นี่ไม่ใช่ตัวเลือกการใช้งาน — **Google ปฏิเสธอย่างชัดเจน** (ยืนยันทั้งสองวิธี):

```bash
# 1) Query parameter
curl -X POST "https://publicca.googleapis.com/v1/projects/<ID>/locations/global/externalAccountKeys?key=AIza..." -d '{}'
# 2) x-goog-api-key header recommended by the official docs
curl -X POST "https://publicca.googleapis.com/v1/projects/<ID>/locations/global/externalAccountKeys" \
     -H "x-goog-api-key: AIza..." -d '{}'
```

ทั้งสองกลับมา:

```json
{"error":{"code":401,"status":"UNAUTHENTICATED",
  "message":"API keys are not supported by this API. Expected OAuth2 access token
             or other authentication credentials that assert a principal."}}
```

สำหรับการเปรียบเทียบ ผู้ถือ OAuth** (ปลอม) จะส่งกลับ
`Request had invalid authentication credentials. Expected OAuth 2 access token...` —
ดังนั้น OAuth จึงได้รับการยอมรับในขณะที่ **คีย์ API ถูกปฏิเสธทันที** ✗

**เหตุผล**: การสร้าง EAB เป็น **การดำเนินการด้านการบริหาร** ที่ต้องรู้ว่า “คุณเป็นใครและคุณมี `roles/publicca.externalAccountKeyCreator` หรือไม่” ✗
— คีย์ API ระบุเฉพาะโปรเจ็กต์/แอปพลิเคชัน ✓ และ **ไม่ได้แสดงข้อมูลประจำตัวหลัก** ✓
("แนวทางปฏิบัติที่ดีที่สุดสำหรับการจัดการคีย์ API" ของ Google แนะนำ **IAM + ข้อมูลรับรองบัญชีบริการที่มีอายุการใช้งานสั้น** สำหรับสถานการณ์ด้านการดูแลระบบ ✓ — แนวทางเดียวกับที่ใช้ที่นี่ ✓)

**มีเพียงสามเส้นทางเท่านั้น** ✓ (ดู§3): บัญชีบริการ JSON ✓ / โทเค็นการเข้าถึงชั่วคราว ✓ /
หรือ **ไม่มีข้อมูลประจำตัวเลย** — เรียกใช้ `gcloud publicca external-account-keys create` ใน Cloud Shell ✓
และป้อน `keyId` / `b64MacKey` ลงในแผง ✓ (**ใช้สิ่งนี้หาก GCP IAM บล็อกคุณ** ✓)

## 5. การลงทะเบียนและต่ออายุอัตโนมัติ (สำคัญ)

```
Panel: CA = Google Public CA
  ├─ usable EAB present in the config → use it
  └─ missing/expired → request a new one on the spot with the stored service-account JSON (auto-registration)
        │
First issuance on the node/panel ── registers the ACME account with EAB (one-time!)
        │
Account persisted: data/acme/accounts/google.json (panel) / <Agent data_dir>/acme/accounts/google.json (node)
        │
Every later renewal ── uses the account key only; **EAB is never needed again**
```

ดังนั้น:

- **การออกครั้งแรกจะลงทะเบียนโดยอัตโนมัติ**; ไม่จำเป็นต้องมีขั้นตอน GCP ด้วยตนเอง
- การต่ออายุ **อย่า** ใช้ EAB (ตราบใดที่ไฟล์บัญชีมีอยู่และไดเร็กทอรีข้อมูลยังคงมีเสถียรภาพ)
- ⚠ ไดเร็กทอรีข้อมูลฝั่งเอเจนต์ ACME เป็นพาธสัมบูรณ์คงที่ (ค่าเริ่มต้น `/var/lib/corefusion-agent/acme`)
 **อย่าเปลี่ยนโดยไม่ตั้งใจ** ไม่เช่นนั้นจะถือว่าเป็นบัญชีใหม่ → ต้องใช้รหัส EAB อื่น

## 6. การแก้ไขปัญหา

| อาการ/ข้อผิดพลาด | สาเหตุ | แก้ไข |
|---|---|---|
| `PERMISSION_DENIED` (403) | บัญชีบริการขาด `roles/publicca.externalAccountKeyCreator` | กลับไปที่ส่วนที่ 3 ④ |
| `SERVICE_DISABLED` (403) | `publicca.googleapis.com` ไม่ได้เปิดใช้งานสำหรับโปรเจ็กต์ | ส่วนที่ 3 ② |
| `NOT_FOUND` (404) | รหัสโปรเจ็กต์ผิด / ลบโปรเจ็กต์แล้ว | ตรวจสอบรหัสโปรเจ็กต์ |
| รายงานการออก `externalAccountRequired` | CA นี้ไม่มี EAB | ขอ/กำหนดค่า EAB ในแผงควบคุมก่อน |
| รายงานการออก `Accounts must have at least one contact.` | ไม่มีการระบุอีเมลระหว่างการลงทะเบียน | ตั้งค่าอีเมลบัญชี ACME ในหน้าใบรับรอง (แผงควบคุมใช้บัญชีเริ่มต้น) |
| การต่ออายุขอ EAB อีกครั้ง / การลงทะเบียนล้มเหลว | ไฟล์บัญชี ACME สูญหาย (ไดเร็กทอรีข้อมูลถูกเปลี่ยน/ล้าง) | **กู้คืนข้อมูลสำรอง**; หากไม่มี ให้ขอ EAB ใหม่โดยใช้บัญชีบริการ |
| ผู้ออกเปลี่ยนจาก Google เป็น Let's Encrypt | คำสั่งการต่ออายุไม่มี CA (ข้อผิดพลาดเก่า แก้ไขใน v0.12.101) | อัปเกรดและออกใหม่ |

## 7. คำแนะนำด้านความปลอดภัยและการดำเนินงาน

1. **สิทธิ์ขั้นต่ำ**: ให้สิทธิ์บัญชีบริการเท่านั้น `roles/publicca.externalAccountKeyCreator` ไม่ใช่เจ้าของ/ผู้แก้ไข
2. **อย่าลบโปรเจ็กต์**: การลบโปรเจ็กต์ GCP จะทำให้บัญชี ACME ที่เป็นโมฆะทั้งหมด → ใบรับรองไม่สามารถต่ออายุได้
3. **สำรองข้อมูลเสมอ** `data/acme/accounts/` (ข้อมูลประจำตัวของบัญชี) และการกำหนดค่า EAB ของฐานข้อมูลพาเนล
4. **อย่าตกใจกับการหมดอายุของ EAB**: ตราบใดที่ยังมีไฟล์บัญชี ACME การต่ออายุจะไม่ได้รับผลกระทบ จำเป็นต้องใช้ EAB ใหม่เพื่อลงทะเบียนบัญชีใหม่เท่านั้น
5. หากคีย์บัญชีบริการอาจรั่วไหล ให้ลบคีย์นั้นใน GCP และวาง JSON ใหม่ลงในแผงควบคุม

## 8. จุดสิ้นสุดที่เกี่ยวข้อง (สำหรับการเขียนสคริปต์)

| จุดสิ้นสุด | คำอธิบาย |
|---|---|
| `POST /api/v1/eab-configs/fetch-google` | สร้าง EAB โดยใช้การให้สิทธิ์ GCP ร่างกาย: `{project_id, service_account_json?, access_token?}` |
