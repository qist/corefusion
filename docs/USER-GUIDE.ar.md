## 1. نظرة عامة على النظام

CoreFusion عبارة عن لوحة إدارة وكيل متعددة البروتوكولات تدعم VLESS وVMess وTrojan وShadowsocks وHysteria2 وTUIC والمزيد، مع إدارة العقد وتسليم الاشتراك وإدارة العملاء والفوترة والشهادات والوكلاء المتسلسلين.

### 1.1 الميزات الأساسية

| الوحدة النمطية | الوصف |
|--------|-------------|
| متعدد البروتوكولات | VLESS، VMess، Trojan، Shadowsocks، Hysteria2، TUIC، WireGuard، إلخ. |
| متعدد النواة | Xray-core وsing-box (Hysteria2/TUIC وبروتوكولات QUIC الأخرى تعمل على sing-box) |
| متعدد العقدة | خمسة أنواع من العقد: مستقلة، مرآة، نشطة/استعدادية، دخول متسلسل، خروج متسلسل |
| تسليم الاشتراك | تنسيقات الاشتراك المتعددة ونقاط النهاية وإدارة التنسيق |
| الفواتير | قوالب الخطط، بطاقات الشحن، الرصيد، الطلبات، عمولة الموزع |
| الشهادات | دعونا نقوم بتشفير الإصدار، والتحقق من صحة DNS-01/HTTP-01، وتوزيع الشهادات |
| وكيل بالسلاسل | موازنة التحميل متعددة المخارج، وتسجيل العقدة الخارجية، والتوجيه المتسلسل |
| حصص المرور | مراقبة حركة المرور الشهرية لكل عقدة، والتعليق التلقائي، وإعادة تعيين السجلات |
| البوابة | محرر البوابة المرئية، قوالب مخصصة متعددة اللغات |
| الإخطارات | البريد الإلكتروني وTelegram والقوالب وعمليات البث |

### 1.2 الهندسة المعمارية

- **الخلفية**: انطلق، gRPC
- **الواجهة الأمامية**: Vue 3 + Element Plus
- **قاعدة البيانات**: SQLite (افتراضي) / MySQL / PostgreSQL
- ** الوكيل **: الوكيل العكسي Caddy / Nginx
- **منفذ اللوحة**: يتم تعيينه بواسطة معالج الإعداد (منفذ مجاني عشوائي بشكل افتراضي؛ 8080 هو خيار شائع)
- **منفذ gRPC للوكيل**: 18443 بشكل افتراضي

## 2. التثبيت

### 2.1 البيئات المدعومة

| البند | الدعم |
|------|---------|
| توزيعات | ديبيان / أوبونتو، RHEL / CentOS / Rocky / AlmaLinux / Fedora، Alpine، Arch، openSUSE |
| بنيات وحدة المعالجة المركزية | الثنائيات الرسمية: `amd64`، `arm64`؛ تدعم إصدارات المصدر أيضًا `armv7`، و`armv6`، و`386`، و`ppc64le`، و`s390x`، و`riscv64`، و`loong64` |
| مدير الخدمة | systemd (مستحسن)؛ يعود إلى `nohup` في الحاويات أو البيئات الأخرى بدون systemd |
| الذاكرة / القرص | ≥ 1 جيجابايت / ≥ 10 جيجابايت (قاعدة البيانات والشهادات والسجلات والثنائيات الأساسية موجودة في دليل البيانات) |
| منفذ اللوحة | تم اختياره في معالج الإعداد (المنفذ الحر العشوائي افتراضيًا؛ `8080` وما شابه جيد) |
| وكيل جي آر بي سي | `18443` بشكل افتراضي |

يتم تثبيت أوامر وقت التشغيل الخارجية تلقائيًا بواسطة برنامج التثبيت (`scripts/install.sh` والبرنامج النصي لتثبيت Agent الذي تم إنشاؤه بواسطة اللوحة؛ انتقل إلى `--no-deps` / `CF_SKIP_DEPS=1`):

| الغرض | الحزمة |
|---------|---------|
| جدار الحماية / حد المعدل / وضع علامات التزامن | `nftables` (`nft`) |
| تشكيل حركة المرور والروابط والمآخذ | `iproute2` (`tc` / `ip` / `ss`) |
| الإجراء الاحتياطي عندما لا يكون nft متاحًا | `iptables` (`iptables-nft` على EL8+، `iptables` على EL7) |
| تتبع الاتصال | `conntrack-tools` (`conntrack`) |
| تحميل `nf_conntrack` / `ifb` | `kmod` (`modprobe` / `lsmod`) |
| الكشف عن العملية والتنظيف | `procps` (`pgrep` / `pkill`) |
| فحص المنفذ / معلمات DH | `lsof` / `openssl` |
| إنشاء مستخدم الوكيل | `shadow-utils` (ديبيان `passwd`، جبال الألب/قوس `shadow`) |
| التنزيلات والمحفوظات | `curl` / `ca-certificates` / `tar` / `gzip` / `xz` |

> يؤثر فقدان `nft` / `tc` فقط على تحديد المعدل وميزات جدار الحماية؛ لا تزال اللوحة تبدأ.
> قم بتشغيل `--cpu-info` أولاً لمعرفة كيفية اكتشاف البيئة والحزم المفقودة.

### 2.2 التثبيت في سطر واحد (مستحسن)

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh -o install.sh
sudo bash install.sh
```

أو قم بتوجيهه مباشرةً (بدون تفاعل، ولا توجد علامات إضافية):

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash
```

البرنامج النصي سوف:

1. اكتشاف التوزيع وبنية وحدة المعالجة المركزية وlibc، ثم تثبيت الحزم الأساسية وتبعيات وقت التشغيل؛
2. قم بتنزيل `corefusion-linux-<arch>` من إصدارات GitHub وتحقق منه باستخدام `.sha256` المطابق؛
3. التثبيت على `/opt/corefusion` وإنشاء `data/{sqlite,certs,logs,runtime}`؛
4. اكتب فقط عنصرًا نائبًا `.env` مع `SAFE_PATHS=data` - لا يوجد تكوين لقاعدة البيانات - بحيث تدخل البداية الأولى إلى معالج الإعداد (يتم إنشاء `.env` الكامل بواسطة المعالج)؛
5. تثبيت خدمة systemd وبدء تشغيلها (أو تشغيلها تحت `nohup` عندما لا يكون systemd متاحًا)؛
6. انتظر حتى تصبح جاهزًا، ثم اطبع مسار الإعداد URL والرمز المميز والدليل.

مثال الإخراج:

```text
==================================================================
 CoreFusion installation complete
------------------------------------------------------------------
 Install dir : /opt/corefusion
 Data dir    : /opt/corefusion/data
 Binary      : /opt/corefusion/corefusion
 Logs        : journalctl -u corefusion -f
------------------------------------------------------------------
 Setup wizard : http://<server-ip>:<random-port>/init?init_token=<token>
 Setup token  : <token>
 Valid for    : 2 hours (see startup log)
 Note         : the token is shown once; after setup this port closes and the panel switches to its normal port.
==================================================================
```

إذا كانت اللوحة تستمع فقط إلى `127.0.0.1` (على سبيل المثال خلف وكيل عكسي)، فسيقوم البرنامج النصي بطباعة أمر نفق SSH بدلاً من URL الذي لا يمكن الوصول إليه.

> فقدت الرمز؟ اقرأ سجل بدء التشغيل مرة أخرى: `journalctl -u corefusion -n 50 --no-pager`
> (بدون systemd: `tail -n 50 /opt/corefusion/data/logs/panel.log`).

### 2.3 تثبيت الإصدار / المرايا / التثبيت دون اتصال

```bash
# Pin a version
sudo bash install.sh --version v0.13.0-alpha.2

# GitHub download mirror (used as a URL prefix)
sudo bash install.sh --mirror https://ghproxy.net --version latest

# Use a local binary (offline / intranet / pre-built)
sudo bash install.sh --local ./dist/corefusion-linux-arm64

# Explicit target architecture
sudo bash install.sh --arch arm64 --local ./corefusion-linux-arm64
```

> بدون `--version`، يستخدم البرنامج النصي أحدث إدخال في قائمة إصدارات GitHub.
> معظم الإصدارات هي إصدارات مسبقة، لذلك لا يتم استخدام نقطة النهاية `/releases/latest`.
>
> الإصدارات الرسمية توفر فقط `amd64` / `arm64`؛ استخدم `--source` أو ثنائي مترجم مع `--local` للبنيات الأخرى.

### 2.4 البناء من المصدر

```bash
sudo bash install.sh --source --version v0.13.0-alpha.2
```

يقوم `--source` باستنساخ المستودع (أو يستخدم عملية السحب الموجودة عندما يكون البرنامج النصي بداخله) ويقوم بتشغيل `make panel`. يتم اختيار إصدارات Toolchain لكل بيئة:

| التبعية | التحديد |
|------------|-----------|
| اذهب | القراءة من `toolchain` / `go` في `go.mod` (حاليًا **Go 1.27+**)؛ إذا كان إصدار النظام قديمًا جدًا، فسيتم تنزيل سلسلة الأدوات المطابقة إلى `<install-dir>/.toolchain` |
| عقدة | **العقدة 22 LTS** افتراضيًا (يتطلب Vite ≥ 18)؛ يتم تنزيل الإصدار الرسمي المطابق عند الحاجة |
| العقدة (glibc <2.28) | يستخدم الإصدار `unofficial-builds` glibc-217 (على سبيل المثال CentOS 7) |
| العقدة (جبال الألب / musl) | يستخدم التوزيع `nodejs` / `npm` |

التجاوزات:

```bash
# Force Go / Node versions
sudo CF_GO_VERSION=1.27.5 CF_NODE_MAJOR=22 bash install.sh --source

# Go toolchain mirror (default https://go.dev/dl)
sudo CF_GO_MIRROR=https://golang.google.cn/dl bash install.sh --source
```

البناء اليدوي (التطوير / التصحيح):

```bash
git clone https://github.com/qist/corefusion.git
cd corefusion

# Frontend + panel for the current architecture; the frontend is embedded via go:embed
make panel

# Cross-compile
make panel-linux-amd64
make panel-linux-arm64
```

> `go build ./...` لا ينتج ثنائي. قم ببناء اللوحة باستخدام
> `go build -o corefusion ./cmd/corefusion/` أو `make panel`.

### 2.5 أعلام المثبت

| العلم | الوصف |
|------|-------------|
| `-d, --dir <PATH>` | دليل التثبيت، الافتراضي `/opt/corefusion` |
| `-v, --version <TAG>` | نسخة اللوحة، على سبيل المثال. `v0.13.0-alpha.2`; الافتراضي `latest` |
| `--binary` | استخدم الإصدار الثنائي GitHub (افتراضي) |
| `--source` | البناء من المصدر وإعداد مطابقة Go / Node |
| `--local <FILE>` | استخدام ثنائي محلي (تثبيت دون اتصال) |
| `--arch <ARCH>` | البنية المستهدفة: `amd64` / `arm64` / `armv7` / `armv6` / `386` / `ppc64le` / `s390x` / `riscv64` / `loong64` |
| `--mirror <URL>` | بادئة التنزيل GitHub، على سبيل المثال. `https://ghproxy.net` |
| `--repo <URL>` | مستودع المصدر، الافتراضي `https://github.com/qist/corefusion.git` |
| `--ref <REF>` | فرع / علامة المصدر؛ الإعدادات الافتراضية هي `--version`، وإلا `main` |
| `--no-deps` | تخطي تثبيت تبعية النظام |
| `--no-start` | تثبيت وكتابة ملف الخدمة دون البدء |
| `--cpu-info` | قم بطباعة الكشف عن البيئة والتبعيات المفقودة، ثم قم بالخروج |
| `--uninstall` | إيقاف الخدمة وإزالة البرنامج (يحتفظ بالبيانات و`.env`) |
| `--purge` | باستخدام `--uninstall`، قم أيضًا بإزالة دليل البيانات و`.env` |

متغيرات البيئة ذات الصلة:

| متغير | الغرض |
|----------|---------|
| `CF_GO_VERSION` | تجاوز إصدار Go المطلوب للبنيات المصدر |
| `CF_NODE_MAJOR` | تجاوز إصدار Node الرئيسي (الافتراضي 22) |
| `CF_GO_MIRROR` | اذهب إلى مرآة تنزيل سلسلة الأدوات |
| `CF_SKIP_DEPS` | اضبط على `1` في البرنامج النصي لتثبيت Agent لتخطي تثبيت التبعية |

### 2.6 تخطيط الدليل

```text
/opt/corefusion/
├── corefusion                 # panel binary
├── corefusion.bak             # previous version (when upgrading)
├── .env                       # environment file (0600, generated by the setup wizard)
├── .toolchain/                # Go / Node downloaded for source builds
└── data/                      # data directory (SAFE_PATHS)
    ├── sqlite/app.db          # default SQLite database
    ├── certs/                 # certificates and keys
    ├── logs/                  # runtime logs (without systemd)
    ├── runtime/               # core runtime config and state
    ├── binaries/              # downloaded xray / sing-box cores
    └── proxy/                 # proxy (Caddy/Nginx) sites and config
```

> يقوم برنامج التثبيت بإنشاء `sqlite/` و`certs/` و`logs/` و`runtime/` فقط؛ يتم إنشاء `binaries/`، `proxy/`، `rules/` وغيرها بواسطة اللوحة أو عند تثبيت النوى.
> يأتي دليل البيانات من `SAFE_PATHS` في `.env` وقد يكون مسارًا مطلقًا. لا يؤدي تغيير دليل التثبيت إلى نقل البيانات الموجودة.

### 2.7 إدارة الخدمة

systemd (معظم التوزيعات):

```bash
systemctl status corefusion --no-pager
systemctl restart corefusion
systemctl stop corefusion
journalctl -u corefusion -f          # follow logs
journalctl -u corefusion -n 100      # last 100 lines
```

بدون systemd (الحاويات، وما إلى ذلك):

```bash
cd /opt/corefusion && ./corefusion            # foreground (debugging)
cd /opt/corefusion && setsid nohup ./corefusion >> data/logs/panel.log 2>&1 &
tail -f data/logs/panel.log
```

> بدون systemd، لا تبدأ العملية عند التمهيد؛ أعد تشغيله يدويًا بعد إعادة التشغيل (أو أعد تشغيل برنامج التثبيت).

### 2.8 الترقية وإلغاء التثبيت

الترقية (تحتفظ بالبيانات والتكوين):

```bash
sudo bash install.sh --version <new-version>
```

يقوم البرنامج النصي بإيقاف الخدمة، وعمل نسخة احتياطية للملف الثنائي القديم باسم `corefusion.bak`، واستبداله وإعادة التشغيل. تم ترك `.env` و `data/` الحاليين دون تغيير.

إلغاء التثبيت:

```bash
# Remove the program only; keep data and .env
sudo bash install.sh --uninstall

# Also remove the data directory and .env (irreversible)
sudo bash install.sh --uninstall --purge
```

### 2.9 ملف البيئة (.env)

يتم إنشاء `.env` الكامل ** بواسطة معالج الإعداد ** عند حفظ التكوين (قاعدة البيانات DSN، دليل البيانات، الأسرار، المنافذ، المجالات).

في عملية تثبيت جديدة، يكتب المثبت هذا العنصر النائب فقط، وبالتالي لا تخطئ اللوحة في أن `data/` الموجود هو تثبيت مبدئي وتتخطى المعالج:

```env
SAFE_PATHS=data
```

> عندما يكون التكوين الكامل (`.env` مع `CF_DB_DSN`) موجودًا بالفعل، فلن يقوم المثبت بالكتابة فوقه مطلقًا ولن يظهر المعالج مرة أخرى.
> تدخل التعديلات اليدوية اللاحقة على `.env` حيز التنفيذ بعد إعادة التشغيل.

#### دليل البيانات

```env
SAFE_PATHS=data                       # relative to the install directory
# SAFE_PATHS=/srv/corefusion-data     # or an absolute path
```

#### قاعدة البيانات

تم اكتشاف `CF_DB_DSN` بواسطة البادئة:

| بادئة | قاعدة البيانات |
|--------|----------|
| غير محدد أو طريق عارية | SQLite (افتراضي) |
| `sqlite://` | SQLite (صريح) |
| `mysql://` | MySQL |
| `postgres://` / `postgresql://` | PostgreSQL |

`CF_DB_TYPE` اختياري ويتجاوز الكشف (`sqlite` / `mysql` / `postgres`).

> **كلمات المرور المشفرة**: MySQL/PostgreSQL DSNs المكتوبة بواسطة اللوحة (معالج الإعداد / مفتاح قاعدة البيانات)
> يتم تخزينها في `.env` كـ `enc:...` (AES-256-GCM، المفتاح `CF_SECRET_ENCRYPTION_KEY`).
> يتم فك تشفيرها عند القراءة؛ لا تزال أرقام DSN ذات النص العادي المكتوبة يدويًا تعمل.

**SQLite (افتراضي)**

```env
# Bare path (detected as SQLite)
CF_DB_DSN=data/sqlite/app.db

# Or explicit sqlite:// prefix
CF_DB_DSN=sqlite:///opt/corefusion/data/sqlite/app.db
```

**MySQL**

```env
# Format: mysql://user:password@tcp(host:port)/dbname?params
CF_DB_DSN=mysql://corefusion:password@tcp(127.0.0.1:3306)/corefusion?charset=utf8mb4&parseTime=True&loc=Local
```

**PostgreSQL**

```env
# Format: postgres://user:password@host:port/dbname?params
CF_DB_DSN=postgres://corefusion:password@127.0.0.1:5432/corefusion?sslmode=disable
```

#### تجمع الاتصال (اختياري، MySQL/PostgreSQL)

```env
CF_DB_MAX_OPEN_CONNS=100
CF_DB_MAX_IDLE_CONNS=10
```

#### المتغيرات المشتركة الأخرى

| متغير | الوصف |
|----------|-------------|
| `JWT_SECRET` | مفتاح التوقيع لرموز تسجيل الدخول؛ تم إنشاؤها عند البداية الأولى عند فقدانها |
| `CF_SECRET_ENCRYPTION_KEY` | مفتاح تشفير الإعدادات الحساسة (AES-256-GCM)؛ تم إنشاؤها عند فقدانها |
| `CF_INITIAL_ADMIN_PASSWORD` | كلمة مرور المسؤول الأولية (اختيارية؛ عشوائية ويتم طباعتها مرة واحدة بشكل افتراضي) |
| `CF_NETWORK_TRAFFIC_ACCOUNTING` | اضبط على `0` لتعطيل محاسبة حركة المرور المستندة إلى iptables (ممكّن افتراضيًا) |
| `CF_NETWORK_TRAFFIC_TABLE` | جدول iptables المستخدم لحساب حركة المرور، الافتراضي `corefusion` |

> لم يعد يتم تكوين الوكلاء العكسيين الموثوق بهم لحل عناوين IP للعميل الحقيقي عبر متغيرات البيئة؛
> يتم تخزينها كـ `panel.trusted_proxies` في **الإعدادات → الشبكة**.

> `.env` يحتوي على أسرار؛ تقوم اللوحة بتشديد أذوناتها على `0600` عند البداية. لا ترتكبها أبدًا.

### 2.10 Docker (اختياري، قم ببناء صورتك الخاصة)

المستودع **لا** يشحن ملف Dockerfile. إذا قمت بوضعه في حاوية، فاكتب صورتك الخاصة. استدعاء المرجع:

```bash
docker run -d \
  --name corefusion \
  -p 8080:8080 \
  -p 18443:18443 \
  -v /opt/corefusion/data:/app/data \
  -v /opt/corefusion/.env:/app/.env \
  <your-image>
```

> لا تحتوي الحاويات عادةً على امتيازات systemd ولا امتيازات `nft`، لذا لن تعمل ميزات تحديد المعدل/جدار الحماية.
> يجب أن يتطابق دليل العمل مع قاعدة `SAFE_PATHS` النسبية.

## 3. التكوين الأولي

في البداية، إذا لم يكن لدى `.env` `CF_DB_DSN` صالح، فإن اللوحة **لا** ** تخدم واجهة المستخدم الإدارية حتى الآن. يبدأ
**معالج الإعداد** على منفذ عشوائي في 18000-18999 باستخدام رمز مميز لمرة واحدة، ثم تتم إعادة التشغيل كما تم حفظ اللوحة العادية بمجرد حفظها.

### 3.1 افتح معالج الإعداد

1. انسخ "معالج الإعداد" URL من مخرجات برنامج التثبيت؛ أو
2. قراءة السجل على الخادم:

```bash
journalctl -u corefusion -n 50 --no-pager | grep -A2 'setup wizard'
```

```text
CoreFusion first start - setup wizard
  URL   : http://<ip>:<port>/init?init_token=<token>
  Token : <token>
  Valid : 2h0m0s
```

3. افتح URL في المتصفح (يحتوي بالفعل على `init_token`، لذا لا حاجة إلى إدخال يدوي).

> تنتهي صلاحية جلسة المعالج بعد **ساعتين** بشكل افتراضي. إذا انتهت صلاحيتها أو تمت إعادة تشغيل اللوحة، فاحصل على واحدة جديدة.
> لا تشارك الرمز المميز. بمجرد اكتمال الإعداد، يتم إغلاق هذا المنفذ ويبقى منفذ اللوحة العادي فقط.

### 3.2 خطوات المعالج

المعالج لديه 8 خطوات. يمكنك العودة في أي وقت. لا يتم الالتزام بأي شيء حتى الحفظ النهائي.

| خطوة | المحتوى |
|------|---------|
| 1. قاعدة البيانات | SQLite / MySQL / PostgreSQL |
| 2. دليل البيانات | مكتوب على `SAFE_PATHS` في `.env` |
| 3. مفاتيح التشفير | `JWT_SECRET` و`CF_SECRET_ENCRYPTION_KEY` |
| 4. النوى | أي النوى الوكيل لتثبيت |
| 5. الوكيل | لا شيء/Nginx/العلبة |
| 6. المواقع والمجالات | المنافذ، مسار الويب، حساب المسؤول، العملة، المنطقة الزمنية، المجالات |
| 7. شهادة HTTPS | معطل/تحميل/ACME |
| 8. ملخص | قم بمراجعة وتنزيل `.env` وحفظه وإعادة تشغيله |

#### الخطوة 1: قاعدة البيانات

- **SQLite (ملف محلي، مستحسن)**: اترك المسار فارغًا لاستخدام `<data-dir>/sqlite/app.db`.
- **MySQL / PostgreSQL**: المضيف، المنفذ، المستخدم، كلمة المرور، اسم قاعدة البيانات؛ PostgreSQL يدعم أيضًا `disable` / `require` / `verify-full`.
- انقر فوق "اختبار الاتصال" للتحقق من الصحة. الحفظ يختبره أيضًا. يتم إنشاء قاعدة البيانات المفقودة تلقائيًا (قم بإنشائها يدويًا إذا كان الحساب يفتقر إلى `CREATE`).
- يتم تشفير DSN (بما في ذلك كلمة المرور) قبل كتابته إلى `.env`.

#### الخطوة 2: دليل البيانات

يخزن قاعدة البيانات والشهادات والسجلات والثنائيات الأساسية والمزيد؛ هذا هو `SAFE_PATHS` في `.env`. الإعدادات الافتراضية هي `data`
(نسبة إلى دليل التثبيت)؛ يُسمح بالمسار المطلق. **لا تغيرها بشكل عرضي لاحقًا** أو اللوحة
لن تجد قاعدة البيانات والشهادات الموجودة.

#### الخطوة 3: مفاتيح التشفير

- `JWT_SECRET`: علامات تسجيل الدخول المميزة.
- `CF_SECRET_ENCRYPTION_KEY`: يقوم بتشفير الإعدادات الحساسة (كلمة مرور قاعدة البيانات، وبيانات اعتماد DNS، وبطاقات إعادة الشحن، وما إلى ذلك).
- يتم إنشاء كلاهما بشكل عشوائي بشكل افتراضي؛ استخدم "تجديد" للحصول على قيم جديدة. **تغيير `CF_SECRET_ENCRYPTION_KEY` يجعل البيانات المشفرة مسبقًا غير قابلة للقراءة** — قم بعمل نسخة احتياطية منها.

#### الخطوة 4: النوى

حدد مراكز الوكيل لتثبيتها:

- **Xray**: VLESS / VMess / Trojan / Shadowsocks، وما إلى ذلك؛
- **sing-box**: يحمل Hysteria2 / TUIC وبروتوكولات QUIC الأخرى.

بعد الحفظ وإعادة التشغيل، يتم تنزيل اللوحة وتثبيتها تلقائيًا. تحقق من الإصدارات والحالة ضمن "البروتوكولات". ويمكنك أيضًا تثبيتها لاحقًا.

#### الخطوة 5: الوكيل

- **لا شيء**: تخدم اللوحة العملاء مباشرة (تعامل مع TLS بنفسك).
- **Nginx / Caddy**: تدير اللوحة الوكيل العكسي واستضافة الشهادات؛ اختر واحدة.

مع تحديد الوكيل، تستمع اللوحة عادةً إلى `127.0.0.1` فقط ويخدم الوكيل العالم الخارجي.

#### الخطوة 6: المواقع والمجالات

| الميدان | الوصف |
|-------|-------------|
| عنوان الاستماع | مشتق تلقائيًا: الوكيل → `127.0.0.1`؛ لا يوجد وكيل بشهادة → `0.0.0.0`؛ خلاف ذلك → `127.0.0.1` |
| منفذ اللوحة | منفذ حر عشوائي بشكل افتراضي؛ قم بتغييره إذا أردت (على سبيل المثال 8080) |
| منفذ الاشتراك | اختياري؛ يشارك `0` منفذ اللوحة |
| ميناء البوابة | خياري؛ يشارك `0` منفذ اللوحة |
| مسار الويب | مسار واجهة المستخدم الإدارية، الافتراضي `/`؛ API هو دائمًا `/api/v1` |
| اسم المستخدم / كلمة المرور للمسؤول | عشوائي بشكل افتراضي؛ **كلمة المرور تظهر مرة واحدة فقط في الملخص** — احفظها |
| وضع الوصول | "المجال" أو "IP" |
| العملة الافتراضية / المنطقة الزمنية | العملة الافتراضية لبطاقات الشحن والأرصدة. المنطقة الزمنية لسجل اللوحة والوكيل (على سبيل المثال `Asia/Shanghai`) |
| إضافة إلى الوكيل العكسي | عند تعيين الوكيل والمجالات، قم بإضافة نطاقات اللوحة / الاشتراك / البوابة الإلكترونية إلى الوكيل دفعة واحدة |

يؤدي إدخال المجالات إلى كتابة الإعدادات المقابلة (مجال رد الاتصال، ونقطة نهاية الاشتراك، ومجال المشاركة).

#### الخطوة 7: شهادة HTTPS

| المصدر | الوصف |
|--------|-------------|
| تعطيل HTTPS | يتم تقديم اللوحة/البوابة/الاشتراكات عبر HTTP (غير آمن)؛ باستخدام وكيل عكسي يمكنك إضافة TLS على جانب الوكيل لاحقًا |
| تحميل الشهادة | لصق شهادة PEM والمفتاح الخاص PEM (وضع الوصول إلى المجال فقط) |
| ACME | يصدر الشهادة عند تقديم هذه الخطوة؛ يدعم المجال وشهادات IP |

خيارات ACME:

- **CA**: Let's Encrypt، Let's Encrypt (Staging)، ZeroSSL، Google Public CA؛
- **الهدف**: المجال الذي تم تكوينه، أو عنوان IP العام (شهادات IP مدعومة بواسطة Let's Encrypt فقط)؛
- **التحدي**: `HTTP-01` (يتطلب المنفذ 80) أو `DNS-01` (أحرف البدل، لا يوجد منفذ 80؛ اختر موفر DNS وأدخل بيانات الاعتماد)؛
- **نوع/حجم المفتاح**: ECC 256/384 أو RSA 2048/3072/4096؛
- **Google CA العام**: يتطلب EAB؛ أدخل معرف المفتاح / HMAC يدويًا أو استخدم حساب خدمة GCP.

> تكتشف شهادات IP تلقائيًا IPv4/IPv6 العام للمضيف. خلف الوكيل، العنوان المكتشف هو عنوان المضيف، وليس مخرج الوكيل.
> يمكن أيضًا إصدار شهادات المجال لاحقًا ضمن "الشهادات".

#### الخطوة 8: ملخص

يعرض قاعدة البيانات ودليل البيانات والنوى والوكيل والمنافذ وحساب المسؤول والمجالات ومفاتيح `.env` (أسرار مقنعة)، ويوفر:

- **تنزيل .env**: احتفظ بنسخة من التكوين؛
- **عناوين URL للوصول**: عناوين URL النهائية للوحة/الاشتراك/البوابة؛ تم وضع علامة على HTTP على أنها غير آمنة.

انقر فوق "حفظ وإعادة التشغيل" لكتابة قاعدة البيانات و`.env`؛ تتم إعادة تشغيل اللوحة إلى الخدمة العادية.

### 3.3 بعد الإعداد

- تتم إعادة تشغيل الخدمة ويطبع سجل بدء التشغيل عنوان الاستماع النهائي؛
- قم بتسجيل الدخول باستخدام حساب المسؤول، وقم بالوصول إلى URL ومسار الويب من الملخص؛
- في حالة فقدان كلمة المرور، قم بإعادة تعيينها دون الاتصال بالإنترنت باستخدام `./corefusion admin reset-password`.

### 3.4 إعداد CLI غير التفاعلي

بالنسبة للتشغيل الآلي أو الخوادم بدون رأس، اكتب التكوين وقم بوضع علامة على اكتمال الإعداد مباشرةً:

```bash
cd /opt/corefusion
./corefusion init \
  --db-type sqlite \
  --data-dir /opt/corefusion/data \
  --admin-username admin \
  --admin-password 'change-me-strong-password' \
  --listen-port 8080 \
  --proxy-type caddy \
  --cores xray,singbox \
  --panel-domain panel.example.com \
  --tls-mode acme --tls-domain panel.example.com --tls-email you@example.com
```

الأعلام المشتركة:

| العلم | الوصف |
|------|-------------|
| `--db-type` / `--db-host` / `--db-port` / `--db-user` / `--db-password` / `--db-name` | إعدادات قاعدة البيانات |
| `--data-dir` | دليل البيانات؛ الإعدادات الافتراضية هي `SAFE_PATHS` أو `./data` |
| `--listen-port` / `--subscription-port` / `--portal-port` / `--web-path` | المنافذ ومسار الويب (منفذ مجاني عشوائي بشكل افتراضي) |
| `--admin-username` / `--admin-password` | حساب المسؤول (كلمة المرور العشوائية مطبوعة مرة واحدة عند حذفها) |
| `--proxy-type` | `none` / `nginx` / `caddy` |
| `--cores` | النوى المراد تثبيتها، مفصولة بفواصل: `xray,singbox` |
| `--panel-domain` / `--subscription-domain` / `--portal-domain` | المجالات (مكتوبة في الإعدادات وإضافتها إلى الوكيل العكسي) |
| `--tls-mode` | `none` / `self_signed` / `acme` |
| `--tls-domain` / `--tls-email` / `--tls-challenge` / `--tls-key-type` / `--tls-key-bits` | خيارات الشهادة (الإعدادات الافتراضية `--tls-challenge` هي `http-01`؛ `dns-01` تحتاج إلى `--tls-dns-channel` أو `--tls-dns-provider`) |
| `--tls-ip-cert` | إصدار شهادة لعنوان IP العام المكتشف (Let's Encrypt فقط) |
| `--acme-provider` | `lets_encrypt` / `lets_encrypt_staging` / `zerossl` / `google` |
| `--currency` / `--timezone` | العملة الافتراضية / المنطقة الزمنية |

القائمة الكاملة: `./corefusion init --help`. ثم ابدأ الخدمة:

```bash
systemctl restart corefusion
```

### 3.5 إعادة تشغيل معالج الإعداد

للبدء من جديد (إزالة `.env` وعلامات الإعداد، **الاحتفاظ بالبيانات**):

```bash
cd /opt/corefusion
./corefusion reset-init      # type RESET to confirm
systemctl restart corefusion
```

ثم استخدم URL الجديد والرمز المميز من سجل بدء التشغيل.

> تؤدي إعادة التهيئة إلى إعادة تعيين حساب المسؤول ومسار الويب. تبقى بيانات العمل في قاعدة البيانات القديمة، ولكن قد تحتاج إلى إعادة إنشاء حساب تسجيل الدخول.
>
> يقوم `reset-init` بحذف `.env` بالكامل (بما في ذلك `SAFE_PATHS`). **إذا كان دليل البيانات الخاص بك عبارة عن مسار مطلق مخصص**، فاستعد `SAFE_PATHS` قبل إعادة التشغيل، وإلا فستظهر اللوحة في `./data`:
>
> ```باش
> printf 'SAFE_PATHS=/srv/corefusion-data\n' > /opt/corefusion/.env
> ```

### 3.6 الأمان بعد تسجيل الدخول لأول مرة

#### تغيير كلمة المرور الأولية

1. انقر فوق اسم المستخدم في الزاوية العلوية اليمنى؛
2. اختر "تغيير كلمة المرور"؛
3. أدخل كلمات المرور القديمة والجديدة.
4. انقر فوق "حفظ".

#### تمكين تسجيل الدخول بالرمز الديناميكي (2FA / TOTP)

> بمجرد التمكين، يتحول الحساب إلى **تسجيل الدخول بالرمز الديناميكي**: لم تعد كلمة المرور الثابتة مقبولة؛ فقط
> يعمل الرمز المكون من 6 أرقام من تطبيق المصادقة (أو رمز الاسترداد لمرة واحدة). هذا **يستبدل** كلمة مرور تسجيل الدخول — إنه كذلك
> وليس التحقق بخطوتين "كلمة المرور + الرمز".

1. انقر فوق اسم المستخدم في الزاوية العلوية اليمنى؛
2. اختر "تمكين المصادقة الثنائية"؛
3. أدخل كلمة المرور الحالية (فقط لتأكيد هذا التغيير)؛
4. امسح رمز QR ضوئيًا باستخدام تطبيق المصادقة (Google Authenticator / 1Password، وما إلى ذلك)، أو أدخل المفتاح يدويًا؛
5. أدخل الرمز المكون من 6 أرقام لإنهاء التمكين؛
6. **احفظ رموز الاسترداد فورًا** (قابلة للتنزيل)؛ كل رمز يعمل مرة واحدة.

تسجيل الدخول بعد ذلك:

- بعد إدخال اسم المستخدم، يصبح حقل كلمة المرور "رمز مكون من 6 أرقام / رمز الاسترداد" ويصبح الزر "تسجيل الدخول باستخدام الرمز"؛
- أدخل الرمز الحالي. **لم يعد من الممكن استخدام كلمة المرور الثابتة**;
- رموز الاسترداد مخصصة للاستخدام مرة واحدة؛ قم بإعادة إنشائها ضمن "تسجيل الدخول بالرمز الديناميكي (2FA)" عند نفادها (وهذا يبطل جميع الرموز القديمة).

إذا فقدت أداة المصادقة واستنفدت رموز الاسترداد، فقم بتعطيل المصادقة الثنائية في وضع عدم الاتصال على الخادم:

```bash
cd /opt/corefusion
./corefusion admin 2fa reset -u admin    # disables 2FA, clears the secret and recovery codes, revokes all sessions
```

> لا يمكن للمشرف المتميز الوحيد الذي ليس لديه المصادق ولا رموز الاسترداد الاسترداد من خلال واجهة مستخدم الويب ويجب عليه استخدام الأمر أعلاه.

#### تسجيل Passkey (اختياري)

1. انقر فوق اسم المستخدم في الزاوية العلوية اليمنى؛
2. اختر "إدارة Passkey"؛
3. انقر فوق "تسجيل Passkey الجديد"؛
4. أكمل موجه الجهاز.

> **ملاحظة**: تتطلب مفاتيح المرور HTTPS أو مضيفًا محليًا، ويجب أن يكون النطاق مدرجًا في القائمة المسموح بها.

## 4. لوحة القيادة

تعرض لوحة المعلومات نظرة عامة على المجموعة متعددة العقد وصحة العقدة.

### 4.1 ما يظهر

- **معلومات النظام**: اسم المضيف، إصدار نظام التشغيل، وقت التشغيل، وحدة المعالجة المركزية، الذاكرة
- **حركة المرور**: عرض النطاق الترددي في الوقت الفعلي، إجمالي حركة المرور، الاتجاه الشهري
- ** صحة العقدة **: الأعداد المتصلة / غير المتصلة بالإنترنت / المتدهورة، والعقد ذات التحميل العالي
- **التنبيهات**: العقد غير المتصلة بالإنترنت، والعقد المتدهورة، والشهادات التي تنتهي صلاحيتها قريبًا، وتحذيرات الحصص
- **موارد المجموعة**: متوسط وحدة المعالجة المركزية والذاكرة والقرص والإنتاجية

### 4.2 الإجراءات

- انقر على "عرض التفاصيل" لفتح صفحة تفاصيل العقدة
- انقر فوق بطاقة عقدة لرؤية حالتها المباشرة
- استخدم عوامل التصفية للتضييق حسب الحالة أو النوع أو المنطقة

## 5. إدارة العقدة

تعد إدارة العقدة جوهر CoreFusion وتدعم العديد من أنواع العقد.

### 5.1 أنواع العقد

| اكتب | الوصف |
|------|-------------|
| مستقل (`standalone`) | عقدة أساسية مستقلة |
| مرآة (`mirror`) | مزامنة التكوين من العقدة المستهدفة |
| أساسي/احتياطي (`primary_backup`) | العقد الشريكة التي تفشل مع بعضها البعض |
| دخول السلسلة (`chain_entry`) | عقدة دخول الوكيل المتسلسل |
| مخرج السلسلة (`chain_exit`) | عقدة الخروج من الوكيل المتسلسل |

### 5.2 إضافة عقدة

1. افتح "إدارة العقدة"؛
2. انقر فوق "إضافة خادم";
3. املأ الأساسيات:
   - الاسم، على سبيل المثال. `HongKong-HK01`
   - اسم المضيف: IP أو المجال
   - المنطقة، على سبيل المثال. `HK`، `JP`، `US`
   - نوع العقدة؛
4. قم بتعيين منفذ الوكيل (`18443` الافتراضي)؛
5. حدد النوى المدعومة؛
6. انقر فوق "حفظ".

### 5.3 النشر بنقرة واحدة

1. بعد إضافة العقدة، انقر فوق "أمر Bootstrap"؛
2. انسخ أمر التثبيت؛
3. قم بتشغيله كجذر على العقدة البعيدة:

   ```bash
   curl -fsSL https://your-panel/install.sh | bash
   ```

4. يقوم الوكيل بالتنزيل والتسجيل والبدء تلقائيًا.

### 5.4 تفاصيل العقدة

انقر فوق العقدة لفتح صفحة التفاصيل الخاصة بها:

- **نظرة عامة**: المعلومات الأساسية، وحالة الوكيل، وحالة الشهادة
- **مركز البروتوكول**: تكوين العملية الأساسية
- ** الوكيل **: تكوين العلبة / Nginx
- ** العمليات الأساسية **: البدء / الإيقاف / إعادة التشغيل
- **WARP**: تكوين WARP
- **المجالات المباشرة**: إدارة المجال
- ** حد السعر **: تشكيل حركة المرور
- **الشهادات**: روابط الشهادات
- **المستخدمون عبر الإنترنت**: المستخدمون عبر الإنترنت في الوقت الفعلي

### 5.5 إجراءات العقدة

- **تكوين المزامنة**: ادفع تكوين اللوحة إلى العقدة
- **فرض إعادة الاتصال**: قم بإسقاط اتصال الوكيل ثم أعد الاتصال
- **تحديث الوكيل**: ادفع تحديث الوكيل
- ** إبطال الشهادة **: إبطال شهادة وكيل العقدة

## 6. مركز البروتوكول

يقوم مركز البروتوكول بتكوين معلمات البروتوكول للعمليات الأساسية.

### 6.1 النوى المدعومة

| الأساسية | الوصف |
|------|-------------|
| Xray-النواة | VLESS / VMess / Trojan / Shadowsocks وأكثر من ذلك |
| sing-box | منصة وكيل عالمية معيارية مع دعم TUN؛ يحمل Hysteria2 / TUIC وبروتوكولات QUIC الأخرى |

### 6.2 وحدات التكوين

- **السجل**: سجل الوصول، سجل الأخطاء، وضع الإخراج
- **API**: عنوان الاستماع gRPC API، قائمة الخدمات
- **DNS**: خوادم DNS، واستراتيجية الاستعلام، والمضيفات الثابتة
- ** التوجيه **: قواعد التوجيه، موازنة التحميل، توجيه VLESS
- **الواردات**: قائمة الواردين، إعدادات البروتوكول، النقل، TLS
- **الصادرات**: القائمة الصادرة، وإعدادات البروتوكول، والنقل
- **النقل**: WebSocket، وgRPC، وXHTTP، وTUN، وما إلى ذلك.
- **TLS**: الشهادات، ALPN، بصمة uTLS، ECH
- **Reality**: إدارة الأهداف، وأزواج المفاتيح، والمعرفات القصيرة
- **فحص السلامة**: مسبار URL، الفاصل الزمني، التزامن
- **FakeDNS**: تجمع IP، حجم التجمع
- **المقاييس**: مستمع مقاييس بروميثيوس
- **السياسة**: مهلات الاتصال، والمخازن المؤقتة، والإحصائيات
- ** البيانات الجغرافية **: التحديث التلقائي، ملفات الموارد
- ** حدود الإصدار **: الحد الأدنى / الحد الأقصى للإصدار

### 6.3 التكوين الوارد

1. حدد الأساسية والبروتوكول؛
2. املأ الأساسيات:
   - علامة
   - الاستماع عنوان والميناء
   - نوع البروتوكول
3. تعيين معلمات البروتوكول (UUID، كلمة المرور، وما إلى ذلك)؛
4. اختر وسيلة النقل (TCP، WebSocket، gRPC، وما إلى ذلك)؛
5. تكوين TLS (الشهادة، ALPN)؛
6. حفظ وتطبيق على القلب.

### 6.4 التكوين الصادر

1. إضافة الصادرة؛
2. تعيين العلامة والبروتوكول؛
3. تعيين عنوان الخادم والمنفذ؛
4. تكوين النقل وTLS؛
5. حفظ وتطبيق.

### 6.5 مشاركة الروابط

1. انقر على "مشاركة الرابط" في القائمة الواردة؛
2. اختر التنسيق:
   - مشاركة URI
   - ميهومو YAML
   - sing-box JSON
   - Xray JSON
3. انسخ الرابط أو قم بإنشاء رمز الاستجابة السريعة.

## 7. إدارة الوكيل

تقوم إدارة الوكيل بتكوين الوكيل العكسي Caddy أو Nginx.

### 7.1 أنواع الوكيل

- **العلبة**: HTTPS أوتوماتيكي، HTTP/2، HTTP/3
- **Nginx**: أداء عالي وتكوين مرن

### 7.2 تكوين الموقع

1. افتح "إدارة الوكيل"؛
2. اختر نوع الوكيل (Caddy / Nginx)؛
3. إضافة موقع:
   - المجال
   - المنبع
   - ميناء محلي
4. حفظ.

### 7.3 الحقول

- **المنبع**: عنوان الواجهة الخلفية، على سبيل المثال. `127.0.0.1:8082`
- **local_port**: منفذ الاستماع المحلي، على سبيل المثال. `8443`
- **portal_forward**: قاعدة إعادة توجيه البوابة
- **subscription_forward**: قاعدة إعادة توجيه الاشتراك

### 11.2 متغيرات الخطة

## 14. إدارة الشهادات

تتعامل إدارة الشهادات مع شهادات TLS.

### 14.1 إصدار الشهادة

1. افتح "إدارة الشهادات"؛
2. انقر على "إصدار الشهادة"؛
3. املأ:
   - قائمة النطاق (واحدة في كل سطر)
   - نوع الشهادة (المجال / IP)
   - نوع المفتاح (ECC/RSA)
   - طريقة التحقق (DNS-01 / HTTP-01)
   - مزود DNS
   - موقع الإصدار (مضيف/عقدة اللوحة)
4. انقر فوق "مشكلة".

### 14.2 إجراءات الشهادة

- **التجديد**: التجديد يدويًا
- **النشر**: النشر إلى العقدة
- ** التوزيع **: ادفع إلى جميع العقد المرتبطة
- **الترحيل**: نقل المراجع من شهادة قديمة إلى شهادة جديدة
- **التنزيل**: تنزيل `cert` / `fullchain` / `privkey`

### 14.3 تحميل الشهادة

1. انقر فوق "تحميل الشهادة"؛
2. اختر الطريقة:
   - الصق المحتوى
   - تحميل الملفات
3. تحميل سلسلة الشهادة والمفتاح الخاص؛
4. يحفظ.

### 14.4 التكوين EAB

- إدارة بيانات اعتماد EAB لـ Google Public CA / ZeroSSL
- احصل على EAB تلقائيًا
- إرفاقه تلقائيا عند الإصدار

## 26. الأسئلة الشائعة

### 26.1 لا تبدأ اللوحة

- تحقق مما إذا كان المنفذ قيد الاستخدام بالفعل
- تأكد من صلاحية `.env`
- تحقق من السجلات: `journalctl -u corefusion -f`؛ بدون systemd، `tail -f <install-dir>/data/logs/panel.log`

### 26.2 العقدة غير متصلة بالإنترنت

- تأكد من تشغيل الوكيل: `systemctl status corefusion-agent`
- تحقق من اتصال الشبكة
- التحقق من قواعد جدار الحماية (المنفذ `18443`)

### 26.3 فشل إصدار الشهادة

- تحقق من دقة DNS
- تأكد من إمكانية الوصول إلى المنفذ 80
- تحقق من تكوين موفر DNS
- تحقق من سجلات الشهادات

### 26.4 الاشتراك لا يعمل

- التحقق من رابط الاشتراك
- تأكد من أن العقدة متصلة بالإنترنت
- تأكد من أن العملية الأساسية قيد التشغيل
- تحقق من قواعد جدار الحماية

### 26.5 فشل رد الاتصال بإعادة الشحن

- تحقق من رد الاتصال URL
- تأكد من تطابق مفتاح الموقع
- تحقق من قائمة IP المسموح بها
- تحقق من سجلات الطلب

### 26.6 صفحة البوابة غير قابلة للوصول

- تأكد من أن منفذ البوابة مفتوح
- تحقق من تكوين مسار البوابة
- **هام**: تأكد من أن الوكيل العكسي يعيد توجيه مجال البوابة الإلكترونية إلى **منفذ محرك البوابة**، وليس منفذ اللوحة الرئيسية — تؤدي إعادة التوجيه إلى المنفذ الخاطئ إلى ظهور صفحة فارغة أو اللوحة بدلاً من البوابة الإلكترونية. تحقق من `upstream` / `local_port` في سجل موقع الوكيل.
- افتح `http://<portal-domain>:<portal-port>` مباشرة للتحقق من محرك البوابة نفسه
- تحقق من تكوين الوكيل العكسي
- التحقق من سجلات البوابة

## الملحق

### أ. المنافذ الافتراضية

| ميناء | الغرض |
|------|---------|
| تم تعيينه بواسطة معالج الإعداد (منفذ مجاني عشوائي بشكل افتراضي) | لوحة الإدارة (قابلة للتغيير) |
| 18443 | وكيل gRPC (قابل للتغيير) |
| 0 (معطل افتراضيًا) | منفذ محرك الاشتراك المخصص (فارغ أو يشارك `0` المنفذ الرئيسي) |
| 0 (معطل افتراضيًا) | منفذ محرك البوابة المخصص (فارغ أو يشارك `0` المنفذ الرئيسي) |
| 80 / 443 | الوكيل العكسي (العلبة / Nginx) HTTP / HTTPS |

### ب. المسارات الافتراضية

| المسار | الغرض |
|------|---------|
| `/` | لوحة الإدارة (توجد البوابة أيضًا في `/` عند عدم تكوين محرك بوابة مخصص) |
| `/sub/:token` | جلب الاشتراك (عند عدم تكوين منفذ اشتراك مخصص) |
| `/p` | صفحة البوابة (في حالة عدم تكوين منفذ بوابة مخصص) |
| `/:token` | جلب الاشتراك (مع منفذ اشتراك مخصص، بدون البادئة `/sub`) |

### ج. أداة سطر الأوامر

يدعم ثنائي اللوحة هذه الأوامر الفرعية (لا توجد وسيطات لبدء تشغيل الخادم):

```bash
# Start the panel (same as ./corefusion server)
./corefusion

# Run database migrations
./corefusion migrate

# Offline administration (when you cannot sign in)
./corefusion admin reset-password -u admin -p 'new-password'
./corefusion admin 2fa reset -u admin
./corefusion admin list

# Version / help
./corefusion version
./corefusion help
```

> بدون وحدة systemd، أعد التشغيل عن طريق إيقاف العملية القديمة وبدء تشغيلها مرة أخرى باستخدام `nohup`؛ السجلات موجودة في `<install-dir>/data/logs/panel.log`.
