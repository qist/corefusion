# ตัวแปรเทมเพลตการแจ้งเตือน

> ภาษา: [简体中文](notification-templates.md) · [English](notification-templates.en.md) · [繁體中文](notification-templates.zh-TW.md) · [Русский](notification-templates.ru.md) · [日本語](notification-templates.ja.md) · [한국어](notification-templates.ko.md) · [Deutsch](notification-templates.de.md) · [Français](notification-templates.fr.md) · [Español](notification-templates.es.md) · [Português](notification-templates.pt.md) · [Türkçe](notification-templates.tr.md) · [Bahasa Indonesia](notification-templates.id.md) · ไทย · [Tiếng Việt](notification-templates.vi.md) · [العربية](notification-templates.ar.md) · [فارسی](notification-templates.fa.md)

เทมเพลตการแจ้งเตือนใช้ตัวยึดตำแหน่ง `{variable}` ซึ่งจะถูกแทนที่ด้วยค่าจริงเมื่อส่ง เอกสารนี้แสดงรายการตัวแปรที่รองรับทั้งหมด ตัวแปรที่ใช้ได้ต่อเหตุการณ์ และกฎทริกเกอร์อัตโนมัติ

## 1. ประเภทเทมเพลตและผู้ชม

| ผู้ชม | ช่อง | ผู้รับ | การใช้งานทั่วไป |
|---|---|---|---|
| **ผู้ใช้แผงควบคุม** (ผู้ดูแลระบบ) | Telegram / อีเมล์ | ช่องและผู้รับที่กำหนดค่าโดยผู้ดูแลระบบ | การแจ้งเตือนโหนด รายงานสำรอง ประกาศของระบบ |
| **สมาชิก** | อีเมล | อีเมลของลูกค้าเอง (กรอกอัตโนมัติ) | ยอดคงเหลือต่ำ การแจ้งเตือนการหมดอายุการสมัครสมาชิก |

## 2. ตัวแปรทั่วไป

มีอยู่ในเทมเพลตทั้งหมด:

| ตัวแปร | คำอธิบาย | ตัวอย่าง |
|---|---|---|
| `{time}` | ส่งเวลา | `2026-09-28 14:30:00` |
| `{user}` | อีเมลลูกค้า (เทมเพลตสมาชิก) / ตัวระบุผู้ใช้ | `user@example.com` |
| `{message}` | เนื้อหาการแจ้งเตือน | ข้อความประกาศการบำรุงรักษา |

## 3. ตัวแปรเหตุการณ์สมาชิก

### การแจ้งเตือนการหมดอายุการสมัครสมาชิก (event_key = `subscription_expire`)

สแกนทุกวันและส่งไปยังสมาชิกที่ใช้งานอยู่ซึ่งจะหมดอายุภายใน 7 วัน:

| ตัวแปร | คำอธิบาย | ตัวอย่าง |
|---|---|---|
| `{user}` | อีเมล์ลูกค้า | `user@example.com` |
| `{expire_date}` | การสมัครสมาชิกหมดอายุ | `2026-10-05 09:00` |
| `{days}` | วันที่เหลืออยู่ | `7` |
| `{time}` | ส่งเวลา | `2026-09-28 09:05:00` |

### การแจ้งเตือนยอดคงเหลือต่ำ (event_key = `balance_low`)

สแกนทุกวันและส่งให้กับลูกค้าที่มียอดคงเหลือต่ำกว่าเกณฑ์:

| ตัวแปร | คำอธิบาย | ตัวอย่าง |
|---|---|---|
| `{user}` | อีเมล์ลูกค้า | `user@example.com` |
| `{balance}` | ยอดเงินปัจจุบัน (หน่วยสกุลเงิน ทศนิยม 2 ตำแหน่ง) | `0.85` |
| `{time}` | ส่งเวลา | `2026-09-28 09:05:00` |

## 4. ตัวแปรตัวอย่างเทมเพลตการดำเนินงาน

เมื่อคุณคลิก "ส่ง" เพื่อทดสอบการเชื่อมต่อ เทมเพลตผู้ใช้แผงจะเติมตัวยึดตำแหน่งด้วยตัวอย่างเหล่านี้:

| ตัวแปร | คำอธิบาย | ตัวอย่าง |
|---|---|---|
| `{node}` | ชื่อโหนด | `node-01` |
| `{backup_file}` | ชื่อไฟล์สำรอง | `corefusion-20260101-0900.tar.gz` |
| `{size}` | ขนาดไฟล์ | `128MB` |
| `{domain}` | โดเมน | `example.com` |
| `{expire_date}` | วันหมดอายุ | `2026-10-12` |
| `{days}` | วันที่เหลืออยู่ | `14` |
| `{count}` | นับ | `3` |

## 5. กฎทริกเกอร์อัตโนมัติ

- **กำหนดการ**: การสแกนครั้งแรกจะดำเนินการ 30 วินาทีหลังจากที่แผงเริ่มต้น จากนั้นทุกวันในเวลา **09:05**
- **การสมัครสมาชิกหมดอายุ**: สแกนการสมัครสมาชิกที่ใช้งานอยู่ (`status=active`) ที่หมดอายุภายใน 7 วัน ลูกค้าจะต้องมีความกระตือรือร้นด้วย
- **ยอดคงเหลือต่ำ**: สแกนลูกค้าที่ใช้งานอยู่ด้วยยอดคงเหลือ ≤ เกณฑ์; เกณฑ์คือ `notify.balance_threshold` **เป็นเซนต์** (ค่าเริ่มต้น `100` = 1.00)
- **การขจัดความซ้ำซ้อน**: สูงสุดหนึ่งข้อความต่อลูกค้าต่อเหตุการณ์ **ต่อวัน** (`notification_send_logs` ขจัดความซ้ำซ้อนในแต่ละวัน)

## 6. การตรวจสอบสุขภาพของโหนด

มีการตรวจสอบการเต้นของหัวใจของโหนดอย่างต่อเนื่อง **การแจ้งเตือนจะถูกส่งเฉพาะเมื่อสถานะเปลี่ยนแปลง — รอบที่ไม่มีการเปลี่ยนแปลงจะถูกเงียบ**:

| คีย์การตั้งค่า | คำอธิบาย | ค่าเริ่มต้น |
|---|---|---|
| `monitor.node_interval_seconds` | ตรวจสอบช่วงเวลา (วินาที) | `60` (ขั้นต่ำ 30) |
| `monitor.node_offline_timeout_seconds` | หมดเวลาการเต้นของหัวใจ (วินาที) | `120` |

- **การแจ้งเตือนออฟไลน์**: เมื่อโหนดเปลี่ยนจากออนไลน์เป็นออฟไลน์ ให้ส่งเทมเพลตผู้ดูแลระบบ “**การแจ้งเตือนโหนดออฟไลน์**” พร้อมด้วย `{node}` (ชื่อ) และ `{time}`
- **ประกาศการกู้คืน**: เมื่อโหนดกู้คืน ให้ส่ง “**ประกาศการกู้คืนโหนด**” พร้อมตัวแปรเดียวกัน
- **รอบเงียบ**: ไม่มีข้อความเมื่อสถานะไม่เปลี่ยนแปลง หลังจากแผงรีสตาร์ท รอบแรกจะสร้างเส้นฐานเท่านั้น
- **ตรวจสอบโดยไม่ต้องส่ง**: ปิดการใช้งานเทมเพลตที่เกี่ยวข้อง (เปิดใช้งาน = ปิด)

## 7. การแจ้งเตือนโควต้าการรับส่งข้อมูลรายเดือนของโหนด (อัตโนมัติ)

- **ทริกเกอร์**: เมื่อการรับส่งข้อมูลรายเดือนของโหนดถึงเกณฑ์โควต้า จะส่ง “**การแจ้งเตือนโควต้าการรับส่งข้อมูลโหนด**”; เมื่อเกิน 100% และถูกระงับจะส่งการแจ้งเตือนเกินขีดจำกัด (คีย์เหตุการณ์ `traffic_quota_threshold` / `traffic_quota_exceeded`)
- **เกณฑ์**: `monitor.traffic_quota_threshold_percent` (เปอร์เซ็นต์, ค่าเริ่มต้น `80`; ตั้งค่า `0` เพื่อปิดใช้งานการแจ้งเตือนเกณฑ์)
- **การขจัดข้อมูลซ้ำซ้อน**: มากที่สุดหนึ่งรายการต่อโหนดต่อรอบการเรียกเก็บเงิน (รอบจะเป็นไปตาม `traffic_quota_reset_day` ของโหนด)
- ตัวแปรที่ใช้ได้: `{node}` (ชื่อ), `{used}` (ใช้ GB), `{quota}` (โควต้า GB), `{percent}` (เปอร์เซ็นต์), `{time}`

## 8. การแจ้งเตือนผลการสำรองข้อมูล (อัตโนมัติ)

- **ทริกเกอร์**: ส่งทันทีหลังจากการสำรองข้อมูลตามกำหนดเวลา (`BackupScheduler`) รัน — สำเร็จจะส่ง “**รายงานการสำรองข้อมูลรายวัน**” ความล้มเหลว (การสร้างการสำรองข้อมูล / การอ่านพื้นที่เก็บข้อมูล / การอัปโหลดไปยังระยะไกล) จะส่ง “**การแจ้งเตือนความล้มเหลวในการสำรองข้อมูล**”
- ตัวแปรที่ใช้ได้: `{backup_file}` (ชื่อ), `{size}` (ขนาด, รายงานความสำเร็จเท่านั้น), `{message}` (เหตุผลความล้มเหลว, การแจ้งเตือนความล้มเหลวเท่านั้น), `{time}`
- **ตรวจสอบโดยไม่ต้องส่ง**: ข้ามอย่างเงียบ ๆ เมื่อปิดใช้งานเทมเพลต (เปิดใช้งาน = ปิด)

## 9. การแจ้งเตือนการหมดอายุของใบรับรอง (อัตโนมัติ)

- **ทริกเกอร์**: ทุกวันเวลา 09:05 น. สแกนใบรับรอง `active` ที่ใกล้จะหมดอายุ (**ใบรับรอง IP ที่เหลืออีก 3 วัน**, **ใบรับรองโดเมนที่เหลืออีก 7 วัน**) และส่งเทมเพลตผู้ดูแลระบบ “**การแจ้งเตือนการหมดอายุใบรับรอง**” ต่อใบรับรอง
- **การขจัดข้อมูลซ้ำซ้อน**: แจ้งเตือนได้สูงสุด 1 รายการต่อใบรับรองต่อวัน หลังจากต่ออายุการหมดอายุจะย้ายออกไปนอกหน้าต่าง (IP 3 วัน / โดเมน 7 วัน) และการแจ้งเตือนจะหยุดลง
- ตัวแปรที่มี: `{domain}` (โดเมนใบรับรอง), `{expire_date}` (วันหมดอายุ), `{days}` (วันที่เหลือ), `{time}`

## 10. การแจ้งเตือนข้อขัดข้องของกระบวนการหลัก (อัตโนมัติ)

- **ทริกเกอร์**: เมื่อกระบวนการหลัก (xray/singbox) ออกอย่างผิดปกติ หรือกระบวนการพร็อกซี (แคดดี้/nginx) ขัดข้อง ให้ส่งเทมเพลตผู้ดูแลระบบ “**การแจ้งเตือนข้อขัดข้องของกระบวนการหลัก**” ทันที จากนั้นหัวหน้างานจะรีสตาร์ทโดยมีการถอยกลับแบบเอกซ์โปเนนเชียล
- ตัวแปรที่ใช้ได้: `{core}` (ประเภทกระบวนการ), `{restarts}` / `{max}` (จำนวนการรีสตาร์ท / ขีดจำกัด), `{message}` (ข้อความออก, กระบวนการหลักเท่านั้น), `{time}`
- **ตรวจสอบโดยไม่ต้องส่ง**: ข้ามอย่างเงียบ ๆ เมื่อปิดใช้งานเทมเพลต (เปิดใช้งาน = ปิด)

## 11. ประกาศการลงทะเบียนผู้ใช้ใหม่ (อัตโนมัติ)

- **ทริกเกอร์**: ส่งทันทีหลังจากที่ลูกค้าลงทะเบียนสำเร็จ โดยใช้เทมเพลตผู้ดูแลระบบ “**ประกาศการลงทะเบียนผู้ใช้ใหม่**”
- ตัวแปรที่ใช้ได้: `{user}` (อีเมลลูกค้า), `{time}`

## 12. การใช้งาน

1. **เพิ่มเทมเพลต**: การตั้งค่าการแจ้งเตือน → เทมเพลตการแจ้งเตือน → เพิ่มเทมเพลต → “กรอกจากการตั้งค่าล่วงหน้า” และปรับเปลี่ยนตามต้องการ
2. **เปิดใช้งาน**: ทำเครื่องหมายที่เปิดใช้งานแล้วบันทึก ทริกเกอร์อัตโนมัติจะประมวลผลเฉพาะเทมเพลตที่เปิดใช้งานเท่านั้น
3. **ทดสอบ**: คลิก “ส่ง” ในรายการเพื่อส่งข้อความจริงพร้อมตัวแปรตัวอย่าง (อีเมลทดสอบเทมเพลตสมาชิกไปที่ที่อยู่ผู้ส่งของผู้ดูแลระบบ)
4. **การแจ้งเตือนทันที** (รหัสธุรกิจ): โทรไปที่ `NotifyClientEvent(ctx, db, settingSvc, eventKey, clientEmail, vars)` ที่สถานที่จัดงาน (เติมเงิน หักเงิน ต่ออายุ) เพื่อแจ้งให้ลูกค้ารายเดียวทราบทันที นอกขีดจำกัดการสแกนรายวัน
