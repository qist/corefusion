## 1. ภาพรวมของระบบ

CoreFusion เป็นแผงการจัดการพร็อกซีหลายโปรโตคอลที่รองรับ VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC และอื่นๆ อีกมากมาย พร้อมการจัดการโหนด การจัดส่งการสมัครสมาชิก การจัดการลูกค้า การเรียกเก็บเงิน ใบรับรอง และพร็อกซีแบบลูกโซ่

### 1.1 คุณสมบัติหลัก

| โมดูล | คำอธิบาย |
|--------|-------------|
| หลายโปรโตคอล | VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, WireGuard, ฯลฯ. |
| มัลติคอร์ | Xray-core และ sing-box (Hysteria2/TUIC และโปรโตคอล QUIC อื่นๆ ทำงานบน sing-box) |
| หลายโหนด | โหนดห้าประเภท: สแตนด์อโลน, มิเรอร์, ใช้งาน/สแตนด์บาย, การเข้าแบบโซ่, ทางออกแบบโซ่ |
| การจัดส่งการสมัครสมาชิก | รูปแบบการสมัครสมาชิกหลายรูปแบบ อุปกรณ์ปลายทาง และการจัดการรูปแบบ |
| การเรียกเก็บเงิน | เทมเพลตแผน บัตรเติมเงิน ยอดคงเหลือ คำสั่งซื้อ ค่าคอมมิชชันของผู้ค้าปลีก |
| ใบรับรอง | มาเข้ารหัสกันเถอะ, การตรวจสอบ DNS-01/HTTP-01, การแจกจ่ายใบรับรอง |
| พร็อกซีที่ถูกล่ามโซ่ | การปรับสมดุลโหลดหลายทางออก การลงทะเบียนโหนดภายนอก การกำหนดเส้นทางแบบลูกโซ่ |
| โควต้าการจราจร | การตรวจสอบการรับส่งข้อมูลรายเดือนต่อโหนด, ระงับอัตโนมัติ, บันทึกการรีเซ็ต |
| พอร์ทัล | โปรแกรมแก้ไขพอร์ทัลแบบเห็นภาพ เทมเพลตแบบกำหนดเองได้หลายภาษา |
| การแจ้งเตือน | อีเมลและ Telegram เทมเพลตและการออกอากาศ |

### 1.2 สถาปัตยกรรม

- **แบ็กเอนด์**: ไปซะ gRPC
- **ส่วนหน้า**: Vue 3 + Element Plus
- **ฐานข้อมูล**: SQLite (ค่าเริ่มต้น) / MySQL / PostgreSQL
- **พร็อกซี**: Caddy / Nginx พร็อกซีย้อนกลับ
- **พอร์ตแผง**: กำหนดโดยวิซาร์ดการตั้งค่า (พอร์ตสุ่มฟรีตามค่าเริ่มต้น 8080 เป็นตัวเลือกทั่วไป)
- **พอร์ตตัวแทน gRPC**: 18443 โดยค่าเริ่มต้น

## 2. การติดตั้ง

### 2.1 สภาพแวดล้อมที่รองรับ

| รายการ | สนับสนุน |
|------|---------|
| การแจกแจง | เดเบียน / อูบุนตู, RHEL / CentOS / ร็อคกี้ / AlmaLinux / Fedora, อัลไพน์, Arch, openSUSE |
| สถาปัตยกรรมซีพียู | ไบนารีอย่างเป็นทางการ: `amd64`, `arm64`; การสร้างซอร์สยังรองรับ `armv7`, `armv6`, `386`, `ppc64le`, `s390x`, `riscv64`, `loong64` |
| ผู้จัดการฝ่ายบริการ | systemd (แนะนำ); ถอยกลับไปเป็น `nohup` ในคอนเทนเนอร์หรือสภาพแวดล้อมอื่นๆ ที่ไม่มี systemd |
| หน่วยความจำ / ดิสก์ | ≥ 1 GB / ≥ 10 GB (ฐานข้อมูล ใบรับรอง บันทึก และไบนารีหลักอยู่ในไดเร็กทอรีข้อมูล) |
| พอร์ตแผง | เลือกในตัวช่วยสร้างการตั้งค่า (พอร์ตสุ่มฟรีตามค่าเริ่มต้น `8080` และที่คล้ายกันนั้นใช้ได้) |
| ตัวแทน gRPC | `18443` โดยค่าเริ่มต้น |

คำสั่งภายนอกรันไทม์ได้รับการติดตั้งโดยอัตโนมัติโดยตัวติดตั้ง (`scripts/install.sh` และสคริปต์การติดตั้ง Agent ที่สร้างโดยแผงควบคุม ข้ามด้วย `--no-deps` / `CF_SKIP_DEPS=1`):

| วัตถุประสงค์ | แพ็คเกจ |
|---------|---------|
| ไฟร์วอลล์ / ขีด จำกัด อัตรา / การทำเครื่องหมายการทำงานพร้อมกัน | `nftables` (`nft`) |
| การกำหนดรูปแบบการจราจร ลิงก์ และซ็อกเก็ต | `iproute2` (`tc` / `ip` / `ss`) |
| ทางเลือกเมื่อ nft ไม่พร้อมใช้งาน | `iptables` (`iptables-nft` บน EL8+, `iptables` บน EL7) |
| การติดตามการเชื่อมต่อ | `conntrack-tools` (`conntrack`) |
| โหลด `nf_conntrack` / `ifb` | `kmod` (`modprobe` / `lsmod`) |
| การตรวจจับกระบวนการและการล้างข้อมูล | `procps` (`pgrep` / `pkill`) |
| ตรวจสอบพอร์ต / พารามิเตอร์ DH | `lsof` / `openssl` |
| การสร้างผู้ใช้พร็อกซี | `shadow-utils` (Debian `passwd`, อัลไพน์/Arch `shadow`) |
| ดาวน์โหลดและเก็บถาวร | `curl` / `ca-certificates` / `tar` / `gzip` / `xz` |

> การขาด `nft` / `tc` ส่งผลต่อการจำกัดอัตราและคุณสมบัติไฟร์วอลล์เท่านั้น แผงยังคงเริ่มต้น
> รัน `--cpu-info` ก่อนเพื่อดูว่าสภาพแวดล้อมถูกตรวจพบอย่างไร และแพ็คเกจใดบ้างที่ขาดหายไป

### 2.2 การติดตั้งบรรทัดเดียว (แนะนำ)

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh -o install.sh
sudo bash install.sh
```

หรือไพพ์โดยตรง (ไม่มีการโต้ตอบ ไม่มีแฟล็กเพิ่มเติม):

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash
```

สคริปต์จะ:

1. ตรวจจับการกระจาย สถาปัตยกรรม CPU และ libc จากนั้นติดตั้งแพ็คเกจพื้นฐานและการขึ้นต่อกันของรันไทม์
2. ดาวน์โหลด `corefusion-linux-<arch>` จาก GitHub Release และตรวจสอบด้วย `.sha256` ที่ตรงกัน
3. ติดตั้งไปที่ `/opt/corefusion` และสร้าง `data/{sqlite,certs,logs,runtime}`;
4. เขียนเฉพาะตัวยึดตำแหน่ง `.env` ด้วย `SAFE_PATHS=data` — ไม่มีการกำหนดค่าฐานข้อมูล — ดังนั้นการเริ่มต้นครั้งแรกจะเข้าสู่วิซาร์ดการตั้งค่า (ตัวช่วยสร้าง `.env` แบบเต็มจะถูกสร้างขึ้นโดยวิซาร์ด)
5. ติดตั้งและเริ่มบริการ systemd (หรือทำงานภายใต้ `nohup` เมื่อ systemd ไม่พร้อมใช้งาน)
6. รอจนกว่าจะพร้อม จากนั้นพิมพ์การตั้งค่า URL โทเค็น และเส้นทางไดเรกทอรี

ตัวอย่างผลลัพธ์:

```text
==================================================================
 CoreFusion installation complete
------------------------------------------------------------------
 Install dir : /opt/corefusion
 Data dir    : /opt/corefusion/data
 Binary      : /opt/corefusion/corefusion
 Logs        : journalctl -u corefusion -f
------------------------------------------------------------------
 Setup wizard : http://<server-ip>:<random-port>/init?init_token=<token>
 Setup token  : <token>
 Valid for    : 2 hours (see startup log)
 Note         : the token is shown once; after setup this port closes and the panel switches to its normal port.
==================================================================
```

หากแผงควบคุมรับฟังเฉพาะ `127.0.0.1` (เช่น หลังพร็อกซีย้อนกลับ) สคริปต์จะพิมพ์คำสั่งช่องสัญญาณ SSH แทน URL ที่ไม่สามารถเข้าถึงได้

> โทเค็นสูญหายใช่ไหม อ่านบันทึกการเริ่มต้นอีกครั้ง: `journalctl -u corefusion -n 50 --no-pager`
> (ไม่มี systemd: `tail -n 50 /opt/corefusion/data/logs/panel.log`)

### 2.2.1 เอาต์พุตหลายภาษา

ตัวติดตั้งประกอบด้วยภาษา UI สี่ภาษา: จีนตัวย่อ อังกฤษ เปอร์เซีย (FAARسی) และรัสเซีย (Русский) โดยจะตรวจจับระบบ `LANG` โดยอัตโนมัติ หรือคุณสามารถเลือกอย่างชัดเจน:

```bash
# English
sudo bash install.sh --lang en

# Persian via environment variable
sudo CF_LANG=fa bash install.sh

# Pass options through a pipe
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash -s -- --lang ru
```

ค่าที่รองรับ: `zh` / `en` / `fa` / `ru`; `--lang=ru` ก็ได้รับการยอมรับเช่นกัน ค่าที่ชัดเจนที่ไม่รองรับจะล้มเหลวเมื่อมีรายการภาษาที่ใช้ได้

### 2.3 การปักหมุดเวอร์ชัน / มิเรอร์ / การติดตั้งออฟไลน์

```bash
# Pin a version
sudo bash install.sh --version v0.13.0-beta.90

# GitHub download mirror (used as a URL prefix)
sudo bash install.sh --mirror https://ghproxy.net --version latest

# Use a local binary (offline / intranet / pre-built)
sudo bash install.sh --local ./dist/corefusion-linux-arm64

# Explicit target architecture
sudo bash install.sh --arch arm64 --local ./corefusion-linux-arm64
```

> หากไม่มี `--version` สคริปต์จะใช้รายการใหม่ล่าสุดในรายการ GitHub Releases
> รีลีสส่วนใหญ่เป็นรุ่นก่อนรีลีส ดังนั้นจึงไม่ได้ใช้ตำแหน่งข้อมูล `/releases/latest`
>
> การเปิดตัวอย่างเป็นทางการมีเฉพาะ `amd64` / `arm64`; ใช้ `--source` หรือไบนารีที่คอมไพล์ข้ามกับ `--local` สำหรับสถาปัตยกรรมอื่นๆ

### 2.4 การสร้างจากแหล่งที่มา

```bash
sudo bash install.sh --source --version v0.13.0-beta.90
```

`--source` โคลนที่เก็บ (หรือใช้การชำระเงินที่มีอยู่เมื่อมีสคริปต์อยู่ข้างใน) และรัน `make panel` เวอร์ชันของ Toolchain จะถูกเลือกตามสภาพแวดล้อม:

| การพึ่งพาอาศัยกัน | การคัดเลือก |
|------------|-----------|
| ไป | อ่านจาก `toolchain` / `go` ใน `go.mod` (ปัจจุบัน **ไป 1.27+**); หากเวอร์ชันของระบบเก่าเกินไป toolchain ที่ตรงกันจะถูกดาวน์โหลดไปที่ `<install-dir>/.toolchain` |
| โหนด | **โหนด 22 LTS** โดยค่าเริ่มต้น (Vite ต้องการ ≥ 18) ระบบจะดาวน์โหลดบิลด์อย่างเป็นทางการที่ตรงกันเมื่อจำเป็น |
| โหนด (glibc < 2.28) | ใช้ `unofficial-builds` glibc-217 build (เช่น CentOS 7) |
| โหนด (อัลไพน์ / มัสล) | ใช้การกระจาย `nodejs` / `npm` |

แทนที่:

```bash
# Force Go / Node versions
sudo CF_GO_VERSION=1.27.5 CF_NODE_MAJOR=22 bash install.sh --source

# Go toolchain mirror (default https://go.dev/dl)
sudo CF_GO_MIRROR=https://golang.google.cn/dl bash install.sh --source
```

การสร้างด้วยตนเอง (การพัฒนา / การดีบัก):

```bash
git clone https://github.com/qist/corefusion.git
cd corefusion

# Frontend + panel for the current architecture; the frontend is embedded via go:embed
make panel

# Cross-compile
make panel-linux-amd64
make panel-linux-arm64
```

> `go build ./...` ไม่ได้สร้างไบนารี สร้างแผงด้วย
> `go build -o corefusion ./cmd/corefusion/` หรือ `make panel`

### 2.5 แฟล็กตัวติดตั้ง

| ธง | คำอธิบาย |
|------|-------------|
| `-d, --dir <PATH>` | ติดตั้งไดเร็กทอรี ค่าเริ่มต้น `/opt/corefusion` |
| `-v, --version <TAG>` | เวอร์ชันแผง เช่น `v0.13.0-beta.90`; ค่าเริ่มต้น `latest` |
| `--binary` | ใช้ไบนารี่ Release GitHub (ค่าเริ่มต้น) |
| `--source` | สร้างจากแหล่งที่มาและเตรียมการจับคู่ Go / Node |
| `--local <FILE>` | ใช้ไบนารีท้องถิ่น (ติดตั้งออฟไลน์) |
| `--arch <ARCH>` | สถาปัตยกรรมเป้าหมาย: `amd64` / `arm64` / `armv7` / `armv6` / `386` / `ppc64le` / `s390x` / `riscv64` / `loong64` |
| `--mirror <URL>` | คำนำหน้าการดาวน์โหลด GitHub เช่น `https://ghproxy.net` |
| `--repo <URL>` | ที่เก็บซอร์ส ดีฟอลต์ `https://github.com/qist/corefusion.git` |
| `--ref <REF>` | สาขา / แท็กต้นทาง ค่าเริ่มต้นเป็น `--version` หรือมิฉะนั้น `main` |
| `--no-deps` | ข้ามการติดตั้งการพึ่งพาระบบ |
| `--no-start` | ติดตั้งและเขียนไฟล์บริการโดยไม่ต้องเริ่มต้น |
| `--cpu-info` | การตรวจจับสภาพแวดล้อมการพิมพ์และการขึ้นต่อกันที่ขาดหายไป จากนั้นออก |
| `--lang <LANG>` | ภาษาเอาต์พุต: `zh` / `en` / `fa` / `ru` (ค่าเริ่มต้น: ระบบ `LANG`) |
| `--uninstall` | หยุดบริการและลบโปรแกรม (เก็บข้อมูลและ `.env`) |
| `--purge` | ด้วย `--uninstall` ให้ลบไดเร็กทอรีข้อมูลและ `.env` ด้วย |

> การเปิดตัวอย่างเป็นทางการจะจัดส่งเฉพาะไบนารี `amd64` / `arm64` เท่านั้น สถาปัตยกรรมอื่นๆ ต้องใช้ `--source`,
> มิฉะนั้นการดาวน์โหลดจะส่งคืน 404

ตัวแปรสภาพแวดล้อมที่เกี่ยวข้อง:

| ตัวแปร | วัตถุประสงค์ |
|----------|---------|
| `CF_GO_VERSION` | แทนที่เวอร์ชัน Go ที่จำเป็นสำหรับบิวด์ซอร์ส |
| `CF_NODE_MAJOR` | แทนที่เวอร์ชันหลักของโหนด (ค่าเริ่มต้น 22) |
| `CF_GO_MIRROR` | ไปที่มิเรอร์ดาวน์โหลด toolchain |
| `CF_SKIP_DEPS` | ตั้งค่าเป็น `1` ในสคริปต์การติดตั้ง Agent เพื่อข้ามการติดตั้งการขึ้นต่อกัน |
| `CF_LANG` | แทนที่ภาษาเอาต์พุตของตัวติดตั้ง (เหมือนกับ `--lang`) |

### 2.6 เค้าโครงไดเร็กทอรี

```text
/opt/corefusion/
├── corefusion                 # panel binary
├── corefusion.bak             # previous version (when upgrading)
├── .env                       # environment file (0600, generated by the setup wizard)
├── .env.secret                # encryption key file (0600, generated on first start)
├── .toolchain/                # Go / Node downloaded for source builds
└── data/                      # data directory (SAFE_PATHS)
    ├── sqlite/app.db          # default SQLite database
    ├── certs/                 # certificates and keys
    ├── logs/                  # runtime logs (without systemd)
    ├── runtime/               # core runtime config and state
    ├── binaries/              # downloaded xray / sing-box cores
    └── proxy/                 # proxy (Caddy/Nginx) sites and config
```

> โปรแกรมติดตั้งจะสร้างเฉพาะ `sqlite/`, `certs/`, `logs/` และ `runtime/` เท่านั้น `binaries/`, `proxy/`, `rules/` และอื่นๆ ถูกสร้างขึ้นโดยแผงควบคุมหรือเมื่อมีการติดตั้งแกน
> ไดเร็กทอรีข้อมูลมาจาก `SAFE_PATHS` ใน `.env` และอาจเป็นพาธสัมบูรณ์ การเปลี่ยนไดเร็กทอรีการติดตั้งจะไม่ย้ายข้อมูลที่มีอยู่

### 2.9 ไฟล์สภาพแวดล้อม (.env)

`.env` ที่สมบูรณ์ **สร้างโดยวิซาร์ดการตั้งค่า** เมื่อมีการบันทึกการกำหนดค่า (DSN ฐานข้อมูล ไดเร็กทอรีข้อมูล ข้อมูลลับ พอร์ต โดเมน)

ในการติดตั้งใหม่ ตัวติดตั้งจะเขียนเฉพาะตัวยึดตำแหน่งนี้ ดังนั้นแผงควบคุมจึงไม่เข้าใจผิดว่า `data/` ที่มีอยู่เป็นการติดตั้งเริ่มต้นและข้ามวิซาร์ด:

```env
SAFE_PATHS=data
```

> เมื่อมีการกำหนดค่าที่สมบูรณ์ (`.env` กับ `CF_DB_DSN`) อยู่แล้ว โปรแกรมติดตั้งจะไม่เขียนทับการกำหนดค่านั้น และวิซาร์ดจะไม่ปรากฏขึ้นอีก
> การแก้ไข `.env` ด้วยตนเองในภายหลังจะมีผลหลังจากการรีสตาร์ท

#### ไดเร็กทอรีข้อมูล

```env
SAFE_PATHS=data                       # relative to the install directory
# SAFE_PATHS=/srv/corefusion-data     # or an absolute path
```

#### ฐานข้อมูล

ตรวจพบ `CF_DB_DSN` โดยคำนำหน้า:

| คำนำหน้า | ฐานข้อมูล |
|--------|----------|
| ไม่ได้ตั้งค่าหรือเส้นทางเปล่า | SQLite (ค่าเริ่มต้น) |
| `sqlite://` | SQLite (ชัดเจน) |
| `mysql://` | MySQL |
| `postgres://` / `postgresql://` | PostgreSQL |

`CF_DB_TYPE` เป็นทางเลือกและแทนที่การตรวจจับ (`sqlite` / `mysql` / `postgres`)

> **รหัสผ่านที่เข้ารหัส**: MySQL/PostgreSQL DSN ที่เขียนโดยแผงควบคุม (ตัวช่วยสร้างการตั้งค่า / สวิตช์ฐานข้อมูล)
> จะถูกเก็บไว้ใน `.env` เป็น `enc:...` (AES-256-GCM, คีย์ `CF_SECRET_ENCRYPTION_KEY`)
> พวกเขาจะถูกถอดรหัสเมื่ออ่าน DSN แบบข้อความธรรมดาที่เขียนด้วยมือยังคงใช้งานได้

**SQLite (ค่าเริ่มต้น)**

```env
# Bare path (detected as SQLite)
CF_DB_DSN=data/sqlite/app.db

# Or explicit sqlite:// prefix
CF_DB_DSN=sqlite:///opt/corefusion/data/sqlite/app.db
```

**MySQL**

```env
# Format: mysql://user:password@tcp(host:port)/dbname?params
CF_DB_DSN=mysql://corefusion:password@tcp(127.0.0.1:3306)/corefusion?charset=utf8mb4&parseTime=True&loc=Local
```

**PostgreSQL**

```env
# Format: postgres://user:password@host:port/dbname?params
CF_DB_DSN=postgres://corefusion:password@127.0.0.1:5432/corefusion?sslmode=disable
```

#### พูลการเชื่อมต่อ (อุปกรณ์เสริม MySQL/PostgreSQL)

```env
CF_DB_MAX_OPEN_CONNS=100
CF_DB_MAX_IDLE_CONNS=10
```

#### ตัวแปรทั่วไปอื่นๆ

| ตัวแปร | คำอธิบาย |
|----------|-------------|
| `JWT_SECRET` | คีย์การลงนามสำหรับโทเค็นการเข้าสู่ระบบ สร้างขึ้นเมื่อเริ่มต้นครั้งแรกเมื่อหายไป |
| `CF_SECRET_ENCRYPTION_KEY` | รหัสสำหรับการเข้ารหัสการตั้งค่าที่ละเอียดอ่อน (AES-256-GCM) สร้างขึ้นเมื่อขาดหายไป |
| `CF_INITIAL_ADMIN_PASSWORD` | รหัสผ่านผู้ดูแลระบบเริ่มต้น (ไม่จำเป็น; สุ่มและพิมพ์ครั้งเดียวตามค่าเริ่มต้น) |
| `CF_NETWORK_TRAFFIC_ACCOUNTING` | ตั้งค่าเป็น `0` เพื่อปิดใช้งานบัญชีการรับส่งข้อมูลตาม iptables (เปิดใช้งานตามค่าเริ่มต้น) |
| `CF_NETWORK_TRAFFIC_TABLE` | ตาราง iptables ที่ใช้สำหรับการบัญชีปริมาณข้อมูล ค่าเริ่มต้น `corefusion` |

> **คีย์การเข้ารหัสอยู่ใน `.env.secret`**: เมื่อเริ่มครั้งแรก `CF_SECRET_ENCRYPTION_KEY` จะถูกเขียนไปยัง `.env.secret` (0600, ไดเร็กทอรีเดียวกันกับ `.env`) แทนที่จะเป็น `.env`; คีย์เดิมใน `.env` จะถูกย้ายโดยอัตโนมัติ สำรองไฟล์นี้แยกกัน การสูญเสียไฟล์จะทำให้ค่า `enc:` ทุกค่าไม่สามารถเข้ารหัสได้

> Reverse Proxies ที่เชื่อถือได้สำหรับการแก้ไข IP ไคลเอ็นต์จริงจะไม่ได้รับการกำหนดค่าผ่านตัวแปรสภาพแวดล้อมอีกต่อไป
> โดยจะถูกจัดเก็บเป็น `panel.trusted_proxies` ใน **การตั้งค่า → เครือข่าย**

> ทั้ง `.env` และ `.env.secret` ต่างก็เป็นความลับ แผงจะกระชับการอนุญาตของ `0600` เมื่อเริ่มต้น อย่ากระทำการเหล่านั้น

## 3. การกำหนดค่าเริ่มต้น

ในการเริ่มต้นครั้งแรก หาก `.env` ไม่มี `CF_DB_DSN` ที่ถูกต้อง แผงควบคุมจะ **ยังไม่** ให้บริการ UI ผู้ดูแลระบบ มันเริ่มต้น
**วิซาร์ดการตั้งค่า** บนพอร์ตสุ่มใน 18000–18999 ด้วยโทเค็นแบบครั้งเดียว จากนั้นรีสตาร์ทเหมือนแผงปกติเมื่อบันทึกแล้ว

### 3.1 เปิดตัวช่วยการตั้งค่า

1. คัดลอก “วิซาร์ดการตั้งค่า” URL จากเอาต์พุตของตัวติดตั้ง หรือ
2. อ่านบันทึกบนเซิร์ฟเวอร์:

```bash
journalctl -u corefusion -n 50 --no-pager | grep -A2 'setup wizard'
```

```text
CoreFusion first start - setup wizard
  URL   : http://<ip>:<port>/init?init_token=<token>
  Token : <token>
  Valid : 2h0m0s
```

3. เปิด URL ในเบราว์เซอร์ (มี `init_token` อยู่แล้ว ดังนั้นจึงไม่จำเป็นต้องป้อนข้อมูลด้วยตนเอง)

> เซสชันตัวช่วยสร้างจะหมดอายุหลังจาก **2 ชั่วโมง** ตามค่าเริ่มต้น หากหมดอายุหรือแผงรีสตาร์ท ให้ขอรับอันใหม่
> อย่าแชร์โทเค็น เมื่อการตั้งค่าเสร็จสิ้น พอร์ตนี้จะปิดและเหลือเพียงพอร์ตแผงปกติเท่านั้น

### 3.2 ขั้นตอนของวิซาร์ด

วิซาร์ดมี 8 ขั้นตอน คุณสามารถย้อนกลับได้ตลอดเวลา ไม่มีสิ่งใดเกิดขึ้นจนกว่าจะบันทึกครั้งสุดท้าย

| ขั้นตอน | เนื้อหา |
|------|---------|
| 1. ฐานข้อมูล | SQLite / MySQL / PostgreSQL |
| 2. ไดเร็กทอรีข้อมูล | เขียนถึง `SAFE_PATHS` ใน `.env` |
| 3. คีย์การเข้ารหัส | `JWT_SECRET` และ `CF_SECRET_ENCRYPTION_KEY` |
| 4. แกน | พร็อกซีคอร์ใดที่จะติดตั้ง |
| 5. หนังสือมอบฉันทะ | ไม่มี / Nginx / Caddy |
| 6. ไซต์และโดเมน | พอร์ต เส้นทางเว็บ บัญชีผู้ดูแลระบบ สกุลเงิน เขตเวลา โดเมน |
| 7. ใบรับรอง HTTPS | ปิดการใช้งาน / อัพโหลด / ACME |
| 8. สรุป | ตรวจสอบ ดาวน์โหลด `.env` บันทึกและรีสตาร์ท |

#### ขั้นตอนที่ 1: ฐานข้อมูล

- **SQLite (แนะนำให้ใช้ไฟล์ในเครื่อง)**: ปล่อยพาธว่างไว้เพื่อใช้ `<data-dir>/sqlite/app.db`
- **MySQL / PostgreSQL**: โฮสต์ พอร์ต ผู้ใช้ รหัสผ่าน ชื่อฐานข้อมูล PostgreSQL ยังรองรับ `disable` / `require` / `verify-full` อีกด้วย
- คลิก “ทดสอบการเชื่อมต่อ” เพื่อตรวจสอบ การบันทึกยังทดสอบด้วย ฐานข้อมูลที่ขาดหายไปจะถูกสร้างขึ้นโดยอัตโนมัติ (สร้างด้วยตนเองหากบัญชีไม่มี `CREATE`)
- DSN (รวมถึงรหัสผ่าน) จะถูกเข้ารหัสก่อนที่จะเขียนลงใน `.env`

#### ขั้นตอนที่ 2: ไดเรกทอรีข้อมูล

จัดเก็บฐานข้อมูล ใบรับรอง บันทึก ไบนารีหลัก และอื่นๆ นี่คือ `SAFE_PATHS` ใน `.env` ค่าเริ่มต้นคือ `data`
(สัมพันธ์กับไดเร็กทอรีการติดตั้ง); อนุญาตให้ใช้เส้นทางที่แน่นอนได้ **อย่าเปลี่ยนแบบลวกๆ ในภายหลัง** หรือแผง
จะไม่พบฐานข้อมูลและใบรับรองที่มีอยู่

#### ขั้นตอนที่ 3: คีย์การเข้ารหัส

- `JWT_SECRET`: ลงนามโทเค็นการเข้าสู่ระบบ
- `CF_SECRET_ENCRYPTION_KEY`: เข้ารหัสการตั้งค่าที่ละเอียดอ่อน (รหัสผ่านฐานข้อมูล ข้อมูลประจำตัว DNS บัตรเติมเงิน ฯลฯ)
- ทั้งสองถูกสร้างขึ้นแบบสุ่มโดยค่าเริ่มต้น ใช้ "สร้างใหม่" เพื่อรับค่าใหม่ **การเปลี่ยน `CF_SECRET_ENCRYPTION_KEY` ทำให้ข้อมูลที่เข้ารหัสก่อนหน้านี้ไม่สามารถอ่านได้** — สำรองข้อมูล

#### ขั้นตอนที่ 4: แกน

เลือกแกนพร็อกซีที่จะติดตั้ง:

- **Xray**: VLESS / VMess / Trojan / Shadowsocks ฯลฯ ;
- **sing-box**: รองรับ Hysteria2 / TUIC และโปรโตคอล QUIC อื่นๆ

หลังจากบันทึกและรีสตาร์ทแผงควบคุมให้ดาวน์โหลดและติดตั้งโดยอัตโนมัติ ตรวจสอบเวอร์ชันและสถานะภายใต้ “โปรโตคอล” คุณยังสามารถติดตั้งได้ในภายหลัง

#### ขั้นตอนที่ 5: หนังสือมอบฉันทะ

- **ไม่มี**: แผงควบคุมให้บริการลูกค้าโดยตรง (จัดการ TLS ด้วยตัวเอง)
- **Nginx / Caddy**: แผงควบคุมจัดการพร็อกซีย้อนกลับและการโฮสต์ใบรับรอง เลือกอันหนึ่ง

เมื่อเลือกพร็อกซี แผงมักจะฟังเฉพาะบน `127.0.0.1` และพร็อกซีให้บริการโลกภายนอก

#### ขั้นตอนที่ 6: ไซต์และโดเมน

| สนาม | คำอธิบาย |
|-------|-------------|
| ที่อยู่ฟัง | ได้มาโดยอัตโนมัติ: พรอกซี → `127.0.0.1`; ไม่มีพร็อกซีที่มีใบรับรอง → `0.0.0.0`; มิฉะนั้น → `127.0.0.1` |
| พอร์ตแผง | พอร์ตสุ่มฟรีตามค่าเริ่มต้น เปลี่ยนถ้าคุณต้องการ (เช่น 8080) |
| พอร์ตการสมัครสมาชิก | ไม่จำเป็น; `0` ใช้พอร์ตแผงร่วมกัน |
| พอร์ตพอร์ทัล | ไม่จำเป็น; `0` ใช้พอร์ตแผงร่วมกัน |
| เส้นทางเว็บ | เส้นทาง UI ของผู้ดูแลระบบ ค่าเริ่มต้น `/`; API จะเป็น `/api/v1` เสมอ |
| ชื่อผู้ใช้ / รหัสผ่านของผู้ดูแลระบบ | สุ่มตามค่าเริ่มต้น **รหัสผ่านจะแสดงเพียงครั้งเดียวในการสรุป** — บันทึกไว้ |
| โหมดการเข้าถึง | “โดเมน” หรือ “ไอพี” |
| สกุลเงินเริ่มต้น / เขตเวลา | สกุลเงินเริ่มต้นสำหรับบัตรเติมเงินและยอดคงเหลือ เขตเวลาบันทึกพาเนลและพร็อกซี (เช่น `Asia/Shanghai`) |
| เพิ่มไปยังพร็อกซีย้อนกลับ | เมื่อตั้งค่าพร็อกซีและโดเมนแล้ว ให้เพิ่มโดเมนพาเนล / การสมัครสมาชิก / พอร์ทัลให้กับพร็อกซีในครั้งเดียว |

การป้อนโดเมนจะเขียนการตั้งค่าที่เกี่ยวข้อง (โดเมนติดต่อกลับ จุดสิ้นสุดการสมัครสมาชิก โดเมนที่ใช้ร่วมกัน)

#### ขั้นตอนที่ 7: ใบรับรอง HTTPS

| แหล่งที่มา | คำอธิบาย |
|--------|-------------|
| ปิดการใช้งาน HTTPS | แผง/พอร์ทัล/การสมัครสมาชิกให้บริการผ่าน HTTP (ไม่ปลอดภัย); ด้วย Reverse proxy คุณสามารถเพิ่ม TLS ในด้านพร็อกซีได้ในภายหลัง |
| อัปโหลดใบรับรอง | วางใบรับรอง PEM และคีย์ส่วนตัว PEM (โหมดการเข้าถึงโดเมนเท่านั้น) |
| ACME | ออกใบรับรองเมื่อคุณส่งขั้นตอนนี้ รองรับโดเมนและใบรับรอง IP |

ตัวเลือก ACME:

- **CA**: มาเข้ารหัสกันเถอะ มาเข้ารหัสกัน (Staging), ZeroSSL, Google Public CA;
- **เป้าหมาย**: โดเมนที่กำหนดค่าหรือ IP สาธารณะ (Let's Encrypt เท่านั้นรองรับใบรับรอง IP)
- **ความท้าทาย**: `HTTP-01` (ต้องใช้พอร์ต 80) หรือ `DNS-01` (ไวด์การ์ด ไม่มีพอร์ต 80 เลือกผู้ให้บริการ DNS และป้อนข้อมูลประจำตัว)
- **ประเภท/ขนาดกุญแจ**: ECC 256/384 หรือ RSA 2048/3072/4096;
- **Google Public CA**: ต้องใช้ EAB; ป้อนรหัสคีย์ / HMAC ด้วยตนเองหรือใช้บัญชีบริการ GCP

> ใบรับรอง IP จะตรวจหา IPv4/IPv6 สาธารณะของโฮสต์โดยอัตโนมัติ ด้านหลังพรอกซี ที่อยู่ที่ตรวจพบจะเป็นของโฮสต์ ไม่ใช่ขาออกของพร็อกซี
> ใบรับรองโดเมนสามารถออกได้ในภายหลังภายใต้ "ใบรับรอง"

#### ขั้นตอนที่ 8: สรุป

แสดงฐานข้อมูล ไดเร็กทอรีข้อมูล คอร์ พร็อกซี พอร์ต บัญชีผู้ดูแลระบบ โดเมน และคีย์ `.env` (ปกปิดความลับ) และจัดเตรียม:

- **ดาวน์โหลด .env**: เก็บสำเนาการกำหนดค่าไว้
- **URL การเข้าถึง**: URL สุดท้ายสำหรับแผง / การสมัครสมาชิก / พอร์ทัล; HTTP ถูกทำเครื่องหมายว่าไม่ปลอดภัย

คลิก “บันทึกและรีสตาร์ท” เพื่อเขียนฐานข้อมูลและ `.env`; แผงควบคุมจะรีสตาร์ทเข้าสู่บริการตามปกติ

### 3.3 หลังจากตั้งค่าแล้ว

- บริการจะรีสตาร์ทและบันทึกการเริ่มต้นจะพิมพ์ที่อยู่การฟังสุดท้าย
- ลงชื่อเข้าใช้ด้วยบัญชีผู้ดูแลระบบ เข้าถึง URL และเส้นทางเว็บจากสรุป
- หากรหัสผ่านสูญหาย ให้รีเซ็ตออฟไลน์ด้วย `./corefusion admin reset-password`

### 3.4 การตั้งค่า CLI แบบไม่โต้ตอบ

สำหรับเซิร์ฟเวอร์อัตโนมัติหรือเซิร์ฟเวอร์ headless ให้เขียนการกำหนดค่าและทำเครื่องหมายว่าการตั้งค่าเสร็จสมบูรณ์โดยตรง:

```bash
cd /opt/corefusion
./corefusion init \
  --db-type sqlite \
  --data-dir /opt/corefusion/data \
  --admin-username admin \
  --admin-password 'change-me-strong-password' \
  --listen-port 8080 \
  --proxy-type caddy \
  --cores xray,singbox \
  --panel-domain panel.example.com \
  --tls-mode acme --tls-domain panel.example.com --tls-email you@example.com
```

ธงทั่วไป:

| ธง | คำอธิบาย |
|------|-------------|
| `--db-type` / `--db-host` / `--db-port` / `--db-user` / `--db-password` / `--db-name` | การตั้งค่าฐานข้อมูล |
| `--data-dir` | ไดเร็กทอรีข้อมูล ค่าเริ่มต้นคือ `SAFE_PATHS` หรือ `./data` |
| `--listen-port` / `--subscription-port` / `--portal-port` / `--web-path` | พอร์ตและเส้นทางเว็บ (พอร์ตสุ่มฟรีตามค่าเริ่มต้น) |
| `--admin-username` / `--admin-password` | บัญชีผู้ดูแลระบบ (พิมพ์รหัสผ่านแบบสุ่มหนึ่งครั้งเมื่อละเว้น) |
| `--proxy-type` | `none` / `nginx` / `caddy` |
| `--cores` | แกนที่จะติดตั้ง คั่นด้วยเครื่องหมายจุลภาค: `xray,singbox` |
| `--panel-domain` / `--subscription-domain` / `--portal-domain` | โดเมน (เขียนลงในการตั้งค่าและเพิ่มลงในพร็อกซีย้อนกลับ) |
| `--tls-mode` | `none` / `self_signed` / `acme` |
| `--tls-domain` / `--tls-email` / `--tls-challenge` / `--tls-key-type` / `--tls-key-bits` | ตัวเลือกใบรับรอง (`--tls-challenge` มีค่าเริ่มต้นเป็น `http-01`; `dns-01` ต้องการ `--tls-dns-channel` หรือ `--tls-dns-provider`) |
| `--tls-ip-cert` | ออกใบรับรองสำหรับ IP สาธารณะที่ตรวจพบ (มาเข้ารหัสเท่านั้น) |
| `--acme-provider` | `lets_encrypt` / `lets_encrypt_staging` / `zerossl` / `google` |
| `--currency` / `--timezone` | สกุลเงินเริ่มต้น / เขตเวลา |

รายการทั้งหมด: `./corefusion init --help` จากนั้นเริ่มบริการ:

```bash
systemctl restart corefusion
```

### 3.5 เรียกใช้ตัวช่วยสร้างการตั้งค่าอีกครั้ง

หากต้องการเริ่มต้นใหม่ (ลบ `.env` และเครื่องหมายการตั้งค่า **เก็บข้อมูล**):

```bash
cd /opt/corefusion
./corefusion reset-init      # type RESET to confirm
systemctl restart corefusion
```

จากนั้นใช้ URL และโทเค็นใหม่จากบันทึกการเริ่มต้นระบบ

> การเริ่มต้นใหม่จะรีเซ็ตบัญชีผู้ดูแลระบบและเส้นทางเว็บ ข้อมูลธุรกิจในฐานข้อมูลเก่ายังคงอยู่ แต่คุณอาจต้องสร้างบัญชีเข้าสู่ระบบใหม่
>
> `reset-init` จะลบ `.env` ทั้งหมด (รวมถึง `SAFE_PATHS` ด้วย) **หากไดเร็กทอรีข้อมูลของคุณเป็นพาธสัมบูรณ์ที่กำหนดเอง** ให้กู้คืน `SAFE_PATHS` ก่อนที่จะรีสตาร์ท ไม่เช่นนั้นพาเนลจะดูใน `./data`:
>
> ```ทุบตี
> printf 'SAFE_PATHS=/srv/corefusion-data\n' > /opt/corefusion/.env
> ```

### 3.6 การรักษาความปลอดภัยหลังจากการลงชื่อเข้าใช้ครั้งแรก

#### เปลี่ยนรหัสผ่านเริ่มต้น

1. คลิกชื่อผู้ใช้ที่มุมขวาบน
2. เลือก "เปลี่ยนรหัสผ่าน";
3. ป้อนรหัสผ่านเก่าและใหม่
4. คลิก "บันทึก"

#### เปิดใช้งานการเข้าสู่ระบบด้วยรหัสแบบไดนามิก (2FA / TOTP)

> เมื่อเปิดใช้งานแล้ว บัญชีจะสลับไปที่ **การเข้าสู่ระบบด้วยรหัสแบบไดนามิก**: ระบบไม่ยอมรับรหัสผ่านแบบคงที่อีกต่อไป เท่านั้น
> รหัส 6 หลักจากแอปยืนยันตัวตนของคุณ (หรือรหัสกู้คืนแบบครั้งเดียว) ใช้งานได้ การ **แทนที่** รหัสผ่านเข้าสู่ระบบ — มันคือ
> ไม่ใช่ "รหัสผ่าน + รหัส" การยืนยันแบบสองขั้นตอน

1. คลิกชื่อผู้ใช้ที่มุมขวาบน
2. เลือก "เปิดใช้งาน 2FA";
3. ป้อนรหัสผ่านปัจจุบัน (เพื่อยืนยันการเปลี่ยนแปลงนี้เท่านั้น)
4. สแกนรหัส QR ด้วยแอปตรวจสอบความถูกต้อง (Google Authenticator / 1Password ฯลฯ ) หรือป้อนรหัสด้วยตนเอง
5. ป้อนรหัส 6 หลักเพื่อเปิดใช้งานให้เสร็จสิ้น
6. **บันทึกรหัสกู้คืนทันที** (ดาวน์โหลดได้) แต่ละรหัสใช้งานได้เพียงครั้งเดียว

ลงชื่อเข้าใช้ภายหลัง:

- หลังจากป้อนชื่อผู้ใช้ ช่องรหัสผ่านจะกลายเป็น “รหัส 6 หลัก / รหัสกู้คืน” และปุ่มจะกลายเป็น “ลงชื่อเข้าใช้ด้วยรหัส”
- ป้อนรหัสปัจจุบัน **รหัสผ่านแบบคงที่ไม่สามารถใช้งานได้อีกต่อไป**;
- รหัสการกู้คืนเป็นแบบใช้ครั้งเดียว สร้างใหม่ภายใต้ "การเข้าสู่ระบบรหัสแบบไดนามิก (2FA)" เมื่อหมด (ซึ่งจะทำให้รหัสเก่าทั้งหมดเป็นโมฆะ)

หากตัวตรวจสอบความถูกต้องสูญหายและรหัสกู้คืนหมด ให้ปิดการใช้งาน 2FA ออฟไลน์บนเซิร์ฟเวอร์:

```bash
cd /opt/corefusion
./corefusion admin 2fa reset -u admin    # disables 2FA, clears the secret and recovery codes, revokes all sessions
```

> ผู้ดูแลระบบขั้นสูงเพียงคนเดียวที่ไม่มีทั้งตัวตรวจสอบสิทธิ์หรือรหัสกู้คืนจะไม่สามารถกู้คืนผ่าน UI ของเว็บได้ และต้องใช้คำสั่งด้านบน

#### ลงทะเบียน Passkey (ทางเลือก)

1. คลิกชื่อผู้ใช้ที่มุมขวาบน
2. เลือก “การจัดการ Passkey”;
3. คลิก “ลงทะเบียน Passkey ใหม่”;
4. กรอกข้อความแจ้งอุปกรณ์

> **หมายเหตุ**: Passkeys ต้องใช้ HTTPS หรือ localhost และโดเมนจะต้องอยู่ในรายการที่อนุญาต

## 4. แดชบอร์ด

แดชบอร์ดแสดงภาพรวมคลัสเตอร์แบบหลายโหนดและสถานภาพของโหนด

### 4.1 สิ่งที่แสดงให้เห็น

- **ข้อมูลระบบ**: ชื่อโฮสต์, เวอร์ชันระบบปฏิบัติการ, สถานะการออนไลน์, CPU, หน่วยความจำ
- **การรับส่งข้อมูล**: แบนด์วิดท์แบบเรียลไทม์ การรับส่งข้อมูลทั้งหมด แนวโน้มรายเดือน
- **ความสมบูรณ์ของโหนด**: จำนวนออนไลน์ / ออฟไลน์ / ลดลง โหนดที่มีภาระงานสูง
- **การแจ้งเตือน**: โหนดออฟไลน์, โหนดลดระดับ, ใบรับรองจะหมดอายุเร็วๆ นี้, คำเตือนโควต้า
- **ทรัพยากรคลัสเตอร์**: CPU, หน่วยความจำ, ดิสก์ และปริมาณงานโดยเฉลี่ย

### 4.2 การดำเนินการ

- คลิก "ดูรายละเอียด" เพื่อเปิดหน้ารายละเอียดของโหนด
- คลิกการ์ดโหนดเพื่อดูสถานะปัจจุบัน
- ใช้ตัวกรองเพื่อจำกัดตามสถานะ ประเภท หรือภูมิภาค

## 5. การจัดการโหนด

การจัดการโหนดเป็นแกนหลักของ CoreFusion และรองรับโหนดหลายประเภท

### 5.1 ประเภทโหนด

| ประเภท | คำอธิบาย |
|------|-------------|
| แบบสแตนด์อโลน (`standalone`) | โหนดหลักที่เป็นอิสระ |
| กระจกมองข้าง (`mirror`) | ซิงค์การกำหนดค่าจากโหนดเป้าหมาย |
| หลัก/สำรอง (`primary_backup`) | โหนดพันธมิตรที่ล้มเหลวซึ่งกันและกัน |
| รายการโซ่ (`chain_entry`) | โหนดรายการของพร็อกซีที่ถูกลูกโซ่ |
| ทางออกโซ่ (`chain_exit`) | โหนดทางออกของพร็อกซีที่ถูกลูกโซ่ |

### 5.2 การเพิ่มโหนด

1. เปิด "การจัดการโหนด";
2. คลิก "เพิ่มเซิร์ฟเวอร์";
3. กรอกข้อมูลพื้นฐาน:
   - ชื่อ เช่น `HongKong-HK01`
   - ชื่อโฮสต์: IP หรือโดเมน
   - ภูมิภาค เช่น `HK`, `JP`, `US`
   - ประเภทโหนด
4. ตั้งค่าพอร์ตตัวแทน (ค่าเริ่มต้น `18443`)
5. เลือกคอร์ที่รองรับ
6. คลิก "บันทึก"

### 5.3 การปรับใช้เพียงคลิกเดียว

1. หลังจากเพิ่มโหนดแล้ว ให้เลือก “คำสั่งปรับใช้” ในรายการโหนด (หน้ารายละเอียดก็มีให้เช่นกัน
 “คำสั่งการติดตั้ง Bootstrap”);
2. คัดลอกคำสั่ง — ประกอบด้วยโทเค็นการลงทะเบียนแบบครั้งเดียว (ใช้ได้ 24 ชั่วโมง ห้ามใช้ซ้ำ)
3. รันเป็นรูทบนโหนดระยะไกล ดูเหมือนว่า:

   ```bash
   bash <(curl -fsSL "http://<panel-host>:<panel-port>/api/v1/agent/install?id=<node-id>&token=<one-time-token>&port=<panel-port>")
   ```

4. เอเจนต์จะดาวน์โหลดแพ็คเกจ ลงทะเบียนกับแผงควบคุมและเริ่มต้น

### 5.4 รายละเอียดโหนด

คลิกโหนดเพื่อเปิดหน้ารายละเอียด:

- **ภาพรวม**: ข้อมูลพื้นฐาน สถานะตัวแทน สถานะใบรับรอง การ์ดทรัพยากรแสดงการใช้งาน CPU / หน่วยความจำ / ดิสก์ อัตราการเพิ่ม/ลง NIC อัตราการรับส่งข้อมูลผู้ใช้หลัก การรับส่งข้อมูลที่ใช้รายเดือน การเชื่อมต่อ TCP โหลดระบบและการรับส่งข้อมูลสะสม NIC ทางออก (รีเฟรชแบบเงียบทุกๆ 10 วินาที)
- **ศูนย์โปรโตคอล**: การกำหนดค่ากระบวนการหลัก
- **พร็อกซี**: การกำหนดค่า Caddy / Nginx
- **กระบวนการหลัก**: เริ่ม / หยุด / รีสตาร์ท
- **ปริมาณการใช้งานหลัก**: ปริมาณการใช้งานของผู้ใช้ที่ส่งต่อโดยแกนหลักและยอดรวมรายเดือน
- **WARP**: การกำหนดค่า WARP
- **โดเมนโดยตรง**: การจัดการโดเมน
- **ขีดจำกัดอัตรา**: การกำหนดรูปแบบการรับส่งข้อมูล
- **ใบรับรอง**: การผูกใบรับรอง
- **ผู้ใช้ออนไลน์**: ผู้ใช้ออนไลน์แบบเรียลไทม์

### 5.5 การทำงานของโหนด

- **การกำหนดค่าการซิงค์**: พุชการกำหนดค่าพาเนลไปที่โหนด
- **บังคับเชื่อมต่อใหม่**: ยกเลิกการเชื่อมต่อตัวแทนและเชื่อมต่อใหม่
- **Update Agent**: พุชการอัปเดต Agent
- **เพิกถอนใบรับรอง**: เพิกถอนใบรับรองตัวแทนของโหนด

## 6. ศูนย์โปรโตคอล

ศูนย์โปรโตคอลจะกำหนดค่าพารามิเตอร์โปรโตคอลสำหรับกระบวนการหลัก

### 6.1 แกนประมวลผลที่รองรับ

| แกนกลาง | คำอธิบาย |
|------|-------------|
| Xray-คอร์ | VLESS / VMess / Trojan / Shadowsocks และอื่นๆ |
| sing-box | แพลตฟอร์มพร็อกซีสากลแบบแยกส่วนพร้อมรองรับ TUN ดำเนินการ Hysteria2 / TUIC และโปรโตคอล QUIC อื่น ๆ |

### 6.2 โมดูลการกำหนดค่า

โมดูลที่แตกต่างกันระหว่างสองคอร์; แผงแสดงชุดที่ตรงกับแกนที่เลือก:

**Xray-คอร์**

- **บันทึก**: บันทึกการเข้าถึง บันทึกข้อผิดพลาด โหมดเอาต์พุต
- **API**: ที่อยู่การฟัง gRPC API รายการบริการ
- **DNS**: เซิร์ฟเวอร์ DNS, กลยุทธ์การสืบค้น, โฮสต์แบบคงที่
- **การกำหนดเส้นทาง**: กฎการกำหนดเส้นทาง, การปรับสมดุลโหลด, การกำหนดเส้นทาง VLESS
- **ขาเข้า/ขาออก**: โปรโตคอล การขนส่ง TLS
- **การขนส่ง**: WebSocket, gRPC, XHTTP ฯลฯ (TUN เป็นโปรโตคอลขาเข้า ไม่ใช่การขนส่ง)
- **TLS**: ใบรับรอง, ALPN, ลายนิ้วมือ uTLS, ECH
- **Reality**: การจัดการเป้าหมาย, คู่คีย์, ID แบบสั้น
- **การตรวจสอบประสิทธิภาพ / FakeDNS / ตัวชี้วัด / นโยบาย / ข้อมูลทางภูมิศาสตร์ / การจำกัดเวอร์ชัน**: โพรบ, พูล IP, Prometheus, การหมดเวลาและบัฟเฟอร์, ไฟล์ทรัพยากร, ช่วงเวอร์ชันคอร์

**sing-box**

- **บันทึก**: ระดับ, เวลาประทับ, เอาต์พุต
- **NTP**: การซิงโครไนซ์เวลา
- **DNS**: เซิร์ฟเวอร์และกฎ DNS
- **การกำหนดเส้นทาง**: ขาออกเริ่มต้นของ `final`, **ชุดกฎ**, **กฎ**, ตัวแก้ไขโดเมนเริ่มต้น, กลยุทธ์เครือข่าย และทางเลือก (ดู 6.6)
- **ขาเข้า/ขาออก**: โปรโตคอล การขนส่ง TLS
- **จุดสิ้นสุด**: WireGuard (รวมถึงการกำหนดค่า WARP), ไคลเอนต์ MASQUE และที่คล้ายกัน หลายอย่างสามารถอยู่ร่วมกันได้และโดดเด่นด้วย `tag`

> เมื่อเปิดใช้งาน “ใช้การรวมเครือข่ายระบบ” **ชื่อ** ของอุปกรณ์ปลายทางคือชื่ออินเทอร์เฟซเคอร์เนล:
> สูงสุด 15 ตัวอักษร ตัวอักษร/ตัวเลข/`._-` เท่านั้น ชื่อที่ยาวเกินไปหรือไม่ถูกต้องจะย้อนกลับไปโดยอัตโนมัติ
> ไปยังจุดสิ้นสุด `tag` จุดสิ้นสุดใหม่จะมีคำนำหน้าต่อโปรโตคอล (`wg-` / `ts-` / `oc-` / `ovpn-c-` /
> `ovpn-s-` / `mq-c-` / `mq-s-`) และบันทึกแบบเดิม เช่น `WireGuard-xxxxxx` จะถูกแสดงให้เป็นมาตรฐาน
> ทันทีที่เปิดโปรแกรมแก้ไข
- **บริการ**: อาร์เรย์ sing-box `services` ระดับบนสุด เช่น `hysteria-realm`, DERP หรือ `resolved`
- **ใบรับรอง / ไคลเอนต์ HTTP / เนมสเปซเครือข่าย**: ส่วน JSON ที่คุณขยายเมื่อจำเป็นเท่านั้น
- **ทดลอง**: `clash_api` และที่คล้ายกัน **ไม่มีการเขียนสิ่งใดลงในการกำหนดค่าที่สร้างขึ้นเว้นแต่จะเปิดใช้งาน**

> sing-box 1.12 ลบฟิลด์การกำหนดเส้นทาง `geosite` / `geoip` ออก การกำหนดเส้นทางตามภูมิศาสตร์ตอนนี้ผ่านไปแล้ว
> `rule_set`. การรักษาฟิลด์เก่าจะทำให้คอร์ไม่สามารถถอดรหัสการกำหนดค่า (`unknown field`)

### 6.3 การกำหนดค่าขาเข้า

1. เลือกแกนหลักและโปรโตคอล
2. กรอกข้อมูลพื้นฐาน:
   - แท็ก
   - ฟังที่อยู่และพอร์ต
   - ประเภทโปรโตคอล
3. ตั้งค่าพารามิเตอร์โปรโตคอล (UUID, รหัสผ่าน ฯลฯ );
4. เลือกการขนส่ง (TCP, WebSocket, gRPC ฯลฯ )
5. กำหนดค่า TLS (ใบรับรอง, ALPN)
6. บันทึกและนำไปใช้กับแกนกลาง

> ขาเข้าใหม่ฟังบน `::` ตามค่าเริ่มต้น (สแต็กคู่บน Linux จัดการทั้ง IPv4 และ IPv6)
> เปลี่ยนเป็น `0.0.0.0` หรือที่อยู่เฉพาะเมื่อคุณต้องการจำกัดอินเทอร์เฟซเท่านั้น

โหมดพอร์ต "ใช้พอร์ตขาเข้า" ยังมี **สร้างกฎการอนุญาตไฟร์วอลล์โดยอัตโนมัติ**: การเปิดไฟล์
ตัวแก้ไขขาเข้าจะตรวจสอบไฟร์วอลล์ของโหนดก่อน และเมื่อตรวจพบไฟร์วอลล์ / ufw / nftables / iptables
คุณสามารถอนุญาตให้พอร์ตบันทึกตามโปรโตคอลการฟัง (TCP/UDP)

- การกระโดดพอร์ต hy2 / ฮิสทีเรียช่วยให้ทั้งพอร์ตการฟังและทุกช่วงพอร์ตไดนามิก (เช่น `20000-30000`) หลายช่วงคั่นด้วยเครื่องหมายจุลภาค
- ค่าเผื่อเป็นค่าคงที่: กฎที่ครอบคลุมที่มีอยู่ (ช่วงพอร์ต / มัลติพอร์ต) จะไม่ถูกสร้างขึ้นอีกครั้ง
- การเปลี่ยนพอร์ตจะเพิกถอนกฎเก่าก่อนที่จะอนุญาตกฎใหม่ การลบขาเข้า การปิดใช้งานการกระโดดพอร์ต หรือการเปลี่ยนไปใช้ Unix Socket / tun (ไม่มีพอร์ตการฟัง) จะเป็นการล้างข้อมูล
- เมื่อตรวจไม่พบไฟร์วอลล์ที่เปิดใช้งาน ระบบจะแสดงเฉพาะคำใบ้และไม่มีการเขียนกฎใดๆ

### 6.3.1 เส้นทางพร็อกซีย้อนกลับ (โดเมนการเข้าถึง → ด้านหน้า TLS → เส้นทางพร็อกซีย้อนกลับ)

เมื่อพาธการขนส่งของขาเข้าคือ `/` แต่ nginx / caddy ภายนอกจะเมาท์ไว้ใต้พาธย่อย
(เช่น `location /apps { proxy_pass http://127.0.0.1:8080/; }`) ไคลเอ็นต์จะต้องเชื่อมต่อกับ `/apps` หรือ
คำขอไม่เคยไปถึงตำแหน่งนั้น — การสมัครสมาชิกยังคงดาวน์โหลดอยู่ แต่โหนดไม่ได้เชื่อมต่อ
กรอก **เส้นทางพร็อกซีย้อนกลับ** ใต้ “โดเมนการเข้าถึง → ด้านหน้า TLS”:

- ป้อน `/apps` หรือ `/apps?ed=2560` (พร้อมข้อมูลเริ่มต้น) การสมัครสมาชิกและแชร์ลิงก์ **แทนที่** เส้นทางการขนส่งขาเข้าด้วย
- ใช้กับ ws, httpupgrade, xhttp และ h2/http; การขนส่งที่ไม่มีเส้นทาง (raw/tcp, kcp) จะถูกละเว้น
- ไม่ขึ้นกับตำแหน่งที่ TLS สิ้นสุด: พาธยังคงใช้เมื่อ Front TLS ปิดอยู่ (ตามแกน);
- gRPC ไม่มีแนวคิดคำนำหน้า URL (เส้นทางไคลเอ็นต์จะเป็น `/{serviceName}/…` เสมอ) ดังนั้นเส้นทางจึง **รวมเข้ากับชื่อบริการ**
(`/apps` + `svc` → `apps/svc`); พร็อกซีย้อนกลับต้องตัดคำนำหน้านั้นใน `grpc_pass`

### 6.6 การกำหนดเส้นทาง sing-box และชุดกฎ

ใน “Protocol center” → sing-box → “Routing” มีสองส่วน: **ชุดกฎ** ประกาศให้ใช้ซ้ำได้
ไฟล์กฎ และ **กฎ** จะตัดสินเงื่อนไขการจับคู่และขาออก กฎเกณฑ์มีการประเมินจาก
จากบนลงล่างและนัดแรกชนะ

#### 6.6.1 ชุดกฎ

| สนาม | คำอธิบาย |
|-------|-------------|
| แท็ก | ตัวระบุชุดกฎที่อ้างอิงโดยกฎ จะต้องไม่ซ้ำกัน |
| ประเภท | `local` อ่านไฟล์บนโหนด `remote` ให้คอร์ดาวน์โหลดบน `update_interval` |
| รูปแบบ | `binary` สำหรับ `.srs` (ค่าเริ่มต้น); `source` สำหรับรูปแบบต้นฉบับ `.json` |
| เส้นทาง | พาธ `local` สัมพันธ์กับไดเร็กทอรีข้อมูลโหนด ไฟล์ใน `data/rules/` ใช้ `rules/xxx.srs` |
| URL | ดาวน์โหลดที่อยู่สำหรับ `remote`; `download_detour` เลือกขาออกที่ใช้สำหรับการดาวน์โหลด (ปกติคือ `direct`) |

ชุดกฎท้องถิ่น (แนะนำ ดาวน์โหลดไฟล์ก่อนภายใต้ “ทรัพยากรบริการ → ไฟล์กฎ”):

```jsonc
"route": {
  "rule_set": [
    { "type": "local", "tag": "geosite-cn", "format": "binary", "path": "rules/geosite-cn.srs" },
    { "type": "local", "tag": "geoip-cn", "format": "binary", "path": "rules/geoip-cn.srs" }
  ]
}
```

> การดาวน์โหลดไฟล์บนแผงควบคุมไม่เพียงพอ: ต้องส่งชุดกฎ `local` ไปที่
> nodes (“Push to all nodes”) เพื่อให้ไฟล์มีอยู่ใน `data/rules/` ของโหนด; มิฉะนั้นแกนกลาง
> ไม่สามารถเริ่มต้นได้เนื่องจากไม่พบไฟล์

ชุดกฎระยะไกล (โหนดต้องสามารถเข้าถึง URL):

```jsonc
{ "type": "remote", "tag": "geosite-openai", "format": "binary",
  "url": "https://raw.githubusercontent.com/SagerNet/sing-geosite/rule-set/geosite-openai.srs",
  "download_detour": "direct", "update_interval": "1d" }
```

เมื่อคุณเลือกไฟล์ในเครื่อง แท็กจะมาจากชื่อไฟล์ (`rules/geosite-cn.srs` →
`geosite-cn`); สำหรับชุดรีโมทจะมาจากส่วนท้ายของ URL รูปแบบก็กรอกมาจาก
ส่วนขยาย (`.srs` → `binary`, `.json` → `source`) ค่าที่ได้มาสามารถแก้ไขได้อย่างอิสระและ
ค่าที่คุณพิมพ์ไปแล้วจะไม่ถูกเขียนทับ

> `download_detour` เลิกใช้แล้วตั้งแต่ sing-box 1.14 และจะถูกลบออกใน 1.16; มันยังคงอยู่
> ทำงานใน 1.15 การกำหนดค่าใหม่ควรใช้ `http_clients` ระดับบนสุดด้วย
> `route.default_http_client` แทน

#### 6.6.2 กฎเกณฑ์

| สนาม | ไม้ขีด |
|-------|---------|
| `domain` | โดเมนที่แน่นอน |
| `domain_suffix` | ส่วนต่อท้ายโดเมน รวมถึงโดเมนย่อย |
| `domain_keyword` | การจับคู่สตริงย่อย |
| `domain_regex` | การแสดงออกปกติ |
| `ip_cidr` / `ip_is_private` | IP ปลายทาง |
| `source_ip_cidr` | IP ต้นทาง |
| `port` / `port_range` | พอร์ตปลายทาง |
| `network` | `tcp` / `udp` |
| `rule_set` | แท็กของชุดกฎที่จะใช้ |
| `outbound` | แท็กขาออกที่จะใช้ (ต้องมีอยู่ภายใต้ "ขาออก" หรือ "ปลายทาง") |
| `type: "logical"` | เงื่อนไขรวมที่ตั้งค่า `mode` เป็น `and` / `or` |

หลายช่องในกฎเดียวจะรวมกับ AND (เช่น `network` + `port`) ดังนั้นจึงไม่มี
จำเป็นต้องใช้เครื่องห่อ `logical` ใช้ `type: "logical"` สำหรับการผสม OR / NOT เท่านั้น `rule_set`
จะต้องวางไว้ภายในกฎย่อย `rules` ไม่ใช่ถัดจาก `rules`:

```jsonc
"rules": [
  { "domain_suffix": ["gstatic.com", "googleapis.com"], "outbound": "direct" },
  { "domain_keyword": ["ip.sb", "yandex.com"], "outbound": "warp" },
  { "rule_set": ["geosite-openai", "geosite-google"], "outbound": "warp" },
  { "rule_set": ["geoip-cn"], "outbound": "warp" },
  { "network": "tcp", "port": 443,
    "rule_set": ["geosite-google"], "outbound": "warp" },
  { "type": "logical", "mode": "or",
    "rules": [
      { "rule_set": ["geosite-google"] },
      { "rule_set": ["geosite-openai"] }
    ],
    "outbound": "warp" }
]
```

#### 6.6.3 การโอนย้ายกฎ xray

| xray | sing-box |
|------|----------|
| สตริงเปล่า (รวมถึงค่าเปล่าใน `domain`; การจับคู่สตริงย่อย) | `"domain_keyword": ["ip.sb"]` |
| `"domain": ["a.com"]` | `"domain_keyword": ["a.com"]`; ใช้ `"domain_suffix": ["a.com"]` สำหรับการจับคู่ส่วนต่อท้ายจริง หรือใช้ `"domain": ["a.com"]` สำหรับการจับคู่แบบตรงทั้งหมด |
| `"domain:clstorage.net"` | `"domain_suffix": ["clstorage.net"]` |
| `"full:a.com"` | `"domain": ["a.com"]` |
| `"regexp:..."` | `"domain_regex": ["..."]` |
| `"ip": ["geoip:cn"]` | `"rule_set": ["geoip-cn"]` |
| `"domain": ["geosite:cn"]` | `"rule_set": ["geosite-cn"]` |
| `"outboundTag": "direct"` | `"outbound": "direct"` |

หมายเหตุ:

- **แท็กจะไม่แชร์ระหว่างคอร์**: แท็กขาออก xray ไม่สามารถใช้ในกฎ sing-box;
 ใช้แท็กที่มีอยู่จริงภายใต้ sing-box “Outbounds” หรือ “Endpoints”
- แท็กขาออกหรือจุดสิ้นสุดที่ไม่ถูกต้องรายงาน `outbound not found`; รายงานแท็กชุดกฎที่ไม่ถูกต้อง
 `rule-set not found`.
- ใส่กฎโดยตรง / รายการที่อนุญาตก่อน เมื่อกฎตรงกัน กฎในภายหลังจะไม่ใช้อีกต่อไป

## 7. การจัดการพร็อกซี

การจัดการพร็อกซีกำหนดค่าพร็อกซีย้อนกลับ Caddy หรือ Nginx

### 7.1 ประเภทพร็อกซี

- **Caddy**: อัตโนมัติ HTTPS, HTTP/1.1 และ HTTP/2 (HTTP/3 / QUIC ถูกปิดใช้งานเพื่อหลีกเลี่ยงความขัดแย้งของ UDP 443 กับการกำหนดเส้นทางเลเยอร์ 4)
- **Nginx**: ประสิทธิภาพสูง การกำหนดค่าที่ยืดหยุ่น

### 7.2 การกำหนดค่าไซต์

1. เปิด "การจัดการพร็อกซี";
2. เลือกประเภทพร็อกซี (Caddy / Nginx)
3. เพิ่มไซต์:
   - โดเมน
   - ต้นน้ำ
   - ท่าเรือท้องถิ่น
4. บันทึก

### 7.3 สนาม

- **อัปสตรีม**: ที่อยู่แบ็กเอนด์ เช่น `127.0.0.1:8082`
- **local_port**: พอร์ตการฟังในเครื่อง เช่น `8443`
- **portal_forward**: กฎการส่งต่อพอร์ทัล
- **subscription_forward**: กฎการส่งต่อการสมัครรับข้อมูล
- **การกำหนดเส้นทาง SNI**: เมื่อขาเข้าใช้ TLS / REALITY และไคลเอนต์เชื่อมต่อที่ 443 เสมอ แผงควบคุมจะได้รับ
 443 กฎการกำหนดเส้นทาง TCP จาก ClientHello SNI (ทั้ง xray `streamSettings` และ sing-box `tls.reality`);
 พร็อกซีด้านหน้าส่งต่อเฉพาะ TCP และ TLS ยังคงสิ้นสุดภายในคอร์

## 8. ทรัพยากรการกำหนดเส้นทาง

ทรัพยากรการกำหนดเส้นทางรวบรวมเนื้อหาที่ใช้ร่วมกันที่ใช้โดยการสมัครรับข้อมูลและการกำหนดเส้นทาง หน้านี้ประกอบด้วยห้าแท็บ:

| แท็บ | วัตถุประสงค์ |
|-----|---------|
| โดเมนที่ต้องการโดยตรงและ CF | โดเมนตรงทางเข้า / IP และโดเมนที่ต้องการ Cloudflare ใช้เมื่อเขียนที่อยู่การเข้าถึงใหม่ในการสมัครสมาชิกและโหนดภายนอก |
| CF IP พูล | แหล่ง IP พอร์ต และการตั้งค่าโพรบที่ต้องการ ใช้โดย "โดเมนการเข้าถึง" |
| กฎสากล WAF | แหล่งที่มาของกฎและไฟล์กฎสำหรับ Reverse-proxy WAF ถูกพุชไปที่โหนด |
| ไฟล์กฎ | ดาวน์โหลด ตั้งเวลาซิงค์และพุชไฟล์กฎ (`.srs` / `.json` / `.dat`) |
| โหนดภายนอก | นำเข้าโหนดภายนอกจาก v2ray URI / Base64 / การสมัครสมาชิก URL (ดู 16.3) |

### 8.1 โดเมนที่ต้องการ Direct และ CF

- **การเข้าถึงโดยตรง**: โดเมนขาเข้าหรือ IP, พอร์ต 443 เป็นค่าเริ่มต้น ผูกโหนดหรือเว้นว่างไว้สำหรับโกลบอล
- **โดเมนที่ต้องการ CF**: โดเมนที่ต้องการ Cloudflare พร้อมพอร์ต พร้อมด้วยการตรวจสอบการเชื่อมต่อ
- ทั้งสองฟีดผู้สมัคร "โดเมนการเข้าถึง" ที่ใช้โดยการสมัครสมาชิกและการเขียนโหนดภายนอกใหม่ (ดู 16.3)

### 8.2 CF IP พูล

- รักษาแหล่ง IP ที่ต้องการ (รวมถึงแหล่งที่มาสไตล์ `bestproxy`) ช่วงเวลาการดึงข้อมูลและพอร์ต
- “การตั้งค่าโพรบ” ควบคุมช่วงเวลาโพรบ เกณฑ์แฝง และโหนดรายการโพรบ การตรวจสอบในท้องถิ่น
 กรองเฉพาะ IP ที่ไม่สามารถเข้าถึงได้อย่างชัดเจน ในขณะที่การเลือกโหนดรายการจะจำลองบรรทัดของโหนดนั้น
- “ตัวเรียกเลขหมาย” อาจเป็นแบบอัตโนมัติ (แกนที่ติดตั้ง), `singbox`, `xray` หรือ `mihomo`; แกนที่ไม่ใช่
 การติดตั้งไม่อยู่ในรายการ การตรวจสอบทำงานเป็นกระบวนการชั่วคราวที่จะออกเมื่อเสร็จสิ้นและไม่เคยอ่านหรือ
 เขียนการกำหนดค่าของคอร์เอง
- เมื่อ “โดเมนการเข้าถึง” ใช้ CF IP Pool โดยไม่มีค่าที่เป็นรูปธรรม จะมีหนึ่งรายการ (พร้อมพอร์ต)
 เลือกโดยการสุ่ม

### 8.3 กฎสากล WAF

- กำหนดค่าแหล่งที่มาของกฎ WAF URL และไฟล์กฎที่จะซิงค์
- หลังจากการซิงค์จะถูกส่งไปยังโหนดและโหลดโดยพร็อกซีโหนด (Nginx / Caddy)
- ไฟล์ที่มี URL แบบเต็มจะถูกดาวน์โหลดจาก URL นั้น มิฉะนั้นจะใช้ "แหล่งที่มา URL + /ชื่อไฟล์"
- “จับคู่แคช” (`match_cache` / `config_match_cache`) ถูกเปิดใช้งานโดยค่าเริ่มต้น: ขอบเขตทั่วทั้งกระบวนการ
 แคชของผลลัพธ์การจับคู่กฎยอดนิยมช่วยลดการข้ามผ่านกฎตามคำขอ มันเป็นเพียงระดับโลกเท่านั้นโดยไม่มี
 การแทนที่ต่อโดเมน ปิดใช้งานชั่วคราวสำหรับการเปรียบเทียบ A/B เมื่อตรวจสอบผลบวกลวง
 (การปิดใช้งานหมายถึงการประเมินกฎทั้งหมดในทุกคำขอและการใช้งาน CPU ที่สูงขึ้น)

### 8.4 ไฟล์กฎ (ไฟล์กฎการกำหนดเส้นทาง)

แท็บนี้จะดาวน์โหลดเฉพาะไฟล์กฎบนพาเนลและพุชไปที่โหนด ไม่มีอะไรมีผล
โดยอัตโนมัติ หากต้องการใช้ในการกำหนดเส้นทาง ให้อ้างอิงภายใต้ “Protocol center → sing-box → Routing”
ในชุดกฎและกฎ (ดู 6.6)

- **ที่เก็บกฎ**: ป้อน `owner/repo` (GitHub เรียกดูได้) หรือดาวน์โหลด URL ฉบับเต็ม กำหนดไว้
 การซิงค์สามารถทำงานได้ทุกๆ 6 / 12 ชั่วโมง ทุกวันเวลา 03:00 น. ทุกวันเวลาเที่ยงคืนหรือรายสัปดาห์ในวันอาทิตย์
- **เพิ่มไฟล์**: สำหรับไฟล์เดียวที่อยู่นอกรุ่นพื้นที่เก็บข้อมูล (เช่น สาขา SagerNet `.srs`
 ไฟล์); ป้อน URL แบบเต็มแล้วดาวน์โหลดโดยอัตโนมัติ
- **รายการไฟล์**: แสดงชื่อ ขนาด การอัปเดตครั้งล่าสุด และสวิตช์ “ซิงค์อัตโนมัติ” พร้อมด้วย “ดาวน์โหลด” ต่อไฟล์
 ปุ่ม “พุชไปยังโหนดทั้งหมด” ที่ด้านบนจะผลักไฟล์กฎทุกไฟล์ไปยังโหนดทั้งหมด
- ไฟล์จะถูกดาวน์โหลดลงใน `data/rules/` ของแผงควบคุม และเมื่อพุชแล้ว จะอยู่ใต้ข้อมูลโหนด
 `rules/` ของไดเร็กทอรี; อ้างอิงใน sing-box เป็น `rules/<file name>`;
- รูปแบบ:
  - `.srs`: ชุดกฎไบนารี sing-box แนะนำและเล็กที่สุด
  - `.json`: ชุดกฎรูปแบบแหล่งที่มา; `rule_set` ต้องตั้งค่า `format: "source"`;
  - `.dat`: xray `geosite.dat` / `geoip.dat` ซึ่ง sing-box ไม่สามารถใช้งานได้โดยตรง

> บล็อก "การใช้งาน" ที่ยุบได้ที่ด้านบนของหน้าประกอบด้วยตัวอย่างอ้างอิง การแมป xray
> ตารางและข้อผิดพลาดทั่วไป

### 8.5 โหนดภายนอก

การนำเข้าและการจัดการโหนดภายนอกครอบคลุมอยู่ใน [16.3 โหนดภายนอก](#163-external-nodes)

## 9. ศูนย์สมัครสมาชิก

ศูนย์สมัครสมาชิกจะจัดแพ็คเกจโหนดเป็นการสมัครสมาชิกที่พร้อมสำหรับไคลเอนต์: กำหนดการสมัครสมาชิก **รูปแบบ** (สิ่งที่จะปล่อย กฎข้อใด ซึ่งแผนสามารถดูได้) จากนั้นสมัครสมาชิก **จุดสิ้นสุด** (โดเมนสาธารณะ / เส้นทาง) จากนั้นแจกลิงก์

### 9.1 รูปแบบการสมัครสมาชิก

“ศูนย์สมัครสมาชิก” → “รูปแบบการสมัครสมาชิก”; หนึ่งแถวต่อเอาต์พุตไคลเอนต์:

| สนาม | คำอธิบาย |
|---|---|
| ชื่อ | ไม่ซ้ำใคร; `?config=<name>` ตรงกัน และกล่องโต้ตอบของลูกค้าจะแสดง |
| ประเภทลูกค้า | clash / shadowrocket / singbox / v2ray — การจัดกลุ่มการแสดงผลเท่านั้น |
| รูปแบบเอาต์พุต | `mihomo_yaml` (Clash/Mihomo), `singbox_json`, `xray_json`, `base64_uri`, `raw_uri` |
| ประเภทเนื้อหา / ส่วนขยาย | ส่วนหัวการตอบกลับและชื่อไฟล์ |
| แพลตฟอร์ม | ชนะ / mac / android / ios / สากล; จับคู่โดย `?platform=` ว่างเปล่า = สากล |
| แผนผูกพัน | ว่างเปล่า = ใช้ได้กับทุกแผน มิฉะนั้นเฉพาะแผนเหล่านั้นเท่านั้นที่สามารถใช้งานได้ |
| กฎเกณฑ์ | กฎการกำหนดเส้นทางต่อรูปแบบ (ตัวแก้ไขแบบมีโครงสร้างสำหรับ Mihomo, JSON แบบดิบต่อกฎสำหรับ sing-box / Xray) **กฎจะไม่ถูกแปลงระหว่างรูปแบบ** |

หมายเหตุ:

- อาจมีการกำหนดค่าหลายอย่างสำหรับรูปแบบเอาต์พุตเดียวกัน (เช่น `out`, `home`) เลือกอันที่มี `config=` ในลิงค์
- หากไม่มี `config` ลำดับคือ “config เชื่อมโยงกับการสมัครสมาชิก → การจับคู่ `platform` → ค่าเริ่มต้น”;
- เทมเพลต sing-box อาจมี `route.rule_set` ของตัวเองสำหรับไคลเอนต์ โดยปกติจะเป็น `remote` ดังนั้น
 ลูกค้าดาวน์โหลด; ไฟล์ในเครื่องที่พุชไปยัง `rules/` ของโหนดภายใต้ "ไฟล์กฎ" จะพร้อมใช้งานเท่านั้น
 ไปยังแกนหลักบนโหนดนั้น ไม่ใช่ไปยังการสมัครสมาชิกไคลเอนต์
- เมื่อสร้างเทมเพลต sing-box / Xray แผงจะลบการอ้างอิงที่ห้อยอยู่ (`final`, `dns.final`,
 `default_domain_resolver`, `download_detour`, `rule_set` ในเครื่อง, คำจำกัดความ `rule_set` ไม่ถูกต้อง, ว่างเปล่า
 `balancer` ฯลฯ) เพื่อให้ไคลเอ็นต์ไม่ล้มเหลวเมื่อเริ่มต้นระบบโดยมีข้อผิดพลาด FATAL
- นามแฝงขาออกในกฎได้รับการแก้ไขโดยเทียบกับแท็กจริง (`REJECT` / `blocked` → `block`, `DIRECT` →
 `direct` ไม่คำนึงถึงขนาดตัวพิมพ์); ขาออกที่ไม่สามารถแก้ไขได้จะกลับไปเป็นขาออกเริ่มต้นและกฎ
 รักษาตำแหน่งไว้
- กลุ่มที่มี `tag = proxy` จะถูกสร้างขึ้นเสมอ: `selector` สำหรับ sing-box และบาลานเซอร์ `random` สำหรับ
 Xray และ `outbound: proxy` ในกฎจะถูกเขียนใหม่เป็น `balancerTag` ที่ตรงกัน ตัวแก้ไขกฎกำลังโหลด
 ผู้สมัครขาออกแบบไดนามิกจาก "กลุ่มพร็อกซี + ขาออกที่กำหนดเอง" และแท็กที่ป้อนด้วยตนเองคือ
 ยังคงได้รับการตรวจสอบ;
- ต้องสร้างการกำหนดค่า sing-box / Xray แยกต่างหาก หากไม่มีอยู่ ก็จะไม่ปรากฏในลิงก์ของลูกค้า (ดู 10.3)

### 9.2 จุดสิ้นสุดการสมัครสมาชิก

“ศูนย์สมัครสมาชิก” → “จุดสิ้นสุดการสมัครสมาชิก”; หนึ่งแถวต่อที่อยู่สาธารณะ:

| สนาม | คำอธิบาย |
|---|---|
| โดเมน | โดเมนการสมัครสมาชิกสาธารณะ |
| เส้นทาง | คำนำหน้าภายใต้โดเมน ค่าเริ่มต้น `/` |
| เปิดใช้งานแล้ว | จุดสิ้นสุดที่ถูกปิดใช้งานจะถูกละเว้นเมื่อสร้างลิงก์ |
| คำอธิบาย | หมายเหตุข้อความอิสระ |

- **รองรับหลายแถว (หลายโดเมน)** เมื่อเปิดใช้งานหลายรายการ โดเมนของผู้ให้บริการจะติดตามโดเมนที่ใช้โดยคำขอปัจจุบัน (ดู 9.4)
- พอร์ตการสมัครสมาชิกเฉพาะให้บริการที่รูท (`/<token>` ไม่ใช่ `/sub`) เมื่อแชร์พอร์ตพาเนลจะเป็น `/sub/<token>`;
- พร็อกซีย้อนกลับจะต้องส่งต่อ `X-Forwarded-Proto` / `X-Forwarded-Host` มิฉะนั้นจะใช้จุดสิ้นสุดที่เปิดใช้งานครั้งแรก เทมเพลตไซต์ Caddy / Nginx ที่สร้างขึ้นโดยแผงประกอบด้วยส่วนหัวทั้งสอง การกำหนดค่าพร็อกซีที่ดูแลรักษาด้วยมือจำเป็นต้องเพิ่มด้วยตนเอง

### 9.3 ลิงค์สมัครสมาชิก

รูปแบบฐาน: `https://<sub-domain>/<token>` (พอร์ตแผง: `https://<panel-domain>/sub/<token>`)

| พารามิเตอร์ | คำอธิบาย |
|---|---|
| `format` | รูปแบบเอาต์พุต; นามแฝง: `clash` → mihomo_yaml, `singbox`/`sing-box` → singbox_json, `xray` → xray_json, `raw` → raw_uri, `base64`/`v2ray` → base64_uri |
| `config` | ใช้รูปแบบการสมัครสมาชิกตามชื่อ ต้องตรงกับ `format` มิฉะนั้นจะถูกละเว้น |
| `platform` | จับคู่การกำหนดค่าตามแพลตฟอร์ม (เมื่อละเว้น `config`) |
| `providers` | `1` / `true`: โหมดผู้ให้บริการ Clash (`proxy-providers` + `use`); โหนดอินไลน์เริ่มต้น |

ตัวอย่าง:

```bash
# Clash dynamic subscription (config template + providers)
https://sub.example.com/<token>?format=clash&config=out&providers=1

# sing-box / Xray (only meaningful when such a config exists)
https://sub.example.com/<token>?format=singbox_json&config=sing-box-home
https://sub.example.com/<token>?format=xray_json&config=xray-home

# generic clients / plain text
https://sub.example.com/<token>?format=base64_uri
https://sub.example.com/<token>?format=raw_uri
```

### 9.4 โหมดหลายโดเมนและผู้ให้บริการ

ด้วย `providers=1` ทุกรายการ `proxy-providers` จะนำกลับไปยังจุดสิ้นสุดการสมัครสมาชิก การเลือกโดเมน:

1. **โดเมนที่คำขอนี้ใช้** (ค่าแรกของ `X-Forwarded-Host`, พอร์ตถูกตัดออก หรืออย่างอื่น `Host`) หากตรงกับจุดสิ้นสุดที่ **เปิดใช้งาน**
2. มิฉะนั้นปลายทางที่เปิดใช้งานด้วย **ID ต่ำสุด**;
3. พาธมาจากจุดสิ้นสุดนั้น: `https://<domain><path>/<token>?format=mihomo_proxies_yaml...`

ดังนั้นการเปลี่ยนโดเมนจึงไม่จำเป็นต้องเปลี่ยนแผง: ไคลเอนต์ที่ดึงข้อมูลผ่านโดเมนใหม่จะได้รับโดเมนใหม่ภายในผู้ให้บริการ และโดเมนเก่าที่เปิดใช้งานไว้จะไม่ฮาร์ดโค้ดอีกต่อไป หากไคลเอนต์แคชผู้ให้บริการเก่า URL ให้อัปเดตการสมัครสมาชิก (หรือล้างแคชของผู้ให้บริการ / รีสตาร์ทไคลเอนต์)

หมายเหตุเพิ่มเติม:

- `proxy-providers` ภายในรูปแบบที่ใช้ร่วมกัน (`config_json`) จะถูกละเว้น (หลีกเลี่ยงการรั่วไหลของแผนข้าม) ผู้ให้บริการมาจากกลุ่มโหนดแผนและแหล่งภายนอก
- เส้นทางแคชของผู้ให้บริการภายในและภายนอกมักจะมาจาก “ค่าเริ่มต้นของผู้ให้บริการภายใน → เทมเพลตเส้นทางแคช” (ค่าเริ่มต้น `./providers/{key}.yaml`) แหล่งข้อมูลภายนอกไม่สามารถตั้งค่าของตนเองได้
- ผู้ให้บริการที่สงวนไว้เดิม `subscription-nodes` จะไม่ถูกปล่อยออกมาอีกต่อไป: กลุ่มที่ใช้ "โหนดทั้งหมด" จะขยายไปยังผู้ให้บริการที่เป็นรูปธรรม หรือโหนดอินไลน์เมื่อแผนไม่มี

## 10. การจัดการลูกค้า

การจัดการลูกค้าจัดการผู้ใช้ปลายทาง

### 10.1 การเพิ่มลูกค้า

1. เปิด "การจัดการลูกค้า";
2. คลิก "เพิ่มลูกค้า";
3. กรอก:
   - อีเมล
   - รหัสผ่าน
   - แผน
   - โควต้าการจราจร
   - เวลาหมดอายุ
4. บันทึก.

### 10.2 การกระทำของลูกค้า

- **แก้ไข**: เปลี่ยนแปลงรายละเอียดลูกค้า
- **ระงับ**: ระงับบริการ
- **ดำเนินการต่อ**: กู้คืนลูกค้าที่ถูกระงับ
- **รีเซ็ตการรับส่งข้อมูล**: รีเซ็ตการรับส่งข้อมูลที่ใช้
- **รีเซ็ตรหัสผ่าน**: รีเซ็ตรหัสผ่านของลูกค้า
- **ต่ออายุ**: ขยายวันหมดอายุ
- **อัปเกรด/ดาวน์เกรด**: เปลี่ยนแผน
- **ลบ**: ลบลูกค้า

### 10.3 รายละเอียดการสมัครสมาชิก

การจัดการลูกค้า → คอลัมน์ “การสมัครสมาชิก” → “รายละเอียด” กล่องโต้ตอบจะแสดงลิงก์สำหรับทุกรูปแบบที่มีในแผนของลูกค้า:

- **Clash / Mihomo**: สองแถว — โหนดแบบอินไลน์และ `providers=1` (ผู้ให้บริการพร็อกซี) ทั้งสองแถวมี `config=<name>`;
- **Sing-box / Xray**: แสดงเฉพาะเมื่อมีการกำหนดค่าของรูปแบบนั้นและแผนมองเห็นได้เท่านั้น ลิงค์พกพา `config=<name>`;
- **Base64 URI / Raw URI**: แสดงเสมอ (ไม่มี `config`);
- แต่ละแถวจะมีปุ่มคัดลอกของตัวเอง การคลิกที่แถวจะเปลี่ยนโค้ด QR ด้านล่างเป็นรูปแบบนั้น

ดังนั้น ด้วยการกำหนดค่า Clash เท่านั้น กล่องโต้ตอบจะแสดง Clash + Base64 + Raw; ลิงก์ sing-box / Xray จะปรากฏหลังจากสร้างการกำหนดค่าแล้วเท่านั้น

กล่องโต้ตอบเดียวกันนี้ยังแสดงปริมาณการใช้งาน ประวัติการสั่งซื้อ และประวัติการทำธุรกรรมอีกด้วย

## 12. การจัดการการเติมเงิน

การจัดการการเติมเงินจัดการไซต์เติมเงิน คำสั่งซื้อ และบัตรเติมเงิน

> **บูรณาการการชำระเงิน**
>
> แผงนี้ **ไม่ได้ทำงานร่วมกับสถาบันการชำระเงินโดยตรง** (Alipay, WeChat Pay, Stripe, ธนาคาร ฯลฯ) โดยจะเชื่อมต่อกับ **แพลตฟอร์มการชำระเงินระดับกลาง** เท่านั้น ซึ่งจะทำงานร่วมกับสถาบันการชำระเงินที่เกี่ยวข้อง จัดการการทำสัญญา การรับเงิน และการชำระเงิน และรายงานผลการชำระเงินกลับมาผ่านการเรียกกลับ [charge API](api/charge-callback.md)
>
> แพลตฟอร์มการชำระเงินระดับกลาง **ไม่ได้เป็นส่วนหนึ่งของโครงการนี้ ผู้ปฏิบัติงานจะต้องพัฒนาเอง (หรือใช้ระบบของตนเอง)** เมื่อใช้งานแล้ว ให้ลงทะเบียนภายใต้ “ไซต์เติมเงิน” และทำการยืนยันโดเมนให้เสร็จสิ้นเพื่อใช้เป็นจุดเริ่มต้นในการเติมเงิน ไซต์เติมเงินที่นี่คือแพลตฟอร์มระดับกลาง ไม่ใช่สถาบันการชำระเงิน คุณสมบัติการชำระเงิน ค่าธรรมเนียม การชำระบัญชี และการปฏิบัติตามข้อกำหนดเป็นไปตามที่ผู้ดำเนินการ สถาบันการชำระเงิน และแพลตฟอร์มระดับกลางเป็นผู้ตกลงและเป็นผู้รับภาระ

### 12.1 ไซต์เติมเงิน

1. เปิด “การจัดการการเติมเงิน” → “ไซต์การเติมเงิน”;
2. เพิ่มไซต์:
   - ชื่อไซต์
   - วิธีการชำระเงินที่รองรับโดยแพลตฟอร์มระดับกลางนั้น (Alipay, WeChat, USDT, Stripe ฯลฯ ผ่านการบูรณาการกับสถาบันการชำระเงิน)
   - สกุลเงิน
   - อัตราแลกเปลี่ยน
3. บันทึก;
4. ตรวจสอบไซต์ (ไฟล์ HTTP หรือการตรวจสอบ DNS)

### 12.2 คำสั่งเติมเงิน

- ดูคำสั่งเติมเงินทั้งหมด
- กรองตามสถานะ (รอดำเนินการ, ชำระเงินแล้ว, ล้มเหลว, หมดอายุแล้ว, คืนเงินแล้ว)
- ดูรายละเอียดการสั่งซื้อ
- ปัญหาการคืนเงินของผู้ดูแลระบบ

### 12.3 บัตรเติมเงิน

1. เปิด "บัตรเติมเงิน";
2. เพิ่มการ์ด:
   - ประเภท (จำนวน แผน ส่วนเสริมการรับส่งข้อมูล)
   - มูลค่าที่ตราไว้ / แผน
   - เวลาหมดอายุ
3. หรือสร้างเป็นกลุ่ม:
   - จำนวน (สูงสุด 1,000)
   - คำนำหน้าหมายเลขบัตร
   - รูปแบบหมายเลขบัตร
4. ส่งออกเป็น CSV

### 12.4 การจัดการยอดคงเหลือ

- ดูยอดคงเหลือของลูกค้า
- ปรับยอดคงเหลือ (เพิ่ม/ลด/กำหนด)

- ดูประวัติการทำธุรกรรม

### 12.5 ตัวแทนจำหน่าย

- ถอนค่าคอมมิชชั่น

## 15. โควต้าการจราจร

โควต้าการรับส่งข้อมูลจะตรวจสอบปริมาณการใช้งานรายเดือนของแต่ละโหนด

### 15.1 รายการโควต้า

- ดูการตั้งค่าโควต้าสำหรับโหนดทั้งหมด
- แสดงขนาดโควต้า ปริมาณการใช้งาน และค่าเผื่อคงเหลือ
- แสดงเปอร์เซ็นต์การใช้งาน

### 15.2 การใช้งานวงจร

- ดูรายละเอียดการใช้งานวงจรต่อโหนด
- แสดงปริมาณข้อมูลขาเข้า/ขาออก

 สุ่มจากพูล (พร้อมพอร์ต) "direct / custom" ต้องใช้ค่าที่ชัดเจน ไม่เช่นนั้น

## 25. ส่วนขยายการดำเนินงาน

“ส่วนขยายการดำเนินงาน” (`/client-ext`) กำหนดค่าการตลาดอ้างอิง ค่าคอมมิชชั่น และการถอนเงิน
“เอกสารทางกฎหมาย” (`/legal-documents`) รักษาข้อตกลงฝั่งพอร์ทัล

### 25.1 การอ้างอิงและค่าคอมมิชชั่น

- **การกำหนดค่าเงินคืน**: อัตราเงินคืน (เปอร์เซ็นต์ของการชำระเงินครั้งแรกของผู้ได้รับเชิญ `0` = ปิดการใช้งาน), โหมดคอมมิชชั่น (การซื้อครั้งแรกเท่านั้น / การซื้อทั้งหมด), จำนวนถอนขั้นต่ำ (ยอดคอมมิชชั่นจะต้องถึงก่อนจึงจะสามารถขอถอนได้)
- **รหัสเชิญ**: เมื่อเปิดใช้งาน การลงทะเบียนต้องใช้รหัสเชิญ กำหนดความยาวโค้ด วันหมดอายุ และการใช้งานสูงสุด (`0` = ไม่จำกัด) และสร้าง/ดูรายการโค้ด
- **การตรวจสอบการถอนเงิน**: กรองตามรอดำเนินการ / อนุมัติ / ปฏิเสธ เพิ่มบันทึกการประมวลผลและบันทึกวิธีการจ่ายเงินและที่อยู่กระเป๋าเงิน
- **บันทึกการอ้างอิง**: ผู้เชิญ ผู้ได้รับเชิญ จำนวนค่าคอมมิชชัน และสถานะค่าคอมมิชชัน

### 25.2 เอกสารทางกฎหมาย

- รักษา "นโยบายความเป็นส่วนตัว" และ "ข้อกำหนดในการให้บริการ" แยกกัน เอกสาร Markdown หนึ่งฉบับต่อสถานที่ พร้อมการแสดงตัวอย่างสด
- แต่ละเอกสารอาจใช้ URL ภายนอกแทนเพจในตัว เมื่อว่างเพจในตัว URL จะถูกใช้ (คัดลอกได้บนเพจ)
- พอร์ทัลแสดงเวอร์ชันสำหรับสถานที่ปัจจุบันและถอยกลับไปยังสถานที่เริ่มต้นเมื่อหายไป

## 26. คำถามที่พบบ่อย

### 26.1 แผงควบคุมไม่เริ่มทำงาน

- ตรวจสอบว่าพอร์ตมีการใช้งานอยู่แล้วหรือไม่
- ตรวจสอบว่า `.env` ถูกต้อง
- ตรวจสอบบันทึก: `journalctl -u corefusion -f`; ไม่มี systemd, `tail -f <install-dir>/data/logs/panel.log`

### 26.2 โหนดออฟไลน์

- ตรวจสอบว่า Agent กำลังทำงานอยู่: `systemctl status corefusion-agent`
- ตรวจสอบการเชื่อมต่อเครือข่าย
- ตรวจสอบกฎไฟร์วอลล์ (พอร์ต `18443`)

### 26.3 การออกใบรับรองล้มเหลว

- ตรวจสอบความละเอียด DNS
- ตรวจสอบว่าสามารถเข้าถึงพอร์ต 80 ได้
- ตรวจสอบการกำหนดค่าผู้ให้บริการ DNS
- ตรวจสอบบันทึกใบรับรอง

### 26.4 การสมัครสมาชิกไม่ทำงาน

- ตรวจสอบลิงค์สมัครสมาชิก
- ตรวจสอบว่าโหนดออนไลน์อยู่
- ตรวจสอบว่ากระบวนการหลักกำลังทำงานอยู่
- ตรวจสอบกฎไฟร์วอลล์

### 26.5 การเติมเงินโทรกลับล้มเหลว

- ตรวจสอบการโทรกลับ URL
- ตรวจสอบว่าคีย์ไซต์ตรงกัน
- ตรวจสอบรายการอนุญาต IP
- ตรวจสอบบันทึกการสั่งซื้อ

### 26.6 หน้าพอร์ทัลไม่สามารถเข้าถึงได้

- ตรวจสอบว่าพอร์ตพอร์ทัลเปิดอยู่
- ตรวจสอบการกำหนดค่าพาธพอร์ทัล
- **สำคัญ**: ตรวจสอบให้แน่ใจว่าพร็อกซีย้อนกลับส่งต่อโดเมนพอร์ทัลไปยัง **พอร์ตกลไกพอร์ทัล** ไม่ใช่พอร์ตแผงหลัก — การส่งต่อไปยังพอร์ตที่ไม่ถูกต้องจะแสดงหน้าว่างหรือแผงแทนพอร์ทัล ตรวจสอบ `upstream` / `local_port` ในบันทึกไซต์พร็อกซี
- เปิด `http://<portal-domain>:<portal-port>` โดยตรงเพื่อตรวจสอบพอร์ทัลเอ็นจิ้นเอง
- ตรวจสอบการกำหนดค่าพร็อกซีย้อนกลับ
- ตรวจสอบบันทึกของพอร์ทัล

| กำหนดโดยวิซาร์ดการตั้งค่า (พอร์ตสุ่มฟรีตามค่าเริ่มต้น) | แผงผู้ดูแลระบบ (เปลี่ยนแปลงได้) |
| 18443 | ตัวแทน gRPC (เปลี่ยนแปลงได้) |
| 0 (ปิดใช้งานโดยค่าเริ่มต้น) | พอร์ตเอ็นจิ้นการสมัครสมาชิกเฉพาะ (ว่างเปล่าหรือ `0` แชร์พอร์ตหลัก) |
| 0 (ปิดใช้งานโดยค่าเริ่มต้น) | พอร์ตเอ็นจิ้นพอร์ทัลเฉพาะ (ว่างเปล่าหรือ `0` แชร์พอร์ตหลัก) |
| 80/443 | พร็อกซีย้อนกลับ (Caddy / Nginx) HTTP / HTTPS |

### B. เส้นทางเริ่มต้น

| เส้นทาง | วัตถุประสงค์ |
|------|---------|
| `/` | แผงผู้ดูแลระบบ (พอร์ทัลยังอยู่ที่ `/` เมื่อไม่มีการกำหนดค่ากลไกพอร์ทัลเฉพาะ) |
| `/sub/:token` | การดึงข้อมูลการสมัครสมาชิก (เมื่อไม่มีการกำหนดค่าพอร์ตการสมัครสมาชิกเฉพาะ) |
| `/p` | พอร์ทัลเพจ (เมื่อไม่มีการกำหนดค่าพอร์ตพอร์ทัลเฉพาะ) |
| `/:token` | การดึงข้อมูลการสมัครสมาชิก (พร้อมพอร์ตการสมัครสมาชิกเฉพาะ โดยไม่มีคำนำหน้า `/sub`) |

### C. เครื่องมือบรรทัดคำสั่ง

ไบนารีพาเนลสนับสนุนคำสั่งย่อยเหล่านี้ (ไม่มีอาร์กิวเมนต์ที่สตาร์ทเซิร์ฟเวอร์):

```bash
# Start the panel (same as ./corefusion server)
./corefusion

# Run database migrations
./corefusion migrate

# Non-interactive init / reset init state (see 3.4, 3.5)
./corefusion init --help
./corefusion reset-init

# Offline administration (when you cannot sign in)
./corefusion admin reset-password -u admin -p 'new-password'
./corefusion admin 2fa reset -u admin
./corefusion admin list

# Version / help
./corefusion version
./corefusion help
```

> ด้วย systemd ให้ใช้ `systemctl restart corefusion` และ `journalctl -u corefusion -f` โดยไม่ต้อง
> systemd (คอนเทนเนอร์และสิ่งที่คล้ายกัน) หยุดกระบวนการเก่าและเริ่มต้นใหม่อีกครั้งด้วย `nohup` บันทึกคือ
> ใน `data/logs/panel.log`
