## v0.13.0-beta.98 — 2026-11-19

### 中文

- **仪表盘数据修正**：核心服务拆分为「运行中 / 停止 / 未上报」，远端节点未上报不再被当成「已停止」；节点数改用节点服务器口径；在线订阅人数跨节点去重；活跃订阅之外单独展示「暂停订阅」「过期订阅」，不再凭空消失。
- **桌面端国旗显示**：Windows 桌面浏览器不渲染国旗 emoji，登录页、侧边栏语言切换与「导入地区路由」按钮统一改用内置 PNG 国旗（`LangFlag` 组件），手机端与桌面端表现一致。
- **远程节点 sing-box 监控打通**：Agent 新增 gRPC 命令 `fetch_singbox_connections`，面板可读取远端节点的 `clash_api` 连接数据；节点详情直接展示后端返回的具体原因。
- **规则管理修复**：关闭定时开关的源不再被启动同步偷偷更新；已删除的规则文件不再在重启后复活（内置源改为一次性播种）；启动时只补「库里有记录但磁盘缺失」的文件。
- **大文件下载稳定性**：单文件下载超时 120 秒 → 20 分钟，失败自动重试 3 次（退避 2 秒 / 4 秒）；推送到节点失败重试 2 次，每次重新签发一次性票据。
- **下载接口不再被客户端取消打断**：改用 `context.WithoutCancel`，浏览器切换页面、网关超时后服务端仍继续下载并正确落库，不会卡在 `downloading` 或 `error`。
- **链路探测字节统计修复**：上行字节改为先计数再写 socket，避免快机器上「请求已发出、响应已收到」却统计成 `up=0`，把健康节点误判为不通（CI 上稳定复现）。

### English

- **Dashboard metrics fixed**: core services are now split into running / stopped / not-reported, so remote nodes that have not reported yet are no longer counted as stopped; node count uses node servers; online subscriber count is de-duplicated across nodes; suspended and expired subscriptions are shown next to active ones.
- **Flags on desktop**: Windows desktop browsers do not render flag emoji. The login page, the sidebar language switcher and the "Import region routes" buttons now use bundled PNG flags (`LangFlag`), consistent with mobile.
- **Remote sing-box monitoring**: a new Agent gRPC command `fetch_singbox_connections` lets the panel read `clash_api` connections from remote nodes; the node detail page shows the concrete reason returned by the backend.
- **Rule management fixes**: sources with the schedule switch off are no longer updated by startup sync; deleted rule files no longer come back after a restart (built-in sources are seeded only once); startup only restores files that exist in the database but are missing on disk.
- **Large file download reliability**: per-file timeout raised from 120s to 20 minutes with up to 3 attempts (2s / 4s backoff); pushing files to nodes retries twice, re-issuing a one-time ticket each time.
- **Download endpoint no longer aborted by the client**: it now uses `context.WithoutCancel`, so a page switch or gateway timeout no longer kills the download; the file is stored correctly instead of being stuck in `downloading` or `error`.
- **Chain probe byte counting fixed**: upload bytes are counted before the socket write, so fast machines no longer report `up=0` after a successful exchange and wrongly mark healthy nodes as unreachable (this reproduced reliably in CI).

### Русский

- **Исправлены метрики панели**: сервисы ядра разделены на «работает / остановлен / нет данных», поэтому удалённые узлы без отчёта больше не считаются остановленными; количество узлов считается по серверам узлов; число онлайн-подписчиков дедуплицируется между узлами; приостановленные и истёкшие подписки показываются отдельно от активных.
- **Флаги в десктопных браузерах**: Windows не отображает эмодзи-флаги. Страница входа, переключатель языка в боковом меню и кнопки «Импорт региональных маршрутов» теперь используют встроенные PNG-флаги (`LangFlag`), как на мобильных.
- **Мониторинг sing-box на удалённых узлах**: в Agent добавлена gRPC-команда `fetch_singbox_connections`, панель может читать данные подключений `clash_api` с удалённых узлов; страница узла показывает конкретную причину, возвращённую бэкендом.
- **Исправления управления правилами**: источники с выключенным расписанием больше не обновляются при старте; удалённые файлы правил не восстанавливаются после перезапуска (встроенные источники создаются только один раз); при старте восстанавливаются только файлы, которые есть в базе, но отсутствуют на диске.
- **Надёжность загрузки больших файлов**: таймаут одного файла увеличен со 120 секунд до 20 минут, до 3 попыток с паузой 2 / 4 секунды; отправка файлов на узлы повторяется дважды с перевыпуском одноразового тикета.
- **Загрузка больше не прерывается клиентом**: используется `context.WithoutCancel`, поэтому переход на другую страницу или таймаут шлюза не обрывает загрузку; файл сохраняется корректно и не зависает в состоянии `downloading` или `error`.
- **Исправлен подсчёт байт при проверке цепочки**: байты исходящего трафика учитываются до записи в сокет, поэтому на быстрых машинах успешный обмен больше не даёт `up=0` и здоровые узлы не считаются недоступными (в CI воспроизводилось стабильно).

### فارسی

- **اصلاح آمار داشبورد**: سرویس‌های هسته به «در حال اجرا / متوقف / بدون گزارش» تفکیک شدند، بنابراین نودهای راه‌دوری که هنوز گزارش نداده‌اند «متوقف» شمرده نمی‌شوند؛ تعداد نودها بر اساس سرورهای نود محاسبه می‌شود؛ تعداد مشترکان آنلاین بین نودها یکتا می‌شود؛ اشتراک‌های متوقف و منقضی در کنار اشتراک‌های فعال نمایش داده می‌شوند.
- **نمایش پرچم در دسکتاپ**: مرورگرهای ویندوز پرچم‌های اموجی را نمایش نمی‌دهند؛ صفحه ورود، تغییر زبان در نوار کناری و دکمه‌های «ورود مسیرهای منطقه‌ای» اکنون از تصاویر PNG داخلی (`LangFlag`) استفاده می‌کنند.
- **پایش sing-box روی نودهای راه‌دور**: فرمان gRPC جدید `fetch_singbox_connections` در Agent اضافه شد و پنل می‌تواند داده‌های اتصال `clash_api` نودهای راه‌دور را بخواند؛ صفحه جزئیات نود دلیل دقیق بازگشتی از بک‌اند را نشان می‌دهد.
- **اصلاح مدیریت قواعد**: منابعی که کلید زمان‌بندی آن‌ها خاموش است دیگر در همگام‌سازی آغازین به‌روزرسانی نمی‌شوند؛ فایل‌های حذف‌شده پس از راه‌اندازی مجدد بازنمی‌گردند (منابع داخلی فقط یک‌بار ایجاد می‌شوند)؛ در شروع فقط فایل‌هایی بازیابی می‌شوند که در پایگاه داده هستند ولی روی دیسک نیستند.
- **پایداری دانلود فایل‌های بزرگ**: مهلت هر فایل از ۱۲۰ ثانیه به ۲۰ دقیقه افزایش یافت و تا ۳ بار تلاش مجدد انجام می‌شود (فاصله ۲ و ۴ ثانیه)؛ ارسال فایل به نودها دو بار تکرار می‌شود و هر بار بلیت یک‌بارمصرف تازه صادر می‌گردد.
- **دانلود دیگر با قطع کلاینت متوقف نمی‌شود**: از `context.WithoutCancel` استفاده می‌شود، بنابراین تغییر صفحه یا پایان مهلت درگاه دانلود را قطع نمی‌کند و فایل به‌درستی ذخیره می‌شود.
- **اصلاح شمارش بایت در بررسی زنجیره**: بایت‌های ارسالی اکنون پیش از نوشتن در سوکت شمارش می‌شوند تا در ماشین‌های سریع مقدار `up=0` رخ ندهد و نودهای سالم اشتباهاً خراب شمرده نشوند (در CI به‌طور پایدار بازتولید می‌شد).

## v0.13.0-beta.97 — 2026-11-19

### 中文

- **CDN 链路探测通用化**：不再只支持 Cloudflare，任意 CDN 的域名/IP 都可探测；探测出口与探针入站都必须显式选择，系统不再随机挑入口。
- **单个探针入站测完全部条目**：一轮探测只用一个显式选定的入站，把全部 CDN 域名/IP 测完；结果写回健康度（连续失败 3 次标记失败，成功立即恢复），其他入站可直接复用通过的条目。
- **排除不该测的条目**：直连域名/IP 与各节点自定义域名不参与链路探测（入口不同，用同一入站凭据必然假失败）。
- **订阅下发收紧**：只下发「健康且延迟低于阈值」的 CDN 域名/IP，`direct` 条目不受延迟阈值限制。
- **探测调度复用探测设置**：链路探测跟随「探测设置」的时间间隔与拨号核心，拨号核心按 xray → sing-box → mihomo 自动选择。

### English

- **Generic CDN chain probing**: no longer limited to Cloudflare — any CDN domain/IP can be probed. Both the exit and the probe inbound must be selected explicitly; the system no longer picks an inbound at random.
- **One probe inbound covers all entries**: a round uses a single explicitly selected inbound to test every CDN domain/IP, then writes the health result back (3 consecutive failures mark it failed, one success restores it) so other inbounds can reuse the passing entries.
- **Entries excluded from probing**: direct domains/IPs and per-node custom domains are skipped, since a different entry point would produce false failures with the same inbound credentials.
- **Tighter subscription output**: only healthy CDN domains/IPs with latency below the threshold are emitted; `direct` entries ignore the latency threshold.
- **Probe scheduling reuses probe settings**: chain probing follows the interval and dialer of the probe settings, with the dialer chosen automatically in the order xray → sing-box → mihomo.

### Русский

- **Универсальная проверка цепочки CDN**: поддержка не только Cloudflare — проверяется домен/IP любого CDN. Выход и проверяющий inbound выбираются явно, случайный выбор inbound исключён.
- **Один inbound проверяет все записи**: за один раунд выбранный inbound проверяет все домены/IP CDN, результат записывается в состояние здоровья (3 ошибки подряд — неисправен, первый успех — восстановлен), другие inbound могут использовать прошедшие записи.
- **Исключения из проверки**: прямые домены/IP и пользовательские домены отдельных узлов не проверяются — другая точка входа даёт ложные ошибки с теми же учётными данными.
- **Более строгая выдача подписки**: выдаются только здоровые домены/IP CDN с задержкой ниже порога; записи `direct` порог задержки игнорируют.
- **Планировщик использует настройки проверки**: интервал и диалайзер берутся из настроек проверки, диалайзер выбирается автоматически: xray → sing-box → mihomo.

### فارسی

- **بررسی زنجیره CDN به‌صورت عمومی**: دیگر محدود به Cloudflare نیست و دامنه/IP هر CDN قابل بررسی است. خروجی و inbound بررسی‌کننده باید صریحاً انتخاب شوند و انتخاب تصادفی حذف شده است.
- **یک inbound برای همه ورودی‌ها**: در هر دور، تنها یک inbound انتخاب‌شده همه دامنه‌ها/IPهای CDN را بررسی می‌کند و نتیجه در سلامت ثبت می‌شود (سه شکست پیاپی = خراب، نخستین موفقیت = سالم)، سایر inboundها می‌توانند از ورودی‌های سالم استفاده کنند.
- **حذف موارد غیرقابل بررسی**: دامنه/IPهای مستقیم و دامنه‌های اختصاصی هر نود بررسی نمی‌شوند، چون نقطه ورود متفاوت است و با همان اعتبارنامه نتیجه اشتباه می‌دهد.
- **خروجی سخت‌گیرانه‌تر اشتراک**: فقط دامنه/IPهای سالم CDN با تأخیر کمتر از آستانه صادر می‌شوند؛ ورودی‌های `direct` از آستانه تأخیر مستثنا هستند.
- **زمان‌بندی بر اساس تنظیمات بررسی**: بازه و دیالر از تنظیمات بررسی گرفته می‌شود و دیالر به‌ترتیب xray → sing-box → mihomo انتخاب می‌گردد.
