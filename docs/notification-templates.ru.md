# Переменные шаблона уведомлений

> Языки: [简体中文](notification-templates.md) · [English](notification-templates.en.md) · [繁體中文](notification-templates.zh-TW.md) · Русский · [日本語](notification-templates.ja.md) · [한국어](notification-templates.ko.md) · [Deutsch](notification-templates.de.md) · [Français](notification-templates.fr.md) · [Español](notification-templates.es.md) · [Português](notification-templates.pt.md) · [Türkçe](notification-templates.tr.md) · [Bahasa Indonesia](notification-templates.id.md) · [ไทย](notification-templates.th.md) · [Tiếng Việt](notification-templates.vi.md) · [العربية](notification-templates.ar.md) · [فارسی](notification-templates.fa.md)

В шаблонах уведомлений используются заполнители `{variable}`, которые при отправке заменяются фактическими значениями. В этом документе перечислены все поддерживаемые переменные, переменные, доступные для каждого события, и правила автоматического запуска.

## 1. Типы шаблонов и аудитории

| Аудитория | Канал | Получатель | Типичное использование |
|---|---|---|---|
| **Пользователи панели** (администратор) | Telegram / Электронная почта | Каналы и получатели, настроенные администратором | Оповещения узлов, отчеты о резервном копировании, системные объявления |
| **Подписчики** | электронная почта | Собственный адрес электронной почты клиента (заполняется автоматически) | Низкий баланс, напоминания об окончании подписки |

## 2. Общие переменные

Доступно во всех шаблонах:

| Переменная | Описание | Пример |
|---|---|---|
| `{time}` | Отправить время | `2026-09-28 14:30:00` |
| `{user}` | Адрес электронной почты клиента (шаблоны подписчика) / идентификатор пользователя | `user@example.com` |
| `{message}` | Тело уведомления | Текст объявления о техническом обслуживании |

## 3. Переменные событий подписчика

### Напоминание об истечении срока подписки (event_key = `subscription_expire`)

Сканируются ежедневно и отправляются активным подписчикам, срок действия которых истекает в течение 7 дней:

| Переменная | Описание | Пример |
|---|---|---|
| `{user}` | Электронная почта клиента | `user@example.com` |
| `{expire_date}` | Срок действия подписки истек | `2026-10-05 09:00` |
| `{days}` | Осталось дней | `7` |
| `{time}` | Отправить время | `2026-09-28 09:05:00` |

### Напоминание о низком балансе (event_key = `balance_low`)

Сканируются ежедневно и отправляются клиентам, чей баланс ниже порога:

| Переменная | Описание | Пример |
|---|---|---|
| `{user}` | Электронная почта клиента | `user@example.com` |
| `{balance}` | Текущий баланс (денежные единицы, два десятичных знака) | `0.85` |
| `{time}` | Отправить время | `2026-09-28 09:05:00` |

## 4. Пример переменных шаблона операций

Когда вы нажимаете «Отправить» для проверки подключения, шаблоны пользователей панели заполняют заполнители следующими примерами:

| Переменная | Описание | Пример |
|---|---|---|
| `{node}` | Имя узла | `node-01` |
| `{backup_file}` | Имя файла резервной копии | `corefusion-20260101-0900.tar.gz` |
| `{size}` | Размер файла | `128MB` |
| `{domain}` | Домен | `example.com` |
| `{expire_date}` | Срок годности | `2026-10-12` |
| `{days}` | Осталось дней | `14` |
| `{count}` | Граф | `3` |

## 5. Правила автоматического запуска

- **Расписание**: первое сканирование запускается через 30 секунд после запуска панели, затем ежедневно в **09:05**.
- **Срок действия подписки**: сканирует активные подписки (`status=active`), срок действия которых истекает в течение 7 дней; клиент также должен быть активным
- **Низкий баланс**: сканируются активные клиенты с балансом ≤ порогового значения; пороговое значение — `notify.balance_threshold`, **в центах** (по умолчанию `100` = 1,00).
- **Дедупликация**: не более одного сообщения на каждого клиента на событие **в день** (дедупликация `notification_send_logs` по дням)

## 6. Мониторинг состояния узла

Сердцебиение узла проверяется постоянно; **уведомления отправляются только при изменении состояния — раунды без изменений выполняются без звука**:

| Ключ настройки | Описание | По умолчанию |
|---|---|---|
| `monitor.node_interval_seconds` | Интервал проверки (секунды) | `60` (минимум 30) |
| `monitor.node_offline_timeout_seconds` | Тайм-аут пульса (секунды) | `120` |

- **Офлайн-оповещение**: когда узел переходит из онлайн-в автономный режим, отправляется шаблон администратора «**Офлайн-оповещение узла**» с `{node}` (имя) и `{time}`.
- **Уведомление о восстановлении**: при восстановлении узла отправляется «**Уведомление о восстановлении узла**» с теми же переменными.
- **Тихие раунды**: нет сообщений, если состояние не изменилось; после перезапуска панели первый раунд устанавливает только базовый уровень
- **Мониторинг без отправки**: отключить соответствующий шаблон (Включено = ВЫКЛ)

## 7. Ежемесячные оповещения о квоте трафика узла (автоматически)

- **Триггер**: когда ежемесячный трафик узла достигает порога квоты, отправляется «**Предупреждение о квоте трафика узла**»; когда он превышает 100% и приостанавливается, отправляет предупреждение о превышении лимита (ключи событий `traffic_quota_threshold`/`traffic_quota_exceeded`)
- **Порог**: `monitor.traffic_quota_threshold_percent` (процент, `80` по умолчанию; установите `0`, чтобы отключить оповещения о пороговых значениях)
- **Дедупликация**: не более одного на узел за расчетный цикл (цикл соответствует `traffic_quota_reset_day` узла).
- Доступные переменные: `{node}` (имя), `{used}` (используемый ГБ), `{quota}` (квота ГБ), `{percent}` (процент), `{time}`

## 8. Уведомления о результатах резервного копирования (автоматически)

- **Триггер**: отправляется сразу после запуска запланированного резервного копирования (`BackupScheduler`) — при успехе отправляется «**Ежедневный отчет о резервном копировании**», при сбое (создание резервной копии/чтение хранилища/выгрузка на удаленное устройство) отправляется «**Предупреждение об ошибке резервного копирования**».
- Доступные переменные: `{backup_file}` (имя), `{size}` (размер, только отчет об успехе), `{message}` (причина сбоя, только предупреждение об сбое), `{time}`
- **Мониторинг без отправки**: автоматически пропускается, если шаблон отключен (Включено = ВЫКЛ).

## 9. Напоминания об истечении срока действия сертификата (автоматические)

- **Триггер**: ежедневно в 09:05, сканирует сертификаты `active`, срок действия которых истекает (**IP-сертификаты, у которых осталось 3 дня**, **сертификаты домена, у которых осталось 7 дней**) и отправляет администратору шаблон «**Напоминание об истечении срока действия сертификата**» для каждого сертификата.
- **Дедупликация**: не более одного напоминания на каждый сертификат в день; после продления срок действия выходит за пределы окна (IP 3 дня/домен 7 дней) и напоминания прекращаются
- Доступные переменные: `{domain}` (домен сертификата), `{expire_date}` (срок действия), `{days}` (оставшиеся дни), `{time}`.

## 10. Оповещения о сбоях основного процесса (автоматически)

- **Триггер**: при аварийном завершении основного процесса (xray/singbox) или сбое прокси-процесса (caddy/nginx) немедленно отправляется шаблон администратора «**Оповещение о сбое основного процесса**»; затем супервизор перезапускает его с экспоненциальной задержкой
- Доступные переменные: `{core}` (тип процесса), `{restarts}` / `{max}` (количество/ограничение перезапусков), `{message}` (сообщение о выходе, только основные процессы), `{time}`
- **Мониторинг без отправки**: автоматически пропускается, если шаблон отключен (Включено = ВЫКЛ).

## 11. Уведомления о регистрации новых пользователей (автоматически)

- **Триггер**: отправляется сразу после успешной регистрации клиента с использованием шаблона администратора «**Уведомление о регистрации нового пользователя**».
- Доступные переменные: `{user}` (электронная почта клиента), `{time}`.

## 12. Использование

1. **Добавить шаблон**: Настройки уведомлений → Шаблоны уведомлений → Добавить шаблон → «Заполнить из предустановки» и внести необходимые изменения.
2. **Включить**: отметьте «Включено» и сохраните; автоматические триггеры обрабатывают только включенные шаблоны
3. **Тест**: нажмите «Отправить» в списке, чтобы отправить реальное сообщение с примерами переменных (тестовые электронные письма шаблона подписчика отправляются на адрес отправителя администратора).
4. **Немедленные уведомления** (бизнес-код): позвоните по `NotifyClientEvent(ctx, db, settingSvc, eventKey, clientEmail, vars)` на месте мероприятия (пополнение счета, списание, продление), чтобы немедленно уведомить одного клиента за пределами дневного лимита сканирования.
