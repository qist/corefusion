## 1. システム概要

CoreFusion は、ノード管理、サブスクリプション配信、顧客管理、請求、証明書、チェーン プロキシを備えた VLESS、VMess、Trojan、Shadowsocks、Hysteria2、TUIC などをサポートするマルチプロトコル プロキシ管理パネルです。

### 1.1 コア機能

| モジュール | 説明 |
|--------|-------------|
| マルチプロトコル | VLESS、VMess、Trojan、Shadowsocks、Hysteria2、TUIC、WireGuardなど。 |
| マルチコア | Xray コアおよび sing-box (Hysteria2/TUIC およびその他の QUIC プロトコルは sing-box で実行されます) |
| マルチノード | 5 つのノード タイプ: スタンドアロン、ミラー、アクティブ/スタンバイ、連鎖エントリ、連鎖出口 |
| 定期購入の配信 | 複数のサブスクリプション形式、エンドポイント、形式管理 |
| 請求 | プラン テンプレート、リチャージ カード、残高、注文、再販業者手数料 |
| 証明書 | Let's Encrypt発行、DNS-01/HTTP-01検証、証明書配布 |
| チェーンされたプロキシ | マルチ出口ロードバランシング、外部ノード登録、チェーンルーティング |
| トラフィック割り当て | ノードごとの月次トラフィック監視、自動一時停止、ログのリセット |
| ポータル | ビジュアルポータルエディター、多言語、カスタムテンプレート |
| 通知 | 電子メールと Telegram、テンプレートとブロードキャスト |

### 1.2 アーキテクチャ

- **バックエンド**: Go、gRPC
- **フロントエンド**: Vue 3 + Element Plus
- **データベース**: SQLite (デフォルト) / MySQL / PostgreSQL
- **プロキシ**: Caddy / Nginx リバース プロキシ
- **パネル ポート**: セットアップ ウィザードによって割り当てられます (デフォルトではランダムな空きポート。8080 が一般的な選択です)
- **エージェント gRPC ポート**: デフォルトは 18443

## 2. インストール

### 2.1 サポートされる環境

| アイテム | サポート |
|------|---------|
| 分布 | Debian / Ubuntu、RHEL / CentOS / Rocky / AlmaLinux / Fedora、Alpine、Arch、openSUSE |
| CPUアーキテクチャ | 公式バイナリ: `amd64`、`arm64`;ソース ビルドは `armv7`、`armv6`、`386`、`ppc64le`、`s390x`、`riscv64`、`loong64` もサポートします |
| サービスマネージャー | systemd (推奨); systemd のないコンテナまたは他の環境では `nohup` にフォールバックします |
| メモリ/ディスク | ≥ 1 GB / ≥ 10 GB (データベース、証明書、ログ、コア バイナリはデータ ディレクトリに存在します) |
| パネルポート | セットアップ ウィザードで選択 (デフォルトではランダムな空きポート。`8080` などで問題ありません) |
| エージェント gRPC | デフォルトでは`18443` |

ランタイム外部コマンドは、インストーラーによって自動的にインストールされます (`scripts/install.sh` およびパネルによって生成されたエージェント インストール スクリプト。`--no-deps` / `CF_SKIP_DEPS=1` はスキップします)。

| 目的 | パッケージ |
|---------|---------|
| ファイアウォール / レート制限 / 同時実行マーキング | `nftables` (`nft`) |
| トラフィックシェーピング、リンク、ソケット | `iproute2` (`tc` / `ip` / `ss`) |
| NFT が利用できない場合のフォールバック | `iptables` (EL8+ では `iptables-nft`、EL7 では `iptables`) |
| 接続追跡 | `conntrack-tools` (`conntrack`) |
| `nf_conntrack` / `ifb`をロードする | `kmod` (`modprobe` / `lsmod`) |
| プロセスの検出とクリーンアップ | `procps` (`pgrep` / `pkill`) |
| ポートチェック/DHパラメータ | `lsof` / `openssl` |
| プロキシユーザーの作成 | `shadow-utils` (Debian `passwd`、Alpine/Arch `shadow`) |
| ダウンロードとアーカイブ | `curl` / `ca-certificates` / `tar` / `gzip` / `xz` |

> `nft` / `tc` がない場合は、レート制限とファイアウォール機能にのみ影響します。パネルはまだ開始されています。
> 最初に `--cpu-info` を実行して、環境がどのように検出され、どのパッケージが欠落しているかを確認します。

### 2.2 1 行インストール (推奨)

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh -o install.sh
sudo bash install.sh
```

または、直接パイプします (インタラクションや追加のフラグは必要ありません)。

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash
```

スクリプトは次のことを行います。

1. ディストリビューション、CPU アーキテクチャ、libc を検出し、基本パッケージとランタイムの依存関係をインストールします。
2. GitHub リリースから `corefusion-linux-<arch>` をダウンロードし、一致する `.sha256` で検証します。
3. `/opt/corefusion` にインストールし、`data/{sqlite,certs,logs,runtime}` を作成します。
4. プレースホルダー `.env` と `SAFE_PATHS=data` のみを書き込みます (データベース構成はなし)。これにより、初回起動時にセットアップ ウィザードが開始されます (完全な `.env` がウィザードによって生成されます)。
5. systemd サービスをインストールして開始します (または、systemd が使用できない場合は `nohup` で実行します)。
6. 準備ができるまで待ってから、セットアップ URL、トークン、およびディレクトリ パスを出力します。

出力例:

```text
==================================================================
 CoreFusion installation complete
------------------------------------------------------------------
 Install dir : /opt/corefusion
 Data dir    : /opt/corefusion/data
 Binary      : /opt/corefusion/corefusion
 Logs        : journalctl -u corefusion -f
------------------------------------------------------------------
 Setup wizard : http://<server-ip>:<random-port>/init?init_token=<token>
 Setup token  : <token>
 Valid for    : 2 hours (see startup log)
 Note         : the token is shown once; after setup this port closes and the panel switches to its normal port.
==================================================================
```

パネルが `127.0.0.1` のみをリッスンする場合 (たとえば、リバース プロキシの背後で)、スクリプトは到達不能な URL の代わりに SSH トンネル コマンドを出力します。

> トークンを紛失しましたか?起動ログをもう一度読みます: `journalctl -u corefusion -n 50 --no-pager`
> (systemdなし: `tail -n 50 /opt/corefusion/data/logs/panel.log`)。

### 2.2.1 多言語出力

インストーラーには簡体字中国語、English、فارسی、Русский の 4 つの UI 言語が組み込まれています。システムの `LANG` から自動判定するほか、明示的に指定できます。

```bash
# 英語
sudo bash install.sh --lang en

# 環境変数でペルシア語
sudo CF_LANG=fa bash install.sh

# パイプ実行時に引数を渡す
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash -s -- --lang ru
```

`zh` / `en` / `fa` / `ru` に対応し、`--lang=ru` も使用できます。明示的に未対応の言語を指定すると、利用可能な言語一覧とともにエラーになります。

### 2.3 バージョンの固定 / ミラー / オフライン インストール

```bash
# Pin a version
sudo bash install.sh --version v0.13.0-alpha.2

# GitHub download mirror (used as a URL prefix)
sudo bash install.sh --mirror https://ghproxy.net --version latest

# Use a local binary (offline / intranet / pre-built)
sudo bash install.sh --local ./dist/corefusion-linux-arm64

# Explicit target architecture
sudo bash install.sh --arch arm64 --local ./corefusion-linux-arm64
```

> `--version` がない場合、スクリプトは GitHub リリース リストの最新のエントリを使用します。
> ほとんどのリリースはプレリリースであるため、`/releases/latest` エンドポイントは使用されません。
>
> 公式リリースでは `amd64` / `arm64` のみが提供されます。他のアーキテクチャの場合は、`--source` または `--local` とクロスコンパイルされたバイナリを使用してください。

### 2.4 ソースからのビルド

```bash
sudo bash install.sh --source --version v0.13.0-alpha.2
```

`--source` はリポジトリのクローンを作成し (スクリプトがリポジトリ内にある場合は既存のチェックアウトを使用し)、`make panel` を実行します。ツールチェーンのバージョンは環境ごとに選択されます。

| 依存関係 | 選択 |
|------------|-----------|
| 行く | `go.mod` の `toolchain` / `go` から読み取ります (現在 **Go 1.27+**)。システムのバージョンが古すぎる場合、一致するツールチェーンが `<install-dir>/.toolchain` にダウンロードされます |
| ノード | **デフォルトではノード 22 LTS** (Vite には 18 以上が必要です)。必要に応じて、一致する公式ビルドがダウンロードされます |
| ノード (glibc < 2.28) | `unofficial-builds` glibc-217 ビルドを使用します (CentOS 7 など) |
| ノード（アルパイン/イガイ） | `nodejs` / `npm` ディストリビューションを使用 |

オーバーライド:

```bash
# Force Go / Node versions
sudo CF_GO_VERSION=1.27.5 CF_NODE_MAJOR=22 bash install.sh --source

# Go toolchain mirror (default https://go.dev/dl)
sudo CF_GO_MIRROR=https://golang.google.cn/dl bash install.sh --source
```

手動ビルド (開発/デバッグ):

```bash
git clone https://github.com/qist/corefusion.git
cd corefusion

# Frontend + panel for the current architecture; the frontend is embedded via go:embed
make panel

# Cross-compile
make panel-linux-amd64
make panel-linux-arm64
```

> `go build ./...` はバイナリを生成しません。パネルを構築します
> `go build -o corefusion ./cmd/corefusion/`または`make panel`。

### 2.5 インストーラーのフラグ

| 旗 | 説明 |
|------|-------------|
| `-d, --dir <PATH>` | インストールディレクトリ、デフォルト `/opt/corefusion` |
| `-v, --version <TAG>` | パネルのバージョン、例: `v0.13.0-alpha.2`;デフォルト `latest` |
| `--binary` | GitHub リリース バイナリを使用します (デフォルト) |
| `--source` | ソースからビルドし、一致する Go / Node を準備する |
| `--local <FILE>` | ローカルバイナリを使用する(オフラインインストール) |
| `--arch <ARCH>` | ターゲットアーキテクチャ: `amd64` / `arm64` / `armv7` / `armv6` / `386` / `ppc64le` / `s390x` / `riscv64` / `loong64` |
| `--mirror <URL>` | GitHub ダウンロード プレフィックス、例: `https://ghproxy.net` |
| `--repo <URL>` | ソースリポジトリ、デフォルトは `https://github.com/qist/corefusion.git` |
| `--ref <REF>` | ソースブランチ/タグ;デフォルトは `--version`、それ以外の場合は `main` |
| `--no-deps` | システム依存関係のインストールをスキップする |
| `--no-start` | 起動せずにサービスファイルをインストールして書き込みます |
| `--cpu-info` | 環境の検出と不足している依存関係を出力して終了します。 |
| `--lang <LANG>` | 出力言語：`zh` / `en` / `fa` / `ru`（既定：システム `LANG`） |
| `--uninstall` | サービスを停止し、プログラムを削除します（データと`.env`は保持します）。 |
| `--purge` | `--uninstall` では、データ ディレクトリと `.env` も削除します。 |

関連する環境変数:

| 変数 | 目的 |
|----------|---------|
| `CF_GO_VERSION` | ソースビルドに必要な Go バージョンをオーバーライドする |
| `CF_NODE_MAJOR` | ノードのメジャー バージョン (デフォルトは 22) をオーバーライドします。 |
| `CF_GO_MIRROR` | Go ツールチェーンのダウンロード ミラー |
| `CF_SKIP_DEPS` | 依存関係のインストールをスキップするには、エージェントのインストール スクリプトで `1` に設定します。 |
| `CF_LANG` | インストーラーの出力言語を上書き（`--lang` と同じ） |

### 2.6 ディレクトリのレイアウト

```text
/opt/corefusion/
├── corefusion                 # panel binary
├── corefusion.bak             # previous version (when upgrading)
├── .env                       # environment file (0600, generated by the setup wizard)
├── .toolchain/                # Go / Node downloaded for source builds
└── data/                      # data directory (SAFE_PATHS)
    ├── sqlite/app.db          # default SQLite database
    ├── certs/                 # certificates and keys
    ├── logs/                  # runtime logs (without systemd)
    ├── runtime/               # core runtime config and state
    ├── binaries/              # downloaded xray / sing-box cores
    └── proxy/                 # proxy (Caddy/Nginx) sites and config
```

> インストーラーは、`sqlite/`、`certs/`、`logs/`、および `runtime/` のみを作成します。 `binaries/`、`proxy/`、`rules/` などはパネルまたはコアの取り付け時に作成されます。
> データ ディレクトリは `.env` の `SAFE_PATHS` から取得され、絶対パスである可能性があります。インストール ディレクトリを変更しても、既存のデータは移動されません。

### 2.7 サービス管理

systemd (ほとんどのディストリビューション):

```bash
systemctl status corefusion --no-pager
systemctl restart corefusion
systemctl stop corefusion
journalctl -u corefusion -f          # follow logs
journalctl -u corefusion -n 100      # last 100 lines
```

systemd なし (コンテナなど):

```bash
cd /opt/corefusion && ./corefusion            # foreground (debugging)
cd /opt/corefusion && setsid nohup ./corefusion >> data/logs/panel.log 2>&1 &
tail -f data/logs/panel.log
```

> systemd がないと、起動時にプロセスが開始されません。再起動後に手動で再起動します (またはインストーラーを再実行します)。

### 2.8 アップグレードとアンインストール

アップグレード (データと構成を保持):

```bash
sudo bash install.sh --version <new-version>
```

スクリプトはサービスを停止し、古いバイナリを `corefusion.bak` としてバックアップし、それを置き換えて再起動します。既存の `.env` および `data/` はそのまま残されます。

アンインストール:

```bash
# Remove the program only; keep data and .env
sudo bash install.sh --uninstall

# Also remove the data directory and .env (irreversible)
sudo bash install.sh --uninstall --purge
```

### 2.9 環境ファイル(.env)

完全な `.env` は、構成 (データベース DSN、データ ディレクトリ、シークレット、ポート、ドメイン) が保存されるときに **セットアップ ウィザードによって** 生成されます。

新規インストールでは、インストーラーはこのプレースホルダーのみを書き込むため、パネルが既存の `data/` を初期化されたインストールと誤って認識し、ウィザードをスキップすることはありません。

```env
SAFE_PATHS=data
```

> 完全な構成 (`.env` と `CF_DB_DSN`) がすでに存在する場合、インストーラーはそれを上書きせず、ウィザードは再度表示されません。
> 後で `.env` に手動で編集した内容は、再起動後に有効になります。

#### データディレクトリ

```env
SAFE_PATHS=data                       # relative to the install directory
# SAFE_PATHS=/srv/corefusion-data     # or an absolute path
```

#### データベース

`CF_DB_DSN` はプレフィックスによって検出されます。

| プレフィックス | データベース |
|--------|----------|
| 設定解除または裸のパス | SQLite (デフォルト) |
| `sqlite://` | SQLite (明示的) |
| `mysql://` | MySQL |
| `postgres://` / `postgresql://` | PostgreSQL |

`CF_DB_TYPE` はオプションであり、検出 (`sqlite` / `mysql` / `postgres`) をオーバーライドします。

> **暗号化されたパスワード**: パネルによって書き込まれた MySQL/PostgreSQL DSN (セットアップ ウィザード/データベース スイッチ)
> `.env` に `enc:...` (AES-256-GCM、キー `CF_SECRET_ENCRYPTION_KEY`) として保存されます。
> これらは読み取り時に復号化されます。手動で作成された平文 DSN は引き続き機能します。

**SQLite (デフォルト)**

```env
# Bare path (detected as SQLite)
CF_DB_DSN=data/sqlite/app.db

# Or explicit sqlite:// prefix
CF_DB_DSN=sqlite:///opt/corefusion/data/sqlite/app.db
```

**MySQL**

```env
# Format: mysql://user:password@tcp(host:port)/dbname?params
CF_DB_DSN=mysql://corefusion:password@tcp(127.0.0.1:3306)/corefusion?charset=utf8mb4&parseTime=True&loc=Local
```

**PostgreSQL**

```env
# Format: postgres://user:password@host:port/dbname?params
CF_DB_DSN=postgres://corefusion:password@127.0.0.1:5432/corefusion?sslmode=disable
```

#### 接続プール (オプション、MySQL/PostgreSQL)

```env
CF_DB_MAX_OPEN_CONNS=100
CF_DB_MAX_IDLE_CONNS=10
```

#### その他の一般的な変数

| 変数 | 説明 |
|----------|-------------|
| `JWT_SECRET` | ログイントークンの署名キー。欠落している場合に最初の起動時に生成される |
| `CF_SECRET_ENCRYPTION_KEY` | 機密設定を暗号化するためのキー (AES-256-GCM)。欠落時に生成される |
| `CF_INITIAL_ADMIN_PASSWORD` | 初期管理者パスワード (オプション; デフォルトではランダムで 1 回印刷されます) |
| `CF_NETWORK_TRAFFIC_ACCOUNTING` | iptables ベースのトラフィック アカウンティングを無効にするには、`0` に設定します (デフォルトで有効) |
| `CF_NETWORK_TRAFFIC_TABLE` | トラフィック アカウンティングに使用される iptables テーブル、デフォルトは `corefusion` |

> 実際のクライアント IP を解決するための信頼されたリバース プロキシは、環境変数を介して構成されなくなりました。
> これらは **[設定] → [ネットワーク]** に `panel.trusted_proxies` として保存されます。

> `.env` には秘密が含まれています。パネルは起動時に権限を `0600` に強化します。決してコミットしないでください。

### 2.10 Docker (オプション、独自のイメージを構築)

リポジトリは Dockerfile を**提供しません**。コンテナ化する場合は、独自のイメージを記述します。参照呼び出し:

```bash
docker run -d \
  --name corefusion \
  -p 8080:8080 \
  -p 18443:18443 \
  -v /opt/corefusion/data:/app/data \
  -v /opt/corefusion/.env:/app/.env \
  <your-image>
```

> 通常、コンテナには systemd 権限も `nft` 権限もないため、レート制限/ファイアウォール機能は機能しません。
> 作業ディレクトリは、相対 `SAFE_PATHS` のベースと一致する必要があります。

### 2.11 インストール後のチェック

```bash
# Environment and dependencies
sudo bash install.sh --cpu-info

# Service state
systemctl is-active corefusion

# Startup log (contains the setup URL and token)
journalctl -u corefusion -n 50 --no-pager

# Listening ports
ss -lntp | grep corefusion
```

## 3. 初期設定

最初の起動時に、`.env` に有効な `CF_DB_DSN` がない場合、パネルはまだ管理 UI を**提供しません**。それは、
**セットアップ ウィザード**は、ワンタイム トークンを使用して 18000 ～ 18999 のランダムなポート上で実行され、保存されると通常のパネルとして再起動されます。

### 3.1 セットアップウィザードを開く

1. インストーラーの出力から「セットアップ ウィザード」URL をコピーします。または
2. サーバー上のログを読み取ります。

```bash
journalctl -u corefusion -n 50 --no-pager | grep -A2 'setup wizard'
```

```text
CoreFusion first start - setup wizard
  URL   : http://<ip>:<port>/init?init_token=<token>
  Token : <token>
  Valid : 2h0m0s
```

3. ブラウザで URL を開きます (すでに `init_token` が含まれているため、手動入力は必要ありません)。

> ウィザード セッションは、デフォルトでは **2 時間**後に期限切れになります。有効期限が切れた場合、またはパネルが再起動した場合は、新しいものを入手してください。
> トークンを共有しないでください。セットアップが完了すると、このポートは閉じられ、通常のパネル ポートのみが残ります。

### 3.2 ウィザードの手順

ウィザードには 8 つのステップがあります。いつでも戻ることができます。最終保存するまで何もコミットされません。

| ステップ | 内容 |
|------|---------|
| 1. データベース | SQLite / MySQL / PostgreSQL |
| 2. データディレクトリ | `.env` で `SAFE_PATHS` に書き込まれます |
| 3. 暗号化キー | `JWT_SECRET` および `CF_SECRET_ENCRYPTION_KEY` |
| 4. コア | どのプロキシ コアをインストールするか |
| 5. プロキシ | なし/Nginx/キャディ |
| 6. サイトとドメイン | ポート、Web パス、管理者アカウント、通貨、タイムゾーン、ドメイン |
| 7.HTTPS証明書 | 無効 / アップロード / ACME |
| 8. まとめ | `.env`を確認してダウンロードし、保存して再起動します |

#### ステップ 1: データベース

- **SQLite (ローカル ファイル、推奨)**: `<data-dir>/sqlite/app.db` を使用するには、パスを空のままにしておきます。
- **MySQL / PostgreSQL**: ホスト、ポート、ユーザー、パスワード、データベース名。 PostgreSQLは`disable` / `require` / `verify-full`もサポートします。
- 「接続をテスト」をクリックして検証します。保存するとテストも行われます。不足しているデータベースは自動的に作成されます (アカウントに `CREATE` がない場合は手動で作成します)。
- DSN (パスワードを含む) は、`.env` に書き込まれる前に暗号化されます。

#### ステップ 2: データ ディレクトリ

データベース、証明書、ログ、コアバイナリなどを保存します。これは`.env`の`SAFE_PATHS`です。デフォルトは`data`
(インストールディレクトリを基準にして);絶対パスが許可されます。 **後から何気なく変更しないでください** またはパネル
既存のデータベースと証明書が見つかりません。

#### ステップ 3: 暗号化キー

- `JWT_SECRET`: ログイン トークンに署名します。
- `CF_SECRET_ENCRYPTION_KEY`: 機密設定 (データベース パスワード、DNS 資格情報、リチャージ カードなど) を暗号化します。
- どちらもデフォルトではランダムに生成されます。新しい値を取得するには「再生成」を使用します。 **`CF_SECRET_ENCRYPTION_KEY` を変更すると、以前に暗号化されたデータが読み取れなくなります** - バックアップしてください。

#### ステップ 4: コア

インストールするプロキシ コアを選択します。

- **Xray**: VLESS / VMess / Trojan / Shadowsocks など;
- **sing-box**: Hysteria2 / TUIC およびその他の QUIC プロトコルを伝送します。

保存して再起動すると、パネルが自動的にダウンロードしてインストールします。 「プロトコル」でバージョンとステータスを確認します。後でインストールすることもできます。

#### ステップ 5: プロキシ

- **なし**: パネルはクライアントに直接サービスを提供します (TLS を自分で処理します)。
- **Nginx / Caddy**: パネルはリバース プロキシと証明書ホスティングを管理します。 1つ選んでください。

プロキシを選択すると、パネルは通常、`127.0.0.1` でのみリッスンし、プロキシは外部にサービスを提供します。

#### ステップ 6: サイトとドメイン

| フィールド | 説明 |
|-------|-------------|
| リッスンアドレス | 自動的に派生: プロキシ → `127.0.0.1`;証明書のあるプロキシなし → `0.0.0.0`;それ以外の場合 → `127.0.0.1` |
| パネルポート | デフォルトではランダムな空きポート。必要に応じて変更してください (例: 8080) |
| サブスクリプションポート | オプション。 `0` はパネル ポートを共有します |
| ポータルポート | オプション。 `0` はパネル ポートを共有します |
| ウェブパス | 管理 UI パス、デフォルトは `/`。 API は常に `/api/v1` です |
| 管理者のユーザー名/パスワード | デフォルトではランダム。 **パスワードは概要に 1 回だけ表示されます** - 保存してください |
| アクセスモード | 「ドメイン」または「IP」 |
| デフォルトの通貨/タイムゾーン | リチャージカードと残高のデフォルト通貨。パネルとプロキシログのタイムゾーン (例: `Asia/Shanghai`) |
| リバースプロキシに追加 | プロキシとドメインを設定したら、パネル/サブスクリプション/ポータルのドメインを一度にプロキシに追加します |

ドメインを入力すると、対応する設定 (コールバック ドメイン、サブスクリプション エンドポイント、共有ドメイン) が書き込まれます。

#### ステップ 7: HTTPS 証明書

| ソース | 説明 |
|--------|-------------|
| HTTPSを無効にする | パネル/ポータル/サブスクリプションは HTTP (安全ではありません) 経由で提供されます。リバース プロキシを使用すると、後でプロキシ側に TLS を追加できます |
| 証明書のアップロード | 証明書 PEM と秘密キー PEM を貼り付けます (ドメイン アクセス モードのみ) |
| ACME | このステップを送信すると証明書が発行されます。ドメイン証明書とIP証明書をサポートします |

ACME オプション:

- **CA**: Let's Encrypt、Let's Encrypt (ステージング)、ZeroSSL、Google パブリック CA。
- **ターゲット**: 構成されたドメインまたはパブリック IP (IP 証明書は Let's Encrypt でのみサポートされます)。
- **チャレンジ**: `HTTP-01` (ポート 80 が必要) または `DNS-01` (ワイルドカード、ポート 80 なし。DNS プロバイダーを選択し、資格情報を入力);
- **キーのタイプ/サイズ**: ECC 256/384 または RSA 2048/3072/4096。
- **Google パブリック CA**: EAB が必要です。キー ID / HMAC を手動で入力するか、GCP サービス アカウントを使用します。

> IP 証明書は、ホストのパブリック IPv4/IPv6 を自動検出します。プロキシの背後では、検出されたアドレスはホストのアドレスであり、プロキシの出力アドレスではありません。
> ドメイン証明書は、後から「証明書」で発行することもできます。

#### ステップ 8: まとめ

データベース、データ ディレクトリ、コア、プロキシ、ポート、管理者アカウント、ドメイン、`.env` キー (マスクされたシークレット) が表示され、以下が提供されます。

- **.env をダウンロード**: 構成のコピーを保存します。
- **アクセス URL**: パネル/サブスクリプション/ポータルの最終 URL。 HTTP は安全でないとしてマークされています。

「保存して再起動」をクリックしてデータベースと `.env` を書き込みます。パネルは通常のサービスを再開します。

### 3.3 セットアップ後

- サービスが再起動され、起動ログに最終的なリッスン アドレスが出力されます。
- 管理者アカウントでサインインし、概要から URL と Web パスにアクセスします。
- パスワードを紛失した場合は、`./corefusion admin reset-password` を使用してオフラインでパスワードをリセットします。

### 3.4 非対話型 CLI セットアップ

自動化サーバーまたはヘッドレスサーバーの場合は、構成を書き込み、セットアップが完了したことを直接マークします。

```bash
cd /opt/corefusion
./corefusion init \
  --db-type sqlite \
  --data-dir /opt/corefusion/data \
  --admin-username admin \
  --admin-password 'change-me-strong-password' \
  --listen-port 8080 \
  --proxy-type caddy \
  --cores xray,singbox \
  --panel-domain panel.example.com \
  --tls-mode acme --tls-domain panel.example.com --tls-email you@example.com
```

共通フラグ:

| 旗 | 説明 |
|------|-------------|
| `--db-type` / `--db-host` / `--db-port` / `--db-user` / `--db-password` / `--db-name` | データベース設定 |
| `--data-dir` | データディレクトリ。デフォルトは `SAFE_PATHS` または `./data` |
| `--listen-port` / `--subscription-port` / `--portal-port` / `--web-path` | ポートと Web パス (デフォルトではランダムな空きポート) |
| `--admin-username` / `--admin-password` | 管理者アカウント（省略時はランダムなパスワードが1回印刷されます） |
| `--proxy-type` | `none` / `nginx` / `caddy` |
| `--cores` | インストールするコア、カンマ区切り: `xray,singbox` |
| `--panel-domain` / `--subscription-domain` / `--portal-domain` | ドメイン (設定に書き込まれ、リバース プロキシに追加される) |
| `--tls-mode` | `none` / `self_signed` / `acme` |
| `--tls-domain` / `--tls-email` / `--tls-challenge` / `--tls-key-type` / `--tls-key-bits` | 証明書オプション (`--tls-challenge` のデフォルトは `http-01`、`dns-01` には `--tls-dns-channel` または `--tls-dns-provider` が必要です) |
| `--tls-ip-cert` | 検出されたパブリックIPの証明書を発行します(Let's Encryptのみ) |
| `--acme-provider` | `lets_encrypt` / `lets_encrypt_staging` / `zerossl` / `google` |
| `--currency` / `--timezone` | デフォルトの通貨/タイムゾーン |

完全なリスト: `./corefusion init --help`。次にサービスを開始します。

```bash
systemctl restart corefusion
```

### 3.5 セットアップウィザードの再実行

やり直すには (`.env` とセットアップ マークを削除し、**データを保持します**):

```bash
cd /opt/corefusion
./corefusion reset-init      # type RESET to confirm
systemctl restart corefusion
```

次に、新しい URL と起動ログのトークンを使用します。

> 再初期化すると、管理者アカウントと Web パスがリセットされます。古いデータベース内のビジネス データは残りますが、ログイン アカウントを再作成する必要がある場合があります。
>
> `reset-init` は、`.env` 全体 (`SAFE_PATHS` を含む) を削除します。 **データ ディレクトリがカスタム絶対パスである場合**、再起動する前に `SAFE_PATHS` を復元します。それ以外の場合、パネルは `./data` で表示されます。
>
> ```バッシュ
> printf 'SAFE_PATHS=/srv/corefusion-data\n' > /opt/corefusion/.env
> ```

### 3.6 初回サインイン後のセキュリティ

#### 初期パスワードを変更する

1. 右上隅にあるユーザー名をクリックします。
2. 「パスワードを変更」を選択します。
3. 古いパスワードと新しいパスワードを入力します。
4. 「保存」をクリックします。

#### 動的コードログインを有効にする (2FA / TOTP)

> 有効にすると、アカウントは **動的コード ログイン** に切り替わります。静的パスワードは受け入れられなくなります。だけ
> 認証アプリの 6 桁のコード (またはワンタイム リカバリ コード) が機能します。これはログインパスワードを**置き換えます**。
> 「パスワード + コード」の 2 段階認証ではありません。

1. 右上隅にあるユーザー名をクリックします。
2. 「2FA を有効にする」を選択します。
3. 現在のパスワードを入力します (この変更を確認するためのみ)。
4. 認証アプリ (Google Authenticator / 1Password など) で QR コードをスキャンするか、キーを手動で入力します。
5. 6 桁のコードを入力して有効化を完了します。
6. **リカバリ コードをすぐに保存します** (ダウンロード可能)。各コードは一度だけ機能します。

その後サインインします:

- ユーザー名を入力すると、パスワードフィールドが「6桁のコード/リカバリコード」に変わり、ボタンが「コードでサインイン」に変わります。
- 現在のコードを入力します。 **静的パスワードは使用できなくなりました**。
- リカバリ コードは 1 回限りの使用です。不足した場合は、「動的コード ログイン (2FA)」で再生成します (これにより、古いコードはすべて無効になります)。

オーセンティケータが失われ、リカバリ コードが使い果たされた場合は、サーバー上で 2FA オフラインを無効にします。

```bash
cd /opt/corefusion
./corefusion admin 2fa reset -u admin    # disables 2FA, clears the secret and recovery codes, revokes all sessions
```

> 認証コードも回復コードも持たない唯一のスーパー管理者は、Web UI から回復できないため、上記のコマンドを使用する必要があります。

#### Passkey を登録する (オプション)

1. 右上隅にあるユーザー名をクリックします。
2. 「Passkey管理」を選択します。
3. 「新しいPasskeyを登録」をクリックします。
4. デバイスのプロンプトを完了します。

> **注意**: パスキーには HTTPS または localhost が必要で、ドメインが許可リストに登録されている必要があります。

## 4. ダッシュボード

ダッシュボードには、マルチノード クラスターの概要とノードの健全性が表示されます。

### 4.1 表示内容

- **システム情報**: ホスト名、OS バージョン、稼働時間、CPU、メモリ
- **トラフィック**: リアルタイム帯域幅、総トラフィック、月次傾向
- **ノードの健全性**: オンライン/オフライン/劣化した数、高負荷ノード
- **アラート**: オフライン ノード、機能低下したノード、まもなく期限切れになる証明書、クォータ警告
- **クラスター リソース**: 平均 CPU、メモリ、ディスク、およびスループット

### 4.2 アクション

- 「詳細を表示」をクリックしてノードの詳細ページを開きます
- ノード カードをクリックすると、そのライブ ステータスが表示されます
- フィルターを使用してステータス、タイプ、または地域で絞り込みます

## 5. ノード管理

ノード管理は CoreFusion の中核であり、複数のノード タイプをサポートします。

### 5.1 ノードの種類

| タイプ | 説明 |
|------|-------------|
| スタンドアロン (`standalone`) | 独立したコアノード |
| ミラー(`mirror`) | ターゲットノードから構成を同期します |
| プライマリ/バックアップ (`primary_backup`) | 相互にフェイルオーバーするパートナー ノード |
| チェーンエントリー (`chain_entry`) | チェーンされたプロキシのエントリ ノード |
| チェーン出口 (`chain_exit`) | チェーンされたプロキシの出口ノード |

### 5.2 ノードの追加

1. 「ノード管理」を開きます。
2. 「サーバーを追加」をクリックします。
3. 基本事項を入力します。
   - 名前、例: `HongKong-HK01`
   - ホスト名: IP またはドメイン
   - 地域、例: `HK`、`JP`、`US`
   - ノードタイプ。
4. エージェントのポートを設定します (デフォルトは `18443`)。
5. サポートされているコアを選択します。
6. 「保存」をクリックします。

### 5.3 ワンクリック展開

1. ノードを追加した後、「ブートストラップ コマンド」をクリックします。
2. インストール コマンドをコピーします。
3. リモート ノードで root として実行します。

   ```bash
   curl -fsSL https://your-panel/install.sh | bash
   ```

4. エージェントは自動的にダウンロード、登録、開始されます。

### 5.4 ノードの詳細

ノードをクリックして詳細ページを開きます。

- **概要**: 基本情報、エージェントのステータス、証明書のステータス
- **プロトコル センター**: コア プロセス構成
- **プロキシ**: Caddy / Nginx 構成
- **コアプロセス**: 開始 / 停止 / 再起動
- **WARP**: WARP 設定
- **直接ドメイン**: ドメイン管理
- **レート制限**: トラフィック シェーピング
- **証明書**: 証明書バインディング
- **オンライン ユーザー**: リアルタイム オンライン ユーザー

### 5.5 ノードのアクション

- **構成を同期**: パネル構成をノードにプッシュします
- **強制再接続**: エージェント接続を切断し、再接続します。
- **エージェントの更新**: エージェントの更新をプッシュします
- **証明書の取り消し**: ノードのエージェント証明書を取り消します。

## 6. プロトコルセンター

プロトコル センターは、コア プロセスのプロトコル パラメーターを構成します。

### 6.1 サポートされるコア

| コア | 説明 |
|------|-------------|
| Xrayコア | VLESS / VMess / Trojan / Shadowsocks など |
| sing-box | TUN をサポートするモジュール式ユニバーサル プロキシ プラットフォーム。 Hysteria2 / TUIC およびその他の QUIC プロトコルを搭載 |

### 6.2 構成モジュール

- **ログ**: アクセスログ、エラーログ、出力モード
- **API**: gRPC API リッスン アドレス、サービス リスト
- **DNS**: DNS サーバー、クエリ戦略、静的ホスト
- **ルーティング**: ルーティング ルール、ロード バランシング、VLESS ルーティング
- **受信**: 受信リスト、プロトコル設定、トランスポート、TLS
- **アウトバウンド**: アウトバウンドリスト、プロトコル設定、トランスポート
- **トランスポート**: WebSocket、gRPC、XHTTP、TUN など。
- **TLS**: 証明書、ALPN、uTLS フィンガープリント、ECH
- **Reality**: ターゲット管理、キーペア、短縮 ID
- **ヘルスチェック**: プローブ URL、間隔、同時実行性
- **FakeDNS**: IP プール、プール サイズ
- **メトリクス**: Prometheus メトリクス リスナー
- **ポリシー**: 接続タイムアウト、バッファ、統計
- **地理データ**: 自動更新、リソース ファイル
- **バージョン制限**: 最小/最大バージョン

### 6.3 インバウンド構成

1. コアとプロトコルを選択します。
2. 基本事項を入力します。
   - タグ
   - リッスンアドレスとポート
   - プロトコルの種類
3. プロトコルパラメータ（UUID、パスワードなど）を設定します。
4. トランスポート (TCP、WebSocket、gRPC など) を選択します。
5. TLS (証明書、ALPN) を構成します。
6. 保存してコアに適用します。

### 6.4 アウトバウンド構成

1. アウトバウンドを追加します。
2. タグとプロトコルを設定します。
3. サーバーのアドレスとポートを設定します。
4. トランスポートと TLS を構成します。
5. 保存して適用します。

### 6.5 リンクを共有する

1. 受信リストの「リンクを共有」をクリックします。
2. 形式を選択してください:
   - URIをシェアする
   - ミホモ YAML
   - sing-box JSON
   - Xray JSON

## 26. よくある質問

### 26.1 パネルが起動しない

- ポートがすでに使用されているかどうかを確認する
- `.env`が有効であることを確認してください
- ログを確認してください: `journalctl -u corefusion -f`; systemd、`tail -f <install-dir>/data/logs/panel.log`なし

### 26.2 ノードがオフラインである

- エージェントが実行されていることを確認します: `systemctl status corefusion-agent`
- ネットワーク接続を確認する
- ファイアウォールルールを確認してください（ポート`18443`）

### 26.3 証明書の発行に失敗する

- DNSの解像度を確認する
- ポート 80 が到達可能であることを確認する
- DNSプロバイダー構成を確認してください
- 証明書ログを確認する

### 26.4 サブスクリプションが機能しない

- 購読リンクを確認してください
- ノードがオンラインであることを確認します
- コアプロセスが実行されていることを確認します
- ファイアウォールルールを確認する

### 26.5 リチャージコールバックが失敗する

- コールバック URL を確認してください
- サイトキーが一致していることを確認してください
- IP許可リストを確認してください
- 注文履歴を確認する

### 26.6 ポータル ページにアクセスできない

- ポータルポートが開いているか確認してください
- ポータルのパス構成を確認してください
- **重要**: リバース プロキシがポータル ドメインをメイン パネル ポートではなく、**ポータル エンジン ポート**に転送していることを確認してください。間違ったポートに転送すると、ポータルではなく空白のページまたはパネルが表示されます。プロキシ サイト レコードの `upstream` / `local_port` を確認します。
- `http://<portal-domain>:<portal-port>` を直接開いて、ポータル エンジン自体を確認します。
- リバースプロキシ構成を確認してください
- ポータルのログを確認する

## 付録

### A. デフォルトのポート

| 港 | 目的 |
|------|---------|
| セットアップ ウィザードによって割り当てられます (デフォルトではランダムな空きポート) | 管理パネル（変更可能） |
| 18443 | エージェント gRPC (変更可能) |
| 0 (デフォルトでは無効) | 専用のサブスクリプション エンジン ポート (空、または `0` がメイン ポートを共有) |
| 0 (デフォルトでは無効) | 専用ポータル エンジン ポート (空、または `0` がメイン ポートを共有) |
| 80 / 443 | リバースプロキシ (Caddy / Nginx) HTTP / HTTPS |

### B. デフォルトのパス

| パス | 目的 |
|------|---------|
| `/` | 管理パネル (専用のポータル エンジンが構成されていない場合、ポータルは `/` にも存在します) |
| `/sub/:token` | サブスクリプションの取得 (専用のサブスクリプション ポートが構成されていない場合) |
| `/p` | ポータル ページ (専用ポータル ポートが構成されていない場合) |
| `/:token` | サブスクリプションのフェッチ (専用のサブスクリプション ポートを使用、`/sub` プレフィックスなし) |

### C. コマンドラインツール

パネル バイナリは次のサブコマンドをサポートしています (引数なしでサーバーが起動します)。

```bash
# Start the panel (same as ./corefusion server)
./corefusion

# Run database migrations
./corefusion migrate

# Offline administration (when you cannot sign in)
./corefusion admin reset-password -u admin -p 'new-password'
./corefusion admin 2fa reset -u admin
./corefusion admin list

# Version / help
./corefusion version
./corefusion help
```

> systemd ユニットがない場合は、古いプロセスを停止し、`nohup` で再度開始することで再起動します。ログは`<install-dir>/data/logs/panel.log`にあります。
