## 1. Обзор системы

CoreFusion — это многопротокольная панель управления прокси, поддерживающая VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC и другие, с управлением узлами, доставкой подписки, управлением клиентами, выставлением счетов, сертификатами и цепочками прокси.

### 1.1 Основные функции

| Модуль | Описание |
|--------|-------------|
| Мультипротокольный | VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, WireGuard и т. д. |
| Многоядерный | Xray-core и sing-box (Hysteria2/TUIC и другие протоколы QUIC, работающие на sing-box) |
| Многоузловой | Пять типов узлов: автономный, зеркальный, активный/резервный, цепочка входа, цепочка выхода. |
| Доставка подписки | Несколько форматов подписки, конечные точки и управление форматами |
| Биллинг | Шаблоны планов, карты пополнения баланса, заказы, комиссия реселлера |
| Сертификаты | Выдача Let's Encrypt, проверка DNS-01/HTTP-01, распространение сертификата |
| Привязанный прокси | Балансировка нагрузки с несколькими выходами, регистрация внешних узлов, цепная маршрутизация |
| Квоты на трафик | Ежемесячный мониторинг трафика для каждого узла, автоматическая приостановка, сброс журналов |
| Портал | Визуальный редактор портала, многоязычный, пользовательские шаблоны |
| Уведомления | Электронная почта и Telegram, шаблоны и трансляции |

### 1.2 Архитектура

- **Бэкэнд**: Вперёд, gRPC
- **Фронтенд**: Vue 3 + Element Plus
- **База данных**: SQLite (по умолчанию) / MySQL / PostgreSQL.
- **Прокси**: обратный прокси-сервер Caddy/Nginx.
- **Порт панели**: назначается мастером настройки (по умолчанию произвольный свободный порт; обычно выбирается 8080)
- **Порт агента gRPC**: 18443 по умолчанию.

## 2. Установка

### 2.1 Поддерживаемые среды

| Товар | Поддержка |
|------|---------|
| Распределения | Debian/Ubuntu, RHEL/CentOS/Rocky/AlmaLinux/Fedora, Alpine, Arch, openSUSE |
| Архитектуры ЦП | Официальные бинарные файлы: `amd64`, `arm64`; исходные сборки также поддерживают `armv7`, `armv6`, `386`, `ppc64le`, `s390x`, `riscv64`, `loong64`. |
| Менеджер по обслуживанию | systemd (рекомендуется); возвращается к `nohup` в контейнерах или других средах без systemd. |
| Память/диск | ≥ 1 ГБ/≥ 10 ГБ (база данных, сертификаты, журналы и основные двоичные файлы находятся в каталоге данных) |
| Порт панели | выбранный в мастере настройки (по умолчанию произвольный свободный порт; `8080` и подобные подходят) |
| Агент gRPC | `18443` по умолчанию |

Внешние команды среды выполнения устанавливаются автоматически установщиком (`scripts/install.sh` и сценарий установки агента, созданный панелью; пропустите с помощью `--no-deps` / `CF_SKIP_DEPS=1`):

| Цель | Пакет |
|---------|---------|
| Брандмауэр/ограничение скорости/маркировка параллелизма | `nftables` (`nft`) |
| Формирование трафика, ссылки и сокеты | `iproute2` (`tc` / `ip` / `ss`) |
| Резервный вариант, когда nft недоступен | `iptables` (`iptables-nft` на EL8+, `iptables` на EL7) |
| Отслеживание соединения | `conntrack-tools` (`conntrack`) |
| Загрузить `nf_conntrack` / `ifb` | `kmod` (`modprobe` / `lsmod`) |
| Обнаружение и очистка процессов | `procps` (`pgrep` / `pkill`) |
| Проверка портов/параметры DH | `lsof` / `openssl` |
| Создание пользователя прокси | `shadow-utils` (Debian `passwd`, Alpine/Arch `shadow`) |
| Загрузки и архивы | `curl` / `ca-certificates` / `tar` / `gzip` / `xz` |

> Отсутствие `nft`/`tc` влияет только на функции ограничения скорости и брандмауэра; панель все равно запускается.
> Сначала запустите `--cpu-info`, чтобы увидеть, как определяется среда и какие пакеты отсутствуют.

### 2.2 Однолинейная установка (рекомендуется)

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh -o install.sh
sudo bash install.sh
```

Или перенаправьте его напрямую (без взаимодействия, без дополнительных флагов):

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash
```

Скрипт будет:

1. Определите дистрибутив, архитектуру ЦП и libc, затем установите базовые пакеты и зависимости времени выполнения;
2. Загрузите `corefusion-linux-<arch>` из выпусков GitHub и сверьте его с соответствующим `.sha256`;
3. Установите `/opt/corefusion` и создайте `data/{sqlite,certs,logs,runtime}`;
4. Запишите только заполнитель `.env` с `SAFE_PATHS=data` — без конфигурации базы данных — поэтому при первом запуске происходит вход в мастер настройки (полный `.env` генерируется мастером);
5. Установите и запустите службу systemd (или запустите под `nohup`, когда systemd недоступен);
6. Подождите, пока все будет готово, затем распечатайте настройки URL, токены и пути к каталогам.

Пример вывода:

```text
==================================================================
 CoreFusion installation complete
------------------------------------------------------------------
 Install dir : /opt/corefusion
 Data dir    : /opt/corefusion/data
 Binary      : /opt/corefusion/corefusion
 Logs        : journalctl -u corefusion -f
------------------------------------------------------------------
 Setup wizard : http://<server-ip>:<random-port>/init?init_token=<token>
 Setup token  : <token>
 Valid for    : 2 hours (see startup log)
 Note         : the token is shown once; after setup this port closes and the panel switches to its normal port.
==================================================================
```

Если панель прослушивает только `127.0.0.1` (например, через обратный прокси-сервер), сценарий печатает команду туннеля SSH вместо недоступного URL.

> Потеряли жетон? Прочтите журнал запуска еще раз: `journalctl -u corefusion -n 50 --no-pager`.
> (без systemd: `tail -n 50 /opt/corefusion/data/logs/panel.log`).

### 2.3 Закрепление версии/зеркала/автономная установка

```bash
# Pin a version
sudo bash install.sh --version v0.13.0-alpha.2

# GitHub download mirror (used as a URL prefix)
sudo bash install.sh --mirror https://ghproxy.net --version latest

# Use a local binary (offline / intranet / pre-built)
sudo bash install.sh --local ./dist/corefusion-linux-arm64

# Explicit target architecture
sudo bash install.sh --arch arm64 --local ./corefusion-linux-arm64
```

> Без `--version` сценарий использует новейшую запись в списке выпусков GitHub.
> Большинство выпусков являются предварительными, поэтому конечная точка `/releases/latest` не используется.
>
> Официальные выпуски предоставляют только `amd64`/`arm64`; используйте `--source` или кросс-скомпилированный двоичный файл с `--local` для других архитектур.

### 2.4 Сборка из исходного кода

```bash
sudo bash install.sh --source --version v0.13.0-alpha.2
```

`--source` клонирует репозиторий (или использует существующую проверку, когда в нем находится скрипт) и запускает `make panel`. Версии Toolchain выбираются для каждой среды:

| Зависимость | Выбор |
|------------|-----------|
| Иди | Чтение из `toolchain`/`go` в `go.mod` (в настоящее время **Go 1.27+**); если версия системы слишком старая, соответствующая цепочка инструментов загружается в `<install-dir>/.toolchain`. |
| Узел | **Узел 22 LTS** по умолчанию (для Vite требуется ≥ 18); соответствующая официальная сборка загружается при необходимости |
| Узел (glibc < 2.28) | Использует сборку `unofficial-builds` glibc-217 (например, CentOS 7). |
| Узел (Альпийский/мусл) | Использует дистрибутив `nodejs`/`npm`. |

Переопределения:

```bash
# Force Go / Node versions
sudo CF_GO_VERSION=1.27.5 CF_NODE_MAJOR=22 bash install.sh --source

# Go toolchain mirror (default https://go.dev/dl)
sudo CF_GO_MIRROR=https://golang.google.cn/dl bash install.sh --source
```

Ручная сборка (разработка/отладка):

```bash
git clone https://github.com/qist/corefusion.git
cd corefusion

# Frontend + panel for the current architecture; the frontend is embedded via go:embed
make panel

# Cross-compile
make panel-linux-amd64
make panel-linux-arm64
```

> `go build ./...` не создает двоичный файл. Создайте панель с помощью
> `go build -o corefusion ./cmd/corefusion/` или `make panel`.

### 2.5 Флаги установщика

| Флаг | Описание |
|------|-------------|
| `-d, --dir <PATH>` | Каталог установки, по умолчанию `/opt/corefusion` |
| `-v, --version <TAG>` | Панельная версия, напр. `v0.13.0-alpha.2`; по умолчанию `latest` |
| `--binary` | Используйте двоичный файл выпуска GitHub (по умолчанию). |
| `--source` | Сборка из исходного кода и подготовка соответствующего Go/Node. |
| `--local <FILE>` | Используйте локальный двоичный файл (автономная установка) |
| `--arch <ARCH>` | Целевая архитектура: `amd64` / `arm64` / `armv7` / `armv6` / `386` / `ppc64le` / `s390x` / `riscv64` / `loong64` |
| `--mirror <URL>` | GitHub префикс загрузки, например. `https://ghproxy.net` |
| `--repo <URL>` | Репозиторий исходного кода, по умолчанию `https://github.com/qist/corefusion.git` |
| `--ref <REF>` | Исходная ветка/тег; по умолчанию `--version`, в противном случае `main` |
| `--no-deps` | Пропустить установку системных зависимостей |
| `--no-start` | Установить и записать сервисный файл не запуская |
| `--cpu-info` | Распечатайте обнаружение среды и отсутствующие зависимости, затем выйдите. |
| `--uninstall` | Остановите службу и удалите программу (сохраняет данные и `.env`) |
| `--purge` | С помощью `--uninstall` также удалите каталог данных и `.env`. |

Связанные переменные среды:

| Переменная | Цель |
|----------|---------|
| `CF_GO_VERSION` | Переопределить версию Go, необходимую для исходных сборок. |
| `CF_NODE_MAJOR` | Переопределить основную версию узла (по умолчанию 22). |
| `CF_GO_MIRROR` | Зеркало загрузки Go Toolchain |
| `CF_SKIP_DEPS` | Установите значение `1` в сценарии установки агента, чтобы пропустить установку зависимостей. |

### 2.6 Структура каталога

```text
/opt/corefusion/
├── corefusion                 # panel binary
├── corefusion.bak             # previous version (when upgrading)
├── .env                       # environment file (0600, generated by the setup wizard)
├── .toolchain/                # Go / Node downloaded for source builds
└── data/                      # data directory (SAFE_PATHS)
    ├── sqlite/app.db          # default SQLite database
    ├── certs/                 # certificates and keys
    ├── logs/                  # runtime logs (without systemd)
    ├── runtime/               # core runtime config and state
    ├── binaries/              # downloaded xray / sing-box cores
    └── proxy/                 # proxy (Caddy/Nginx) sites and config
```

> Установщик создает только `sqlite/`, `certs/`, `logs/` и `runtime/`; `binaries/`, `proxy/`, `rules/` и другие создаются панелью или при установке ядер.
> Каталог данных происходит от `SAFE_PATHS` в `.env` и может быть абсолютным путем. Изменение каталога установки не приводит к перемещению существующих данных.

### 2.7 Управление услугами

systemd (большинство дистрибутивов):

```bash
systemctl status corefusion --no-pager
systemctl restart corefusion
systemctl stop corefusion
journalctl -u corefusion -f          # follow logs
journalctl -u corefusion -n 100      # last 100 lines
```

Без systemd (контейнеры и т.п.):

```bash
cd /opt/corefusion && ./corefusion            # foreground (debugging)
cd /opt/corefusion && setsid nohup ./corefusion >> data/logs/panel.log 2>&1 &
tail -f data/logs/panel.log
```

> Без systemd процесс при загрузке не запускается; перезапустите его вручную после перезагрузки (или перезапустите установщик).

### 2.8 Обновление и удаление

Обновление (сохраняет данные и конфигурацию):

```bash
sudo bash install.sh --version <new-version>
```

Сценарий останавливает службу, создает резервную копию старого двоичного файла под именем `corefusion.bak`, заменяет его и перезапускается. Существующие `.env` и `data/` остаются нетронутыми.

Удалить:

```bash
# Remove the program only; keep data and .env
sudo bash install.sh --uninstall

# Also remove the data directory and .env (irreversible)
sudo bash install.sh --uninstall --purge
```

### 2.9 Файл среды (.env)

Полный `.env` **создается мастером установки** при сохранении конфигурации (DSN базы данных, каталог данных, секреты, порты, домены).

При новой установке установщик записывает только этот заполнитель, чтобы панель не приняла существующий `data/` за инициализированную установку и не пропустила мастер:

```env
SAFE_PATHS=data
```

> Если полная конфигурация (`.env` с `CF_DB_DSN`) уже существует, программа установки никогда не перезаписывает ее, и мастер больше не появляется.
> Более поздние ручные изменения в `.env` вступят в силу после перезагрузки.

#### Каталог данных

```env
SAFE_PATHS=data                       # relative to the install directory
# SAFE_PATHS=/srv/corefusion-data     # or an absolute path
```

#### База данных

`CF_DB_DSN` обнаруживается по префиксу:

| Префикс | База данных |
|--------|----------|
| не установлен или пустой путь | SQLite (по умолчанию) |
| `sqlite://` | SQLite (явный) |
| `mysql://` | MySQL |
| `postgres://` / `postgresql://` | PostgreSQL |

`CF_DB_TYPE` является необязательным и имеет приоритет над обнаружением (`sqlite` / `mysql` / `postgres`).

> **Зашифрованные пароли**: DSN MySQL/PostgreSQL, записанные панелью (мастер настройки/переключатель базы данных)
> хранятся в `.env` как `enc:...` (AES-256-GCM, ключ `CF_SECRET_ENCRYPTION_KEY`).
> Они расшифровываются при чтении; Уведомления о доставке в виде открытого текста, написанные вручную, по-прежнему работают.

**SQLite (по умолчанию)**

```env
# Bare path (detected as SQLite)
CF_DB_DSN=data/sqlite/app.db

# Or explicit sqlite:// prefix
CF_DB_DSN=sqlite:///opt/corefusion/data/sqlite/app.db
```

**MySQL**

```env
# Format: mysql://user:password@tcp(host:port)/dbname?params
CF_DB_DSN=mysql://corefusion:password@tcp(127.0.0.1:3306)/corefusion?charset=utf8mb4&parseTime=True&loc=Local
```

**PostgreSQL**

```env
# Format: postgres://user:password@host:port/dbname?params
CF_DB_DSN=postgres://corefusion:password@127.0.0.1:5432/corefusion?sslmode=disable
```

#### Пул соединений (дополнительно, MySQL/PostgreSQL)

```env
CF_DB_MAX_OPEN_CONNS=100
CF_DB_MAX_IDLE_CONNS=10
```

#### Другие общие переменные

| Переменная | Описание |
|----------|-------------|
| `JWT_SECRET` | Ключ подписи для токенов входа; генерируется при первом запуске при отсутствии |
| `CF_SECRET_ENCRYPTION_KEY` | Ключ для шифрования конфиденциальных настроек (AES-256-GCM); генерируется при отсутствии |
| `CF_INITIAL_ADMIN_PASSWORD` | Начальный пароль администратора (необязательно; по умолчанию случайный и печатается один раз) |
| `CF_NETWORK_TRAFFIC_ACCOUNTING` | Установите значение `0`, чтобы отключить учет трафика на основе iptables (включено по умолчанию). |
| `CF_NETWORK_TRAFFIC_TABLE` | таблица iptables, используемая для учета трафика, по умолчанию `corefusion` |

> Доверенные обратные прокси-серверы для разрешения реальных IP-адресов клиентов больше не настраиваются через переменные среды;
> они хранятся как `panel.trusted_proxies` в **Настройки → Сеть**.

> `.env` содержит секреты; при запуске панель ужесточает разрешения для `0600`. Никогда не совершайте этого.

### 2.10 Docker (необязательно, создайте свой образ)

Репозиторий **не** отправляет Dockerfile. Если вы помещаете его в контейнер, напишите свой собственный образ. Ссылочный вызов:

```bash
docker run -d \
  --name corefusion \
  -p 8080:8080 \
  -p 18443:18443 \
  -v /opt/corefusion/data:/app/data \
  -v /opt/corefusion/.env:/app/.env \
  <your-image>
```

> Контейнеры обычно не имеют привилегий systemd и `nft`, поэтому функции ограничения скорости/брандмауэра не будут работать.
> Рабочий каталог должен соответствовать базе относительного `SAFE_PATHS`.

### 2.11 Проверки после установки

```bash
# Environment and dependencies
sudo bash install.sh --cpu-info

# Service state
systemctl is-active corefusion

# Startup log (contains the setup URL and token)
journalctl -u corefusion -n 50 --no-pager

# Listening ports
ss -lntp | grep corefusion
```

## 3. Начальная конфигурация

Если при первом запуске `.env` не имеет действующего `CF_DB_DSN`, панель еще **не** обслуживает пользовательский интерфейс администратора. Это начинает
**Мастер настройки** на случайном порту в диапазоне 18000–18999 с одноразовым токеном, затем перезапускается как обычная панель после сохранения.

### 3.1 Откройте мастер настройки

1. Скопируйте «мастер установки» URL из вывода программы установки; или
2. Читаем лог на сервере:

```bash
journalctl -u corefusion -n 50 --no-pager | grep -A2 'setup wizard'
```

```text
CoreFusion first start - setup wizard
  URL   : http://<ip>:<port>/init?init_token=<token>
  Token : <token>
  Valid : 2h0m0s
```

3. Откройте URL в браузере (он уже содержит `init_token`, поэтому ввод вручную не требуется).

> По умолчанию сеанс мастера завершается через **2 часа**. Если срок его действия истек или панель перезапускается, получите новую.
> Не делитесь токеном. После завершения настройки этот порт закрывается, и остается только обычный порт панели.

### 3.2 Шаги мастера

Мастер имеет 8 шагов. Вы можете вернуться в любое время; ничего не фиксируется до последнего сохранения.

| Шаг | Содержание |
|------|---------|
| 1. База данных | SQLite / MySQL / PostgreSQL |
| 2. Каталог данных | Написано `SAFE_PATHS` в `.env` |
| 3. Ключи шифрования | `JWT_SECRET` и `CF_SECRET_ENCRYPTION_KEY` |
| 4. Ядра | Какие прокси-ядра установить |
| 5. Прокси | Нет / Nginx / Кэдди |
| 6. Сайты и домены | Порты, веб-путь, учетная запись администратора, валюта, часовой пояс, домены |
| 7. Сертификат HTTPS. | Отключено/загрузка/ACME |
| 8. Резюме | Просмотрите, скачайте `.env`, сохраните и перезапустите. |

#### Шаг 1: База данных

- **SQLite (рекомендуется локальный файл)**: оставьте путь пустым, чтобы использовать `<data-dir>/sqlite/app.db`.
- **MySQL / PostgreSQL**: хост, порт, пользователь, пароль, имя базы данных; PostgreSQL также поддерживает `disable`/`require`/`verify-full`.
- Нажмите «Проверить соединение» для подтверждения. Сохранение также проверяет это. Недостающая база данных создается автоматически (создайте ее вручную, если в учетной записи отсутствует `CREATE`).
- DSN (включая пароль) шифруется перед записью в `.env`.

#### Шаг 2: Каталог данных

Хранит базу данных, сертификаты, журналы, основные двоичные файлы и многое другое; это `SAFE_PATHS` в `.env`. По умолчанию `data`.
(относительно каталога установки); разрешен абсолютный путь. **Не меняйте его позже** или панель
не найдет существующую базу данных и сертификаты.

#### Шаг 3. Ключи шифрования

- `JWT_SECRET`: подписывает токены входа.
- `CF_SECRET_ENCRYPTION_KEY`: шифрует конфиденциальные настройки (пароль базы данных, учетные данные DNS, карты пополнения счета и т. д.).
- По умолчанию оба генерируются случайным образом; используйте «Регенерировать», чтобы получить новые значения. **Изменение `CF_SECRET_ENCRYPTION_KEY` делает ранее зашифрованные данные нечитаемыми** — сделайте резервную копию.

#### Шаг 4: Ядра

Выберите ядра прокси для установки:

- **Xray**: VLESS / VMess / Trojan / Shadowsocks и т. д.;
- **sing-box**: поддерживает Hysteria2/TUIC и другие протоколы QUIC.

После сохранения и перезапуска панель автоматически загрузит и установит их. Проверьте версии и статус в разделе «Протоколы». Вы также можете установить их позже.

#### Шаг 5: Прокси

- **Нет**: панель обслуживает клиентов напрямую (обработайте TLS самостоятельно).
- **Nginx/Caddy**: панель управляет обратным прокси и хостингом сертификатов; выберите один.

Если выбран прокси-сервер, панель обычно прослушивает только `127.0.0.1`, а прокси-сервер обслуживает внешний мир.

#### Шаг 6. Сайты и домены

| Поле | Описание |
|-------|-------------|
| Прослушать адрес | Производится автоматически: прокси → `127.0.0.1`; нет прокси с сертификатом → `0.0.0.0`; в противном случае → `127.0.0.1` |
| Порт панели | Случайный свободный порт по умолчанию; измените его, если хотите (например, 8080) |
| Порт подписки | Необязательно; `0` использует общий порт панели |
| Портальный порт | Необязательный; `0` использует общий порт панели |
| Веб-путь | Путь к интерфейсу администратора, по умолчанию `/`; API всегда `/api/v1` |
| Имя пользователя/пароль администратора | Случайно по умолчанию; **пароль отображается в сводке только один раз** — сохраните его |
| Режим доступа | «Домен» или «IP» |
| Валюта/часовой пояс по умолчанию | Валюта по умолчанию для пополнения карт и балансов; часовой пояс панели и журнала прокси (например, `Asia/Shanghai`) |
| Добавить в обратный прокси | Когда прокси и домены настроены, добавьте к прокси домены панели/подписки/портала за один раз. |

При вводе доменов прописываются соответствующие настройки (домен обратного вызова, конечная точка подписки, общий домен).

#### Шаг 7: Сертификат HTTPS

| Источник | Описание |
|--------|-------------|
| Отключить HTTPS | Панель/портал/подписки обслуживаются через HTTP (небезопасно); с обратным прокси-сервером вы можете добавить TLS на стороне прокси позже |
| Загрузить сертификат | Вставьте сертификат PEM и закрытый ключ PEM (только режим доступа к домену) |
| ACME | Выдает сертификат при отправке этого шага; поддерживает доменные и IP-сертификаты |

Варианты ACME:

- **CA**: Let's Encrypt, Let's Encrypt (промежуточный), ZeroSSL, Google общедоступный центр сертификации;
- **Цель**: настроенный домен или общедоступный IP-адрес (IP-сертификаты поддерживаются только Let's Encrypt);
- **Задание**: `HTTP-01` (требуется порт 80) или `DNS-01` (подстановочные знаки, без порта 80; выберите поставщика DNS и введите учетные данные);
- **Тип/размер ключа**: ECC 256/384 или RSA 2048/3072/4096;
- **Google Публичный ЦС**: требуется EAB; введите идентификатор ключа/HMAC вручную или используйте учетную запись службы GCP.

> IP-сертификаты автоматически определяют общедоступный IPv4/IPv6 хоста. За прокси-сервером обнаруженный адрес принадлежит хосту, а не выходу прокси.
> Сертификаты домена также можно выдать позже в разделе «Сертификаты».

#### Шаг 8: Резюме

Показывает базу данных, каталог данных, ядра, прокси, порты, учетную запись администратора, домены и ключи `.env` (секреты замаскированы) и предоставляет:

- **Загрузить .env**: сохраните копию конфигурации;
- **URL-адреса доступа**: конечные URL-адреса панели/подписки/портала; HTTP помечен как небезопасный.

Нажмите «Сохранить и перезапустить», чтобы записать базу данных и `.env`; панель перезапускается в обычном режиме.

### 3.3 После установки

- Служба перезапускается, и в журнале запуска печатается окончательный адрес прослушивания;
- Войдите в систему с учетной записью администратора, получите доступ к URL и веб-пути из сводки;
- Если пароль утерян, сбросьте его в автономном режиме с помощью `./corefusion admin reset-password`.

### 3.4 Неинтерактивная настройка CLI

Для автоматизированных или автономных серверов напишите конфигурацию и отметьте установку как завершенную:

```bash
cd /opt/corefusion
./corefusion init \
  --db-type sqlite \
  --data-dir /opt/corefusion/data \
  --admin-username admin \
  --admin-password 'change-me-strong-password' \
  --listen-port 8080 \
  --proxy-type caddy \
  --cores xray,singbox \
  --panel-domain panel.example.com \
  --tls-mode acme --tls-domain panel.example.com --tls-email you@example.com
```

Общие флаги:

| Флаг | Описание |
|------|-------------|
| `--db-type` / `--db-host` / `--db-port` / `--db-user` / `--db-password` / `--db-name` | Настройки базы данных |
| `--data-dir` | Каталог данных; по умолчанию `SAFE_PATHS` или `./data` |
| `--listen-port` / `--subscription-port` / `--portal-port` / `--web-path` | Порты и веб-путь (по умолчанию произвольный свободный порт) |
| `--admin-username` / `--admin-password` | Учетная запись администратора (случайный пароль печатается один раз, если его опустить) |
| `--proxy-type` | `none` / `nginx` / `caddy` |
| `--cores` | Ядра для установки, через запятую: `xray,singbox`. |
| `--panel-domain` / `--subscription-domain` / `--portal-domain` | Домены (прописаны в настройках и добавлены в обратный прокси) |
| `--tls-mode` | `none` / `self_signed` / `acme` |
| `--tls-domain` / `--tls-email` / `--tls-challenge` / `--tls-key-type` / `--tls-key-bits` | Параметры сертификата (для `--tls-challenge` по умолчанию — `http-01`; для `dns-01` требуется `--tls-dns-channel` или `--tls-dns-provider`) |
| `--tls-ip-cert` | Выдать сертификат для обнаруженного общедоступного IP-адреса (только Let’s Encrypt) |
| `--acme-provider` | `lets_encrypt` / `lets_encrypt_staging` / `zerossl` / `google` |
| `--currency` / `--timezone` | Валюта/часовой пояс по умолчанию |

Полный список: `./corefusion init --help`. Затем запустите службу:

```bash
systemctl restart corefusion
```

### 3.5 Повторный запуск мастера установки

Чтобы начать заново (удаляет `.env` и метки настройки, **сохраняет данные**):

```bash
cd /opt/corefusion
./corefusion reset-init      # type RESET to confirm
systemctl restart corefusion
```

Затем используйте новый URL и токен из журнала запуска.

> Повторная инициализация сбрасывает учетную запись администратора и веб-путь. Бизнес-данные в старой базе данных остаются, но вам может потребоваться заново создать учетную запись для входа.
>
> `reset-init` удаляет весь `.env` (включая `SAFE_PATHS`). **Если ваш каталог данных имеет пользовательский абсолютный путь**, восстановите `SAFE_PATHS` перед перезапуском, иначе панель будет выглядеть в `./data`:
>
> ```баш
> printf 'SAFE_PATHS=/srv/corefusion-data\n' > /opt/corefusion/.env
> ```

### 3.6 Безопасность после первого входа в систему

#### Изменить первоначальный пароль

1. Нажмите на имя пользователя в правом верхнем углу;
2. Выберите «Сменить пароль»;
3. Введите старый и новый пароли;
4. Нажмите «Сохранить».

#### Включить вход с динамическим кодом (2FA / TOTP)

> После включения учетная запись переключается на **вход с динамическим кодом**: статический пароль больше не принимается; только
> Шестизначный код из вашего приложения для аутентификации (или одноразовый код восстановления) работает. Это **заменяет** пароль для входа в систему — это
> не двухэтапная проверка «пароль + код».

1. Нажмите на имя пользователя в правом верхнем углу;
2. Выберите «Включить 2FA»;
3. Введите текущий пароль (только для подтверждения этого изменения);
4. Отсканируйте QR-код с помощью приложения-аутентификатора (Google Authenticator / 1Password и т. д.) или введите ключ вручную;
5. Введите 6-значный код, чтобы завершить включение;
6. **Сохраните коды восстановления немедленно** (можно загрузить); каждый код работает один раз.

Вход в систему после:

- После ввода имени пользователя поле пароля становится «6-значный код/код восстановления», а кнопка — «Войти с кодом»;
- Введите текущий код; **статический пароль больше нельзя использовать**;
- Коды восстановления одноразовые; восстановить их в разделе «Вход с динамическим кодом (2FA)», когда они закончатся (это аннулирует все старые коды).

Если аутентификатор утерян и коды восстановления исчерпаны, отключите 2FA в автономном режиме на сервере:

```bash
cd /opt/corefusion
./corefusion admin 2fa reset -u admin    # disables 2FA, clears the secret and recovery codes, revokes all sessions
```

> Единственный суперадминистратор, не имеющий ни аутентификатора, ни кодов восстановления, не может выполнить восстановление через веб-интерфейс и должен использовать приведенную выше команду.

#### Зарегистрируйте Passkey (необязательно)

1. Нажмите на имя пользователя в правом верхнем углу;
2. Выберите «Управление Passkey»;
3. Нажмите «Зарегистрировать новый Passkey»;
4. Заполните подсказку устройства.

> **Примечание**. Для ключей доступа требуется HTTPS или localhost, а домен должен быть внесен в список разрешенных.

## 4. Панель управления

На панели мониторинга отображается обзор кластера с несколькими узлами и состояние узла.

### 4.1 Что это показывает

- **Информация о системе**: имя хоста, версия ОС, время безотказной работы, процессор, память.
- **Трафик**: пропускная способность в реальном времени, общий трафик, ежемесячный тренд.
- **Работоспособность узлов**: количество онлайн/оффлайн/деградация, узлы с высокой нагрузкой
- **Оповещения**: автономные узлы, устаревшие узлы, скоро истечение срока действия сертификатов, предупреждения о квотах.
- **Ресурсы кластера**: среднее значение ЦП, памяти, диска и пропускной способности.

### 4.2 Действия

- Нажмите «Просмотреть подробности», чтобы открыть страницу сведений об узле.
- Нажмите карточку узла, чтобы увидеть ее текущий статус.
- Используйте фильтры, чтобы сузить список по статусу, типу или региону.

## 5. Управление узлами

Управление узлами является ядром CoreFusion и поддерживает несколько типов узлов.

### 5.1 Типы узлов

| Тип | Описание |
|------|-------------|
| Автономный (`standalone`) | Независимый основной узел |
| Зеркало (`mirror`) | Синхронизирует конфигурацию с целевого узла |
| Основной/резервный (`primary_backup`) | Партнерские узлы, которые переключаются друг на друга |
| Цепной вход (`chain_entry`) | Входной узел связанного прокси |
| Цепной выход (`chain_exit`) | Выходной узел связанного прокси |

### 5.2 Добавление узла

1. Откройте «Управление узлами»;
2. Нажмите «Добавить сервер»;
3. Заполните основные сведения:
   - Имя, например `HongKong-HK01`
   - Имя хоста: IP или домен
   - Регион, например `HK`, `JP`, `US`
   - Тип узла;
4. Установите порт агента (по умолчанию `18443`);
5. Выберите поддерживаемые ядра;
6. Нажмите «Сохранить».

### 5.3 Развертывание в один клик

1. После добавления узла нажмите «Команда Bootstrap»;
2. Скопируйте команду установки;
3. Запустите его от имени пользователя root на удаленном узле:

   ```bash
   curl -fsSL https://your-panel/install.sh | bash
   ```

4. Агент загружается, регистрируется и запускается автоматически.

### 5.4 Детали узла

Щелкните узел, чтобы открыть страницу его сведений:

- **Обзор**: основная информация, статус агента, статус сертификата.
- **Центр протоколов**: конфигурация основного процесса
- **Прокси**: конфигурация Caddy/Nginx.
- **Основные процессы**: запуск/остановка/перезапуск
- **WARP**: конфигурация WARP
- **Прямые домены**: управление доменами
- **Ограничение скорости**: формирование трафика
- **Сертификаты**: привязки сертификатов.
- **Интернет-пользователи**: онлайн-пользователи в режиме реального времени.

### 5.5 Действия узла

- **Синхронизация конфигурации**: передача конфигурации панели на узел.
- **Принудительное переподключение**: разорвите соединение агента и подключитесь заново.
- **Агент обновления**: отправьте обновление агента.
- **Отозвать сертификат**: отозвать сертификат агента узла.

## 6. Протокольный центр

Центр протоколов настраивает параметры протоколов для основных процессов.

### 6.1 Поддерживаемые ядра

| Ядро | Описание |
|------|-------------|
| Xray-ядро | VLESS / VMess / Trojan / Shadowsocks и другие |
| sing-box | Модульная универсальная прокси-платформа с поддержкой TUN; поддерживает Hysteria2 / TUIC и другие протоколы QUIC |

### 6.2 Модули конфигурации

- **Журнал**: журнал доступа, журнал ошибок, режим вывода.
- **API**: адрес прослушивания gRPC API, список сервисов
- **DNS**: серверы DNS, стратегия запросов, статические хосты.
- **Маршрутизация**: правила маршрутизации, балансировка нагрузки, маршрутизация VLESS.
- **Входящие**: список входящих, настройки протокола, транспорт, TLS.
- **Исходящие**: список исходящих сообщений, настройки протокола, транспорт.
- **Транспорт**: WebSocket, gRPC, XHTTP, TUN и т. д.
- **TLS**: сертификаты, ALPN, отпечаток uTLS, ECH.
- **Reality**: управление целями, пары ключей, короткие идентификаторы.
- **Проверка работоспособности**: зонд URL, интервал, параллелизм
- **FakeDNS**: пул IP-адресов, размер пула.
- **Метрики**: прослушиватель метрик Prometheus.
- **Политика**: таймауты соединения, буферы, статистика.
- **Геоданные**: автоматическое обновление, файлы ресурсов.
- **Ограничения версий**: минимальная/максимальная версия.

### 6.3 Входящая конфигурация

1. Выберите ядро и протокол;
2. Заполните основные сведения:
   - Тег
   - Слушать адрес и порт
   - Тип протокола
3. Установить параметры протокола (UUID, пароль и т.д.);
4. Выберите транспорт (TCP, WebSocket, gRPC и т. д.);
5. Настроить TLS (сертификат, ALPN);
6. Сохраните и примените к ядру.

### 6.4 Исходящая конфигурация

1. Добавить исходящий;
2. Установите тег и протокол;
3. Установите адрес и порт сервера;
4. Настройте транспорт и TLS;
5. Сохраните и примените.

### 6.5 Делитесь ссылками

1. Нажмите «Поделиться ссылкой» в списке входящих;
2. Выберите формат:
   - Поделиться
   - Михомо YAML
   - sing-box JSON
   - Xray JSON
3. Скопируйте ссылку или сгенерируйте QR-код.

## 26. Часто задаваемые вопросы

### 26.1 Панель не запускается

- Проверьте, используется ли порт уже
- Убедитесь, что `.env` действителен.
- Проверьте логи: `journalctl -u corefusion -f`; без systemd, `tail -f <install-dir>/data/logs/panel.log`

### 26.2 Узел не в сети

- Убедитесь, что агент запущен: `systemctl status corefusion-agent`.
- Проверьте подключение к сети
- Проверьте правила брандмауэра (порт `18443`)

### 26.3 Выдача сертификата не удалась

- Проверьте разрешение DNS
- Убедитесь, что порт 80 доступен.
- Проверьте конфигурацию провайдера DNS.
- Проверьте журналы сертификатов

### 26.4 Подписка не работает

- Проверьте ссылку на подписку
- Убедитесь, что узел находится в сети
- Убедитесь, что основной процесс запущен
- Проверьте правила брандмауэра

### 26.5 Не удалось выполнить обратный вызов пополнения счета

- Проверьте обратный вызов URL
- Убедитесь, что ключ сайта соответствует
- Проверьте список разрешенных IP-адресов
- Проверьте журналы заказов

### 26.6 Страница портала недоступна

- Убедитесь, что порт портала открыт
- Проверьте конфигурацию пути портала
- **Важно**: убедитесь, что обратный прокси-сервер перенаправляет домен портала на **порт механизма портала**, а не на порт основной панели — при пересылке на неправильный порт вместо портала отображается пустая страница или панель. Проверьте `upstream`/`local_port` в записи прокси-сайта.
- Откройте `http://<portal-domain>:<portal-port>` напрямую, чтобы проверить сам механизм портала.
- Проверьте конфигурацию обратного прокси
- Проверьте логи портала

## Приложение

### А. Порты по умолчанию

| Порт | Цель |
|------|---------|
| Назначается мастером настройки (по умолчанию произвольный свободный порт) | Админ панель (изменяемая) |
| 18443 | Агент gRPC (изменяемый) |
| 0 (отключено по умолчанию) | Выделенный порт механизма подписки (пустой или `0` использует основной порт) |
| 0 (отключено по умолчанию) | Выделенный порт механизма портала (пустой или `0` использует основной порт) |
| 80 / 443 | Обратный прокси (Caddy/Nginx) HTTP/HTTPS |

### Б. Пути по умолчанию

| Путь | Цель |
|------|---------|
| `/` | Панель администратора (портал также находится по адресу `/`, если не настроен специальный механизм портала) |
| `/sub/:token` | Получение подписки (если выделенный порт подписки не настроен) |
| `/p` | Страница портала (если выделенный порт портала не настроен) |
| `/:token` | Получение подписки (с выделенным портом подписки, без префикса `/sub`) |

### C. Инструмент командной строки

Бинарный файл панели поддерживает следующие подкоманды (без аргументов запускает сервер):

```bash
# Start the panel (same as ./corefusion server)
./corefusion

# Run database migrations
./corefusion migrate

# Offline administration (when you cannot sign in)
./corefusion admin reset-password -u admin -p 'new-password'
./corefusion admin 2fa reset -u admin
./corefusion admin list

# Version / help
./corefusion version
./corefusion help
```

> Без модуля systemd перезапустите, остановив старый процесс и запустив его снова с помощью `nohup`; логи находятся в `<install-dir>/data/logs/panel.log`.
