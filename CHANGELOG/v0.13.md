## v0.13.2 — 2026-11-23

> 出站启用/禁用、xray 保底出站、WAF 三层规则引擎（SCORE 阈值 + combo.jsonl）。

### 中文

- **sing-box 出站开关**：出站列表新增启用/禁用；禁用项在生成配置时剔除，并同步清理 selector/urltest 成员、`detour`、`dns.servers[].detour`、`route.rules[].outbound` 与 `route.final`（回退 direct），空分组级联剔除。
- **xray 保底出站**：出站列表幂等补齐 `direct`（freedom）与 `blocked`（blackhole），并置为只读；补行追加在用户出站之后，避免把路由默认出口静默改掉。
- **WAF 配置口径统一**：全局配置读取时补齐 `cc_mode`、`match_cache`、`score_block_threshold` 等新参数并写回；站点级按全局补全，`match_cache` 仅全局保留，历史误加到站点级的会被清除。
- **WAF 三层规则引擎**：接入 `score_block_threshold`（0=只记分、1=任意 SCORE 命中即拦、>1=累计达阈值），支持域名级覆盖；规则同步默认包含 `combo.jsonl`，历史规则源清单会自动补全该文件。
- **WAF 站点级口径对齐 NginxGuard**：`domain.json` 的键名以 NginxGuard `config_*` 去前缀为准（CaddyGuard 已对齐同一套；`log_dir`/`match_cache`/`output_html` 仅全局生效）。站点级补缺不再固定用 caddy 全局，改为按节点实际运行的代理取基线（本机按运行状态；远程节点只有一套全局配置就用该套，两套都有或都没有时以 Nginx 为准），避免把另一套引擎的限速/跳转值写成站点级显式覆盖。
- **站点级编辑弹窗补齐**：新增 SCORE 拦截阈值输入与 `combo.jsonl` 规则文件（可编辑域名副本、可参考全局内容）；数值参数统一按数字写入。
- 管理端 16 语言补齐相关文案。

### English

- **sing-box outbound toggle**: outbounds can now be enabled/disabled. Disabled entries are removed when generating configs, together with their `selector`/`urltest` memberships, `detour`, `dns.servers[].detour`, `route.rules[].outbound` and `route.final` references (falling back to `direct`); empty groups are pruned recursively.
- **xray fallback outbounds**: `direct` (freedom) and `blocked` (blackhole) are inserted idempotently and marked read-only. New rows are appended after user outbounds so the routing default outbound never changes silently.
- **Consistent WAF config defaults**: reading the global config now fills in `cc_mode`, `match_cache`, `score_block_threshold` and writes them back. Per-domain entries inherit the global defaults; `match_cache` stays global-only and accidental per-domain copies are removed.
- **WAF three-layer rule engine**: added `score_block_threshold` (0 = score only, 1 = block on any SCORE hit, >1 = block once accumulated score reaches the threshold) with per-domain override. Rule sync now includes `combo.jsonl`, and legacy source manifests are completed automatically.
- **WAF site-level semantics aligned with NginxGuard**: `domain.json` keys follow NginxGuard's `config_*` names without the prefix (CaddyGuard now matches the same set; `log_dir`/`match_cache`/`output_html` remain global-only). Site-level defaults are no longer always filled from the caddy global config; the baseline now follows the proxy actually running on the node (local: runtime detection; remote: the only configured set, otherwise Nginx). This prevents another engine's rate-limit/redirect values from silently becoming site-level overrides.
- **Site-level dialog completed**: added the SCORE block threshold input and the `combo.jsonl` rule file (editable per-domain copy with the global content as reference); numeric parameters are written as numbers.
- Related strings added to all 16 admin UI locales.

### Русский

- **Переключатель исходящих sing-box**: у исходящих появилась возможность включения/отключения. Отключённые записи удаляются при генерации конфигурации вместе со ссылками в `selector`/`urltest`, `detour`, `dns.servers[].detour`, `route.rules[].outbound` и `route.final` (с откатом на `direct`); пустые группы удаляются каскадно.
- **Резервные исходящие xray**: `direct` (freedom) и `blocked` (blackhole) идемпотентно добавляются и помечаются только для чтения. Новые строки добавляются после пользовательских, чтобы не менять маршрут по умолчанию незаметно.
- **Единые значения по умолчанию WAF**: при чтении глобальной конфигурации теперь добавляются `cc_mode`, `match_cache`, `score_block_threshold` с записью обратно. Доменные записи наследуют глобальные значения; `match_cache` остаётся только глобальным, ошибочные доменные копии удаляются.
- **Трёхуровневый движок правил WAF**: добавлен `score_block_threshold` (0 — только баллы, 1 — блокировка при любом срабатывании SCORE, >1 — блокировка при накоплении порога) с переопределением на уровне домена. Синхронизация правил теперь включает `combo.jsonl`, старые списки источников дополняются автоматически.
- **Семантика доменных настроек WAF приведена к NginxGuard**: ключи `domain.json` соответствуют именам `config_*` без префикса (CaddyGuard выровнен по тому же набору; `log_dir`/`match_cache`/`output_html` действуют только глобально). Доменные значения по умолчанию больше не берутся всегда из глобальной конфигурации caddy — базой служит прокси, реально работающий на узле (локально — по состоянию процессов; удалённо — единственный настроенный набор, иначе Nginx). Это исключает молчаливое превращение лимитов/редиректа другого движка в доменные переопределения.
- **Диалог доменных настроек дополнен**: добавлены поле порога блокировки SCORE и правило `combo.jsonl` (редактируемая доменная копия с глобальным содержимым для справки); числовые параметры записываются числами.
- Строки интерфейса добавлены во все 16 языков панели.

### فارسی

- **کلید فعال/غیرفعال خروجی‌های sing-box**: خروجی‌ها اکنون قابل فعال/غیرفعال‌سازی هستند. موارد غیرفعال هنگام تولید پیکربندی حذف می‌شوند و ارجاع‌های آن‌ها در `selector`/`urltest`، `detour`، `dns.servers[].detour`، `route.rules[].outbound` و `route.final` (با بازگشت به `direct`) نیز پاک می‌شوند؛ گروه‌های خالی به‌صورت آبشاری حذف می‌گردند.
- **خروجی‌های پیش‌فرض xray**: `direct` (freedom) و `blocked` (blackhole) به‌صورت idempotent اضافه و فقط‌خواندنی می‌شوند. ردیف‌های جدید بعد از خروجی‌های کاربر افزوده می‌شوند تا مسیر پیش‌فرض به‌طور خاموش تغییر نکند.
- **یکسان‌سازی پیش‌فرض‌های WAF**: هنگام خواندن پیکربندی سراسری، `cc_mode`، `match_cache` و `score_block_threshold` تکمیل و بازنویسی می‌شوند. تنظیمات دامنه از سراسری ارث می‌برند؛ `match_cache` فقط سراسری می‌ماند و نسخه‌های اشتباه دامنه‌ای حذف می‌شوند.
- **موتور سه‌لایه قواعد WAF**: `score_block_threshold` اضافه شد (0 = فقط امتیاز، 1 = مسدودسازی با هر برخورد SCORE، >1 = مسدودسازی پس از رسیدن به آستانه) با امکان بازنویسی در سطح دامنه. همگام‌سازی قواعد اکنون `combo.jsonl` را شامل می‌شود و فهرست منابع قدیمی به‌طور خودکار تکمیل می‌گردد.
- **هم‌ترازی معنایی تنظیمات دامنه WAF با NginxGuard**: کلیدهای `domain.json` همان نام‌های `config_*` بدون پیشوند هستند (CaddyGuard نیز با همین مجموعه هم‌تراز شده؛ `log_dir`/`match_cache`/`output_html` فقط سراسری اعمال می‌شوند). مقادیر پیش‌فرض دامنه دیگر همیشه از پیکربندی سراسری caddy گرفته نمی‌شوند؛ مبنا، پروکسی‌ای است که واقعاً روی گره اجرا می‌شود (محلی: بر اساس وضعیت اجرا؛ راه دور: تنها مجموعهٔ پیکربندی‌شده، در غیر این صورت Nginx). این کار مانع می‌شود که محدودیت نرخ/تغییرمسیر موتور دیگر به‌صورت خاموش به بازنویسی سطح دامنه تبدیل شود.
- **تکمیل پنجره ویرایش سطح دامنه**: ورودی آستانه مسدودسازی SCORE و فایل قواعد `combo.jsonl` اضافه شد (نسخه قابل ویرایش دامنه با نمایش محتوای سراسری برای مرجع)؛ پارامترهای عددی به‌صورت عدد نوشته می‌شوند.
- رشته‌های مربوطه به هر ۱۶ زبان رابط مدیریت اضافه شد.

## v0.13.1 — 2026-11-23

> 移除运行配置里无效的 `proxySettings.acceptProxyProtocol`；前置承载标记继续由 `sockopt.acceptProxyProtocol` 直接生效。

### 中文

- 不再派生 `proxySettings.acceptProxyProtocol`。实测 xray 26.x 只认 `streamSettings.sockopt.acceptProxyProtocol`（带上它会打印 `accepting PROXY protocol`），入站根部的 `proxySettings.acceptProxyProtocol` 已被忽略，保留只会让排障时误判。
- 面板存储与订阅渲染不变，nginx/caddy 按 SNI 分流并补发 PROXY 头的节点行为不变。

### English

- No longer derive `proxySettings.acceptProxyProtocol`. Tested on xray 26.x: only `streamSettings.sockopt.acceptProxyProtocol` is honoured (logs `accepting PROXY protocol`); the inbound-level `proxySettings.acceptProxyProtocol` is ignored and only misleads troubleshooting.
- Storage model and subscription rendering are unchanged; nodes fronted by nginx/caddy with PROXY protocol behave the same.

### Русский

- Больше не формируется `proxySettings.acceptProxyProtocol`. Проверено на xray 26.x: учитывается только `streamSettings.sockopt.acceptProxyProtocol` (в логе `accepting PROXY protocol`), а `proxySettings.acceptProxyProtocol` на уровне входа игнорируется и только путает при диагностике.
- Хранение конфигурации и генерация подписок не изменились; поведение узлов за nginx/caddy с PROXY protocol прежнее.

### فارسی

- دیگر `proxySettings.acceptProxyProtocol` تولید نمی‌شود. در xray 26.x تنها `streamSettings.sockopt.acceptProxyProtocol` مؤثر است (در لاگ `accepting PROXY protocol`)، و `proxySettings.acceptProxyProtocol` در سطح inbound نادیده گرفته می‌شود و فقط عیب‌یابی را گمراه می‌کند.
- مدل ذخیره‌سازی و تولید اشتراک تغییری نکرده؛ رفتار گره‌های پشت nginx/caddy با PROXY protocol یکسان است.

## v0.13.0 — 2026-11-23

> 三库（SQLite / MySQL / PostgreSQL）切库与还原、备份远程存储、探测模板、初始化密钥导出等一批修复后的首个正式版。

### 中文

- **初始化与密钥**：向导新增「下载 .env.secret（含主密钥）」并明确提示必须与 `.env` 成对备份；修复完成初始化时重新生成主密钥、导致下载的密钥与落盘不一致的问题。`.env.secret` 固定 `0600`。
- **节点**：安装脚本支持自定义 Agent gRPC 端口（不再写死 18443）；删节点时清理 `node_certificates` 并把 `certificates.issuer_node_id` 置空，启动时幂等修复历史孤儿绑定。
- **备份**：修复 Web 界面下载（ticket 二次解包导致「操作失败」）；SQLite 还原先关闭旧连接再覆盖，避免 WAL 把还原前的数据写回；S3 未配 region 时默认 `us-east-1`；还原状态跨进程持久化；定时备份按 cron 表达式执行，`last_run_at` 改可空。
- **多库**：修复 `TEXT` 列默认值、零值时间（`last_check` / `last_run` / `last_run_at`）导致的 MySQL 建表、空库初始化、创建源失败；跨库还原插入改为幂等 upsert；删除客户端不再按本地 ID 误删 `warp_configs`。
- **探测**：优选探测按入口模板真实拨号（只替换 `server`，SNI/ws/grpc 保持）；入口仅列配置了 CDN 接入的节点/入站；链路探测健康优先 80/20；禁用本机裸 TCP 测活；链路目标在无 SNI 时回退接入域名。
- **订阅**：`base64_uri` 正文恢复纯 base64（此前混入 `Subscription-Userinfo` 文本，标准客户端解码为 0 个节点）。
- **链式代理**：入口/探针入站/出口候选职责互斥；模板模式与「全部出口不可用必须阻断」实测通过。
- **验收**：三库完整 API 各 73 项、手动/定时备份 × FTP/S3/WebDAV、链式代理、线上订阅 15 节点、初始化密钥导出与多证书场景均已实测。

### English

- **Bootstrap & keys**: the wizard can now download `.env.secret` (master key) with an explicit “back up together with `.env`” warning; fixed the master key being regenerated on complete, which made the downloaded key differ from the one on disk. `.env.secret` stays `0600`.
- **Nodes**: the install script honours a custom Agent gRPC port (no longer hard-coded 18443); deleting a node cleans `node_certificates` and clears `certificates.issuer_node_id`, with an idempotent startup repair for historical orphans.
- **Backups**: fixed Web download (double-unwrapped ticket caused “operation failed”); SQLite restore now closes the old connection before overwriting so WAL cannot write pre-restore data back; S3 defaults to `us-east-1` when region is omitted; restore status survives the in-place restart; scheduled backups follow the cron expression and `last_run_at` is nullable.
- **Multi-database**: fixed MySQL DDL / empty-DB init / CF source creation failures caused by TEXT defaults and zero timestamps (`last_check`, `last_run`, `last_run_at`); cross-DB restore inserts are idempotent upserts; deleting a client no longer touches `warp_configs` by local ID.
- **Probing**: preferred-IP probing dials through the selected entry template (only `server` replaced, SNI/ws/grpc untouched); entry candidates only include CDN-backed nodes/inbounds; chain probing prefers healthy entries 80/20; bare local TCP probing is disabled; chain targets fall back to the access-domain SNI.
- **Subscriptions**: `base64_uri` is pure base64 again (the `Subscription-Userinfo` text made standard clients decode zero nodes).
- **Chain proxy**: entry / probe inbound / exit candidate lists are mutually exclusive; template mode and “all exits down must block” verified on real nodes.
- **Verification**: full three-database API suites (73 checks each), manual/scheduled backups across FTP/S3/WebDAV, chain proxy, 15 live subscription nodes, bootstrap key export and multi-certificate scenarios were all exercised.

### Русский

- **Инициализация и ключи**: мастер-ключ можно скачать отдельным файлом `.env.secret` (с явным предупреждением хранить его вместе с `.env`); исправлена повторная генерация ключа при завершении мастера, из-за которой скачанный ключ не совпадал с файлом. Права `0600`.
- **Узлы**: скрипт установки учитывает нестандартный gRPC-порт Agent; при удалении узла очищаются `node_certificates` и `certificates.issuer_node_id`, при старте выполняется идемпотентный ремонт старых «осиротевших» привязок.
- **Резервные копии**: исправлено скачивание из веб-панели; восстановление SQLite сначала закрывает соединение, затем перезаписывает БД (WAL больше не возвращает старые данные); для S3 по умолчанию `us-east-1`; статус восстановления сохраняется между перезапусками; задания по расписанию соблюдают cron, `last_run_at` допускает NULL.
- **Мульти-СУБД**: устранены сбои MySQL при создании таблиц, инициализации пустой БД и создании источника из-за TEXT-значений по умолчанию и нулевых дат; вставка при кросс-СУБД восстановлении идемпотентна; удаление клиента не затрагивает `warp_configs`.
- **Проверки**: шаблонный режим предпочтительных IP, приоритет здоровых целей 80/20, отключение «голого» TCP-опроса, корректный SNI для цепочек.
- **Подписки**: тело `base64_uri` снова чистый base64.
- **Цепочки**: списки входа/пробника/выхода не пересекаются; проверены шаблонный режим и блокировка при недоступности всех выходов.

### فارسی

- **راه‌اندازی و کلیدها**: امکان دانلود جداگانهٔ `.env.secret` (کلید اصلی) با هشدار صریح برای پشتیبان‌گیری همراه `.env`؛ بازتولید ناخواستهٔ کلید در پایان ویزارد که باعث تفاوت کلید دانلودشده با فایل می‌شد رفع شد. دسترسی `0600`.

- **پروکسی زنجیره‌ای**: فهرست ورودی/کاوشگر/خروجی از هم جدا شده‌اند؛ حالت قالب و «مسدودسازی هنگام از کار افتادن همهٔ خروجی‌ها» آزمایش شد.

## v0.13.0-rc.11 — 2026-11-22

> 门户关闭时合规文档页不再显示点进去 404 的「返回门户」链接。

### 中文

- 合规文档页在门户总开关关闭时隐藏「← 站点名」返回链接（门户关闭后 `/p` 返回 `PORTAL_DISABLED`，原链接是死链）。
- 门户开启时行为不变；独立门户端口（根路径 `/legal/*`）仍保留返回门户入口。

### English

- When the portal is disabled, the legal page no longer renders a “← site name” link that leads to `PORTAL_DISABLED` (`/p` is a 404 in that state).
- Behaviour is unchanged while the portal is enabled; the dedicated-port `/legal/*` pages still link back to the portal.

### Русский

- При выключенном портале юридическая страница больше не показывает ссылку «← название сайта», ведущую на `PORTAL_DISABLED` (в этом состоянии `/p` — 404).
- При включённом портале поведение не меняется; страницы `/legal/*` на отдельном порту по-прежнему ссылаются на портал.

- **اصلاح آمار داشبورد**: سرویس‌های هسته به «در حال اجرا / متوقف / بدون گزارش» تفکیک شدند، بنابراین نودهای راه‌دوری که هنوز گزارش نداده‌اند «متوقف» شمرده نمی‌شوند؛ تعداد نودها بر اساس سرورهای نود محاسبه می‌شود؛ تعداد مشترکان آنلاین بین نودها یکتا می‌شود؛ اشتراک‌های متوقف و منقضی در کنار اشتراک‌های فعال نمایش داده می‌شوند.

- **پایش sing-box روی نودهای راه‌دور**: فرمان gRPC جدید `fetch_singbox_connections` در Agent اضافه شد و پنل می‌تواند داده‌های اتصال `clash_api` نودهای راه‌دور را بخواند؛ صفحه جزئیات نود دلیل دقیق بازگشتی از بک‌اند را نشان می‌دهد.
- **اصلاح مدیریت قواعد**: منابعی که کلید زمان‌بندی آن‌ها خاموش است دیگر در همگام‌سازی آغازین به‌روزرسانی نمی‌شوند؛ فایل‌های حذف‌شده پس از راه‌اندازی مجدد بازنمی‌گردند (منابع داخلی فقط یک‌بار ایجاد می‌شوند)؛ در شروع فقط فایل‌هایی بازیابی می‌شوند که در پایگاه داده هستند ولی روی دیسک نیستند.

## v0.13.0-beta.97 — 2026-11-19

### 中文

- **CDN 链路探测通用化**：不再只支持 Cloudflare，任意 CDN 的域名/IP 都可探测；探测出口与探针入站都必须显式选择，系统不再随机挑入口。
- **单个探针入站测完全部条目**：一轮探测只用一个显式选定的入站，把全部 CDN 域名/IP 测完；结果写回健康度（连续失败 3 次标记失败，成功立即恢复），其他入站可直接复用通过的条目。
- **排除不该测的条目**：直连域名/IP 与各节点自定义域名不参与链路探测（入口不同，用同一入站凭据必然假失败）。
- **订阅下发收紧**：只下发「健康且延迟低于阈值」的 CDN 域名/IP，`direct` 条目不受延迟阈值限制。
- **探测调度复用探测设置**：链路探测跟随「探测设置」的时间间隔与拨号核心，拨号核心按 xray → sing-box → mihomo 自动选择。

### English

- **Generic CDN chain probing**: no longer limited to Cloudflare — any CDN domain/IP can be probed. Both the exit and the probe inbound must be selected explicitly; the system no longer picks an inbound at random.
- **One probe inbound covers all entries**: a round uses a single explicitly selected inbound to test every CDN domain/IP, then writes the health result back (3 consecutive failures mark it failed, one success restores it) so other inbounds can reuse the passing entries.
- **Entries excluded from probing**: direct domains/IPs and per-node custom domains are skipped, since a different entry point would produce false failures with the same inbound credentials.
- **Tighter subscription output**: only healthy CDN domains/IPs with latency below the threshold are emitted; `direct` entries ignore the latency threshold.
- **Probe scheduling reuses probe settings**: chain probing follows the interval and dialer of the probe settings, with the dialer chosen automatically in the order xray → sing-box → mihomo.

### Русский

- **Универсальная проверка цепочки CDN**: поддержка не только Cloudflare — проверяется домен/IP любого CDN. Выход и проверяющий inbound выбираются явно, случайный выбор inbound исключён.
- **Один inbound проверяет все записи**: за один раунд выбранный inbound проверяет все домены/IP CDN, результат записывается в состояние здоровья (3 ошибки подряд — неисправен, первый успех — восстановлен), другие inbound могут использовать прошедшие записи.
- **Исключения из проверки**: прямые домены/IP и пользовательские домены отдельных узлов не проверяются — другая точка входа даёт ложные ошибки с теми же учётными данными.
- **Более строгая выдача подписки**: выдаются только здоровые домены/IP CDN с задержкой ниже порога; записи `direct` порог задержки игнорируют.
- **Планировщик использует настройки проверки**: интервал и диалайзер берутся из настроек проверки, диалайзер выбирается автоматически: xray → sing-box → mihomo.

### فارسی

- **بررسی زنجیره CDN به‌صورت عمومی**: دیگر محدود به Cloudflare نیست و دامنه/IP هر CDN قابل بررسی است. خروجی و inbound بررسی‌کننده باید صریحاً انتخاب شوند و انتخاب تصادفی حذف شده است.
- **یک inbound برای همه ورودی‌ها**: در هر دور، تنها یک inbound انتخاب‌شده همه دامنه‌ها/IPهای CDN را بررسی می‌کند و نتیجه در سلامت ثبت می‌شود (سه شکست پیاپی = خراب، نخستین موفقیت = سالم)، سایر inboundها می‌توانند از ورودی‌های سالم استفاده کنند.
- **حذف موارد غیرقابل بررسی**: دامنه/IPهای مستقیم و دامنه‌های اختصاصی هر نود بررسی نمی‌شوند، چون نقطه ورود متفاوت است و با همان اعتبارنامه نتیجه اشتباه می‌دهد.
- **خروجی سخت‌گیرانه‌تر اشتراک**: فقط دامنه/IPهای سالم CDN با تأخیر کمتر از آستانه صادر می‌شوند؛ ورودی‌های `direct` از آستانه تأخیر مستثنا هستند.
- **زمان‌بندی بر اساس تنظیمات بررسی**: بازه و دیالر از تنظیمات بررسی گرفته می‌شود و دیالر به‌ترتیب xray → sing-box → mihomo انتخاب می‌گردد.
