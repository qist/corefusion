# Подписка API (общедоступная)

> Языки: [简体中文](subscription.md) · [English](subscription.en.md) · [繁體中文](subscription.zh-TW.md) · Русский · [日本語](subscription.ja.md) · [한국어](subscription.ko.md) · [Deutsch](subscription.de.md) · [Français](subscription.fr.md) · [Español](subscription.es.md) · [Português](subscription.pt.md) · [Türkçe](subscription.tr.md) · [Bahasa Indonesia](subscription.id.md) · [ไทย](subscription.th.md) · [Tiếng Việt](subscription.vi.md) · [العربية](subscription.ar.md) · [فارسی](subscription.fa.md)

Извлекает список узлов подписки пользователя. **Это наиболее часто используемая конечная точка для конечных пользователей**; заголовки не требуются — доступ предоставляется по токену в URL.

## 1. Конечная точка

| Развертывание | URL |
|---|---|
| Основная панель | `GET https://<panel-domain>/sub/<token>` |
| Выделенный порт подписки | `GET https://<sub-domain>:<port>/<token>` (без префикса `/sub`) |

`<token>` — это уникальный токен доступа к подписке, созданный администратором (его можно увидеть в разделе «Мои подписки» на портале).

## 2. Параметры запроса

| Параметр | Описание |
|---|---|
| `format` | Выходной формат; переопределяет подписку по умолчанию. См. ниже |
| `config` | Имя шаблона конфигурации (определено в разделе «Форматы подписки» в пользовательском интерфейсе администратора). Должен использовать тот же формат, что и `format` этого запроса, в противном случае он игнорируется. |
| `platform` | Сопоставьте шаблон конфигурации с именем платформы (используется, если `config` опущен); формат также должен совпадать |
| `providers` | Только для `mihomo_yaml`: `1`/`true` включает **Режим провайдера** (генерируйте `proxy-providers` и ссылайтесь на них через `use`); значение по умолчанию или любое другое значение сохраняет узлы встроенными в `proxies`. См. §6. |

### Поддерживаемые значения `format`

| Значение | Выход | Клиенты |
|---|---|---|
| `base64_uri` (по умолчанию) | Ссылки общего доступа, соединенные новой строкой, в целом в кодировке Base64 | V2RayN, Shadowrocket, Surge и другие универсальные клиенты. |
| `raw_uri` | Ссылки общего доступа, объединенные новой строкой, простой текст | Клиенты, которым нужны простые ссылки/отладка |
| `mihomo_yaml` | Полная конфигурация Clash/Mihomo YAML (с прокси-группами, правилами) | Clash.Meta / mihomo / Clash Verge Rev |
| `mihomo_proxies_yaml` | YAML только со списком узлов `proxies:` | источник прокси-провайдера mihomo (с запланированным обновлением) |
| `singbox_json` | Полная конфигурация sing-box JSON | sing-box/SFI/FLClash (ядро sing-box) |
| `xray_json` | Полная конфигурация Xray JSON | Xray-ядро |

> Применяется совместимость протокола/формата: например, `anytls` появляется только в форматах sing-box/Mihomo; **Узлы REALITY, обслуживаемые xray, исключены из подписок sing-box** (sing-box не поддерживает реализацию REALITY xray, см. sing-box#4520), но все равно появляются в подписках Xray, хотя **Узлы REALITY, обслуживаемые sing-box, работают как в подписках Xray, так и в sing-box**. Узлы, которые клиент не может распознать, автоматически удаляются, а не прерывают всю подписку.

## 3. Заголовки ответов

| Заголовок | Пример | Описание |
|---|---|---|
| `Subscription-Userinfo` | `upload=1024; download=2048; total=1073741824; expire=1760000000` | Использование и срок действия (байты/Unix-секунды). **Также отправляется по номеру 403**, чтобы клиенты могли показать остаток суммы. |
| `Profile-Update-Interval` | `6` | Рекомендуемый интервал обновления (часы) |
| `Profile-Title` | `CoreFusion` | Имя профиля (показано Clash Verge Rev / V2RayN и т. д.) |
| `Profile-Web-Page-Url` | `https://portal.example.com` | Портал URL («открыть веб-страницу» в клиентах; корневой путь, если у портала есть собственный порт, в противном случае /p) |
| `Content-Type` | В каждом формате: `text/plain` / `text/yaml` / `application/json`. |  |
| `Content-Disposition` | `attachment; filename="subscription.txt"` |  |

## 4. Коды состояния

| HTTP | код | Значение |
|---|---|---|
| 200 | — | Обычный (тело — это подписка, отображаемая в `format`) |
| 400 | `MISSING_TOKEN` | В URL нет токена |
| 403 | (обычный текст) | Подписка приостановлена/истекла/неактивна. Сообщение локализовано (zh/en/ja/ko) через `Accept-Language` и представляет собой однострочную причину. |
| 404 | `SUBSCRIPTION_NOT_FOUND` | Токен не существует |

> Отозванные подписки считаются несуществующими (404).

## 5. Примеры

```bash
# 1) Fetch with the default format
curl -L "https://panel.example.com/sub/abcd1234efgh5678"

# 2) Request Mihomo YAML with the "clash-global" config template
curl -L "https://panel.example.com/sub/abcd1234efgh5678?format=mihomo_yaml&config=clash-global"

# 3) Node list only (for a mihomo proxy-provider)
curl -L "https://panel.example.com/sub/abcd1234efgh5678?format=mihomo_proxies_yaml"

# 4) Check usage (headers only)
curl -sI "https://panel.example.com/sub/abcd1234efgh5678" | grep -i subscription-userinfo

# 5) Clash dynamic subscription: config template + Provider mode
curl -L "https://sub.example.com/abcd1234efgh5678?format=clash&config=out&providers=1"

# 6) sing-box / Xray with their own config templates (rules come from the template)
curl -L "https://sub.example.com/abcd1234efgh5678?format=singbox_json&config=sing-box-home"
curl -L "https://sub.example.com/abcd1234efgh5678?format=xray_json&config=xray-home"
```

Динамическая подписка Clash/Mihomo (периодическое обновление):

```yaml
proxy-providers:
  office:
    type: http
    url: "https://panel.example.com/sub/abcd1234efgh5678?format=mihomo_proxies_yaml&provider=office"
    interval: 3600
    health-check:
      enable: true
      url: https://www.gstatic.com/generate_204
      interval: 300

proxy-groups:
  - name: PROXY
    type: select
    use:
      - office
```

## 6. Режим провайдера и несколько доменов подписки

### 6.1 Что излучает `providers=1`

С `format=mihomo_yaml&providers=1` (или `format=clash&providers=1`) YAML:

- больше не встраиваются узлы на верхнем уровне — выдается `proxy-providers:`;
- прокси-группы ссылаются на источники узлов через `use: [<provider-key>...]`;
- любой `proxy-providers`, написанный в формате общей подписки (`mihomo_configs.config_json`), **игнорируется** (общая конфигурация обслуживает несколько планов; жестко запрограммированные поставщики будут перетекать между планами). Сопоставления группы → источника находятся в разделе «Управление планом → группа → сопоставление источника».

Виды провайдеров:

| Добрый | Ключ | Примечания |
|---|---|---|
| Внутренний | Очищенное имя группы узлов | Создается для каждой группы узлов плана; содержит только узлы этой группы |
| Зарезервировано (устарело) | `subscription-nodes` | Больше не выводится в `proxy-providers`; группа, ссылающаяся на него, разворачивается в конкретные provider, а при их отсутствии узлы встраиваются напрямую |
| Внешний | Имя настроено в плане | Внешний источник (`http` YAML или `file`) |

Общие поля для каждого поставщика:

- `url` — указывает на эту подписку с помощью `format=mihomo_proxies_yaml`, наследуя `config`/`platform` от основного запроса; внутренние поставщики добавляют `provider=<key>`;
- `path` — **всегда извлекается из «внутренних настроек поставщика → шаблон пути к кэшу»** (по умолчанию `./providers/{key}.yaml`, заменено `{key}`). Внешние поставщики также не могут устанавливать свой собственный путь;
- `health-check` — `enable / url / interval`; внутренние провайдеры наследуют настройки по умолчанию, внешние провайдеры настраивают их в плане;
- `interval` — интервал обновления в секундах.

### 6.2 Какой домен переходит к провайдеру URL (мультидоменный)

«Центр подписки → Конечные точки подписки» может содержать **несколько** записей (домен + путь + включено). Провайдер `url` выбирает домен в следующем порядке:

1. **Домен, который фактически использовался в этом запросе**: первое значение `X-Forwarded-Host` (порт удален), в противном случае `Host`; оно должно соответствовать **включенной** конечной точке;
2. Если ничего не совпадает, вернитесь к включенной конечной точке с **самым низким идентификатором**;
3. Путь исходит из совпадающей конечной точки (`path`, по умолчанию `/`), что дает `https://<domain><path>/<token>?format=mihomo_proxies_yaml...`.

Последствия:

- Клиент, получающий новый домен, получает этот домен внутри провайдера — **изменение панели не требуется**;
- Старый домен, все еще включенный в список, больше не является жестко запрограммированным;
- Если клиент закешировал старого провайдера URL, обновление подписки (или очистка кеша провайдера/перезапуск клиента) переключает его.

Обратные прокси должны пересылать `X-Forwarded-Proto` и `X-Forwarded-Host`; в противном случае используется резервная конечная точка. Сгенерированные панелью шаблоны сайтов Caddy/Nginx уже включают оба заголовка (`header_up X-Forwarded-Host {host}`/`proxy_set_header X-Forwarded-Host $host;`); добавьте их вручную, если вы поддерживаете конфигурацию прокси вручную.

## 7. Примечания

- **Формат и конфигурация тесно связаны**: шаблон, выбранный `config`/`platform`, должен соответствовать `format` этого запроса; несовпадающие шаблоны игнорируются — это предотвращает внедрение правил Mihomo в sing-box/Xray JSON.
- **`providers=1` влияет только на Mihomo YAML**: sing-box / Xray / base64 / raw игнорировать его (узлы остаются встроенными).
- **Ограничение скорости**: конечная точка подписки имеет собственный лимит (`SubscribeRateLimit`); злоупотребляющие клиенты отклоняются.
- **Журнал доступа**: при каждой выборке записывается информация об IP/UA/CDN, которая отображается в разделе «Журнал доступа к подписке» в пользовательском интерфейсе администратора.
- Без домена, настроенного на выделенном порту подписки, используются запросы `X-Forwarded-Proto`/`X-Forwarded-Host`; убедитесь, что ваш обратный прокси пересылает оба заголовка.
- При развертывании в нескольких доменах список конечных точек должен соответствовать фактически используемым клиентами доменам; см. §6.2.
