# Xray subscription-format template

<sub>[简体中文](README.md) · English · [Русский](README.ru.md) · [فارسی](README.fa.md)</sub>

[`config.json`](./config.json) is the `config_json` of the **xray_json** subscription
format. It only contains client-side fixed sections:

```text
log / dns / inbounds / routing
```

`outbounds` are generated by the panel, plus `direct` / `block` and a
`tag: proxy` **balancer** (Xray has no selector; a random balancer acts as the proxy
group). Rules written with `"outboundTag": "proxy"` are rewritten to
`"balancerTag": "proxy"`. **The subscription always contains `proxy`** — no manual edits.
Node names colliding with `proxy` / `direct` / `block` are renamed automatically.

## 1. Upload

```text
Panel → Subscription format → New
  client_type: v2ray
  format:      xray_json
  content:     paste config.json
```

```text
https://<panel>/sub/<token>?format=xray_json&config=<format>
```

## 2. Subscribers and standalone use

- **Subscribers only need the subscription URL** — no panel account, no manual edits.
- **Without a panel**, use [`standalone.json`](./standalone.json): a complete config
  that passes `xray run -test`. Replace `node-example` in `outbounds`
  (placeholder `127.0.0.1:1080` socks) with your own node.

## 3. Structure

| Section | Purpose |
| --- | --- |
| `inbounds` | SOCKS `127.0.0.1:10808` + HTTP `127.0.0.1:10809` |
| `dns` | China domains → Alibaba DoH, global → Google DoH, rest → `1.1.1.1` |
| `routing.rules` | ads → `block`; STUN (3478/19302) → `block`; China → `direct`; rest → `proxy` |
| `routing.domainStrategy` | `IPIfNonMatch` |

## 4. Geodata

Rules use built-in `geosite:` / `geoip:` tags:

```text
geosite:category-ads-all
geosite:cn
geosite:geolocation-!cn
geoip:cn
```

The client needs `geosite.dat` / `geoip.dat` (the panel syncs them under `data/rules/`).
For custom data, put them in the directory pointed to by `XRAY_LOCATION_ASSET`.

## 5. Verify

```bash
curl -s "https://<panel>/sub/<token>?format=xray_json&config=<format>" -o xr.json
XRAY_LOCATION_ASSET=/opt/corefusion/data/rules xray run -test -c xr.json
# Configuration OK.
```

## 6. Known warnings

WebSocket `headers.Host` and Trojan without flow trigger deprecation warnings on
Xray 26.x. They come from the node protocol itself and do not block loading.
