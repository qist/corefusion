## 1. ภาพรวมของระบบ

CoreFusion เป็นแผงการจัดการพร็อกซีหลายโปรโตคอลที่รองรับ VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC และอื่นๆ อีกมากมาย พร้อมการจัดการโหนด การจัดส่งการสมัครสมาชิก การจัดการลูกค้า การเรียกเก็บเงิน ใบรับรอง และพร็อกซีแบบลูกโซ่

### 1.1 คุณสมบัติหลัก

| โมดูล | คำอธิบาย |
|--------|-------------|
| หลายโปรโตคอล | VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, WireGuard, ฯลฯ. |
| มัลติคอร์ | Xray-core และ sing-box (Hysteria2/TUIC และโปรโตคอล QUIC อื่นๆ ทำงานบน sing-box) |
| หลายโหนด | โหนดห้าประเภท: สแตนด์อโลน, มิเรอร์, ใช้งาน/สแตนด์บาย, การเข้าแบบโซ่, ทางออกแบบโซ่ |
| การจัดส่งการสมัครสมาชิก | รูปแบบการสมัครสมาชิกหลายรูปแบบ อุปกรณ์ปลายทาง และการจัดการรูปแบบ |
| การเรียกเก็บเงิน | เทมเพลตแผน บัตรเติมเงิน ยอดคงเหลือ คำสั่งซื้อ ค่าคอมมิชชันของผู้ค้าปลีก |
| ใบรับรอง | มาเข้ารหัสกันเถอะ, การตรวจสอบ DNS-01/HTTP-01, การแจกจ่ายใบรับรอง |
| พร็อกซีที่ถูกล่ามโซ่ | การปรับสมดุลโหลดหลายทางออก การลงทะเบียนโหนดภายนอก การกำหนดเส้นทางแบบลูกโซ่ |
| โควต้าการจราจร | การตรวจสอบการรับส่งข้อมูลรายเดือนต่อโหนด, ระงับอัตโนมัติ, บันทึกการรีเซ็ต |
| พอร์ทัล | โปรแกรมแก้ไขพอร์ทัลแบบเห็นภาพ เทมเพลตแบบกำหนดเองได้หลายภาษา |
| การแจ้งเตือน | อีเมลและ Telegram เทมเพลตและการออกอากาศ |

### 1.2 สถาปัตยกรรม

- **แบ็กเอนด์**: ไปซะ gRPC
- **ส่วนหน้า**: Vue 3 + Element Plus
- **ฐานข้อมูล**: SQLite (ค่าเริ่มต้น) / MySQL / PostgreSQL
- **พร็อกซี**: พร็อกซีย้อนกลับของแคดดี้ / Nginx
- **พอร์ตแผง**: กำหนดโดยวิซาร์ดการตั้งค่า (พอร์ตสุ่มฟรีตามค่าเริ่มต้น 8080 เป็นตัวเลือกทั่วไป)
- **พอร์ตตัวแทน gRPC**: 18443 โดยค่าเริ่มต้น

## 2. การติดตั้ง

### 2.1 สภาพแวดล้อมที่รองรับ

| รายการ | สนับสนุน |
|------|---------|
| การแจกแจง | เดเบียน / อูบุนตู, RHEL / CentOS / ร็อคกี้ / AlmaLinux / Fedora, อัลไพน์, Arch, openSUSE |
| สถาปัตยกรรมซีพียู | ไบนารีอย่างเป็นทางการ: `amd64`, `arm64`; การสร้างซอร์สยังรองรับ `armv7`, `armv6`, `386`, `ppc64le`, `s390x`, `riscv64`, `loong64` |
| ผู้จัดการฝ่ายบริการ | systemd (แนะนำ); ถอยกลับไปเป็น `nohup` ในคอนเทนเนอร์หรือสภาพแวดล้อมอื่นๆ ที่ไม่มี systemd |
| หน่วยความจำ / ดิสก์ | ≥ 1 GB / ≥ 10 GB (ฐานข้อมูล ใบรับรอง บันทึก และไบนารีหลักอยู่ในไดเร็กทอรีข้อมูล) |
| พอร์ตแผง | เลือกในตัวช่วยสร้างการตั้งค่า (พอร์ตสุ่มฟรีตามค่าเริ่มต้น `8080` และที่คล้ายกันนั้นใช้ได้) |
| ตัวแทน gRPC | `18443` โดยค่าเริ่มต้น |

คำสั่งภายนอกรันไทม์ได้รับการติดตั้งโดยอัตโนมัติโดยตัวติดตั้ง (`scripts/install.sh` และสคริปต์การติดตั้ง Agent ที่สร้างโดยแผงควบคุม ข้ามด้วย `--no-deps` / `CF_SKIP_DEPS=1`):

| วัตถุประสงค์ | แพ็คเกจ |
|---------|---------|
| ไฟร์วอลล์ / ขีด จำกัด อัตรา / การทำเครื่องหมายการทำงานพร้อมกัน | `nftables` (`nft`) |
| การกำหนดรูปแบบการจราจร ลิงก์ และซ็อกเก็ต | `iproute2` (`tc` / `ip` / `ss`) |
| ทางเลือกเมื่อ nft ไม่พร้อมใช้งาน | `iptables` (`iptables-nft` บน EL8+, `iptables` บน EL7) |
| การติดตามการเชื่อมต่อ | `conntrack-tools` (`conntrack`) |
| โหลด `nf_conntrack` / `ifb` | `kmod` (`modprobe` / `lsmod`) |
| การตรวจจับกระบวนการและการล้างข้อมูล | `procps` (`pgrep` / `pkill`) |
| ตรวจสอบพอร์ต / พารามิเตอร์ DH | `lsof` / `openssl` |
| การสร้างผู้ใช้พร็อกซี | `shadow-utils` (Debian `passwd`, อัลไพน์/Arch `shadow`) |
| ดาวน์โหลดและเก็บถาวร | `curl` / `ca-certificates` / `tar` / `gzip` / `xz` |

> การขาด `nft` / `tc` ส่งผลต่อการจำกัดอัตราและคุณสมบัติไฟร์วอลล์เท่านั้น แผงยังคงเริ่มต้น
> รัน `--cpu-info` ก่อนเพื่อดูว่าสภาพแวดล้อมถูกตรวจพบอย่างไร และแพ็คเกจใดที่ขาดหายไป

### 2.2 การติดตั้งบรรทัดเดียว (แนะนำ)

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh -o install.sh
sudo bash install.sh
```

หรือไพพ์โดยตรง (ไม่มีการโต้ตอบ ไม่มีแฟล็กเพิ่มเติม):

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash
```

สคริปต์จะ:

1. ตรวจจับการกระจาย สถาปัตยกรรม CPU และ libc จากนั้นติดตั้งแพ็คเกจพื้นฐานและการขึ้นต่อกันของรันไทม์
2. ดาวน์โหลด `corefusion-linux-<arch>` จากรุ่น GitHub และตรวจสอบด้วย `.sha256` ที่ตรงกัน
3. ติดตั้งไปที่ `/opt/corefusion` และสร้าง `data/{sqlite,certs,logs,runtime}`;
4. เขียนเฉพาะตัวยึดตำแหน่ง `.env` ด้วย `SAFE_PATHS=data` — ไม่มีการกำหนดค่าฐานข้อมูล — ดังนั้นการเริ่มต้นครั้งแรกจะเข้าสู่วิซาร์ดการตั้งค่า (ตัวช่วยสร้าง `.env` แบบเต็มจะถูกสร้างขึ้นโดยวิซาร์ด)
5. ติดตั้งและเริ่มบริการ systemd (หรือทำงานภายใต้ `nohup` เมื่อ systemd ไม่พร้อมใช้งาน)
6. รอจนกว่าจะพร้อม จากนั้นพิมพ์การตั้งค่า URL โทเค็น และเส้นทางไดเรกทอรี

ตัวอย่างผลลัพธ์:

```text
==================================================================
 CoreFusion installation complete
------------------------------------------------------------------
 Install dir : /opt/corefusion
 Data dir    : /opt/corefusion/data
 Binary      : /opt/corefusion/corefusion
 Logs        : journalctl -u corefusion -f
------------------------------------------------------------------
 Setup wizard : http://<server-ip>:<random-port>/init?init_token=<token>
 Setup token  : <token>
 Valid for    : 2 hours (see startup log)
 Note         : the token is shown once; after setup this port closes and the panel switches to its normal port.
==================================================================
```

หากแผงควบคุมรับฟังเฉพาะ `127.0.0.1` (เช่น หลังพร็อกซีย้อนกลับ) สคริปต์จะพิมพ์คำสั่งช่องสัญญาณ SSH แทน URL ที่ไม่สามารถเข้าถึงได้

> โทเค็นสูญหายใช่ไหม อ่านบันทึกการเริ่มต้นอีกครั้ง: `journalctl -u corefusion -n 50 --no-pager`
> (ไม่มี systemd: `tail -n 50 /opt/corefusion/data/logs/panel.log`)

### 2.2.1 เอาต์พุตหลายภาษา

ตัวติดตั้งมีภาษาของอินเทอร์เฟซ 4 ภาษา: จีนตัวย่อ อังกฤษ เปอร์เซีย (فارسی) และรัสเซีย (Русский) ระบบจะตรวจจับจาก `LANG` โดยอัตโนมัติ หรือระบุเองได้:

```bash
# อังกฤษ
sudo bash install.sh --lang en

# เปอร์เซียผ่านตัวแปรสภาพแวดล้อม
sudo CF_LANG=fa bash install.sh

# ส่งอาร์กิวเมนต์เมื่อติดตั้งผ่านไปป์
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash -s -- --lang ru
```

รองรับ `zh` / `en` / `fa` / `ru` และยอมรับ `--lang=ru` ด้วย หากระบุภาษาที่ไม่รองรับจะแจ้งข้อผิดพลาดพร้อมรายการภาษาที่ใช้ได้

### 2.3 การปักหมุดเวอร์ชัน / มิเรอร์ / การติดตั้งออฟไลน์

```bash
# Pin a version
sudo bash install.sh --version v0.13.0-alpha.2

# GitHub download mirror (used as a URL prefix)
sudo bash install.sh --mirror https://ghproxy.net --version latest

# Use a local binary (offline / intranet / pre-built)
sudo bash install.sh --local ./dist/corefusion-linux-arm64

# Explicit target architecture
sudo bash install.sh --arch arm64 --local ./corefusion-linux-arm64
```

> หากไม่มี `--version` สคริปต์จะใช้รายการใหม่ล่าสุดในรายการ GitHub Releases
> รีลีสส่วนใหญ่เป็นรุ่นก่อนเผยแพร่ ดังนั้นจึงไม่ได้ใช้ตำแหน่งข้อมูล `/releases/latest`
>
> การเปิดตัวอย่างเป็นทางการมีเฉพาะ `amd64` / `arm64`; ใช้ `--source` หรือไบนารีที่คอมไพล์ข้ามกับ `--local` สำหรับสถาปัตยกรรมอื่นๆ

### 2.4 การสร้างจากแหล่งที่มา

```bash
sudo bash install.sh --source --version v0.13.0-alpha.2
```

`--source` โคลนที่เก็บ (หรือใช้การชำระเงินที่มีอยู่เมื่อมีสคริปต์อยู่ข้างใน) และรัน `make panel` เวอร์ชันของ Toolchain จะถูกเลือกตามสภาพแวดล้อม:

| การพึ่งพาอาศัยกัน | การคัดเลือก |
|------------|-----------|
| ไป | อ่านจาก `toolchain` / `go` ใน `go.mod` (ปัจจุบัน **ไป 1.27+**); หากเวอร์ชันของระบบเก่าเกินไป toolchain ที่ตรงกันจะถูกดาวน์โหลดไปที่ `<install-dir>/.toolchain` |
| โหนด | **โหนด 22 LTS** โดยค่าเริ่มต้น (Vite ต้องการ ≥ 18) ระบบจะดาวน์โหลดบิลด์อย่างเป็นทางการที่ตรงกันเมื่อจำเป็น |
| โหนด (glibc < 2.28) | ใช้ `unofficial-builds` glibc-217 build (เช่น CentOS 7) |
| โหนด (อัลไพน์ / มัสล) | ใช้การกระจาย `nodejs` / `npm` |

แทนที่:

```bash
# Force Go / Node versions
sudo CF_GO_VERSION=1.27.5 CF_NODE_MAJOR=22 bash install.sh --source

# Go toolchain mirror (default https://go.dev/dl)
sudo CF_GO_MIRROR=https://golang.google.cn/dl bash install.sh --source
```

การสร้างด้วยตนเอง (การพัฒนา / การดีบัก):

```bash
git clone https://github.com/qist/corefusion.git
cd corefusion

# Frontend + panel for the current architecture; the frontend is embedded via go:embed
make panel

# Cross-compile
make panel-linux-amd64
make panel-linux-arm64
```

> `go build ./...` ไม่ได้สร้างไบนารี สร้างแผงด้วย
> `go build -o corefusion ./cmd/corefusion/` หรือ `make panel`

### 2.5 แฟล็กตัวติดตั้ง

| ธง | คำอธิบาย |
|------|-------------|
| `-d, --dir <PATH>` | ติดตั้งไดเร็กทอรี ค่าเริ่มต้น `/opt/corefusion` |
| `-v, --version <TAG>` | เวอร์ชันแผง เช่น `v0.13.0-alpha.2`; ค่าเริ่มต้น `latest` |
| `--binary` | ใช้ไบนารี่ Release GitHub (ค่าเริ่มต้น) |
| `--source` | สร้างจากแหล่งที่มาและเตรียมการจับคู่ Go / Node |
| `--local <FILE>` | ใช้ไบนารีท้องถิ่น (ติดตั้งออฟไลน์) |
| `--arch <ARCH>` | สถาปัตยกรรมเป้าหมาย: `amd64` / `arm64` / `armv7` / `armv6` / `386` / `ppc64le` / `s390x` / `riscv64` / `loong64` |
| `--mirror <URL>` | คำนำหน้าการดาวน์โหลด GitHub เช่น `https://ghproxy.net` |
| `--repo <URL>` | ที่เก็บซอร์ส ดีฟอลต์ `https://github.com/qist/corefusion.git` |
| `--ref <REF>` | สาขา / แท็กต้นทาง ค่าเริ่มต้นเป็น `--version` หรือมิฉะนั้น `main` |
| `--no-deps` | ข้ามการติดตั้งการพึ่งพาระบบ |
| `--no-start` | ติดตั้งและเขียนไฟล์บริการโดยไม่ต้องเริ่มต้น |
| `--cpu-info` | การตรวจจับสภาพแวดล้อมการพิมพ์และการขึ้นต่อกันที่ขาดหายไป จากนั้นออก |
| `--lang <LANG>` | ภาษาของเอาต์พุต: `zh` / `en` / `fa` / `ru` (ค่าเริ่มต้น: `LANG` ของระบบ) |
| `--uninstall` | หยุดบริการและลบโปรแกรมออก (เก็บข้อมูลและ `.env`) |
| `--purge` | ด้วย `--uninstall` ให้ลบไดเร็กทอรีข้อมูลและ `.env` ด้วย |

ตัวแปรสภาพแวดล้อมที่เกี่ยวข้อง:

| ตัวแปร | วัตถุประสงค์ |
|----------|---------|
| `CF_GO_VERSION` | แทนที่เวอร์ชัน Go ที่จำเป็นสำหรับบิวด์ซอร์ส |
| `CF_NODE_MAJOR` | แทนที่เวอร์ชันหลักของโหนด (ค่าเริ่มต้น 22) |
| `CF_GO_MIRROR` | ไปที่มิเรอร์ดาวน์โหลด toolchain |
| `CF_SKIP_DEPS` | ตั้งค่าเป็น `1` ในสคริปต์การติดตั้ง Agent เพื่อข้ามการติดตั้งการขึ้นต่อกัน |
| `CF_LANG` | แทนที่ภาษาของเอาต์พุตตัวติดตั้ง (เหมือน `--lang`) |

### 2.6 เค้าโครงไดเร็กทอรี

```text
/opt/corefusion/
├── corefusion                 # panel binary
├── corefusion.bak             # previous version (when upgrading)
├── .env                       # environment file (0600, generated by the setup wizard)
├── .toolchain/                # Go / Node downloaded for source builds
└── data/                      # data directory (SAFE_PATHS)
    ├── sqlite/app.db          # default SQLite database
    ├── certs/                 # certificates and keys
    ├── logs/                  # runtime logs (without systemd)
    ├── runtime/               # core runtime config and state
    ├── binaries/              # downloaded xray / sing-box cores
    └── proxy/                 # proxy (Caddy/Nginx) sites and config
```

> โปรแกรมติดตั้งจะสร้างเฉพาะ `sqlite/`, `certs/`, `logs/` และ `runtime/` เท่านั้น `binaries/`, `proxy/`, `rules/` และอื่นๆ ถูกสร้างขึ้นโดยแผงควบคุมหรือเมื่อมีการติดตั้งแกน
> ไดเร็กทอรีข้อมูลมาจาก `SAFE_PATHS` ใน `.env` และอาจเป็นพาธสัมบูรณ์ การเปลี่ยนไดเร็กทอรีการติดตั้งจะไม่ย้ายข้อมูลที่มีอยู่

### 2.8 อัปเกรดและถอนการติดตั้ง

อัปเกรด (เก็บข้อมูลและกำหนดค่า):

```bash

```

สคริปต์หยุดบริการ สำรองข้อมูลไบนารีเก่าเป็น `corefusion.bak` แทนที่และรีสตาร์ท `.env` และ `data/` ที่มีอยู่จะไม่ถูกแตะต้อง


### 2.9 ไฟล์สภาพแวดล้อม (.env)

`.env` ที่สมบูรณ์ **สร้างโดยวิซาร์ดการตั้งค่า** เมื่อมีการบันทึกการกำหนดค่า (DSN ฐานข้อมูล ไดเร็กทอรีข้อมูล ข้อมูลลับ พอร์ต โดเมน)

ในการติดตั้งใหม่ ตัวติดตั้งจะเขียนเฉพาะตัวยึดตำแหน่งนี้ ดังนั้นแผงควบคุมจึงไม่เข้าใจผิดว่า `data/` ที่มีอยู่เป็นการติดตั้งที่เริ่มต้น และข้ามวิซาร์ด:

```env
SAFE_PATHS=data
```

> เมื่อมีการกำหนดค่าที่สมบูรณ์ (`.env` กับ `CF_DB_DSN`) อยู่แล้ว โปรแกรมติดตั้งจะไม่เขียนทับการกำหนดค่าดังกล่าว และตัวช่วยสร้างจะไม่ปรากฏขึ้นอีก
> การแก้ไข `.env` ด้วยตนเองในภายหลังจะมีผลหลังจากการรีสตาร์ท

#### ไดเร็กทอรีข้อมูล

```env
SAFE_PATHS=data                       # relative to the install directory
# SAFE_PATHS=/srv/corefusion-data     # or an absolute path
```

#### ฐานข้อมูล

ตรวจพบ `CF_DB_DSN` โดยคำนำหน้า:

| คำนำหน้า | ฐานข้อมูล |
|--------|----------|
| ไม่ได้ตั้งค่าหรือเส้นทางเปล่า | SQLite (ค่าเริ่มต้น) |
| `sqlite://` | SQLite (ชัดเจน) |
| `mysql://` | MySQL |
| `postgres://` / `postgresql://` | PostgreSQL |

`CF_DB_TYPE` เป็นทางเลือกและแทนที่การตรวจจับ (`sqlite` / `mysql` / `postgres`)

> **รหัสผ่านที่เข้ารหัส**: MySQL/PostgreSQL DSN ที่เขียนโดยแผงควบคุม (ตัวช่วยสร้างการตั้งค่า / สวิตช์ฐานข้อมูล)
> จะถูกเก็บไว้ใน `.env` เป็น `enc:...` (AES-256-GCM, คีย์ `CF_SECRET_ENCRYPTION_KEY`)
> พวกเขาจะถูกถอดรหัสเมื่ออ่าน DSN แบบข้อความธรรมดาที่เขียนด้วยมือยังคงใช้งานได้

**SQLite (ค่าเริ่มต้น)**

```env
# Bare path (detected as SQLite)
CF_DB_DSN=data/sqlite/app.db

# Or explicit sqlite:// prefix
CF_DB_DSN=sqlite:///opt/corefusion/data/sqlite/app.db
```

**MySQL**

```env
# Format: mysql://user:password@tcp(host:port)/dbname?params
CF_DB_DSN=mysql://corefusion:password@tcp(127.0.0.1:3306)/corefusion?charset=utf8mb4&parseTime=True&loc=Local
```

**PostgreSQL**

```env
# Format: postgres://user:password@host:port/dbname?params
CF_DB_DSN=postgres://corefusion:password@127.0.0.1:5432/corefusion?sslmode=disable
```

#### พูลการเชื่อมต่อ (อุปกรณ์เสริม MySQL/PostgreSQL)

```env
CF_DB_MAX_OPEN_CONNS=100
CF_DB_MAX_IDLE_CONNS=10
```

#### ตัวแปรทั่วไปอื่นๆ

| ตัวแปร | คำอธิบาย |
|----------|-------------|
| `JWT_SECRET` | คีย์การลงนามสำหรับโทเค็นการเข้าสู่ระบบ สร้างขึ้นเมื่อเริ่มต้นครั้งแรกเมื่อหายไป |
| `CF_SECRET_ENCRYPTION_KEY` | รหัสสำหรับการเข้ารหัสการตั้งค่าที่ละเอียดอ่อน (AES-256-GCM) สร้างขึ้นเมื่อขาดหายไป |
| `CF_INITIAL_ADMIN_PASSWORD` | รหัสผ่านผู้ดูแลระบบเริ่มต้น (ไม่จำเป็น; สุ่มและพิมพ์ครั้งเดียวตามค่าเริ่มต้น) |
| `CF_NETWORK_TRAFFIC_ACCOUNTING` | ตั้งค่าเป็น `0` เพื่อปิดใช้งานบัญชีการรับส่งข้อมูลตาม iptables (เปิดใช้งานตามค่าเริ่มต้น) |
| `CF_NETWORK_TRAFFIC_TABLE` | ตาราง iptables ที่ใช้สำหรับการบัญชีปริมาณข้อมูล ค่าเริ่มต้น `corefusion` |

> Reverse Proxies ที่เชื่อถือได้สำหรับการแก้ไข IP ไคลเอ็นต์จริงจะไม่ได้รับการกำหนดค่าผ่านตัวแปรสภาพแวดล้อมอีกต่อไป
> โดยจะถูกจัดเก็บเป็น `panel.trusted_proxies` ใน **การตั้งค่า → เครือข่าย**

> `.env` มีความลับ; แผงกระชับการอนุญาตของ `0600` เมื่อเริ่มต้น ไม่เคยกระทำมัน

### 2.10 Docker (เป็นทางเลือก สร้างอิมเมจของคุณเอง)

## 3. การกำหนดค่าเริ่มต้น

ในการเริ่มต้นครั้งแรก หาก `.env` ไม่มี `CF_DB_DSN` ที่ถูกต้อง แผงควบคุมจะ **ยังไม่** ให้บริการ UI ผู้ดูแลระบบ มันเริ่มต้น
**วิซาร์ดการตั้งค่า** บนพอร์ตสุ่มใน 18000–18999 ด้วยโทเค็นแบบครั้งเดียว จากนั้นรีสตาร์ทเหมือนแผงปกติเมื่อบันทึกแล้ว

### 3.1 เปิดตัวช่วยการตั้งค่า

1. คัดลอก “วิซาร์ดการตั้งค่า” URL จากเอาต์พุตของตัวติดตั้ง หรือ
2. อ่านบันทึกบนเซิร์ฟเวอร์:

```bash
journalctl -u corefusion -n 50 --no-pager | grep -A2 'setup wizard'
```

```text
CoreFusion first start - setup wizard
  URL   : http://<ip>:<port>/init?init_token=<token>
  Token : <token>
  Valid : 2h0m0s
```

3. เปิด URL ในเบราว์เซอร์ (มี `init_token` อยู่แล้ว ดังนั้นจึงไม่จำเป็นต้องป้อนข้อมูลด้วยตนเอง)

> เซสชันตัวช่วยสร้างจะหมดอายุหลังจาก **2 ชั่วโมง** ตามค่าเริ่มต้น หากหมดอายุหรือแผงรีสตาร์ท ให้ขอรับอันใหม่
> อย่าแชร์โทเค็น เมื่อการตั้งค่าเสร็จสิ้น พอร์ตนี้จะปิดและเหลือเพียงพอร์ตแผงปกติเท่านั้น

### 3.2 ขั้นตอนของวิซาร์ด

วิซาร์ดมี 8 ขั้นตอน คุณสามารถย้อนกลับได้ตลอดเวลา ไม่มีสิ่งใดเกิดขึ้นจนกว่าจะบันทึกครั้งสุดท้าย

| ขั้นตอน | เนื้อหา |
|------|---------|
| 1. ฐานข้อมูล | SQLite / MySQL / PostgreSQL |
| 2. ไดเร็กทอรีข้อมูล | เขียนถึง `SAFE_PATHS` ใน `.env` |
| 3. คีย์การเข้ารหัส | `JWT_SECRET` และ `CF_SECRET_ENCRYPTION_KEY` |
| 4. แกน | พร็อกซีคอร์ใดที่จะติดตั้ง |
| 5. หนังสือมอบฉันทะ | ไม่มี/Nginx/แคดดี้ |
| 6. ไซต์และโดเมน | พอร์ต เส้นทางเว็บ บัญชีผู้ดูแลระบบ สกุลเงิน เขตเวลา โดเมน |
| 7. ใบรับรอง HTTPS | ปิดการใช้งาน / อัพโหลด / ACME |
| 8. สรุป | ตรวจสอบ ดาวน์โหลด `.env` บันทึกและรีสตาร์ท |

#### ขั้นตอนที่ 1: ฐานข้อมูล

- **SQLite (แนะนำให้ใช้ไฟล์ในเครื่อง)**: ปล่อยพาธว่างไว้เพื่อใช้ `<data-dir>/sqlite/app.db`
- **MySQL / PostgreSQL**: โฮสต์ พอร์ต ผู้ใช้ รหัสผ่าน ชื่อฐานข้อมูล PostgreSQL ยังรองรับ `disable` / `require` / `verify-full` อีกด้วย
- คลิก “ทดสอบการเชื่อมต่อ” เพื่อตรวจสอบ การบันทึกยังทดสอบด้วย ฐานข้อมูลที่หายไปจะถูกสร้างขึ้นโดยอัตโนมัติ (สร้างด้วยตนเองหากบัญชีขาด `CREATE`)
- DSN (รวมถึงรหัสผ่าน) จะถูกเข้ารหัสก่อนที่จะเขียนลงใน `.env`

#### ขั้นตอนที่ 2: ไดเรกทอรีข้อมูล

จัดเก็บฐานข้อมูล ใบรับรอง บันทึก ไบนารีหลัก และอื่นๆ นี่คือ `SAFE_PATHS` ใน `.env` ค่าเริ่มต้นเป็น `data`
(สัมพันธ์กับไดเร็กทอรีการติดตั้ง); อนุญาตให้ใช้เส้นทางที่แน่นอนได้ **อย่าเปลี่ยนแบบลวกๆ ในภายหลัง** หรือแผง
จะไม่พบฐานข้อมูลและใบรับรองที่มีอยู่

#### ขั้นตอนที่ 3: คีย์การเข้ารหัส

- `JWT_SECRET`: ลงนามโทเค็นการเข้าสู่ระบบ
- `CF_SECRET_ENCRYPTION_KEY`: เข้ารหัสการตั้งค่าที่ละเอียดอ่อน (รหัสผ่านฐานข้อมูล ข้อมูลประจำตัว DNS บัตรเติมเงิน ฯลฯ)
- ทั้งสองถูกสร้างขึ้นแบบสุ่มโดยค่าเริ่มต้น ใช้ "สร้างใหม่" เพื่อรับค่าใหม่ **การเปลี่ยน `CF_SECRET_ENCRYPTION_KEY` ทำให้ข้อมูลที่เข้ารหัสก่อนหน้านี้ไม่สามารถอ่านได้** — สำรองข้อมูล

#### ขั้นตอนที่ 4: แกน

เลือกแกนพร็อกซีที่จะติดตั้ง:

- **Xray**: VLESS / VMess / Trojan / Shadowsocks ฯลฯ;
- **sing-box**: รองรับ Hysteria2 / TUIC และโปรโตคอล QUIC อื่นๆ

หลังจากบันทึกและรีสตาร์ทแผงควบคุมให้ดาวน์โหลดและติดตั้งโดยอัตโนมัติ ตรวจสอบเวอร์ชันและสถานะภายใต้ “โปรโตคอล” คุณยังสามารถติดตั้งได้ในภายหลัง

#### ขั้นตอนที่ 5: หนังสือมอบฉันทะ

- **ไม่มี**: แผงควบคุมให้บริการลูกค้าโดยตรง (จัดการ TLS ด้วยตัวเอง)
- **Nginx / Caddy**: แผงควบคุมจัดการพร็อกซีย้อนกลับและการโฮสต์ใบรับรอง เลือกอันหนึ่ง

เมื่อเลือกพร็อกซี แผงมักจะฟังเฉพาะบน `127.0.0.1` และพร็อกซีให้บริการโลกภายนอก

#### ขั้นตอนที่ 6: ไซต์และโดเมน

| สนาม | คำอธิบาย |
|-------|-------------|
| ที่อยู่ฟัง | ได้มาโดยอัตโนมัติ: พรอกซี → `127.0.0.1`; ไม่มีพร็อกซีที่มีใบรับรอง → `0.0.0.0`; มิฉะนั้น → `127.0.0.1` |
| พอร์ตแผง | พอร์ตสุ่มฟรีตามค่าเริ่มต้น เปลี่ยนถ้าคุณต้องการ (เช่น 8080) |
| พอร์ตการสมัครสมาชิก | ไม่จำเป็น; `0` ใช้พอร์ตแผงร่วมกัน |
| พอร์ตพอร์ทัล | ไม่จำเป็น; `0` ใช้พอร์ตแผงร่วมกัน |
| เส้นทางเว็บ | เส้นทาง UI ของผู้ดูแลระบบ ค่าเริ่มต้น `/`; API จะเป็น `/api/v1` เสมอ |
| ชื่อผู้ใช้ / รหัสผ่านของผู้ดูแลระบบ | สุ่มตามค่าเริ่มต้น **รหัสผ่านจะแสดงเพียงครั้งเดียวในการสรุป** — บันทึกไว้ |
| โหมดการเข้าถึง | “โดเมน” หรือ “ไอพี” |
| สกุลเงินเริ่มต้น / เขตเวลา | สกุลเงินเริ่มต้นสำหรับบัตรเติมเงินและยอดคงเหลือ เขตเวลาบันทึกพาเนลและพร็อกซี (เช่น `Asia/Shanghai`) |
| เพิ่มไปยังพร็อกซีย้อนกลับ | เมื่อตั้งค่าพร็อกซีและโดเมนแล้ว ให้เพิ่มโดเมนพาเนล / การสมัครสมาชิก / พอร์ทัลให้กับพร็อกซีในครั้งเดียว |

การป้อนโดเมนจะเขียนการตั้งค่าที่เกี่ยวข้อง (โดเมนติดต่อกลับ จุดสิ้นสุดการสมัครสมาชิก โดเมนที่ใช้ร่วมกัน)

#### ขั้นตอนที่ 7: ใบรับรอง HTTPS

| แหล่งที่มา | คำอธิบาย |
|--------|-------------|
| ปิดการใช้งาน HTTPS | แผง/พอร์ทัล/การสมัครสมาชิกให้บริการผ่าน HTTP (ไม่ปลอดภัย); ด้วยพร็อกซีย้อนกลับ คุณสามารถเพิ่ม TLS ในด้านพร็อกซีได้ในภายหลัง |
| อัปโหลดใบรับรอง | วางใบรับรอง PEM และคีย์ส่วนตัว PEM (โหมดการเข้าถึงโดเมนเท่านั้น) |
| ACME | ออกใบรับรองเมื่อคุณส่งขั้นตอนนี้ รองรับโดเมนและใบรับรอง IP |

ตัวเลือก ACME:

- **CA**: มาเข้ารหัสกันเถอะ (Staging), ZeroSSL, Google Public CA;
- **เป้าหมาย**: โดเมนที่กำหนดค่าหรือ IP สาธารณะ (Let's Encrypt เท่านั้นรองรับใบรับรอง IP)
- **ความท้าทาย**: `HTTP-01` (ต้องใช้พอร์ต 80) หรือ `DNS-01` (ไวด์การ์ด ไม่มีพอร์ต 80 เลือกผู้ให้บริการ DNS และป้อนข้อมูลประจำตัว)
- **ประเภท/ขนาดกุญแจ**: ECC 256/384 หรือ RSA 2048/3072/4096;
- **Google Public CA**: ต้องใช้ EAB; ป้อนรหัสคีย์ / HMAC ด้วยตนเองหรือใช้บัญชีบริการ GCP

> ใบรับรอง IP จะตรวจหา IPv4/IPv6 สาธารณะของโฮสต์โดยอัตโนมัติ ด้านหลังพรอกซี ที่อยู่ที่ตรวจพบจะเป็นของโฮสต์ ไม่ใช่ขาออกของพร็อกซี
> ใบรับรองโดเมนสามารถออกได้ในภายหลังภายใต้ "ใบรับรอง"

#### ขั้นตอนที่ 8: สรุป

แสดงฐานข้อมูล ไดเร็กทอรีข้อมูล คอร์ พร็อกซี พอร์ต บัญชีผู้ดูแลระบบ โดเมน และคีย์ `.env` (ปกปิดความลับ) และจัดเตรียม:

- **ดาวน์โหลด .env**: เก็บสำเนาการกำหนดค่าไว้
- **URL การเข้าถึง**: URL สุดท้ายสำหรับแผง / การสมัครสมาชิก / พอร์ทัล; HTTP ถูกทำเครื่องหมายว่าไม่ปลอดภัย

คลิก “บันทึกและรีสตาร์ท” เพื่อเขียนฐานข้อมูลและ `.env`; แผงควบคุมจะรีสตาร์ทเข้าสู่บริการตามปกติ

### 3.3 หลังจากตั้งค่าแล้ว

- บริการจะรีสตาร์ทและบันทึกการเริ่มต้นจะพิมพ์ที่อยู่การฟังสุดท้าย
- ลงชื่อเข้าใช้ด้วยบัญชีผู้ดูแลระบบ เข้าถึง URL และเส้นทางเว็บจากข้อมูลสรุป
- หากรหัสผ่านสูญหาย ให้รีเซ็ตออฟไลน์ด้วย `./corefusion admin reset-password`

### 3.4 การตั้งค่า CLI แบบไม่โต้ตอบ

สำหรับเซิร์ฟเวอร์อัตโนมัติหรือเซิร์ฟเวอร์ Headless ให้เขียนการกำหนดค่าและทำเครื่องหมายว่าการตั้งค่าเสร็จสมบูรณ์โดยตรง:

```bash
cd /opt/corefusion
./corefusion init \
  --db-type sqlite \
  --data-dir /opt/corefusion/data \
  --admin-username admin \
  --admin-password 'change-me-strong-password' \
  --listen-port 8080 \
  --proxy-type caddy \
  --cores xray,singbox \
  --panel-domain panel.example.com \
  --tls-mode acme --tls-domain panel.example.com --tls-email you@example.com
```

ธงทั่วไป:

| ธง | คำอธิบาย |
|------|-------------|
| `--db-type` / `--db-host` / `--db-port` / `--db-user` / `--db-password` / `--db-name` | การตั้งค่าฐานข้อมูล |
| `--data-dir` | ไดเร็กทอรีข้อมูล ค่าเริ่มต้นคือ `SAFE_PATHS` หรือ `./data` |
| `--listen-port` / `--subscription-port` / `--portal-port` / `--web-path` | พอร์ตและเส้นทางเว็บ (พอร์ตสุ่มฟรีตามค่าเริ่มต้น) |
| `--admin-username` / `--admin-password` | บัญชีผู้ดูแลระบบ (พิมพ์รหัสผ่านแบบสุ่มหนึ่งครั้งเมื่อละเว้น) |
| `--proxy-type` | `none` / `nginx` / `caddy` |
| `--cores` | แกนที่จะติดตั้ง โดยคั่นด้วยเครื่องหมายจุลภาค: `xray,singbox` |
| `--panel-domain` / `--subscription-domain` / `--portal-domain` | โดเมน (เขียนลงในการตั้งค่าและเพิ่มลงในพร็อกซีย้อนกลับ) |
| `--tls-mode` | `none` / `self_signed` / `acme` |
| `--tls-domain` / `--tls-email` / `--tls-challenge` / `--tls-key-type` / `--tls-key-bits` | ตัวเลือกใบรับรอง (`--tls-challenge` มีค่าเริ่มต้นเป็น `http-01`; `dns-01` ต้องการ `--tls-dns-channel` หรือ `--tls-dns-provider`) |
| `--tls-ip-cert` | ออกใบรับรองสำหรับ IP สาธารณะที่ตรวจพบ (มาเข้ารหัสเท่านั้น) |
| `--acme-provider` | `lets_encrypt` / `lets_encrypt_staging` / `zerossl` / `google` |
| `--currency` / `--timezone` | สกุลเงินเริ่มต้น / เขตเวลา |

รายการทั้งหมด: `./corefusion init --help` จากนั้นเริ่มบริการ:

```bash
systemctl restart corefusion
```

### 3.5 เรียกใช้ตัวช่วยสร้างการตั้งค่าอีกครั้ง

หากต้องการเริ่มต้นใหม่ (ลบ `.env` และเครื่องหมายการตั้งค่า **เก็บข้อมูล**):

```bash
cd /opt/corefusion
./corefusion reset-init      # type RESET to confirm
systemctl restart corefusion
```

จากนั้นใช้ URL และโทเค็นใหม่จากบันทึกการเริ่มต้นระบบ

> การเริ่มต้นใหม่จะรีเซ็ตบัญชีผู้ดูแลระบบและเส้นทางเว็บ ข้อมูลธุรกิจในฐานข้อมูลเก่ายังคงอยู่ แต่คุณอาจต้องสร้างบัญชีเข้าสู่ระบบใหม่
>
> `reset-init` จะลบ `.env` ทั้งหมด (รวมถึง `SAFE_PATHS` ด้วย) **หากไดเร็กทอรีข้อมูลของคุณเป็นพาธสัมบูรณ์ที่กำหนดเอง** ให้กู้คืน `SAFE_PATHS` ก่อนที่จะรีสตาร์ท ไม่เช่นนั้นพาเนลจะดูใน `./data`:
>
> ```ทุบตี
> printf 'SAFE_PATHS=/srv/corefusion-data\n' > /opt/corefusion/.env
> ```

### 3.6 การรักษาความปลอดภัยหลังจากการลงชื่อเข้าใช้ครั้งแรก

#### เปลี่ยนรหัสผ่านเริ่มต้น

1. คลิกชื่อผู้ใช้ที่มุมขวาบน
2. เลือก "เปลี่ยนรหัสผ่าน";
3. ป้อนรหัสผ่านเก่าและใหม่
4. คลิก "บันทึก"

#### เปิดใช้งานการเข้าสู่ระบบด้วยรหัสแบบไดนามิก (2FA / TOTP)

> เมื่อเปิดใช้งานแล้ว บัญชีจะสลับไปที่ **การเข้าสู่ระบบด้วยรหัสแบบไดนามิก**: ระบบไม่ยอมรับรหัสผ่านแบบคงที่อีกต่อไป เท่านั้น
> รหัส 6 หลักจากแอปยืนยันตัวตนของคุณ (หรือรหัสกู้คืนแบบครั้งเดียว) ใช้งานได้ การ **แทนที่** รหัสผ่านเข้าสู่ระบบ — มันคือ
> ไม่ใช่ "รหัสผ่าน + รหัส" การยืนยันแบบสองขั้นตอน

1. คลิกชื่อผู้ใช้ที่มุมขวาบน
2. เลือก "เปิดใช้งาน 2FA";
3. ป้อนรหัสผ่านปัจจุบัน (เพื่อยืนยันการเปลี่ยนแปลงนี้เท่านั้น)
4. สแกนโค้ด QR ด้วยแอปตรวจสอบสิทธิ์ (Google Authenticator / 1Password ฯลฯ) หรือป้อนรหัสด้วยตนเอง
5. ป้อนรหัส 6 หลักเพื่อเปิดใช้งานให้เสร็จสิ้น
6. **บันทึกรหัสกู้คืนทันที** (ดาวน์โหลดได้) แต่ละรหัสใช้งานได้เพียงครั้งเดียว

ลงชื่อเข้าใช้ภายหลัง:

- หลังจากป้อนชื่อผู้ใช้ ช่องรหัสผ่านจะกลายเป็น “รหัส 6 หลัก / รหัสกู้คืน” และปุ่มจะกลายเป็น “ลงชื่อเข้าใช้ด้วยรหัส”
- ป้อนรหัสปัจจุบัน **รหัสผ่านแบบคงที่ไม่สามารถใช้งานได้อีกต่อไป**;
- รหัสการกู้คืนเป็นแบบใช้ครั้งเดียว สร้างใหม่ภายใต้ "การเข้าสู่ระบบรหัสแบบไดนามิก (2FA)" เมื่อหมด (ซึ่งจะทำให้รหัสเก่าทั้งหมดเป็นโมฆะ)

หากตัวตรวจสอบความถูกต้องสูญหายและรหัสกู้คืนหมด ให้ปิดการใช้งาน 2FA ออฟไลน์บนเซิร์ฟเวอร์:

```bash
cd /opt/corefusion
./corefusion admin 2fa reset -u admin    # disables 2FA, clears the secret and recovery codes, revokes all sessions
```

> ผู้ดูแลระบบขั้นสูงเพียงคนเดียวที่ไม่มีทั้งตัวตรวจสอบสิทธิ์หรือรหัสกู้คืนจะไม่สามารถกู้คืนผ่าน UI ของเว็บได้ และต้องใช้คำสั่งด้านบน

#### ลงทะเบียน Passkey (ทางเลือก)

1. คลิกชื่อผู้ใช้ที่มุมขวาบน
2. เลือก “การจัดการ Passkey”;
3. คลิก “ลงทะเบียน Passkey ใหม่”;
4. กรอกข้อความแจ้งอุปกรณ์

> **หมายเหตุ**: Passkeys ต้องใช้ HTTPS หรือ localhost และโดเมนจะต้องอยู่ในรายการที่อนุญาต

## 4. แดชบอร์ด

แดชบอร์ดแสดงภาพรวมคลัสเตอร์แบบหลายโหนดและสถานภาพของโหนด

### 4.1 สิ่งที่แสดงให้เห็น

- **ข้อมูลระบบ**: ชื่อโฮสต์, เวอร์ชันระบบปฏิบัติการ, สถานะการออนไลน์, CPU, หน่วยความจำ
- **การรับส่งข้อมูล**: แบนด์วิดท์แบบเรียลไทม์ การรับส่งข้อมูลทั้งหมด แนวโน้มรายเดือน
- **ความสมบูรณ์ของโหนด**: จำนวนออนไลน์ / ออฟไลน์ / ลดลง โหนดที่มีภาระงานสูง
- **การแจ้งเตือน**: โหนดออฟไลน์, โหนดลดระดับ, ใบรับรองจะหมดอายุเร็วๆ นี้, คำเตือนโควต้า
- **ทรัพยากรคลัสเตอร์**: CPU, หน่วยความจำ, ดิสก์ และปริมาณงานโดยเฉลี่ย

### 4.2 การดำเนินการ

- คลิก "ดูรายละเอียด" เพื่อเปิดหน้ารายละเอียดของโหนด
- คลิกการ์ดโหนดเพื่อดูสถานะปัจจุบัน
- ใช้ตัวกรองเพื่อจำกัดตามสถานะ ประเภท หรือภูมิภาค

## 5. การจัดการโหนด

การจัดการโหนดเป็นแกนหลักของ CoreFusion และรองรับโหนดหลายประเภท

### 5.1 ประเภทโหนด

| ประเภท | คำอธิบาย |
|------|-------------|
| แบบสแตนด์อโลน (`standalone`) | โหนดหลักที่เป็นอิสระ |
| กระจกมองข้าง (`mirror`) | ซิงค์การกำหนดค่าจากโหนดเป้าหมาย |
| หลัก/สำรอง (`primary_backup`) | โหนดพันธมิตรที่ล้มเหลวซึ่งกันและกัน |
| รายการโซ่ (`chain_entry`) | โหนดรายการของพร็อกซีที่ถูกลูกโซ่ |
| ทางออกโซ่ (`chain_exit`) | โหนดทางออกของพร็อกซีที่ถูกลูกโซ่ |

### 5.2 การเพิ่มโหนด

1. เปิด "การจัดการโหนด";
2. คลิก "เพิ่มเซิร์ฟเวอร์";
3. กรอกข้อมูลพื้นฐาน:
   - ชื่อ เช่น `HongKong-HK01`
   - ชื่อโฮสต์: IP หรือโดเมน
   - ภูมิภาค เช่น `HK`, `JP`, `US`
   - ประเภทโหนด
4. ตั้งค่าพอร์ตตัวแทน (ค่าเริ่มต้น `18443`)
5. เลือกคอร์ที่รองรับ
6. คลิก "บันทึก"

### 5.3 การปรับใช้เพียงคลิกเดียว

1. หลังจากเพิ่มโหนดแล้วให้คลิก "คำสั่ง Bootstrap";
2. คัดลอกคำสั่งติดตั้ง
3. รันเป็นรูทบนโหนดระยะไกล:

   ```bash
   curl -fsSL https://your-panel/install.sh | bash
   ```

4. Agent จะดาวน์โหลด ลงทะเบียน และเริ่มทำงานโดยอัตโนมัติ

### 5.4 รายละเอียดโหนด

คลิกโหนดเพื่อเปิดหน้ารายละเอียด:

- **ภาพรวม**: ข้อมูลพื้นฐาน สถานะตัวแทน สถานะใบรับรอง
- **ศูนย์โปรโตคอล**: การกำหนดค่ากระบวนการหลัก
- **พร็อกซี**: การกำหนดค่าแคดดี้ / Nginx
- **กระบวนการหลัก**: เริ่ม / หยุด / รีสตาร์ท
- **WARP**: การกำหนดค่า WARP
- **โดเมนโดยตรง**: การจัดการโดเมน
- **ขีดจำกัดอัตรา**: การกำหนดรูปแบบการรับส่งข้อมูล
- **ใบรับรอง**: การผูกใบรับรอง
- **ผู้ใช้ออนไลน์**: ผู้ใช้ออนไลน์แบบเรียลไทม์

### 5.5 การทำงานของโหนด

- **การกำหนดค่าการซิงค์**: พุชการกำหนดค่าพาเนลไปที่โหนด
- **บังคับเชื่อมต่อใหม่**: ยกเลิกการเชื่อมต่อตัวแทนและเชื่อมต่อใหม่
- **Update Agent**: พุชการอัปเดต Agent
- **เพิกถอนใบรับรอง**: เพิกถอนใบรับรองตัวแทนของโหนด

## 6. ศูนย์โปรโตคอล

ศูนย์โปรโตคอลจะกำหนดค่าพารามิเตอร์โปรโตคอลสำหรับกระบวนการหลัก

### 6.1 แกนประมวลผลที่รองรับ

| แกนกลาง | คำอธิบาย |
|------|-------------|
| Xray-คอร์ | VLESS / VMess / Trojan / Shadowsocks และอื่นๆ |
| sing-box | แพลตฟอร์มพร็อกซีสากลแบบแยกส่วนพร้อมรองรับ TUN ดำเนินการ Hysteria2 / TUIC และโปรโตคอล QUIC อื่น ๆ |

### 6.2 โมดูลการกำหนดค่า

- **บันทึก**: บันทึกการเข้าถึง บันทึกข้อผิดพลาด โหมดเอาต์พุต
- **API**: ที่อยู่การฟัง gRPC API รายการบริการ
- **DNS**: เซิร์ฟเวอร์ DNS, กลยุทธ์การสืบค้น, โฮสต์แบบคงที่
- **การกำหนดเส้นทาง**: กฎการกำหนดเส้นทาง, การปรับสมดุลโหลด, การกำหนดเส้นทาง VLESS
- **ขาเข้า**: รายการขาเข้า การตั้งค่าโปรโตคอล การขนส่ง TLS
- **ขาออก**: รายการขาออก การตั้งค่าโปรโตคอล การขนส่ง
- **การขนส่ง**: WebSocket, gRPC, XHTTP, TUN ฯลฯ
- **TLS**: ใบรับรอง, ALPN, ลายนิ้วมือ uTLS, ECH
- **Reality**: การจัดการเป้าหมาย คู่คีย์ รหัสแบบสั้น
- **การตรวจสุขภาพ**: โพรบ URL ช่วงเวลา การทำงานพร้อมกัน
- **FakeDNS**: IP พูล ขนาดพูล
- **ตัวชี้วัด**: ผู้ฟังตัวชี้วัด Prometheus
- **นโยบาย**: การหมดเวลาการเชื่อมต่อ บัฟเฟอร์ สถิติ
- **ข้อมูลภูมิศาสตร์**: อัปเดตอัตโนมัติ ไฟล์ทรัพยากร
- **ข้อ จำกัด เวอร์ชัน **: เวอร์ชันขั้นต่ำ / สูงสุด

### 6.3 การกำหนดค่าขาเข้า

1. เลือกแกนหลักและโปรโตคอล
2. กรอกข้อมูลพื้นฐาน:
   - แท็ก
   - ฟังที่อยู่และพอร์ต
   - ประเภทโปรโตคอล
3. ตั้งค่าพารามิเตอร์โปรโตคอล (UUID, รหัสผ่าน ฯลฯ );
4. เลือกการขนส่ง (TCP, WebSocket, gRPC ฯลฯ )
5. กำหนดค่า TLS (ใบรับรอง, ALPN)
6. บันทึกและนำไปใช้กับแกนกลาง

### 6.4 การกำหนดค่าขาออก

1. เพิ่มขาออก
2. ตั้งค่าแท็กและโปรโตคอล
3. ตั้งค่าที่อยู่เซิร์ฟเวอร์และพอร์ต
4. กำหนดค่าการขนส่งและ TLS;
5. บันทึกและนำไปใช้

### 6.5 แชร์ลิงก์

1. คลิก "แชร์ลิงก์" ในรายการขาเข้า
2. เลือกรูปแบบ:
   - แบ่งปัน URI
   - มิโฮโม YAML
   - sing-box JSON
   - Xray JSON
3. คัดลอกลิงก์หรือสร้างโค้ด QR

## 7. การจัดการพร็อกซี

การจัดการพร็อกซีกำหนดค่าพร็อกซีย้อนกลับของแคดดี้หรือ Nginx

### 7.1 ประเภทพร็อกซี

- **แคดดี้**: อัตโนมัติ HTTPS, HTTP/2, HTTP/3
- **Nginx**: ประสิทธิภาพสูง การกำหนดค่าที่ยืดหยุ่น

### 7.2 การกำหนดค่าไซต์

1. เปิด "การจัดการพร็อกซี";
2. เลือกประเภทพร็อกซี (แคดดี้ / Nginx)
3. เพิ่มไซต์:
   - โดเมน
   - ต้นน้ำ
   - ท่าเรือท้องถิ่น
4. บันทึก

### 7.3 สนาม

- **อัปสตรีม**: ที่อยู่แบ็กเอนด์ เช่น `127.0.0.1:8082`
- **local_port**: พอร์ตการฟังในเครื่อง เช่น `8443`
- **portal_forward**: กฎการส่งต่อพอร์ทัล
- **subscription_forward**: กฎการส่งต่อการสมัครรับข้อมูล

   - รูปแบบหมายเลขบัตร

## 14. การจัดการใบรับรอง

การจัดการใบรับรองจัดการใบรับรอง TLS

### 14.1 การออกใบรับรอง

1. เปิด "การจัดการใบรับรอง";
2. คลิก "ออกใบรับรอง";
3. กรอก:
   - รายการโดเมน (หนึ่งรายการต่อบรรทัด)
   - ประเภทใบรับรอง (โดเมน / IP)
   - ประเภทกุญแจ (ECC / RSA)
   - วิธีการตรวจสอบ (DNS-01 / HTTP-01)
   - ผู้ให้บริการ DNS
   - สถานที่ออก (โฮสต์แผง / โหนด)
4. คลิก "ปัญหา"

### 14.2 การดำเนินการของใบรับรอง

- **ต่ออายุ**: ต่ออายุด้วยตนเอง
- **ปรับใช้**: ปรับใช้กับโหนด
- **กระจาย**: พุชไปยังโหนดที่เกี่ยวข้องทั้งหมด
- **ย้ายข้อมูล**: ย้ายการอ้างอิงจากใบรับรองเก่าไปยังใบรับรองใหม่
- **ดาวน์โหลด**: ดาวน์โหลด `cert` / `fullchain` / `privkey`

### 14.3 การอัพโหลดใบรับรอง

1. คลิก "อัปโหลดใบรับรอง";
2. เลือกวิธีการ:
   - วางเนื้อหา
   - อัพโหลดไฟล์
3. อัปโหลดห่วงโซ่ใบรับรองและคีย์ส่วนตัว
4. บันทึก.

### 14.4 การกำหนดค่า EAB

- จัดการข้อมูลประจำตัว EAB สำหรับ Google Public CA / ZeroSSL
- รับ EAB โดยอัตโนมัติ
- แนบมันโดยอัตโนมัติเมื่อออก

## 26. คำถามที่พบบ่อย

### 26.1 แผงควบคุมไม่เริ่มทำงาน

- ตรวจสอบว่าพอร์ตมีการใช้งานอยู่แล้วหรือไม่
- ตรวจสอบว่า `.env` ถูกต้อง
- ตรวจสอบบันทึก: `journalctl -u corefusion -f`; ไม่มี systemd, `tail -f <install-dir>/data/logs/panel.log`

### 26.2 โหนดออฟไลน์

- ตรวจสอบว่า Agent กำลังทำงานอยู่: `systemctl status corefusion-agent`
- ตรวจสอบการเชื่อมต่อเครือข่าย
- ตรวจสอบกฎไฟร์วอลล์ (พอร์ต `18443`)

### 26.3 การออกใบรับรองล้มเหลว

- ตรวจสอบความละเอียด DNS
- ตรวจสอบว่าสามารถเข้าถึงพอร์ต 80 ได้
- ตรวจสอบการกำหนดค่าผู้ให้บริการ DNS
- ตรวจสอบบันทึกใบรับรอง

### 26.4 การสมัครสมาชิกไม่ทำงาน

- ตรวจสอบลิงค์สมัครสมาชิก
- ตรวจสอบว่าโหนดออนไลน์อยู่
- ตรวจสอบว่ากระบวนการหลักกำลังทำงานอยู่
- ตรวจสอบกฎไฟร์วอลล์

### 26.5 การเติมเงินโทรกลับล้มเหลว

- ตรวจสอบการโทรกลับ URL
- ตรวจสอบว่าคีย์ไซต์ตรงกัน
- ตรวจสอบรายการอนุญาต IP
- ตรวจสอบบันทึกการสั่งซื้อ

### 26.6 หน้าพอร์ทัลไม่สามารถเข้าถึงได้

- ตรวจสอบว่าพอร์ตพอร์ทัลเปิดอยู่
- ตรวจสอบการกำหนดค่าพาธพอร์ทัล
- **สำคัญ**: ตรวจสอบให้แน่ใจว่าพร็อกซีย้อนกลับส่งต่อโดเมนพอร์ทัลไปยัง **พอร์ตกลไกพอร์ทัล** ไม่ใช่พอร์ตแผงหลัก — การส่งต่อไปยังพอร์ตที่ไม่ถูกต้องจะแสดงหน้าว่างหรือแผงแทนพอร์ทัล ตรวจสอบ `upstream` / `local_port` ในบันทึกไซต์พร็อกซี
- เปิด `http://<portal-domain>:<portal-port>` โดยตรงเพื่อตรวจสอบพอร์ทัลเอ็นจิ้นเอง
- ตรวจสอบการกำหนดค่าพร็อกซีย้อนกลับ
- ตรวจสอบบันทึกของพอร์ทัล

## ภาคผนวก

### A. พอร์ตเริ่มต้น

| ท่าเรือ | วัตถุประสงค์ |
|------|---------|
| กำหนดโดยวิซาร์ดการตั้งค่า (พอร์ตสุ่มฟรีตามค่าเริ่มต้น) | แผงผู้ดูแลระบบ (เปลี่ยนแปลงได้) |
| 18443 | ตัวแทน gRPC (เปลี่ยนแปลงได้) |
| 0 (ปิดใช้งานโดยค่าเริ่มต้น) | พอร์ตเอ็นจิ้นการสมัครสมาชิกเฉพาะ (ว่างเปล่าหรือ `0` แชร์พอร์ตหลัก) |
| 0 (ปิดใช้งานโดยค่าเริ่มต้น) | พอร์ตเอ็นจิ้นพอร์ทัลเฉพาะ (ว่างเปล่าหรือ `0` แชร์พอร์ตหลัก) |
| 80/443 | พร็อกซีย้อนกลับ (แคดดี้ / Nginx) HTTP / HTTPS |

### B. เส้นทางเริ่มต้น

| เส้นทาง | วัตถุประสงค์ |
|------|---------|
| `/` | แผงผู้ดูแลระบบ (พอร์ทัลยังอยู่ที่ `/` เมื่อไม่มีการกำหนดค่ากลไกพอร์ทัลเฉพาะ) |
| `/sub/:token` | การดึงข้อมูลการสมัครสมาชิก (เมื่อไม่มีการกำหนดค่าพอร์ตการสมัครสมาชิกเฉพาะ) |
| `/p` | พอร์ทัลเพจ (เมื่อไม่มีการกำหนดค่าพอร์ตพอร์ทัลเฉพาะ) |
| `/:token` | การดึงข้อมูลการสมัครสมาชิก (พร้อมพอร์ตการสมัครสมาชิกเฉพาะ โดยไม่มีคำนำหน้า `/sub`) |

### C. เครื่องมือบรรทัดคำสั่ง

ไบนารีพาเนลสนับสนุนคำสั่งย่อยเหล่านี้ (ไม่มีอาร์กิวเมนต์ที่สตาร์ทเซิร์ฟเวอร์):

```bash
# Start the panel (same as ./corefusion server)
./corefusion

# Run database migrations
./corefusion migrate

# Offline administration (when you cannot sign in)
./corefusion admin reset-password -u admin -p 'new-password'
./corefusion admin 2fa reset -u admin
./corefusion admin list

# Version / help
./corefusion version
./corefusion help
```

> หากไม่มียูนิต systemd ให้รีสตาร์ทโดยหยุดกระบวนการเก่า และเริ่มใหม่อีกครั้งด้วย `nohup` บันทึกอยู่ใน `<install-dir>/data/logs/panel.log`
