# 通知テンプレートの変数

> 言語： [简体中文](notification-templates.md) · [English](notification-templates.en.md) · [繁體中文](notification-templates.zh-TW.md) · [Русский](notification-templates.ru.md) · 日本語 · [한국어](notification-templates.ko.md) · [Deutsch](notification-templates.de.md) · [Français](notification-templates.fr.md) · [Español](notification-templates.es.md) · [Português](notification-templates.pt.md) · [Türkçe](notification-templates.tr.md) · [Bahasa Indonesia](notification-templates.id.md) · [ไทย](notification-templates.th.md) · [Tiếng Việt](notification-templates.vi.md) · [العربية](notification-templates.ar.md) · [فارسی](notification-templates.fa.md)

通知テンプレートは、送信時に実際の値に置き換えられる `{variable}` プレースホルダーを使用します。このドキュメントには、サポートされているすべての変数、イベントごとに使用可能な変数、および自動トリガー ルールがリストされています。

## 1. テンプレートの種類と対象者

| 観客 | チャンネル | 受信者 | 一般的な使用方法 |
|---|---|---|---|
| **パネル ユーザー** (管理者) | Telegram / メール | 管理者によって構成されたチャネルと受信者 | ノードアラート、バックアップレポート、システムアナウンス |
| **購読者** | 電子メール | 顧客自身のメールアドレス (自動的に入力されます) | 残高不足、サブスクリプション有効期限のリマインダー |

## 2. 共通変数

すべてのテンプレートで利用可能:

| 変数 | 説明 | 例 |
|---|---|---|
| `{time}` | 送信時間 | `2026-09-28 14:30:00` |
| `{user}` | 顧客の電子メール (購読者テンプレート) / ユーザー識別子 | `user@example.com` |
| `{message}` | 通知本文 | メンテナンス告知文 |

## 3. サブスクライバイベント変数

### サブスクリプション有効期限リマインダー (event_key = `subscription_expire`)

毎日スキャンされ、7 日以内に有効期限が切れるアクティブな購読者に送信されます。

| 変数 | 説明 | 例 |
|---|---|---|
| `{user}` | 顧客の電子メール | `user@example.com` |
| `{expire_date}` | サブスクリプションの有効期限 | `2026-10-05 09:00` |
| `{days}` | 残り日数 | `7` |
| `{time}` | 送信時間 | `2026-09-28 09:05:00` |

### 残高不足リマインダー (event_key = `balance_low`)

毎日スキャンされ、残高がしきい値を下回っている顧客に送信されます。

| 変数 | 説明 | 例 |
|---|---|---|
| `{user}` | 顧客の電子メール | `user@example.com` |
| `{balance}` | 現在の残高 (通貨単位、小数点以下 2 桁) | `0.85` |
| `{time}` | 送信時間 | `2026-09-28 09:05:00` |

## 4. 操作テンプレートの変数の例

接続テストの [送信] をクリックすると、パネル ユーザー テンプレートのプレースホルダーに次の例が入力されます。

| 変数 | 説明 | 例 |
|---|---|---|
| `{node}` | ノード名 | `node-01` |
| `{backup_file}` | バックアップファイル名 | `corefusion-20260101-0900.tar.gz` |
| `{size}` | ファイルサイズ | `128MB` |
| `{domain}` | ドメイン | `example.com` |
| `{expire_date}` | 有効期限 | `2026-10-12` |
| `{days}` | 残り日数 | `14` |
| `{count}` | カウント | `3` |

## 5. 自動トリガールール

- **スケジュール**: 最初のスキャンはパネルの開始から 30 秒後に実行され、その後は毎日 **09:05** に実行されます。
- **サブスクリプションの有効期限**: 7 日以内に有効期限が切れるアクティブなサブスクリプション (`status=active`) をスキャンします。顧客もアクティブでなければなりません
- **低残高**: 残高がしきい値以下のアクティブな顧客をスキャンします。しきい値は `notify.balance_threshold`、**セント** (デフォルトは `100` = 1.00)
- **重複排除**: **1 日あたり**、イベントごとに顧客ごとに最大 1 つのメッセージ (`notification_send_logs` は日ごとに重複排除します)

## 6. ノードの健全性監視

ノードのハートビートは継続的にチェックされます。 **通知は状態が変化した場合にのみ送信されます - 変化のないラウンドはサイレントです**:

| 設定キー | 説明 | デフォルト |
|---|---|---|
| `monitor.node_interval_seconds` | チェック間隔(秒) | `60` (最低 30) |
| `monitor.node_offline_timeout_seconds` | ハートビートタイムアウト(秒) | `120` |

- **オフライン アラート**: ノードがオンラインからオフラインに移行すると、`{node}` (名前) および `{time}` を含む管理テンプレート「**ノード オフライン アラート**」を送信します。
- **復旧通知**: ノードが復旧すると、同じ変数を使用して「**ノード復旧通知**」を送信します
- **サイレント ラウンド**: 状態が変化しない場合はメッセージはありません。パネルの再起動後、最初のラウンドはベースラインを確立するだけです
- **送信せずに監視**: 対応するテンプレートを無効にします (有効 = オフ)

## 7. ノードの月間トラフィック割り当てアラート (自動)

- **トリガー**: ノードの月間トラフィックがクォータしきい値に達すると、「**ノード トラフィック クォータ アラート**」が送信されます。 100%を超えて中断されると、制限超過アラートを送信します(イベントキー`traffic_quota_threshold` / `traffic_quota_exceeded`)。
- **しきい値**: `monitor.traffic_quota_threshold_percent` (パーセンテージ、デフォルトは `80`、しきい値アラートを無効にするには `0` を設定します)
- **重複排除**: 請求サイクルごとにノードごとに最大 1 つ (サイクルはノードの `traffic_quota_reset_day` に従います)
- 使用可能な変数: `{node}` (名前)、`{used}` (使用 GB)、`{quota}` (GB クォータ)、`{percent}` (パーセント)、`{time}`

## 8. バックアップ結果通知（自動）

- **トリガー**: スケジュールされたバックアップ (`BackupScheduler`) の実行直後に送信されます。成功した場合は「**日次バックアップ レポート**」が送信され、失敗した場合 (バックアップの作成/ストレージの読み取り/リモートへのアップロード) は「**バックアップ失敗アラート**」が送信されます。
- 使用可能な変数: `{backup_file}` (名前)、`{size}` (サイズ、成功レポートのみ)、`{message}` (失敗の理由、失敗アラートのみ)、`{time}`
- **送信せずに監視**: テンプレートが無効になっている場合はサイレントにスキップされます (有効 = オフ)。

## 9. 証明書の有効期限のリマインダー（自動）

- **トリガー**: 毎日 09:05、有効期限が近づいている `active` 証明書 (**残り 3 日の IP 証明書**、**残り 7 日のドメイン証明書**) をスキャンし、証明書ごとに管理テンプレート「**証明書有効期限リマインダー**」を送信します。
- **重複排除**: 証明書ごとに 1 日あたり最大 1 回のリマインダー。更新後は有効期限が枠外（IP 3 日 / ドメイン 7 日）に移動し、リマインダーが停止します。
- 使用可能な変数: `{domain}` (証明書ドメイン)、`{expire_date}` (有効期限)、`{days}` (残り日数)、`{time}`

## 10. コアプロセスクラッシュアラート（自動）

- **トリガー**: コア プロセス (xray/singbox) が異常終了するか、プロキシ プロセス (caddy/nginx) がクラッシュすると、管理テンプレート「**コア プロセス クラッシュ アラート**」が直ちに送信されます。その後、スーパーバイザは指数関数的バックオフで再起動します。
- 使用可能な変数: `{core}` (プロセス タイプ)、`{restarts}` / `{max}` (再起動回数 / 制限)、`{message}` (終了メッセージ、コア プロセスのみ)、`{time}`
- **送信せずに監視**: テンプレートが無効になっている場合はサイレントにスキップされます (有効 = オフ)。

## 11. 新規ユーザー登録のお知らせ（自動）

- **トリガー**: 管理テンプレート「**新規ユーザー登録通知**」を使用して、顧客が登録に成功した直後に送信されます。
- 利用可能な変数: `{user}` (顧客の電子メール)、`{time}`

## 12. 使用法

1. **テンプレートを追加**: 通知設定 → 通知テンプレート → テンプレートを追加 → 「プリセットから入力」し、必要に応じて調整します
2. **有効**: 「有効」にチェックを入れて保存します。自動トリガーは有効なテンプレートのみを処理します
3. **テスト**: リストの [送信] をクリックして、サンプル変数を含む実際のメッセージを送信します (サブスクライバー テンプレートのテスト電子メールは管理者の送信者アドレスに送信されます)。
4. **即時通知** (ビジネス コード): イベント会場で `NotifyClientEvent(ctx, db, settingSvc, eventKey, clientEmail, vars)` に電話して (チャージ、控除、更新)、1 日のスキャン制限を超えて 1 人の顧客にただちに通知します。
