## 1. نمای کلی سیستم

CoreFusion یک پنل مدیریت پروکسی چند پروتکلی است که از VLESS، VMess، Trojan، Shadowsocks، Hysteria2، TUIC و موارد دیگر پشتیبانی می‌کند، با مدیریت گره، مدیریت اشتراک، گواهینامه‌های ارائه شده توسط مشتریان،x.

### 1.1 ویژگی های اصلی

| ماژول | توضیحات |
|--------|-------------|
| چند پروتکلی | VLESS، VMess، Trojan، Shadowsocks، Hysteria2، TUIC، WireGuard، و غیره. |
| چند هسته ای | Xray-core و sing-box (Hysteria2/TUIC و سایر پروتکل‌های QUIC روی sing-box اجرا می‌شوند) |
| چند گره | پنج نوع گره: مستقل، آینه ای، فعال/آماده به کار، ورودی زنجیردار، خروجی زنجیره ای |
| تحویل اشتراک | چندین فرمت اشتراک، نقاط پایانی و مدیریت قالب |
| صورتحساب | قالب های طرح، کارت های شارژ، موجودی، سفارشات، کمیسیون نمایندگی فروش |
| گواهینامه ها | اجازه دهید صدور را رمزگذاری کنیم، اعتبار سنجی DNS-01/HTTP-01، توزیع گواهی |
| پروکسی زنجیر شده | تعادل بار چند خروجی، ثبت گره خارجی، مسیریابی زنجیره ای |
| سهمیه های ترافیکی | نظارت بر ترافیک ماهانه در هر گره، تعلیق خودکار، بازنشانی گزارش‌ها |
| پورتال | ویرایشگر پورتال بصری، چند زبانه، قالب های سفارشی |
| اطلاعیه ها | ایمیل و Telegram، قالب ها و پخش ها |

### 1.2 معماری

- **پشت زمینه**: برو، gRPC
- **Frontend**: Vue 3 + Element Plus
- **پایگاه داده**: SQLite (پیش فرض) / MySQL / PostgreSQL
- **پراکسی**: Caddy / Nginx پراکسی معکوس
- **پورت پانل**: توسط جادوگر راه اندازی اختصاص داده شده است (درگاه آزاد تصادفی به طور پیش فرض؛ 8080 یک انتخاب رایج است)
- **پورت عامل gRPC**: 18443 به طور پیش فرض

## 2. نصب و راه اندازی

### 2.1 محیط های پشتیبانی شده

| مورد | پشتیبانی کنید |
|------|---------|
| توزیع ها | دبیان / اوبونتو، RHEL / CentOS / Rocky / AlmaLinux / Fedora، Alpine، Arch، openSUSE |
| معماری های CPU | باینری های رسمی: `amd64`، `arm64`؛ بیلدهای منبع نیز از `armv7`، `armv6`، `386`، `ppc64le`، `s390x`، `riscv64`، `loong64` پشتیبانی می کنند |
| مدیر خدمات | systemd (توصیه می شود)؛ در کانتینرها یا محیط های دیگر بدون systemd به `nohup` برمی گردد |
| حافظه / دیسک | ≥ 1 گیگابایت / ≥ 10 گیگابایت (پایگاه داده، گواهی‌ها، گزارش‌ها و باینری‌های هسته موجود در فهرست داده‌ها) |
| پورت پنل | انتخاب شده در جادوگر راه اندازی (درگاه آزاد تصادفی به طور پیش فرض؛ `8080` و موارد مشابه خوب هستند) |
| عامل gRPC | `18443` به طور پیش فرض |

دستورات خارجی Runtime به طور خودکار توسط نصب کننده نصب می شوند (`scripts/install.sh` و اسکریپت نصب Agent که توسط پنل تولید می شود؛ با `--no-deps` / `CF_SKIP_DEPS=1` رد شوید):

| هدف | بسته |
|---------|---------|
| فایروال / محدودیت نرخ / علامت گذاری همزمان | `nftables` (`nft`) |
| شکل دهی ترافیک، لینک ها و سوکت ها | `iproute2` (`tc` / `ip` / `ss`) |
| بازگشت زمانی که nft در دسترس نیست | `iptables` (`iptables-nft` در EL8+، `iptables` در EL7) |
| ردیابی اتصال | `conntrack-tools` (`conntrack`) |
| بارگذاری `nf_conntrack` / `ifb` | `kmod` (`modprobe` / `lsmod`) |
| شناسایی و پاکسازی فرآیند | `procps` (`pgrep` / `pkill`) |
| بررسی بندر / پارامترهای DH | `lsof` / `openssl` |
| ایجاد کاربر پروکسی | `shadow-utils` (Debian `passwd`، Alpine/Arch `shadow`) |
| دانلود و آرشیو | `curl` / `ca-certificates` / `tar` / `gzip` / `xz` |

> گم شدن `nft` / `tc` فقط بر محدودیت نرخ و ویژگی های فایروال تأثیر می گذارد. پانل هنوز شروع می شود
> ابتدا `--cpu-info` را اجرا کنید تا ببینید محیط چگونه شناسایی می شود و کدام بسته ها گم شده اند.

### 2.2 نصب تک خطی (توصیه می شود)

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh -o install.sh
sudo bash install.sh
```

یا مستقیماً آن را لوله کنید (بدون تعامل، بدون پرچم اضافی):

```bash
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash
```

اسکریپت:

1. توزیع، معماری CPU و libc را شناسایی کنید، سپس بسته های پایه و وابستگی های زمان اجرا را نصب کنید.
2. `corefusion-linux-<arch>` را از نسخه های GitHub دانلود کنید و آن را با `.sha256` منطبق تأیید کنید.
3. در `/opt/corefusion` نصب کنید و `data/{sqlite,certs,logs,runtime}` را ایجاد کنید.
4. فقط یک مکان نگهدار `.env` با `SAFE_PATHS=data` بنویسید - بدون پیکربندی پایگاه داده - بنابراین اولین شروع وارد جادوگر نصب می شود (`.env` کامل توسط جادوگر تولید می شود).
5. یک سرویس systemd را نصب و راه اندازی کنید (یا زمانی که systemd در دسترس نیست، تحت `nohup` اجرا شود).
6. منتظر بمانید تا آماده شود، سپس مسیرهای راه اندازی URL، نشانه و فهرست راهنما را چاپ کنید.

خروجی نمونه:

```text
==================================================================
 CoreFusion installation complete
------------------------------------------------------------------
 Install dir : /opt/corefusion
 Data dir    : /opt/corefusion/data
 Binary      : /opt/corefusion/corefusion
 Logs        : journalctl -u corefusion -f
------------------------------------------------------------------
 Setup wizard : http://<server-ip>:<random-port>/init?init_token=<token>
 Setup token  : <token>
 Valid for    : 2 hours (see startup log)
 Note         : the token is shown once; after setup this port closes and the panel switches to its normal port.
==================================================================
```

اگر پانل فقط به `127.0.0.1` گوش می دهد (مثلاً پشت پراکسی معکوس)، اسکریپت به جای یک URL غیرقابل دسترس، یک دستور تونل SSH را چاپ می کند.

> رمز را گم کرده اید؟ گزارش راه اندازی را دوباره بخوانید: `journalctl -u corefusion -n 50 --no-pager`
> (بدون systemd: `tail -n 50 /opt/corefusion/data/logs/panel.log`).

### 2.2.1 خروجی چندزبانه

نصب‌کننده چهار زبان رابط دارد: چینی ساده‌شده، انگلیسی، فارسی و روسی. زبان به‌طور خودکار از `LANG` سیستم انتخاب می‌شود و می‌توان آن را صریحاً تعیین کرد:

```bash
# فارسی
sudo bash install.sh --lang fa

# روسی با متغیر محیطی
sudo CF_LANG=ru bash install.sh

# انتقال پارامترها در نصب با pipe
curl -fsSL https://raw.githubusercontent.com/qist/corefusion/main/scripts/install.sh | sudo bash -s -- --lang en
```

مقادیر پشتیبانی‌شده: `zh` / `en` / `fa` / `ru`؛ `--lang=ru` نیز پذیرفته می‌شود. اگر زبان صریحاً پشتیبانی نشود، خطا و فهرست زبان‌های موجود نمایش داده می‌شود.

### 2.3 نسخه پین / آینه / نصب آفلاین

```bash
# Pin a version
sudo bash install.sh --version v0.13.0-alpha.2

# GitHub download mirror (used as a URL prefix)
sudo bash install.sh --mirror https://ghproxy.net --version latest

# Use a local binary (offline / intranet / pre-built)
sudo bash install.sh --local ./dist/corefusion-linux-arm64

# Explicit target architecture
sudo bash install.sh --arch arm64 --local ./corefusion-linux-arm64
```

> بدون `--version`، اسکریپت از جدیدترین ورودی در لیست انتشارات GitHub استفاده می کند.
> اکثر نسخه ها پیش از انتشار هستند، بنابراین نقطه پایانی `/releases/latest` استفاده نمی شود.
>
> نسخه های رسمی فقط `amd64` / `arm64` را ارائه می دهند. از `--source` یا یک باینری متقابل کامپایل شده با `--local` برای معماری های دیگر استفاده کنید.

### 2.4 ساختن از مبدا

```bash
sudo bash install.sh --source --version v0.13.0-alpha.2
```

`--source` مخزن را شبیه سازی می کند (یا وقتی اسکریپت داخل آن است از پرداخت موجود استفاده می کند) و `make panel` را اجرا می کند. نسخه های زنجیره ابزار در هر محیط انتخاب می شوند:

| وابستگی | انتخاب |
|------------|-----------|
| برو | خواندن از `toolchain` / `go` در `go.mod` (در حال حاضر ** برو 1.27+**)؛ اگر نسخه سیستم خیلی قدیمی باشد، زنجیره ابزار منطبق در `<install-dir>/.toolchain` دانلود می شود |
| گره | ** Node 22 LTS ** به طور پیش فرض (Vite به ≥ 18 نیاز دارد). یک بیلد رسمی منطبق در صورت نیاز دانلود می شود |
| گره (glibc < 2.28) | از ساخت `unofficial-builds` glibc-217 استفاده می کند (به عنوان مثال CentOS 7) |
| گره (آلپ / musl) | از توزیع `nodejs` / `npm` استفاده می کند |

لغو:

```bash
# Force Go / Node versions
sudo CF_GO_VERSION=1.27.5 CF_NODE_MAJOR=22 bash install.sh --source

# Go toolchain mirror (default https://go.dev/dl)
sudo CF_GO_MIRROR=https://golang.google.cn/dl bash install.sh --source
```

ساخت دستی (توسعه / اشکال زدایی):

```bash
git clone https://github.com/qist/corefusion.git
cd corefusion

# Frontend + panel for the current architecture; the frontend is embedded via go:embed
make panel

# Cross-compile
make panel-linux-amd64
make panel-linux-arm64
```

> `go build ./...` یک باینری تولید نمی کند. ساخت پانل با
> `go build -o corefusion ./cmd/corefusion/` یا `make panel`.

### 2.5 پرچم نصب

| پرچم | توضیحات |
|------|-------------|
| `-d, --dir <PATH>` | دایرکتوری، پیش فرض `/opt/corefusion` را نصب کنید |
| `-v, --version <TAG>` | نسخه پنل، به عنوان مثال `v0.13.0-alpha.2`; پیش فرض `latest` |
| `--binary` | استفاده از باینری GitHub Release (پیش‌فرض) |
| `--source` | از منبع بسازید و Go/Node مطابق را آماده کنید |
| `--local <FILE>` | استفاده از باینری محلی (نصب آفلاین) |
| `--arch <ARCH>` | معماری هدف: `amd64` / `arm64` / `armv7` / `armv6` / `386` / `ppc64le` / `s390x` / `riscv64` / `loong64` |
| `--mirror <URL>` | پیشوند دانلود GitHub، به عنوان مثال. `https://ghproxy.net` |
| `--repo <URL>` | مخزن منبع، پیش فرض `https://github.com/qist/corefusion.git` |
| `--ref <REF>` | شاخه / برچسب منبع؛ پیش فرض `--version` است، در غیر این صورت `main` |
| `--no-deps` | از نصب وابستگی سیستم صرف نظر کنید |
| `--no-start` | فایل سرویس را بدون شروع نصب کنید و بنویسید |
| `--cpu-info` | شناسایی محیط و وابستگی های از دست رفته را چاپ کنید، سپس خارج شوید |
| `--lang <LANG>` | زبان خروجی: `zh` / `en` / `fa` / `ru` (پیش‌فرض: `LANG` سیستم) |
| `--uninstall` | سرویس را متوقف کنید و برنامه را حذف کنید (داده ها و `.env` را نگه می دارد) |
| `--purge` | با `--uninstall`، دایرکتوری داده و `.env` را نیز حذف کنید |

متغیرهای محیطی مرتبط:

| متغیر | هدف |
|----------|---------|
| `CF_GO_VERSION` | نسخه Go مورد نیاز برای ساخت منبع را لغو کنید |
| `CF_NODE_MAJOR` | لغو نسخه اصلی Node (پیش‌فرض 22) |
| `CF_GO_MIRROR` | Go toolchain دانلود آینه |
| `CF_SKIP_DEPS` | در اسکریپت نصب Agent روی `1` تنظیم کنید تا از نصب وابستگی رد شوید |
| `CF_LANG` | جایگزینی زبان خروجی نصب‌کننده (مانند `--lang`) |

### 2.6 طرح دایرکتوری

```text
/opt/corefusion/
├── corefusion                 # panel binary
├── corefusion.bak             # previous version (when upgrading)
├── .env                       # environment file (0600, generated by the setup wizard)
├── .toolchain/                # Go / Node downloaded for source builds
└── data/                      # data directory (SAFE_PATHS)
    ├── sqlite/app.db          # default SQLite database
    ├── certs/                 # certificates and keys
    ├── logs/                  # runtime logs (without systemd)
    ├── runtime/               # core runtime config and state
    ├── binaries/              # downloaded xray / sing-box cores
    └── proxy/                 # proxy (Caddy/Nginx) sites and config
```

> نصب کننده فقط `sqlite/`، `certs/`، `logs/` و `runtime/` را ایجاد می کند. `binaries/`، `proxy/`، `rules/` و موارد دیگر توسط پنل یا زمانی که هسته ها نصب می شوند ایجاد می شوند.
> دایرکتوری داده از `SAFE_PATHS` در `.env` می آید و ممکن است یک مسیر مطلق باشد. تغییر دایرکتوری نصب، داده های موجود را جابجا نمی کند.

### 2.7 مدیریت خدمات

systemd (اکثر توزیع ها):

```bash
systemctl status corefusion --no-pager
systemctl restart corefusion
systemctl stop corefusion
journalctl -u corefusion -f          # follow logs
journalctl -u corefusion -n 100      # last 100 lines
```

بدون systemd (ظروف و غیره):

```bash
cd /opt/corefusion && ./corefusion            # foreground (debugging)
cd /opt/corefusion && setsid nohup ./corefusion >> data/logs/panel.log 2>&1 &
tail -f data/logs/panel.log
```

> بدون systemd فرآیند در بوت شروع نمی شود. پس از راه اندازی مجدد، آن را به صورت دستی مجدداً راه اندازی کنید (یا نصب کننده را مجدداً اجرا کنید).

### 2.8 ارتقا و حذف نصب کنید

ارتقاء (داده ها و پیکربندی را حفظ می کند):

```bash
sudo bash install.sh --version <new-version>
```

اسکریپت سرویس را متوقف می کند، از باینری قدیمی به عنوان `corefusion.bak` پشتیبان می گیرد، آن را جایگزین می کند و دوباره راه اندازی می شود. `.env` و `data/` موجود دست نخورده باقی مانده اند.

حذف نصب:

```bash
# Remove the program only; keep data and .env
sudo bash install.sh --uninstall

# Also remove the data directory and .env (irreversible)
sudo bash install.sh --uninstall --purge
```

### 2.9 فایل محیطی (.env)

`.env` کامل **توسط جادوگر راه اندازی** هنگامی که پیکربندی ذخیره می شود (پایگاه داده DSN، فهرست داده ها، اسرار، پورت ها، دامنه ها) ایجاد می شود.

در یک نصب جدید، نصب کننده فقط این مکان نگهدارنده را می نویسد، بنابراین پانل `data/` موجود را با نصب اولیه اشتباه نمی گیرد و از جادوگر صرف نظر می کند:

```env
SAFE_PATHS=data
```

> هنگامی که یک پیکربندی کامل (`.env` با `CF_DB_DSN`) از قبل وجود داشته باشد، نصب کننده هرگز آن را رونویسی نمی کند و جادوگر دوباره ظاهر نمی شود.
> ویرایش‌های دستی بعدی `.env` پس از راه‌اندازی مجدد اعمال می‌شوند.

#### دایرکتوری داده ها

```env
SAFE_PATHS=data                       # relative to the install directory
# SAFE_PATHS=/srv/corefusion-data     # or an absolute path
```

#### پایگاه داده

`CF_DB_DSN` با پیشوند شناسایی می شود:

| پیشوند | پایگاه داده |
|--------|----------|
| تنظیم نشده یا یک مسیر خالی | SQLite (پیش‌فرض) |
| `sqlite://` | SQLite (صریح) |
| `mysql://` | MySQL |
| `postgres://` / `postgresql://` | PostgreSQL |

`CF_DB_TYPE` اختیاری است و تشخیص را لغو می کند (`sqlite` / `mysql` / `postgres`).

> **رمزهای رمزگذاری شده**: MySQL/PostgreSQL DSN نوشته شده توسط پنل (جادوگر راه اندازی / سوئیچ پایگاه داده)
> در `.env` به عنوان `enc:...` (AES-256-GCM، کلید `CF_SECRET_ENCRYPTION_KEY`) ذخیره می شوند.
> آنها در خواندن رمزگشایی می شوند. DSNهای متن ساده که با دست نوشته شده اند هنوز کار می کنند.

**SQLite (پیش فرض)**

```env
# Bare path (detected as SQLite)
CF_DB_DSN=data/sqlite/app.db

# Or explicit sqlite:// prefix
CF_DB_DSN=sqlite:///opt/corefusion/data/sqlite/app.db
```

**MySQL**

```env
# Format: mysql://user:password@tcp(host:port)/dbname?params
CF_DB_DSN=mysql://corefusion:password@tcp(127.0.0.1:3306)/corefusion?charset=utf8mb4&parseTime=True&loc=Local
```

**PostgreSQL**

```env
# Format: postgres://user:password@host:port/dbname?params
CF_DB_DSN=postgres://corefusion:password@127.0.0.1:5432/corefusion?sslmode=disable
```

#### استخر اتصال (اختیاری، MySQL/PostgreSQL)

```env
CF_DB_MAX_OPEN_CONNS=100
CF_DB_MAX_IDLE_CONNS=10
```

#### سایر متغیرهای رایج

| متغیر | توضیحات |
|----------|-------------|
| `JWT_SECRET` | کلید امضا برای نشانه های ورود؛ در اولین شروع در هنگام گم شدن تولید می شود |
| `CF_SECRET_ENCRYPTION_KEY` | کلید رمزگذاری تنظیمات حساس (AES-256-GCM)؛ هنگام گم شدن ایجاد می شود |
| `CF_INITIAL_ADMIN_PASSWORD` | رمز عبور اولیه مدیریت (اختیاری؛ تصادفی و یک بار چاپ شده به طور پیش فرض) |
| `CF_NETWORK_TRAFFIC_ACCOUNTING` | برای غیرفعال کردن حسابداری ترافیک مبتنی بر iptables روی `0` تنظیم کنید (به طور پیش فرض فعال است) |
| `CF_NETWORK_TRAFFIC_TABLE` | جدول iptables مورد استفاده برای حسابداری ترافیک، پیش فرض `corefusion` |

> پروکسی های معکوس قابل اعتماد برای حل IP های مشتری واقعی دیگر از طریق متغیرهای محیطی پیکربندی نمی شوند.
> آنها به عنوان `panel.trusted_proxies` در **تنظیمات → شبکه** ذخیره می شوند.

> `.env` حاوی اسرار است. پانل در هنگام شروع مجوزهای خود را به `0600` محکم می کند. هرگز آن را مرتکب نشوید.

### 3.1 ویزارد راه اندازی را باز کنید

2. گزارش روی سرور را بخوانید:


```text

```

3. URL را در یک مرورگر باز کنید (از قبل حاوی `init_token` است، بنابراین نیازی به ورود دستی نیست).

> رمز را به اشتراک نگذارید. پس از اتمام نصب، این پورت بسته می شود و تنها پورت پنل معمولی باقی می ماند.

### 3.2 مراحل جادوگر

جادوگر 8 مرحله دارد. شما می توانید در هر زمان به عقب برگردید. هیچ چیز تا ذخیره نهایی متعهد نیست.

| مرحله | محتوا |
|------|---------|
| 1. پایگاه داده | SQLite / MySQL / PostgreSQL |
| 2. فهرست داده ها | به `SAFE_PATHS` در `.env` نوشته شده است |
| 3. کلیدهای رمزگذاری | `JWT_SECRET` و `CF_SECRET_ENCRYPTION_KEY` |
| 4. هسته ها | کدام هسته های پروکسی را نصب کنیم |
| 5. پروکسی | هیچکدام / Nginx / Caddy |
| 6. سایت ها و دامنه ها | پورت ها، مسیر وب، حساب مدیریت، ارز، منطقه زمانی، دامنه ها |
| 7. گواهی HTTPS | غیرفعال / آپلود / ACME |
| 8. خلاصه | مرور، دانلود `.env`، ذخیره و راه اندازی مجدد |

#### مرحله 1: پایگاه داده

- **SQLite (فایل محلی، توصیه می شود)**: مسیر را برای استفاده از `<data-dir>/sqlite/app.db` خالی بگذارید.
- **MySQL / PostgreSQL**: میزبان، پورت، کاربر، رمز عبور، نام پایگاه داده؛ PostgreSQL همچنین از `disable` / `require` / `verify-full` پشتیبانی می کند.
- برای تأیید اعتبار، روی «آزمایش اتصال» کلیک کنید. ذخیره کردن نیز آن را آزمایش می کند. یک پایگاه داده گم شده به طور خودکار ایجاد می شود (اگر حساب فاقد `CREATE` است آن را به صورت دستی ایجاد کنید).
- DSN (شامل رمز عبور) قبل از نوشتن در `.env` رمزگذاری می شود.

#### مرحله 2: فهرست اطلاعات

پایگاه داده، گواهی ها، لاگ ها، باینری های هسته و موارد دیگر را ذخیره می کند. این `SAFE_PATHS` در `.env` است. پیش‌فرض `data` است
(نسبت به دایرکتوری نصب)؛ یک مسیر مطلق مجاز است. **بعداً آن را به طور تصادفی تغییر ندهید**، یا پانل
پایگاه داده و گواهی های موجود را پیدا نمی کند.

#### مرحله 3: کلیدهای رمزگذاری

- `JWT_SECRET`: نشانه های ورود را امضا می کند.
- `CF_SECRET_ENCRYPTION_KEY`: تنظیمات حساس (رمز عبور پایگاه داده، اعتبار DNS، کارت های شارژ و غیره) را رمزگذاری می کند.
- هر دو به طور پیش فرض به صورت تصادفی تولید می شوند. برای بدست آوردن مقادیر جدید از "Regenerate" استفاده کنید. **تغییر `CF_SECRET_ENCRYPTION_KEY` داده های رمزگذاری شده قبلی را غیرقابل خواندن می کند** — از آن نسخه پشتیبان تهیه کنید.

#### مرحله 4: هسته ها

هسته های پروکسی را برای نصب انتخاب کنید:

- **Xray**: VLESS / VMess / Trojan / Shadowsocks و غیره؛
- **sing-box**: دارای پروتکل های Hysteria2 / TUIC و سایر پروتکل های QUIC است.

پس از ذخیره و راه اندازی مجدد پنل به صورت خودکار آنها را دانلود و نصب می کند. نسخه ها و وضعیت را در قسمت «پروتکل ها» بررسی کنید. شما همچنین می توانید آنها را بعدا نصب کنید.

#### مرحله 5: پروکسی

- **هیچ**: پنل مستقیماً به مشتریان خدمات ارائه می دهد (خودتان با TLS رسیدگی کنید).
- **Nginx / Caddy**: پنل پروکسی معکوس و میزبانی گواهی را مدیریت می کند. یکی را انتخاب کنید

با انتخاب یک پروکسی، پنل معمولاً فقط به `127.0.0.1` گوش می دهد و پروکسی به دنیای خارج سرویس می دهد.

#### مرحله 6: سایت ها و دامنه ها

| میدان | توضیحات |
|-------|-------------|
| آدرس گوش کن | به طور خودکار مشتق می شود: پروکسی → `127.0.0.1`; بدون پروکسی با گواهی → `0.0.0.0`؛ در غیر این صورت → `127.0.0.1` |
| پورت پنل | پورت رایگان تصادفی به طور پیش فرض؛ اگر دوست دارید آن را تغییر دهید (به عنوان مثال 8080) |
| پورت اشتراک | اختیاری؛ `0` پورت پنل را به اشتراک می گذارد |
| پورتال پورتال | اختیاری؛ `0` پورت پنل را به اشتراک می گذارد |
| مسیر وب | مسیر رابط کاربری مدیریت، پیش‌فرض `/`؛ API همیشه `/api/v1` است |
| نام کاربری / رمز عبور ادمین | تصادفی به طور پیش فرض؛ ** رمز عبور فقط یک بار در خلاصه نشان داده می شود ** - آن را ذخیره کنید |
| حالت دسترسی | "دامنه" یا "IP" |
| واحد پول / منطقه زمانی پیش‌فرض | ارز پیش فرض برای کارت های شارژ و موجودی. پانل و منطقه زمانی گزارش پراکسی (مانند `Asia/Shanghai`) |
| به پراکسی معکوس اضافه کنید | هنگامی که یک پروکسی و دامنه تنظیم شد، دامنه های پانل / اشتراک / پورتال را به یکباره به پروکسی اضافه کنید |

با ورود به دامنه ها، تنظیمات مربوطه (دامنه پاسخ به تماس، نقطه پایان اشتراک، دامنه اشتراک گذاری) را می نویسد.

#### مرحله 7: گواهی HTTPS

| منبع | توضیحات |
|--------|-------------|
| HTTPS را غیرفعال کنید | پنل/پورتال/اشتراک‌ها از طریق HTTP (ناامن) ارائه می‌شوند. با یک پروکسی معکوس می توانید TLS را بعداً در سمت پروکسی اضافه کنید |
| گواهی آپلود | چسباندن گواهی PEM و کلید خصوصی PEM (فقط حالت دسترسی به دامنه) |
| ACME | گواهی را هنگام ارسال این مرحله صادر می کند. از گواهینامه های دامنه و IP پشتیبانی می کند |

گزینه های ACME:

- **CA**: Let's Encrypt, Let's Encrypt (Staging), ZeroSSL, Google Public CA;
- **هدف**: دامنه پیکربندی شده یا IP عمومی (گواهینامه های IP فقط توسط Let's Encrypt پشتیبانی می شوند).
- **چالش**: `HTTP-01` (به پورت 80 نیاز دارد) یا `DNS-01` (کارت های عام، بدون پورت 80؛ ارائه دهنده DNS را انتخاب کنید و اعتبارنامه ها را وارد کنید).
- **نوع / اندازه کلید**: ECC 256/384 یا RSA 2048/3072/4096؛
- **Google عمومی CA **: به EAB نیاز دارد. شناسه کلید / HMAC را به صورت دستی وارد کنید یا از یک حساب سرویس GCP استفاده کنید.

> گواهی IP به طور خودکار IPv4/IPv6 عمومی میزبان را شناسایی می کند. در پشت پراکسی، آدرس شناسایی شده مربوط به میزبان است، نه خروجی پروکسی.
> گواهینامه‌های دامنه نیز می‌توانند بعداً تحت «گواهینامه‌ها» صادر شوند.

#### مرحله 8: خلاصه

پایگاه داده، دایرکتوری داده ها، هسته ها، پروکسی، پورت ها، حساب مدیریت، دامنه ها و کلیدهای `.env` (اسرار پنهان شده) را نشان می دهد و ارائه می دهد:

- **دانلود env**: یک کپی از پیکربندی را نگه دارید.
- **آدرس های دسترسی **: آدرس های نهایی برای پنل / اشتراک / پورتال. HTTP به عنوان ناامن علامت گذاری شده است.

برای نوشتن پایگاه داده و `.env` روی "ذخیره و راه اندازی مجدد" کلیک کنید. پانل دوباره به سرویس عادی راه اندازی می شود.

### 3.3 پس از راه اندازی

- سرویس دوباره راه اندازی می شود و گزارش راه اندازی آدرس نهایی گوش دادن را چاپ می کند.
- با حساب مدیریت وارد شوید، به URL و مسیر وب از خلاصه دسترسی پیدا کنید.
- اگر رمز عبور گم شد، آن را به صورت آفلاین با `./corefusion admin reset-password` بازنشانی کنید.

### 3.4 راه اندازی غیر تعاملی CLI

برای سرورهای اتوماسیون یا بدون هد، پیکربندی را بنویسید و تنظیم را به طور مستقیم علامت بزنید:

```bash
cd /opt/corefusion
./corefusion init \
  --db-type sqlite \
  --data-dir /opt/corefusion/data \
  --admin-username admin \
  --admin-password 'change-me-strong-password' \
  --listen-port 8080 \
  --proxy-type caddy \
  --cores xray,singbox \
  --panel-domain panel.example.com \
  --tls-mode acme --tls-domain panel.example.com --tls-email you@example.com
```

پرچم های رایج:

| پرچم | توضیحات |
|------|-------------|
| `--db-type` / `--db-host` / `--db-port` / `--db-user` / `--db-password` / `--db-name` | تنظیمات پایگاه داده |
| `--data-dir` | فهرست اطلاعات؛ پیش فرض `SAFE_PATHS` یا `./data` است |
| `--listen-port` / `--subscription-port` / `--portal-port` / `--web-path` | پورت ها و مسیر وب (درگاه آزاد تصادفی به طور پیش فرض) |
| `--admin-username` / `--admin-password` | حساب مدیریت (پسورد تصادفی یک بار در صورت حذف چاپ می شود) |
| `--proxy-type` | `none` / `nginx` / `caddy` |
| `--cores` | هسته برای نصب، با کاما از هم جدا شده است: `xray,singbox` |
| `--panel-domain` / `--subscription-domain` / `--portal-domain` | دامنه ها (در تنظیمات نوشته شده و به پروکسی معکوس اضافه شده است) |
| `--tls-mode` | `none` / `self_signed` / `acme` |
| `--tls-domain` / `--tls-email` / `--tls-challenge` / `--tls-key-type` / `--tls-key-bits` | گزینه‌های گواهی (`--tls-challenge` پیش‌فرض روی `http-01` است؛ `dns-01` به `--tls-dns-channel` یا `--tls-dns-provider` نیاز دارد) |
| `--tls-ip-cert` | صدور گواهی برای IP عمومی شناسایی شده (فقط اجازه دهید رمزگذاری کنیم) |
| `--acme-provider` | `lets_encrypt` / `lets_encrypt_staging` / `zerossl` / `google` |
| `--currency` / `--timezone` | واحد پول / منطقه زمانی پیش‌فرض |

لیست کامل: `./corefusion init --help`. سپس سرویس را شروع کنید:

```bash
systemctl restart corefusion
```

### 3.5 اجرای مجدد جادوگر راه اندازی

برای شروع دوباره (`.env` و علامت های راه اندازی را حذف می کند، **داده ها را نگه می دارد**):

```bash
cd /opt/corefusion
./corefusion reset-init      # type RESET to confirm
systemctl restart corefusion
```

سپس از URL و توکن جدید از لاگ راه اندازی استفاده کنید.

> راه‌اندازی مجدد حساب مدیریت و مسیر وب را بازنشانی می‌کند. داده های کسب و کار در پایگاه داده قدیمی باقی می مانند، اما ممکن است لازم باشد حساب ورود را دوباره ایجاد کنید.
>
> `reset-init` کل `.env` (از جمله `SAFE_PATHS`) را حذف می کند. **اگر فهرست داده های شما یک مسیر مطلق سفارشی است**، قبل از راه اندازی مجدد، `SAFE_PATHS` را بازیابی کنید، در غیر این صورت پنل در `./data` به نظر می رسد:
>
> ```bash
> printf 'SAFE_PATHS=/srv/corefusion-data\n' > /opt/corefusion/.env
> ```

### 3.6 امنیت پس از اولین ورود به سیستم

#### رمز اولیه را تغییر دهید

1. روی نام کاربری در گوشه سمت راست بالا کلیک کنید.
2. "تغییر رمز عبور" را انتخاب کنید؛
3. رمز عبور قدیمی و جدید را وارد کنید؛
4. روی «ذخیره» کلیک کنید.

#### فعال کردن ورود با کد پویا (2FA / TOTP)

> پس از فعال شدن، حساب به **ورود با کد پویا** تغییر می کند: رمز عبور ثابت دیگر پذیرفته نمی شود. فقط
> کد 6 رقمی از برنامه احراز هویت شما (یا یک کد بازیابی یک بار مصرف) کار می کند. این **جایگزین** ورود رمز عبور می شود - این است
> نه تایید دو مرحله ای "رمز عبور + کد".

1. روی نام کاربری در گوشه سمت راست بالا کلیک کنید.
2. "فعال کردن 2FA" را انتخاب کنید.
3. رمز عبور فعلی را وارد کنید (فقط برای تأیید این تغییر).
4. کد QR را با یک برنامه احراز هویت (Google Authenticator / 1Password و غیره) اسکن کنید یا کلید را به صورت دستی وارد کنید.
5. کد 6 رقمی را وارد کنید تا فعال سازی به پایان برسد.
6. **کدهای بازیابی را فوراً ذخیره کنید** (قابل دانلود)؛ هر کد یک بار کار می کند.

ورود به سیستم پس از آن:

- پس از وارد کردن نام کاربری، قسمت رمز عبور به "کد 6 رقمی / کد بازیابی" تبدیل می شود و دکمه به "ورود با کد" تبدیل می شود.
- کد فعلی را وارد کنید؛ **از رمز عبور ثابت دیگر نمی توان استفاده کرد**.
- کدهای بازیابی یکبار مصرف هستند. وقتی تمام شد آنها را تحت «ورود کد پویا (2FA)» بازسازی کنید (این کار همه کدهای قدیمی را باطل می کند).

اگر احراز هویت گم شده و کدهای بازیابی تمام شده اند، 2FA آفلاین را در سرور غیرفعال کنید:

```bash
cd /opt/corefusion
./corefusion admin 2fa reset -u admin    # disables 2FA, clears the secret and recovery codes, revokes all sessions
```

> یک سوپر سرپرست تنها بدون احراز هویت و کد بازیابی نمی تواند از طریق رابط کاربری وب بازیابی شود و باید از دستور بالا استفاده کند.

#### ثبت Passkey (اختیاری)

1. روی نام کاربری در گوشه سمت راست بالا کلیک کنید.
2. "Passkey management" را انتخاب کنید؛
3. روی "ثبت نام جدید Passkey" کلیک کنید.
4. درخواست دستگاه را کامل کنید.

> **نکته**: کلیدهای عبور به HTTPS یا میزبان محلی نیاز دارند و دامنه باید در لیست مجاز باشد.

## 4. داشبورد

داشبورد نمای کلی خوشه چند گره و سلامت گره را نشان می دهد.

### 4.1 آنچه نشان می دهد

- **اطلاعات سیستم**: نام میزبان، نسخه سیستم عامل، زمان آپدیت، CPU، حافظه
- **ترافیک**: پهنای باند بلادرنگ، کل ترافیک، روند ماهانه
- **سلامت گره**: تعداد آنلاین / آفلاین / کاهش یافته، گره های پر بار
- **هشدارها**: گره های آفلاین، گره های تخریب شده، گواهی ها که به زودی منقضی می شوند، هشدارهای سهمیه
- **منابع خوشه**: متوسط CPU، حافظه، دیسک و توان عملیاتی

### 4.2 اقدامات

- روی «مشاهده جزئیات» کلیک کنید تا صفحه جزئیات یک گره باز شود
- روی کارت گره کلیک کنید تا وضعیت زنده آن را ببینید
- از فیلترها برای محدود کردن وضعیت، نوع یا منطقه استفاده کنید

## 5. مدیریت گره

مدیریت گره هسته CoreFusion است و از چندین نوع گره پشتیبانی می کند.

### 5.1 انواع گره

| تایپ کنید | توضیحات |
|------|-------------|
| مستقل (`standalone`) | یک گره اصلی مستقل |
| آینه (`mirror`) | پیکربندی را از یک گره هدف همگام سازی می کند |
| اصلی/پشتیبان (`primary_backup`) | گره های شریکی که در مقابل یکدیگر شکست می خورند |
| ورودی زنجیره ای (`chain_entry`) | گره ورودی یک پروکسی زنجیره ای |
| خروجی زنجیره ای (`chain_exit`) | گره خروج از یک پروکسی زنجیره ای |

### 5.2 اضافه کردن یک گره

1. "مدیریت گره" را باز کنید؛
2. روی "افزودن سرور" کلیک کنید؛
3. اصول اولیه را پر کنید:
   - نام، به عنوان مثال `HongKong-HK01`
   - نام میزبان: IP یا دامنه
   - منطقه، به عنوان مثال `HK`، `JP`، `US`
   - نوع گره؛
4. پورت Agent (پیش‌فرض `18443`) را تنظیم کنید.
5. هسته های پشتیبانی شده را انتخاب کنید.
6. روی «ذخیره» کلیک کنید.

### 5.3 استقرار با یک کلیک

1. پس از اضافه کردن گره، روی "فرمان بوت استرپ" کلیک کنید.
2. دستور نصب را کپی کنید؛
3. آن را به عنوان root در گره راه دور اجرا کنید:

   ```bash
   curl -fsSL https://your-panel/install.sh | bash
   ```

4. عامل دانلود، ثبت نام و به طور خودکار شروع می شود.

### 5.4 جزئیات گره

روی یک گره کلیک کنید تا صفحه جزئیات آن باز شود:

- ** نمای کلی **: اطلاعات اولیه، وضعیت نماینده، وضعیت گواهی
- **مرکز پروتکل**: پیکربندی فرآیند اصلی
- **پراکسی**: پیکربندی Caddy / Nginx
- ** فرآیندهای اصلی **: شروع / توقف / راه اندازی مجدد
- **WARP**: پیکربندی WARP
- **دامنه های مستقیم**: مدیریت دامنه
- **محدودیت نرخ**: شکل دهی ترافیک
- **گواهی نامه ها**: الزام آور گواهی
- **کاربران آنلاین**: کاربران آنلاین بلادرنگ

### 5.5 اقدامات گره

- ** پیکربندی همگام سازی **: پیکربندی پانل را به گره فشار دهید
- **اجباری اتصال مجدد**: اتصال Agent را رها کرده و دوباره وصل کنید
- **Update Agent**: فشار به روز رسانی عامل
- **Revoke Certificate**: ابطال گواهی Agent گره

## 6. مرکز پروتکل

مرکز پروتکل پارامترهای پروتکل را برای فرآیندهای اصلی پیکربندی می کند.

### 6.1 هسته های پشتیبانی شده

| هسته | توضیحات |
|------|-------------|
| هسته Xray | VLESS / VMess / Trojan / Shadowsocks و موارد دیگر |
| sing-box | پلت فرم پروکسی جهانی مدولار با پشتیبانی TUN. دارای پروتکل های Hysteria2 / TUIC و سایر پروتکل های QUIC |

### 6.2 ماژول های پیکربندی

- ** ثبت نام **: گزارش دسترسی، گزارش خطا، حالت خروجی
- **API**: gRPC API آدرس گوش، لیست خدمات
- **DNS**: سرورهای DNS، استراتژی پرس و جو، هاست استاتیک
- **مسیریابی**: قوانین مسیریابی، تعادل بار، مسیریابی VLESS
- ** ورودی**: لیست ورودی، تنظیمات پروتکل، حمل و نقل، TLS
- **خروجی**: لیست خروجی، تنظیمات پروتکل، حمل و نقل
- **حمل و نقل**: WebSocket، gRPC، XHTTP، TUN و غیره.
- **TLS**: گواهینامه ها، ALPN، اثر انگشت uTLS، ECH
- **Reality**: مدیریت هدف، جفت کلید، شناسه کوتاه
- **بررسی سلامت**: پروب URL، فاصله زمانی، همزمان
- **FakeDNS**: استخر IP، اندازه استخر
- **متریکس**: شنونده متریک پرومتئوس
- **سیاست**: وقفه های اتصال، بافرها، آمار
- ** داده های جغرافیایی **: به روز رسانی خودکار، فایل های منابع
- ** محدودیت های نسخه **: حداقل / حداکثر نسخه

### 6.3 پیکربندی ورودی

1. هسته و پروتکل را انتخاب کنید.
2. اصول اولیه را پر کنید:
   - برچسب بزنید
   - آدرس و پورت گوش کنید
   - نوع پروتکل
3. تنظیم پارامترهای پروتکل (UUID، رمز عبور، و غیره)؛
4. حمل و نقل را انتخاب کنید (TCP، WebSocket، gRPC، و غیره)؛
5. پیکربندی TLS (گواهینامه، ALPN)؛
6. ذخیره کنید و روی هسته اعمال کنید.

### 6.4 پیکربندی خروجی

1. اضافه کردن یک خروجی؛
2. تگ و پروتکل را تنظیم کنید.
3. آدرس سرور و پورت را تنظیم کنید.
4. پیکربندی حمل و نقل و TLS؛
5. ذخیره و اعمال کنید.

### 6.5 پیوندها را به اشتراک بگذارید

1. در لیست ورودی، روی "اشتراک گذاری پیوند" کلیک کنید.
2. یک قالب را انتخاب کنید:
   - URI را به اشتراک بگذارید
   - Mihomo YAML
   - sing-box JSON
   - Xray JSON
3. پیوند را کپی کنید یا یک کد QR ایجاد کنید.

## 7. مدیریت پروکسی

مدیریت پراکسی پروکسی معکوس Caddy یا Nginx را پیکربندی می کند.

### 7.1 انواع پروکسی

- **کدی**: اتوماتیک HTTPS، HTTP/2، HTTP/3
- **Nginx**: عملکرد بالا، پیکربندی انعطاف پذیر

### 7.2 پیکربندی سایت

1. "مدیریت پروکسی" را باز کنید؛
2. نوع پروکسی را انتخاب کنید (Caddy / Nginx)؛
3. اضافه کردن یک سایت:
   - دامنه
   - بالادست
   - بندر محلی
4. ذخیره کنید.

### 7.3 فیلدها

- **بالا جریان**: آدرس باطن، به عنوان مثال. `127.0.0.1:8082`

- **portal_forward**: قانون ارسال پورتال
- **subscription_forward**: قانون حمل و نقل اشتراک

   - ارائه دهنده DNS
   - محل صدور (میزبان پنل / گره)
4. روی "مشکل" کلیک کنید.

### 14.2 اقدامات گواهی

- **تجدید**: تمدید دستی
- **استقرار**: استقرار در یک گره
- **توزیع**: فشار به تمام گره های مرتبط
- ** مهاجرت**: مراجع را از گواهی قدیمی به گواهی جدید منتقل کنید
- **دانلود**: دانلود `cert` / `fullchain` / `privkey`

### 14.3 بارگذاری گواهی

1. روی "آپلود گواهی" کلیک کنید؛
2. روش را انتخاب کنید:
   - محتوا را جایگذاری کنید
   - فایل ها را آپلود کنید
3. بارگذاری زنجیره گواهی و کلید خصوصی؛
4. ذخیره کنید.

### 14.4 پیکربندی EAB

- مدیریت اعتبار EAB برای Google عمومی CA / ZeroSSL
- EAB را به طور خودکار دریافت کنید
- هنگام صدور آن را به طور خودکار وصل کنید

## 26. سوالات متداول

### 26.1 پانل شروع نمی شود

- بررسی کنید که آیا پورت از قبل در حال استفاده است یا خیر
- بررسی کنید که `.env` معتبر است
- سیاهههای مربوط را بررسی کنید: `journalctl -u corefusion -f`; بدون systemd، `tail -f <install-dir>/data/logs/panel.log`

### 26.2 گره آفلاین

- بررسی کنید که Agent در حال اجرا باشد: `systemctl status corefusion-agent`
- اتصال شبکه را بررسی کنید
- قوانین فایروال را بررسی کنید (پورت `18443`)

### 26.3 صدور گواهینامه ناموفق است

- وضوح DNS را بررسی کنید
- بررسی کنید که پورت 80 قابل دسترسی باشد
- پیکربندی ارائه دهنده DNS را بررسی کنید
- گزارش های گواهی را بررسی کنید

### 26.4 اشتراک کار نمی کند

- لینک اشتراک را بررسی کنید
- بررسی کنید که گره آنلاین است
- بررسی کنید که فرآیند اصلی در حال اجرا باشد
- قوانین فایروال را بررسی کنید

### 26.5 شارژ مجدد با شکست مواجه می شود

- پاسخ تماس URL را بررسی کنید
- بررسی کنید که کلید سایت مطابقت داشته باشد
- فهرست مجاز IP را بررسی کنید
- ثبت سفارشات را بررسی کنید

### 26.6 صفحه پورتال غیر قابل دسترسی است

- بررسی کنید که پورت پورتال باز باشد
- پیکربندی مسیر پورتال را بررسی کنید
- **مهم**: مطمئن شوید که پراکسی معکوس دامنه پورتال را به **درگاه موتور پورتال** و نه درگاه اصلی پنل ارسال می کند — ارسال به پورت اشتباه یک صفحه خالی یا پانل را به جای پورتال نشان می دهد. `upstream` / `local_port` را در سابقه سایت پراکسی بررسی کنید.
- `http://<portal-domain>:<portal-port>` را مستقیماً باز کنید تا موتور پورتال را تأیید کنید
- پیکربندی معکوس پروکسی را بررسی کنید
- گزارش های پورتال را بررسی کنید

## ضمیمه

### A. پورت های پیش فرض

| بندر | هدف |
|------|---------|
| اختصاص داده شده توسط جادوگر راه اندازی (درگاه آزاد تصادفی به طور پیش فرض) | پنل مدیریت (قابل تغییر) |
| 18443 | عامل gRPC (قابل تغییر) |
| 0 (به طور پیش فرض غیرفعال است) | پورت موتور اشتراک اختصاصی (خالی یا `0` پورت اصلی را به اشتراک می‌گذارد) |
| 0 (به طور پیش فرض غیرفعال است) | پورت موتور پورتال اختصاصی (خالی یا `0` پورت اصلی را به اشتراک می گذارد) |
| 80/443 | پراکسی معکوس (Caddy / Nginx) HTTP / HTTPS |

### ب. مسیرهای پیش فرض

| مسیر | هدف |
|------|---------|
| `/` | پنل مدیریت (در صورتی که موتور پورتال اختصاصی پیکربندی نشده باشد، پورتال در `/` نیز فعال است) |
| `/sub/:token` | واکشی اشتراک (زمانی که هیچ پورت اشتراک اختصاصی پیکربندی نشده باشد) |
| `/p` | صفحه پورتال (زمانی که پورتال اختصاصی پیکربندی نشده باشد) |
| `/:token` | واکشی اشتراک (با درگاه اشتراک اختصاصی، بدون پیشوند `/sub`) |

### ج. ابزار خط فرمان

پانل باینری از این دستورات فرعی پشتیبانی می کند (بدون آرگومان سرور را شروع می کند):

```bash
# Start the panel (same as ./corefusion server)
./corefusion

# Run database migrations
./corefusion migrate

# Offline administration (when you cannot sign in)
./corefusion admin reset-password -u admin -p 'new-password'
./corefusion admin 2fa reset -u admin
./corefusion admin list

# Version / help
./corefusion version
./corefusion help
```

> بدون واحد systemd، با توقف فرآیند قدیمی و شروع مجدد آن با `nohup`، مجدداً راه اندازی کنید. سیاههها در `<install-dir>/data/logs/panel.log` هستند.
