# Руководство по общедоступному ЦС Google (автоматический выпуск EAB)

> Языки: [简体中文](cert-google-eab.md) · [English](cert-google-eab.en.md) · [繁體中文](cert-google-eab.zh-TW.md) · Русский · [日本語](cert-google-eab.ja.md) · [한국어](cert-google-eab.ko.md) · [Deutsch](cert-google-eab.de.md) · [Français](cert-google-eab.fr.md) · [Español](cert-google-eab.es.md) · [Português](cert-google-eab.pt.md) · [Türkçe](cert-google-eab.tr.md) · [Bahasa Indonesia](cert-google-eab.id.md) · [ไทย](cert-google-eab.th.md) · [Tiếng Việt](cert-google-eab.vi.md) · [العربية](cert-google-eab.ar.md) · [فارسی](cert-google-eab.fa.md)

> Применяется к: панель v0.12.101+ | Страница: **Сертификаты → Конфигурация EAB**
> Код: `internal/service/certificate/eab_google.go`, `internal/api/handlers/certificates/eab_config.go`

## 1. Почему для Google требуется EAB

| Калифорния | EAB обязателен для ACME? | Как получить EAB |
|---|---|---|
| Давайте зашифруем | ❌ Нет | — |
| ZeroSSL | ✅ Да | **Обменяйте электронное письмо на одно** (`api.zerossl.com/acme/eab-credentials-email`, то же, что acme.sh); панель может получить его автоматически |
| **Google Публичный ЦС** | ✅ **Да** | **Должен быть создан с авторизацией GCP** (адреса электронной почты недостаточно) → фокус этой страницы. |

Другими словами, Google **не может избежать «авторизации»**: либо файла служебной учетной записи JSON, либо токена временного доступа.

## 2. Жесткие правила Google (прочитайте сначала)

| Правило | Описание |
|---|---|
| **Использовать в течение 7 дней** | Срок действия ключа EAB истекает**, если он не используется в течение 7 дней, и его необходимо создать заново. |
| **Только один аккаунт** | Один ключ EAB регистрирует ровно одну учетную запись ACME; после регистрации ключ **становится недействительным** и не может быть использован повторно |
| **Срок действия учетных записей ACME не истекает** | Созданная с его помощью учетная запись ACME **долговечна** → **для продления EAB не требуется** |
| ⚠ **Удаление проекта GCP приведет к уничтожению всех учетных записей** | Удаление проекта немедленно делает недействительными **все учетные записи ACME** в нем и **продление становится невозможным**. |

> Вывод: **EAB — это одноразовые «регистрационные учетные данные»; учетная запись ACME – это то, что остается навсегда.**
> Панель сохраняет учетные записи по адресу `data/acme/accounts/<ca>.json` — **сохраните резервную копию этого каталога**.

## 3. Три пути (начните с пути A — без поиска по меню)

> Точки входа в Cloud Console менялись несколько раз, поэтому на первом месте стоят прямые ссылки и Cloud Shell; Пути меню являются резервными.

### Путь A (самый простой, рекомендуется в первую очередь): одна команда в GCP Cloud Shell.

Cloud Shell — это браузерный терминал с предустановленным **gcloud и уже выполненным входом**; нет локальной настройки и меню.

1. Откройте <https://console.cloud.google.com/cloudshell> (или значок `>_` в правом верхнем углу консоли).
2. Выберите проект (идентификатор проекта виден в средстве выбора проектов вверху):
   ```bash
   gcloud config set project <your-project-id>
   ```
3. Включите общедоступный центр сертификации API (**эквивалент** его включению в библиотеке API):
   ```bash
   gcloud services enable publicca.googleapis.com
   ```
4. Создайте EAB (**это две строки, которые вам нужны**):
   ```bash
   gcloud publicca external-account-keys create
   ```
 В выводе: `keyId` → **EAB-KID** панели; `b64MacKey` → **EAB-HMAC-Key** панели.
5. Вернитесь на панель: **Сертификаты → Конфигурация EAB → Добавить конфигурацию EAB → CA: Google Public CA** →
 введите два значения в `EAB-KID` / `EAB-HMAC-Key` → сохранить ✓

> ⚠ Стоимость: Google EAB ключи **7-дневные, одноразовые** ✗ → через 7 дней (или при смене учетной записи) **повторите шаг 4**.
> Чтобы избежать этого, используйте путь B (сохраните учетную запись службы один раз и позвольте панели автоматически повторно запросить).

### Путь Б (однократная настройка, затем автоматическая): ключ сервисной учетной записи JSON

**① Включите общедоступный центр сертификации API** (проще всего использовать прямую ссылку).
<https://console.cloud.google.com/apis/library/publicca.googleapis.com?project=YOUR_PROJECT_ID> → нажмите «Включить».
Резервный вариант: ☰ → **API и службы → Библиотека** → поиск `Public CA` → открыть → «Включить».

**② Создайте учетную запись службы**
<https://console.cloud.google.com/iam-admin/serviceaccounts?project=YOUR_PROJECT_ID>
→ «**+ Создать учетную запись службы**» → любое имя (например, `corefusion-eab`) → «Создать и продолжить» → вы можете **пропустить** шаг роли → «Готово»
Резервный вариант: ☰ → **IAM и администратор → Сервисные учетные записи**

**③ Предоставьте минимальную роль** (проще всего на той же странице)
Нажмите на вновь созданную учетную запись → **Вкладка «Разрешения»** → «Предоставить доступ» → новый субъект: **адрес электронной почты сервисной учетной записи**.
→ найдите роль `publicca` → выберите ** «Создатель ключа внешней учетной записи публичного центра сертификации»** → сохраните.
Альтернативный вариант: ☰ → **IAM и администратор → IAM** → «Предоставить доступ» → тот же адрес электронной почты + роль.
⚠ **Не предоставлять права владельцу/редактору** ✗

**④ Скачать ключ JSON**
Сервисные аккаунты → открыть аккаунт → **Вкладка «Ключи»** → «**Добавить ключ**» → «**Создать новый ключ**» → **JSON** → создать
(браузер загружает `xxx.json`; или строку `⋮` → «Управление ключами» → тот же процесс)

**⑤ Вернитесь на панель**: введите **идентификатор проекта** и вставьте **все содержимое** JSON в «Файл ключей сервисной учетной записи» → нажмите «Запросить EAB автоматически».
→ после этого панель **автоматически повторно запрашивает EAB** по истечении срока его действия ✓, посещений GCP больше не требуется ✓

### Путь C (только разовый тест): вставьте токен доступа.

В Cloud Shell:
```bash
gcloud auth print-access-token
```
Вставьте выходные данные в «Токен временного доступа» панели плюс идентификатор проекта → нажмите «Запросить EAB автоматически».
⚠ Действует около 1 часа и **не хранится** ✓ → только проверка, без автоматического повторного запроса ✗

### Шпаргалка, когда не можете найти точку входа (меню консоли меняются)

| Задача | Прямая ссылка (самая надежная) | Резервный вариант: меню |
|---|---|---|
| Включить общедоступный центр сертификации API | `https://console.cloud.google.com/apis/library/publicca.googleapis.com?project=<PROJECT_ID>` | ☰ → API и сервисы → Библиотека → поиск `Public CA` |
| Сервисные аккаунты | `https://console.cloud.google.com/iam-admin/serviceaccounts?project=<PROJECT_ID>` | ☰ → IAM и администрирование → Сервисные аккаунты |
| Грантовая роль | `https://console.cloud.google.com/iam-admin/iam?project=<PROJECT_ID>` | ☰ → IAM и администрирование → IAM → Предоставить доступ |
| Облачная оболочка | `https://console.cloud.google.com/cloudshell` | Значок `>_` в правом верхнем углу. |

> Совет: замените `<PROJECT_ID>`/`YOUR_PROJECT_ID` реальным идентификатором проекта (например, `my-project-123456`), чтобы сразу перейти на страницу.

## 4. Настройка панели (два способа)

Перейдите в раздел **Сертификаты → Конфигурация EAB → Добавить конфигурацию EAB** и выберите **Google Public CA**:

### Вариант А (рекомендуется): вставьте сервис-аккаунт JSON.

| Поле | Значение |
|---|---|
| Идентификатор проекта GCP | Идентификатор проекта из раздела 3, например. `my-project-123456` |
| Сервисный аккаунт JSON | Вставьте **все содержимое** `corefusion-eab.json`. |
| Токен временного доступа | Оставить пустым |
| Имя | Создается автоматически как `Google Public CA - <project-id>`; редактируемый |

Нажмите **Запросить EAB автоматически** → в случае успеха ключ KID/HMAC будет заполнен и сохранен; позже просто выберите `CA = Google Public CA` при выдаче (EAB связан с каждым центром сертификации; без ручного выбора).

> Сервисный аккаунт JSON **зашифрован в конфигурации EAB базы данных панели** (`json:"-"`, **никогда не возвращается во внешний интерфейс**).
> Цель – **автоматический повторный запрос ключа по истечении 7 дней** вместо посещения GCP вручную.

### Вариант Б: токен временного доступа (одноразовый).

```bash
gcloud auth print-access-token        # valid ~1 hour
```

Вставьте его в «Токен временного доступа», введите идентификатор проекта, нажмите **Запросить EAB автоматически**.
⚠ Этот токен **не хранится** и должен быть получен повторно после истечения срока действия → штраф за разовое тестирование, а не за долгосрочное использование.

### Эквивалент командной строки (необязательно, для сравнения)

```bash
gcloud publicca external-account-keys create
# returns keyId / b64MacKey, corresponding to ACME's --eab-kid / --eab-hmac-key
```

## 4.5 Почему JSON вместо «одного ключа»?

Это самый распространенный вопрос. Разделите два вида «ключа»:

| Чего вы можете ожидать | Что на самом деле нужно |
|---|---|
| **Ключ API** (строка `AIza…`) | ❌ **Бесполезен** — ключ API является всего лишь общедоступным идентификатором и **не несет никакой идентичности**; для создания EAB необходимы **разрешения IAM**, поэтому необходимы учетные данные для подтверждения личности. |
| — | ✅ **Ключ сервисного аккаунта**: **файл**, загруженный с GCP «IAM → Сервисные аккаунты → Ключи → Создать новый ключ → **JSON**» |

Ключевой момент: **файл JSON сам по себе является «ключом»** — GCP упаковывает идентификатор учетной записи (`client_email`) плюс закрытый ключ (`private_key`) в один файл. Панель подписывает с его помощью JWT → обменивается на токен доступа OAuth2 → вызывает публичный центр сертификации API.
Итак, «вставить JSON» ≠ заполнение множества полей; **вставьте весь файл** (панель также заполняет необязательные поля, такие как `type`/`token_uri`).

**Настоящий EAB — это две строки** (`EAB-KID` + `EAB-HMAC-Key`), которые являются **результатом** запроса; панель заполняет их автоматически.

### Не хотите сдавать файл? Две альтернативы

| Метод | Как | Стоимость |
|---|---|---|
| **Токен временного доступа** | `gcloud auth print-access-token` → вставьте в «Токен временного доступа» | Срок действия ~1 час, **не сохраняется** → только единоразово, без автоматического повторного запроса |
| **Руководство KID/HMAC** | Локально запустите `gcloud publicca external-account-keys create` → введите `keyId`/`b64MacKey` в «EAB-KID/EAB-HMAC-Key» | Полномочия не переданы ✓; но Google EAB — **7-дневный, единоразовый** → повторить после истечения срока действия |

> Панель рекомендует использовать сервисный аккаунт JSON по одной причине: **Срок действия EAB истекает через 7 дней**, и только сохраненный сервисный аккаунт допускает **автоматический повторный запрос** без ручной работы.

## 4.6 Часто задаваемые вопросы: могу ли я использовать ключ API?

**Нет.** Это не вариант реализации — **Google явно отклоняет его** (проверено в обоих направлениях):

```bash
# 1) Query parameter
curl -X POST "https://publicca.googleapis.com/v1/projects/<ID>/locations/global/externalAccountKeys?key=AIza..." -d '{}'
# 2) x-goog-api-key header recommended by the official docs
curl -X POST "https://publicca.googleapis.com/v1/projects/<ID>/locations/global/externalAccountKeys" \
     -H "x-goog-api-key: AIza..." -d '{}'
```

Оба возвращаются:

```json
{"error":{"code":401,"status":"UNAUTHENTICATED",
  "message":"API keys are not supported by this API. Expected OAuth2 access token
             or other authentication credentials that assert a principal."}}
```

Для сравнения: возвращается **(поддельный) носитель OAuth**.
`Request had invalid authentication credentials. Expected OAuth 2 access token...` —
поэтому OAuth распознается, в то время как **ключи API полностью отклоняются** ✗.

**Почему**: создание EAB — это **административная операция**, требующая знания того, «кто вы и есть ли у вас `roles/publicca.externalAccountKeyCreator`» ✗
— ключ API идентифицирует только проект/приложение ✓ и **не выражает основную идентичность** ✓.
(В «Рекомендациях по управлению ключами API» Google рекомендуется использовать **IAM + кратковременные учетные данные сервисной учетной записи** для административных сценариев ✓ — здесь используется тот же подход ✓.)

**Итак, есть только три пути** ✓ (см. §3): сервис-аккаунт JSON ✓ / токен временного доступа ✓ /
или **нет учетных данных вообще** — запустите `gcloud publicca external-account-keys create` в Cloud Shell ✓
и введите `keyId` / `b64MacKey` на панель ✓ (**используйте это, если GCP IAM блокирует вас** ✓).

## 5. Автоматическая регистрация и продление (важно)

```
Panel: CA = Google Public CA
  ├─ usable EAB present in the config → use it
  └─ missing/expired → request a new one on the spot with the stored service-account JSON (auto-registration)
        │
First issuance on the node/panel ── registers the ACME account with EAB (one-time!)
        │
Account persisted: data/acme/accounts/google.json (panel) / <Agent data_dir>/acme/accounts/google.json (node)
        │
Every later renewal ── uses the account key only; **EAB is never needed again**
```

Поэтому:

- **Первый выпуск регистрируется автоматически**; никакой ручной шаг GCP не требуется;
- При продлении **не** используется EAB (при условии, что файл учетной записи существует и каталог данных остается стабильным);
- ⚠ Каталог данных ACME на стороне агента представляет собой фиксированный абсолютный путь (по умолчанию `/var/lib/corefusion-agent/acme`);
 **не меняйте его случайно**, иначе он будет считаться новой учетной записью → требуется другой ключ EAB.

## 6. Устранение неполадок

| Симптом/ошибка | Причина | Исправить |
|---|---|---|
| `PERMISSION_DENIED` (403) | В сервисной учетной записи отсутствует `roles/publicca.externalAccountKeyCreator`. | Вернитесь к разделу 3 ④. |
| `SERVICE_DISABLED` (403) | `publicca.googleapis.com` не включен для проекта. | Раздел 3 ② |
| `NOT_FOUND` (404) | Неверный идентификатор проекта / проект удален. | Проверьте идентификатор проекта |
| Отчеты о выдаче `externalAccountRequired` | В этом ЦС нет EAB. | Сначала запросите/настройте EAB на панели. |
| Отчеты о выдаче `Accounts must have at least one contact.` | При регистрации не был указан адрес электронной почты | Установите адрес электронной почты учетной записи ACME на странице сертификата (панель использует учетную запись по умолчанию). |
| При продлении снова запрашивается EAB / регистрация не удалась. | Файл учетной записи ACME потерян (каталог данных изменен/очищен) | **Восстановить резервную копию**; без него запросите новый EAB, используя сервисную учетную запись |
| Эмитент меняется с Google на Let's Encrypt. | В команде обновления отсутствует центр сертификации (старая ошибка, исправлена в версии 0.12.101) | Обновление и переиздание |

## 7. Рекомендации по безопасности и эксплуатации

1. **Наименьшие привилегии**: предоставить сервисной учетной записи только `roles/publicca.externalAccountKeyCreator`, но не владельцу/редактору.
2. **Не удаляйте проект**: удаление проекта GCP делает недействительными все его учетные записи ACME → сертификаты не могут быть продлены.
3. **Всегда создавайте резервные копии** `data/acme/accounts/` (сам идентификатор учетной записи) и конфигурации EAB базы данных панели.
4. **Не паникуйте по поводу истечения срока действия EAB**: пока существует файл учетной записи ACME, продление не затрагивается; новый EAB нужен только для регистрации новой учетной записи.
5. Если ключ сервисной учетной записи мог утечь: удалите этот ключ в GCP и вставьте новый JSON в панель.

|---|---|
