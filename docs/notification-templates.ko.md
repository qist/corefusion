# 알림 템플릿 변수

> 언어: [简体中文](notification-templates.md) · [English](notification-templates.en.md) · [繁體中文](notification-templates.zh-TW.md) · [Русский](notification-templates.ru.md) · [日本語](notification-templates.ja.md) · 한국어 · [Deutsch](notification-templates.de.md) · [Français](notification-templates.fr.md) · [Español](notification-templates.es.md) · [Português](notification-templates.pt.md) · [Türkçe](notification-templates.tr.md) · [Bahasa Indonesia](notification-templates.id.md) · [ไทย](notification-templates.th.md) · [Tiếng Việt](notification-templates.vi.md) · [العربية](notification-templates.ar.md) · [فارسی](notification-templates.fa.md)

알림 템플릿은 전송할 때 실제 값으로 대체되는 `{variable}` 자리 표시자를 사용합니다. 이 문서에는 지원되는 모든 변수, 이벤트당 사용 가능한 변수 및 자동 트리거 규칙이 나열되어 있습니다.

## 1. 템플릿 유형 및 대상

| 청중 | 채널 | 수신자 | 일반적인 사용 |
|---|---|---|---|
| **패널 사용자**(관리자) | Telegram / 이메일 | 관리자가 구성한 채널 및 수신자 | 노드 경고, 백업 보고서, 시스템 공지 |
| **구독자** | 이메일 | 고객 본인의 이메일(자동으로 입력됨) | 잔액 부족, 구독 만료 알림 |

## 2. 공통변수

모든 템플릿에서 사용 가능:

| 변수 | 설명 | 예 |
|---|---|---|
| `{time}` | 보내는 시간 | `2026-09-28 14:30:00` |
| `{user}` | 고객 이메일(구독자 템플릿)/사용자 식별자 | `user@example.com` |
| `{message}` | 통지 본문 | 유지보수 공지 텍스트 |

## 3. 구독자 이벤트 변수

### 구독 만료 알림(event_key = `subscription_expire`)

매일 스캔하여 7일 이내에 만료되는 활성 구독자에게 전송됩니다.

| 변수 | 설명 | 예 |
|---|---|---|
| `{user}` | 고객 이메일 | `user@example.com` |
| `{expire_date}` | 구독 만료 | `2026-10-05 09:00` |
| `{days}` | 남은 일수 | `7` |
| `{time}` | 보내는 시간 | `2026-09-28 09:05:00` |

### 잔액 부족 알림(event_key = `balance_low`)

매일 스캔하여 잔액이 기준액 미만인 고객에게 전송됩니다.

| 변수 | 설명 | 예 |
|---|---|---|
| `{user}` | 고객 이메일 | `user@example.com` |
| `{balance}` | 현재 잔액(통화 단위, 소수점 이하 두 자리) | `0.85` |
| `{time}` | 보내는 시간 | `2026-09-28 09:05:00` |

## 4. 작업 템플릿 예시 변수

연결 테스트를 위해 "보내기"를 클릭하면 패널 사용자 템플릿이 다음 예제로 자리 표시자를 채웁니다.

| 변수 | 설명 | 예 |
|---|---|---|
| `{node}` | 노드 이름 | `node-01` |
| `{backup_file}` | 백업 파일 이름 | `corefusion-20260101-0900.tar.gz` |
| `{size}` | 파일 크기 | `128MB` |
| `{domain}` | 도메인 | `example.com` |
| `{expire_date}` | 만료일 | `2026-10-12` |
| `{days}` | 남은 일수 | `14` |
| `{count}` | 개수 | `3` |

## 5. 자동 트리거 규칙

- **일정**: 첫 번째 검사는 패널이 시작된 후 30초 후에 실행된 후 매일 **09:05**에 실행됩니다.
- **구독 만료**: 7일 이내에 만료되는 활성 구독(`status=active`)을 검색합니다. 고객도 활성 상태여야 합니다.
- **낮은 잔액**: 잔액이 임계값 이하인 활성 고객을 검색합니다. 임계값은 `notify.balance_threshold`(**센트 단위**)입니다(기본값 `100` = 1.00).
- **중복 제거**: 이벤트당 고객당 메시지 최대 1개 **매일**(`notification_send_logs`는 일별 중복 제거)

## 6. 노드 상태 모니터링

노드 하트비트는 지속적으로 확인됩니다. **상태가 변경될 때만 알림이 전송됩니다. 변경 사항이 없는 라운드는 자동으로 처리됩니다**:

| 설정 키 | 설명 | 기본값 |
|---|---|---|
| `monitor.node_interval_seconds` | 확인 간격(초) | `60`(최소 30개) |
| `monitor.node_offline_timeout_seconds` | 하트비트 시간 초과(초) | `120` |

- **오프라인 경고**: 노드가 온라인에서 오프라인으로 전환되면 `{node}`(이름) 및 `{time}`와 함께 관리 템플릿 "**노드 오프라인 경고**"를 보냅니다.
- **복구 알림**: 노드가 복구되면 동일한 변수로 “**노드 복구 알림**”을 보냅니다.
- **자동 라운드**: 상태가 변경되지 않으면 메시지가 표시되지 않습니다. 패널이 다시 시작된 후 첫 번째 라운드에서는 기준선만 설정됩니다.
- **보내지 않고 모니터링**: 해당 템플릿을 비활성화합니다(활성화됨 = 꺼짐).

## 7. 노드 월간 트래픽 할당량 알림(자동)

- **트리거**: 노드의 월간 트래픽이 할당량 임계값에 도달하면 "**노드 트래픽 할당량 알림**"을 보냅니다. 100%를 초과하여 일시 중지되면 제한 초과 경고를 보냅니다(이벤트 키 `traffic_quota_threshold` / `traffic_quota_exceeded`).
- **임계값**: `monitor.traffic_quota_threshold_percent`(백분율, 기본값 `80`, 임계값 경고를 비활성화하려면 `0`를 설정)
- **중복 제거**: 청구 주기당 노드당 최대 1개(주기는 노드의 `traffic_quota_reset_day`를 따릅니다)
- 사용 가능한 변수: `{node}`(이름), `{used}`(사용된 GB), `{quota}`(GB 할당량), `{percent}`(백분율), `{time}`

## 8. 백업 결과 알림(자동)

- **트리거**: 예약된 백업(`BackupScheduler`) 실행 후 즉시 전송됩니다. 성공하면 "**일일 백업 보고서**"가 전송되고, 실패(백업 생성/스토리지 읽기/원격으로 업로드)는 "**백업 실패 경고**"가 전송됩니다.
- 사용 가능한 변수: `{backup_file}`(이름), `{size}`(크기, 성공 보고서만), `{message}`(실패 이유, 실패 경고만), `{time}`
- **보내지 않고 모니터링**: 템플릿이 비활성화되면 자동으로 건너뜁니다(활성화 = 꺼짐).

## 9. 인증서 만료 알림(자동)

- **트리거**: 매일 09:05에 만료가 임박한 `active` 인증서(**3일 남은 IP 인증서**, **7일 남은 도메인 인증서**)를 검색하고 인증서별로 관리 템플릿 "**인증서 만료 알림**"을 보냅니다.
- **중복 제거**: 하루에 인증서당 최대 1개의 알림; 갱신 후 만료 기간(IP 3일/도메인 7일)이 벗어나고 알림이 중지됩니다.
- 사용 가능한 변수: `{domain}`(인증서 도메인), `{expire_date}`(만료일), `{days}`(남은 일수), `{time}`

## 10. 핵심 프로세스 충돌 경고(자동)

- **트리거**: 핵심 프로세스(xray/singbox)가 비정상적으로 종료되거나 프록시 프로세스(caddy/nginx)가 충돌하는 경우 관리 템플릿 "**핵심 프로세스 충돌 경고**"를 즉시 보냅니다. 그런 다음 감독자는 지수 백오프로 다시 시작합니다.
- 사용 가능한 변수: `{core}`(프로세스 유형), `{restarts}` / `{max}`(다시 시작 횟수/제한), `{message}`(종료 메시지, 핵심 프로세스만 해당), `{time}`
- **보내지 않고 모니터링**: 템플릿이 비활성화되면 자동으로 건너뜁니다(활성화 = 꺼짐).

## 11. 신규 사용자 등록 알림(자동)

- **트리거**: 고객이 성공적으로 등록한 직후에 "**신규 사용자 등록 알림**" 관리 템플릿을 사용하여 전송됩니다.
- 사용 가능한 변수: `{user}`(고객 이메일), `{time}`

## 12. 사용법

1. **템플릿 추가**: 알림 설정 → 알림 템플릿 → 템플릿 추가 → "사전 설정에서 채우기" 및 필요에 따라 조정
2. **활성화**: 활성화를 선택하고 저장합니다. 자동 트리거는 활성화된 템플릿만 처리합니다.
3. **테스트**: 목록에서 "보내기"를 클릭하면 예제 변수가 포함된 실제 메시지를 보낼 수 있습니다. (구독자 템플릿 테스트 이메일은 관리자의 보낸 사람 주소로 이동합니다.)
4. **즉시 알림**(비즈니스 코드): 이벤트 현장에서 `NotifyClientEvent(ctx, db, settingSvc, eventKey, clientEmail, vars)`로 전화(충전, 차감, 갱신)하여 일일 스캔 한도를 초과하면 단일 고객에게 즉시 알림
